# 长视频时序检索与高效多模态理解：项目总结

更新时间：2026-10-10

## 1. 项目概述

本项目使用 Qwen3-VL-8B-Instruct 构建长视频时序检索系统。系统不直接让大模型对整段长视频进行密集理解，而是采用“低帧率全局检索 + 候选时间窗口生成 + 多帧候选片段重排”的粗到细方案。

核心目标是：给定一个自然语言 Query，从长视频中定位与 Query 对应的时间片段，并用 Temporal IoU 评估定位质量。

当前系统只使用 Qwen3-VL，没有引入 SigLIP、CLIP 或其他独立视觉检索编码器。

## 2. 系统架构

```text
ActivityNet Captions 视频级标注
        ↓
0.5 FPS 全局采样
        ↓
LoRA-R：Query-Frame 相关性打分
        ↓
Temporal Importance Score + 时间 NMS
        ↓
32 秒候选时间窗口
        ↓
每个候选窗口抽取 4 帧
        ↓
LoRA-U：多帧候选片段理解与 logit 重排
        ↓
输出 Top-1 / Top-K 时间候选片段
```

其中：

- LoRA-R 负责回答“哪些帧值得进入候选片段”；
- 候选窗口模块负责将离散帧分数转换为连续时间区间；
- LoRA-U 负责在候选片段之间进行更细粒度的 Query-片段匹配；
- LoRA-R 和 LoRA-U 都基于同一个 Qwen3-VL-8B-Instruct 基座独立训练。

## 3. 数据集与划分

数据来自 ActivityNet Captions，并保留同一视频的多个 Query。每个 Query 包含一个或多个 Ground Truth 时间区间 `gt_segments`。

| 数据项 | 数量 |
|---|---:|
| 视频 | 300 |
| Query | 726 |
| 0.5 FPS 帧级样本 | 35,001 |
| train 视频 / Query / 帧 | 210 / 507 / 23,844 |
| val 视频 / Query / 帧 | 45 / 109 / 5,646 |
| test 视频 / Query / 帧 | 45 / 110 / 5,511 |

train、val、test 按视频划分，三个 split 之间不存在视频交叉。

### LoRA-U 候选片段数据

候选窗口默认长度为 32 秒，候选窗口与 GT 区间的 Temporal IoU 大于等于 0.3 时标记为正样本；IoU 在 0.1～0.3 之间的窗口优先作为边界 Hard Negative。

| 数据项 | 数量 |
|---|---:|
| LoRA-U train 样本 | 4,559 |
| LoRA-U val 样本 | 948 |
| 每个样本的帧数 | 4 |
| train 正样本 / 负样本 | 2,402 / 2,157 |
| train Hard Negative | 770 |

## 4. LoRA-R：Query-Frame 检索

### 4.1 训练方式

LoRA-R 使用 QLoRA 微调：

- 基座模型：Qwen3-VL-8B-Instruct；
- 4-bit NF4 量化；
- LoRA rank：16；
- LoRA alpha：32；
- 训练目标：只让 assistant 输出单 token `1` 或 `0`；
- 训练步数：1,000 steps。

推理时不依赖自由生成文本，而是计算：

```text
S_q(t) = sigmoid(logit("1") - logit("0"))
```

该分数表示 Query 与时间戳 `t` 对应视频帧的相关性。

### 4.2 帧级检索结果

在完整 0.5 FPS test 帧上的 video macro 结果：

| 指标 | 结果 |
|---|---:|
| AP | 0.6364 |
| Recall@1 | 0.6407 |
| Recall@5 | 0.8704 |
| Recall@10 | 0.9222 |
| Recall@20 | 0.9778 |

对应结果文件：[full_test_metrics_300videos_1000steps.json](./output/full_test_metrics_300videos_1000steps.json)

## 5. 候选时间窗口生成

候选窗口生成过程如下：

1. 对帧级相关性分数进行局部时间平滑；
2. 使用 Temporal Importance Score 排序；
3. 使用时间 NMS 避免候选窗口过度重叠；
4. 以高分帧为中心扩展为 32 秒时间窗口；
5. 计算候选窗口与 GT 区间的 Temporal IoU。

当前配置：

- 窗口长度：32 秒；
- NMS 时间阈值：4 秒；
- 平滑半径：2 秒；
- 平滑权重：0.25；
- 每个 Query 最多保留 10 个候选窗口。

LoRA-R 原始排序在完整 test 候选窗口上的 video macro 结果：

| 指标 | 结果 |
|---|---:|
| Recall@1，tIoU≥0.3 | 52.96% |
| Recall@5，tIoU≥0.3 | 81.11% |
| Recall@10，tIoU≥0.3 | 90.00% |
| mean Best tIoU@5 | 0.5496 |

候选窗口结果：[full_temporal_metrics_300videos_1000steps_w32s.json](./output/full_temporal_metrics_300videos_1000steps_w32s.json)

## 6. LoRA-U：候选片段多帧理解

LoRA-U 以候选窗口内按时间均匀抽取的 4 帧作为输入，训练 Qwen3-VL 判断候选片段是否与 Query 对应。

训练提示词和标签采用：

```text
Query + 4 帧候选片段 → 输出 1 或 0
```

训练结果：

- 训练步数：1,000；
- train loss：0.2487；
- eval loss（500 steps）：0.2206；
- eval loss（1,000 steps）：0.2196；
- Adapter：[lora_u_300videos_1000steps](./output/lora_u_300videos_1000steps)。

正式评估使用 `logit("1") - logit("0")` 作为候选片段相关性分数，并按照该分数对原始 Top-10 候选重排。

## 7. LoRA-U 重排结果

评估集包含 1,064 个候选片段、110 个 Query 和 45 个 test 视频。三种排序方式使用完全相同的候选集合。

| 方法 | Video Recall@1，tIoU≥0.3 | Video Recall@5，tIoU≥0.3 | Video Recall@5，tIoU≥0.5 | Video mean tIoU@5 |
|---|---:|---:|---:|---:|
| LoRA-R 原始排序 | 52.96% | 81.11% | 58.15% | 0.5496 |
| 基础 Qwen3-VL 重排 | 60.74% | 85.56% | 61.48% | 0.5707 |
| LoRA-U 重排 | 57.41% | **86.67%** | 60.74% | **0.5761** |

结论：

- LoRA-U 相比 LoRA-R 原始排序，Top-5 Recall@5 提升 5.56 个百分点；
- LoRA-U 的 Top-5 平均 Temporal IoU 最高；
- 基础 Qwen3-VL 的 Top-1 Recall 更高；
- LoRA-U 没有在所有指标上全面超过基础模型，因此应保守表述为“改善 Top-K 候选排序”，而不是“全面提升检索效果”。

## 9. 当前边界与后续工作

当前已经完成两阶段离线实验，但仍有以下边界：

1. 当前正式评估基于已抽取的 0.5 FPS JPG 帧，尚未封装为从原始 MP4 到最终时间段的一键推理脚本；
2. LoRA-U train 候选由训练过 LoRA-R 的模型生成，存在候选生成偏容易的可能；更严格的方案是使用交叉生成候选；
3. 当前 LoRA-U 与 LoRA-R 分数尚未在 val 集上做融合权重调参；
4. 还没有进行多随机种子和多 checkpoint 稳定性实验；
5. 初期的 YES/NO 生成评估不作为正式结论，正式结果使用了与 LoRA-U 训练一致的 `0/1` logit 打分。

下一步建议：

```text
val 集调节 LoRA-R 分数与 LoRA-U 分数的融合权重
        ↓
固定融合权重
        ↓
在 test 集做一次最终评估
        ↓
固化端到端推理脚本和最终项目指标
```

## 10. 简历表述建议

可以将当前成果表述为：

> 基于 Qwen3-VL-8B-Instruct 构建长视频时序检索系统，采用 QLoRA 分别训练 Query-Frame 检索适配器 LoRA-R 和候选片段多帧理解适配器 LoRA-U；通过 0.5 FPS 全局检索、Temporal Importance Score、时间 NMS 生成候选窗口，并利用多帧 logit 重排提升候选片段定位效果。在 300 个 ActivityNet Captions 视频、726 个 Query 上，LoRA-U 重排将 video macro Recall@5（tIoU≥0.3）从 81.11% 提升至 86.67%，mean Best tIoU@5 从 0.5496 提升至 0.5761。

这里的指标应明确标注为 test 候选重排结果，不应表述为所有 Top-1 指标均提升。

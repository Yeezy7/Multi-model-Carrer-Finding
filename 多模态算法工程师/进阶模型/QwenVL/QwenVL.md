# Qwen-VL 系列：从 Qwen-VL 到 Qwen3-VL

## 一句话解释

**Qwen-VL 系列**是通义千问的视觉语言模型家族，核心设计思路是 **ViT 视觉编码器 + 视觉 Token 压缩/合并 + LLM 生成**，并在四代演进中逐步解决了分辨率适配（动态分辨率）、位置编码（M-RoPE 3D 时空）、视觉 Token 压缩（固定 → 自适应）、超长上下文（256K~1M token）与长视频理解等 VLM 关键难题。

面试记忆点：**四代演进主线 = 分辨率从固定到动态 + 位置编码从 1D/2D 到 3D（时空） + Token 压缩从固定重采样到自适应 + 视觉编码器持续升级。**

---

## 1. 系列演进总览

| 版本 | 时间 | LLM 底座 | 视觉编码器 | 连接方式 | 分辨率策略 | 单图视觉 token | 核心突破 |
|------|------|---------|-----------|---------|-----------|---------------|---------|
| Qwen-VL | 2023.09 | Qwen-7B | OpenCLIP ViT-bigG（1.9B，冻结为主） | 单层 Cross-Attention（256 个可学习 query） | 固定 224/448 | 固定 256 | 首次打通图文对话 + 定位 + OCR，中英双语 |
| Qwen2-VL | 2024.09 | Qwen2-1.5B/7B/72B | 自研 ViT 675M（patch 14） | 2×2 分组卷积 + MLP 合并（4 倍压缩） | **Naive Dynamic Resolution**（任意分辨率） | 动态 4~16384 | 动态分辨率、M-RoPE、视频 2fps 统一建模 |
| Qwen2.5-VL | 2025.01 | Qwen2.5-3B/7B/72B | 自研 ViT 675M（**Window Attention**） | 2×2 分组 + 2 层 MLP（动态 token 预算） | 原生分辨率 + 动态 FPS | 动态 4~16384 | 文档解析、绝对时间戳定位、Agent |
| Qwen3-VL | 2025.09 | Qwen3 密集 + MoE（30B-A3B 等） | **SigLIP-2 架构**（SO-400M 级，patch 16） | 2×2 MLP 合并 + **DeepStack** 多级特征注入 | 原生分辨率 + 256K~1M 上下文 | 动态 256~1280（默认） | MoE、双思维模式、Interleaved-MRoPE、长视频 |

> 面试记忆点：四代演进的本质是解决三个问题——
> 1. **看得清**：分辨率从固定 → 动态（不丢小字、小物体）；
> 2. **看得懂**：位置编码从 1D → 3D（理解空间布局 + 时间先后）；
> 3. **看得久**：token 压缩从固定 → 自适应（控制计算量与显存）。

## 2. Qwen-VL（2023）：第一代，用 Cross-Attention 打开视觉大门

### 2.1 架构总览

Qwen-VL 由三部分组成，总参数量约 9.6B：

| 组件 | 参数量 | 初始化 | 说明 |
|------|--------|--------|------|
| LLM | 7.7B | Qwen-7B | 语言底座，支持中英双语 |
| 视觉编码器 | 1.9B | OpenCLIP ViT-bigG | patch 14，阶段 1/3 冻结 |
| 位置感知 VL Adapter | 0.08B | 随机初始化 | 单层 Cross-Attention 重采样器 |

```text
图像 ──> ViT-bigG (patch 14) ──> N 个 patch token
                                    │
                    单层 Cross-Attention（256 个可学习 query）
                                    │
                            固定 256 个视觉 token
                                    │
                           Qwen-7B LLM 生成
```

### 2.2 Re-Attention 重采样器（核心模块）

ViT 输出的 patch token 数量随分辨率变化（224 时 256 个、448 时 1024 个），直接全量喂 LLM 会导致序列长度不可控。Qwen-VL 的解法是一个轻量的**单层 cross-attention 模块**：

$$\text{Attn}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d}}\right) V$$

- $Q \in \mathbb{R}^{256 \times d}$：256 个**可学习 query 向量**（相当于"从图像里提取哪些信息的模板"）；
- $K, V \in \mathbb{R}^{N \times d}$：ViT 输出的图像 patch 特征（$N$ 为 patch 数）；
- 输出固定 256 个视觉 token，与输入分辨率无关。

**关键工程细节**：2D 绝对位置编码注入 **Q、K pair 中**（而非单独叠加），避免重采样过程中空间位置信息丢失——这就是"位置感知"的来源。

> **⚠️ 精确数字澄清（面试易错）**：网上流传的"448 个 token 压到 256 个"是**错误**说法。正确事实是：**448 是输入分辨率（像素），不是 token 数**。448×448、patch 14 → 32×32 = 1024 个 patch token，重采样压缩到 256 个（4 倍压缩）。224×224 时 ViT 输出 256 个 patch，重采样后仍为 256 个。

### 2.3 三阶段训练

| 阶段 | 数据 | 分辨率 | 冻结策略 |
|------|------|--------|---------|
| 阶段 1 预训练 | 清洗后 14 亿图文对（LAION 等，约 77% 英文 / 23% 中文） | 224×224 | **冻结 LLM**，训练 ViT + Adapter |
| 阶段 2 多任务预训练 | 细粒度标注：字幕、VQA、定位（image-caption-box 三元组）、OCR、交错图文 | 448×448 | **全部解冻**（ViT 用低学习率） |
| 阶段 3 指令微调 | 350K 指令数据（Chat 格式） | 448×448 | **冻结 ViT**，训练 LLM + Adapter |

三个阶段的"冻结策略"各有讲究：
- 阶段 1 冻结 LLM：先让视觉部分学会"把图像翻译成 LLM 能读的 token"；
- 阶段 2 全解冻：多任务数据让视觉塔和 LLM 充分对齐；
- 阶段 3 冻结 ViT：指令微调阶段数据量小，冻结视觉塔防止过拟合与特征漂移。

### 2.4 输入输出接口：为定位而生

- 特殊 token：`<img>` / `</img>` 包裹视觉 token 序列；
- 框坐标归一化到 [0, 1000)，文本化为 `(x_tl, y_tl), (x_br, y_br)`；
- `<box>`/`</box>` 标记检测框、`<ref>`/`</ref>` 标记描述对象——这是最早的"用纯文本 token 表达位置"的方案之一。

### 2.5 局限（为什么必须被第二代取代）

1. **固定分辨率**：448×448 对文档、小字 OCR 依然不够清晰；
2. **固定 256 token**：高分辨率图像的信息被过度压缩；
3. **1D 位置编码**：视频只是"图片串"，没有时空建模能力；
4. **ViT 阶段 1/3 冻结**：视觉表示与 LLM 的对齐不够充分。

## 3. Qwen2-VL（2024）：动态分辨率 + M-RoPE，架构大改版

第二代是架构级的重写，三个核心创新：

### 3.1 Naive Dynamic Resolution（原生动态分辨率）

**旧问题**：固定 resize 到 224/448 会：小字、小物体被压缩模糊；长宽比变形（拉伸）；信息密度不均。

**新方案（Qwen2-VL 的做法）**：

1. 定义**最小 patch 网格单元**：28×28 像素（patch14 × 2×2 合并后的等效单元）；
2. 图像按**原始长宽比**切分为 $n \times m$ 个 28×28 网格（n、m 为整数，可变）；
3. 每个网格交给 ViT（patch14）编码，特征再经 2×2 合并与 MLP 投影；
4. 视觉 token 数 = 网格数（每格 1 个 token），与分辨率成正比。

```text
例：256×256 的图 → 256/28 ≈ 9.1 → 9×9 网格 → 81 个视觉 token
    448×448 的图 → 16×16 网格 → 256 个视觉 token
```

**上限控制**：论文设置单图视觉 token 上限 16384（对应超大分辨率），防止极端大图打爆显存。

**动态分辨率为什么重要**：
- 文档/OCR：小字必须高清输入才能识别；
- 图表/截图：不同长宽比天然适应；
- 细粒度定位：不再因缩放损失空间精度。

### 3.2 M-RoPE（Multimodal Rotary Position Embedding）

**背景**：文本的 RoPE 是 1D（只有序列位置），图像需要 2D（高、宽），视频需要 3D（时间、高、宽）。Qwen2-VL 把 RoPE 扩展为 **3D 时空位置编码**：

$$\text{MRoPE}(x, (t, h, w)) = R(t \cdot \theta_t + h \cdot \theta_h + w \cdot \theta_w) \cdot x$$

- 视频 token：携带 (时间, 高, 宽) 三维位置；
- 图像 token：时间维度为 0，只带 (高, 宽)；
- 文本 token：保持传统 1D RoPE；
- 通过 mrope_section（如 [16, 24, 24]）把隐藏维度切分给时间/高/宽三个轴。

**M-RoPE 为什么重要**：
1. 让 LLM 感知**空间布局**（左上/右下/相对位置）；
2. 让 LLM 感知**时间先后**（视频第几帧、事件先后顺序）；
3. 视频理解、跨帧推理、时间戳定位都依赖它；
4. 记忆口诀：**文本 1D、图像 2D、视频 3D**。

### 3.3 视觉 Token 压缩：2×2 卷积 + MLP

- ViT 输出后先做 **2×2 分组**（相邻 2×2 的 patch 特征合并成 1 组）；
- 合并后过 **MLP** 投影到 LLM 维度；
- **压缩率固定 4 倍**（patch14 的 4×4 patch 区域 → 1 个 token，等效 28×28 像素区域 → 1 token）；
- 权重可学习，属于"固定比例压缩"。

```text
ViT 输出: [B, H_p×W_p, D_vit]   （448 图: 32×32 = 1024 个）
2×2 合并: [B, (H_p/2)×(W_p/2), D_vit]  （1024 → 256 个）
MLP 投影: [B, 256, D_llm]
```

### 3.4 其他升级

- ViT 从冻结变为 675M **可训练**，patch 14；
- 支持**交错图文输入**（同一序列中多张图与文本交错）；
- 视频统一按 **2fps 抽帧**建模，支持 20 分钟以上长视频；
- 多语言 OCR 大幅增强（新增大量文档类训练数据）；
- 尺寸：1.5B / 7B / 72B。

### 3.5 相对第一代的提升（论文数字）

- 文档理解（DocVQA）与 OCR（OCRBench）大幅领先一代；
- 视频理解：MVBench 等任务显著提升（得益于 M-RoPE 时间维度）；
- 定位（RefCOCO 系列）能力跃升（动态分辨率 + 2D 空间感知）。

## 4. Qwen2.5-VL（2025）：Window Attention + 动态 Token 预算

### 4.1 视觉编码器升级

| 改进 | 说明 |
|------|------|
| **Window Attention** | 高分辨率图像在 ViT 内部**分窗**计算注意力（窗口 8×8 patch），计算量随分辨率线性增长而非平方；每 8 层在全局层（如第 7/15/23/31 层）恢复全局交互 |
| **Visual Token Merger** | 用可学习的"合并向量"通过 Cross-Attention 与视觉特征交互，**自适应**决定保留多少视觉 token（替代 Qwen2-VL 的固定 2×2 卷积） |
| **动态 Token 预算** | 可根据任务/显存设置每张图的 token 上限（256~16384），控制计算成本 |

**Window Attention 为什么是必须的**：Qwen2-VL 的全局注意力在超高分辨率下计算量是 $O((H_p W_p)^2)$，4096×4096 的图 patch 数巨大，全局注意力直接不可行。分窗后复杂度降为 $O(H_p W_p \cdot k^2)$（k 为窗口大小），文档/长图场景才跑得动。

### 4.2 能力增强

- **文档解析**：版面分析、表格还原（HTML/LaTeX 输出）、公式 OCR 接近商用 OCR 服务；
- **绝对时间戳定位**：能回答"事件发生在第几秒"，靠 M-RoPE 时间维度 + 绝对时间对齐训练；
- **绝对坐标定位**：输出物体在图像中的绝对坐标（无需固定区间映射）；
- **Agent 能力**：作为视觉 Agent 调用工具（OCR、检测器、搜索）；
- **动态 FPS**：视频按内容复杂度自适应抽帧（静态场景低帧率、运动场景高帧率）；
- 尺寸：3B / 7B / 32B / 72B。

## 5. Qwen3-VL（2025）：MoE + 双思维模式 + 超长上下文

> 如果你的简历里有"Qwen3-VL-32B 部署与视觉 Token 裁剪"，这一节是面试重点。

### 5.1 MoE 架构

- 代表模型 **Qwen3-VL-30B-A3B**：总参数约 30B，每 token 仅激活约 3B（MoE 稀疏激活，推理算力接近 3B 密集模型）；
- 更大的 **Qwen3-VL-235B-A22B**：总参数 235B、激活 22B；
- 视觉编码器：换用 **SigLIP-2 架构**（SO-400M 级，patch 16），并升级位置编码为 **Interleaved-MRoPE**（多维位置交错编码）；
- **DeepStack**：把 ViT 不同层级的特征（浅层纹理 + 深层语义）注入 LLM 不同层，提升细粒度感知；
- 支持超高分辨率（>1M 视觉 token 级输入能力）；
- 部署注意：**MoE 激活参数少 → 单 token 算力低，但全量权重仍需多卡显存**（30B-A3B 的权重按 BF16 约 60GB+）。

### 5.2 双思维模式（Thinking / Non-Thinking）

| 模式 | 行为 | 适用场景 |
|------|------|---------|
| **Thinking** | 先输出推理链（CoT）再给结论 | 复杂视觉推理、数学图表题、多步判断 |
| **Non-Thinking** | 直接输出答案，低延迟 | 快速问答、OCR、命名实体、日常对话 |

- 通过系统提示词切换（如 `<thinking>` 标签）；
- Thinking 模式的能力来自训练阶段用 RL 强化推理（类似 Qwen3 文本模型的思路）；
- 部署含义：复杂任务耗时会翻倍（推理链长），需要按任务类型配置超时与 token 预算。

### 5.3 超长上下文与长视频

- 上下文窗口原生 **256K token**，可扩展至 **1M**（YaRN 外推）；
- 可处理数小时视频；
- 视频 token 做更激进压缩（帧合并 + M-RoPE 时间轴），长视频下视觉 token 仍是主要开销——这正是"视觉 Token 裁剪"优化空间大的原因。

## 6. 关键技术细节（面试深挖）

### 6.1 视觉 Token 完整流程

```text
原始图像
  → 动态网格切分（28×28 单元，原始长宽比）
  → ViT 编码（patch14，Qwen2.5 起 Window Attention）
  → Token 合并（Qwen2: 2×2+MLP 固定 4 倍 / Qwen2.5: Visual Token Merger 自适应）
  → MLP 投影到 LLM 维度
  → 与文本 token 拼接（<image> 占位符）
  → LLM 自回归生成
```

**token 数量估算（面试必答）**：
- Qwen2-VL 一张 448×448 图：448/28 = 16 格/边 → 16×16 = **256 个视觉 token**；
- Qwen-VL（一代）一张 448 图：1024 patch → 重采样后固定 **256 个**；
- 高分辨率图（如 1600×1200）：约 57×43 = 2451 个视觉 token → 显存与 KV cache 压力剧增；
- 多图/视频：token 数线性累加，视频 2fps 抽帧后按帧累加。

### 6.2 M-RoPE 深入

- 传统 2D 位置编码无法表达视频的**时间先后**；
- M-RoPE 把位置拆成 (时间, 高, 宽) 三个轴，每个轴对应一段隐藏维度（mrope_section）；
- 视频理解、跨帧推理、时间戳定位都依赖它；
- Qwen3-VL 升级为 **Interleaved-MRoPE**：把时间/空间维度交错排列进旋转向量，进一步提升多模态混合序列的建模能力。

### 6.3 动态分辨率 vs 固定分辨率

| 项目 | 固定分辨率（Qwen-VL） | 动态分辨率（Qwen2+） |
|------|---------------------|---------------------|
| 小物体/小字 | 压缩模糊 | 保持清晰 |
| 长宽比 | 变形 | 不变形 |
| 计算量 | 固定 | 随分辨率增长（可控） |
| 显存 | 可控 | 高分辨率有爆显存风险 |
| 实现复杂度 | 简单 | 需要动态网格 + token 数变化 |

### 6.4 三代压缩方案对比

| 方案 | 模型 | 压缩率 | 特点 |
|------|------|--------|------|
| Cross-Attention 重采样（固定 256） | Qwen-VL | 不定（随分辨率） | token 数固定，但高分辨率信息丢失 |
| 2×2 卷积 + MLP（固定 4 倍） | Qwen2-VL | 固定 4 倍 | 简单高效，无法自适应 |
| Visual Token Merger（动态预算） | Qwen2.5-VL | 可配置 | 自适应保留信息，支持预算控制 |

## 7. 训练策略详解

### 7.1 训练数据构成（以 Qwen2-VL 为例）

| 阶段 | 数据 | 说明 |
|------|------|------|
| 预训练（对齐） | 大规模图文对（约 6.4 亿） | 视觉塔 + 投影层对齐 |
| 多任务预训练 | VQA、OCR、定位、caption、交错图文 | 全参数训练，视觉塔参与 |
| SFT | 指令数据（图文对话、文档问答、视频 QA） | 对齐到任务格式 |

### 7.2 训练要点

- 视觉塔与 LLM 的**学习率分层**（视觉塔低 lr，LLM 高 lr）；
- 长序列训练：交错图文需要处理超长序列（序列并行、FlashAttention）；
- 视频训练：抽帧 + 帧间位置编码一致性；
- 分辨率动态采样：训练时混用不同分辨率（数据增强式分辨率扰动）。

## 8. 工程部署实践

### 8.1 推理框架

- **vLLM** 原生支持 Qwen2-VL / Qwen2.5-VL / Qwen3-VL 系列（视觉编码器 + LLM 统一管理）；
- HuggingFace Transformers：开发调试方便，性能不如 vLLM；
- 注意视觉编码器的显存占用（6B 级视觉塔需要额外显存）。

### 8.2 显存优化三板斧（简历项目核心）

| 手段 | 原理 | 效果 |
|------|------|------|
| **视觉 Token 裁剪/采样** | 视觉 token 是 KV cache 大头，按注意力分数/重要性裁剪 | 显著降显存、提速，可能损失细节 |
| **FP16/BF16/INT8/INT4 量化** | 压缩 LLM 权重与 KV cache | 显存减半以上 |
| **分辨率上限限制** | 限制 grid 最大 patch 数（如 max_pixels） | 直接控制视觉 token 上限 |

### 8.3 性能指标视角

- **prefill 阶段**：视觉 token 全量参与计算（算力密集）——优化方向是 token 压缩、FlashAttention；
- **decode 阶段**：KV cache 逐 token 累积（显存密集）——优化方向是 KV cache 量化、token 裁剪；
- 高并发场景：P95 延迟、QPS、显存峰值三件套要一起测（见 15_推理优化与部署）。

### 8.4 项目代码说明

`demo.py` 展示了用 HuggingFace 加载 `Qwen/Qwen-VL-Chat` 进行推理的最小代码（trust_remote_code + GenerationConfig）。生产环境建议迁移到 vLLM，并把图像预处理（动态分辨率切分）封装成统一的 processor 管线。

## 10. 高频面试问答

**Q1：Qwen-VL 到 Qwen3-VL 各代解决了什么问题？**
一代解决"能不能看图"（Cross-Attention 重采样 + 冻结 ViT + 三阶段训练）；二代解决"看得清"（动态分辨率）与"看得懂空间/时间"（M-RoPE）；三代（2.5）解决"看得快"（Window Attention）与"看得准时间"（绝对时间戳 + 动态 FPS）；四代解决"看得懂 + 想得深 + 记得久"（MoE、双思维、DeepStack、1M 上下文）。

**Q2：动态分辨率怎么做？为什么比固定分辨率好？**
按最小 28×28 网格切分，保持原始长宽比，token 数 = 网格数。固定分辨率会压糊小字、变形长宽比；动态分辨率保留细节与比例，文档/OCR/细粒度任务大幅提升。

**Q3：M-RoPE 是什么？为什么视频理解需要它？**
M-RoPE 把 RoPE 扩展为 (时间, 高, 宽) 三维位置编码。视频是"有时间顺序的图片序列"，只有时间轴位置编码才能让 LLM 理解帧的先后关系、做跨帧推理与时间戳定位。文本 1D、图像 2D、视频 3D。

**Q4：一张高分辨率图会生成多少视觉 token？怎么算？**
Qwen2-VL：token 数 = 面积/(28×28)（每 28×28 像素 1 个 token）。448×448 → 256 个；1600×1200 → 约 2451 个。上限 16384。token 数直接决定 KV cache 与计算量。

**Q5：视觉 Token 裁剪有哪些方法？剪多了会损失什么？**
常见方法：① 按注意力分数裁剪（保留高关注 patch）；② 均匀采样/拼接；③ 语义合并（token merger）；④ 分辨率限制。剪多会损失细节：小字识别、细粒度属性、空间位置精度下降，甚至引发幻觉。

**Q6：Qwen3-VL 的 MoE 和 Thinking 模式各有什么意义？**
MoE：总参数大（30B）但激活小（3B），推理算力接近小模型、能力接近大模型（稀疏激活）。Thinking：先 CoT 推理再回答，复杂任务准确率提升，但延迟上升；Non-Thinking 低延迟适合简单任务——可按业务场景选择。

**Q7：Qwen2.5-VL 的 Visual Token Merger 为什么比 2×2 卷积好？**
2×2 卷积是固定 4 倍压缩，对信息密度不同的区域一视同仁；Merger 用可学习向量通过 Cross-Attention 与视觉特征交互，能"自适应"决定每个区域保留多少信息，并支持动态 token 预算（按任务/显存配置）。

**Q8：为什么 Qwen2-VL 的视频要按 2fps 抽帧？**
视频帧间冗余极大，全帧输入 token 爆炸；2fps 在保留动作信息与控制 token 数之间取得平衡。2.5 升级为动态 FPS（按运动强度自适应）。

**Q9：交错图文输入对训练和推理有什么挑战？**
训练：序列变长（多图 token 累加），需要长序列训练能力（FlashAttention、序列并行）；推理：prefill 变长、KV cache 增大；此外位置编码必须保证多图之间的空间一致性（M-RoPE 天然支持）。

**Q10：部署 Qwen3-VL-30B-A3B 需要注意什么？**
MoE 激活参数少但全量权重需多卡；视觉塔（SigLIP-2 级）单独占显存；长上下文时 KV cache 是主要显存开销，需要 vLLM + token 裁剪 + 量化组合优化；Thinking 模式推理链长，需要配置合理的 max_tokens 与超时。

## 11. 常见误区

**误区 1：Qwen-VL 一代把"448 个 token 压缩到 256 个"。**
错。448 是分辨率（像素），不是 token 数。正确说法：448×448 产生 1024 个 patch token，重采样压缩到 256 个（4 倍压缩）。

**误区 2：M-RoPE 只是给图像加个 2D 位置编码。**
不完整。M-RoPE 是 3D（时间 × 高 × 宽），文本 token 用 1D 部分、图像用 2D 部分、视频用 3D 部分，通过 mrope_section 维度切分实现统一框架。

**误区 3：动态分辨率 = 只是不 resize。**
不只是。动态分辨率的核心是按 28×28 网格切分 + token 数与分辨率成正比 + 上限控制（16384），且训练时混合多分辨率采样。

**误区 4：视觉 token 越多越好。**
不是。token 多 → KV cache 大、prefill 慢、显存高。实际部署要在"细节保留"与"计算成本"之间权衡，这正是 token 裁剪存在的意义。

**误区 5：MoE 模型部署显存小。**
错。MoE 减少的是**每 token 的计算量**（激活参数），权重仍然全部要加载到显存（30B-A3B 权重仍约 60GB+，BF16）。

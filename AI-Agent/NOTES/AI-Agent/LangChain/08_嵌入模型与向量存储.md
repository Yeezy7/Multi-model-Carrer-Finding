# 嵌入模型与向量存储

## 一、余弦相似度

### 1.1 核心概念

余弦相似度衡量两个向量在方向上的相似程度，值域为 [-1, 1]：

| 值 | 含义 |
|----|------|
| 1 | 方向完全一致（夹角 0°） |
| 0 | 方向正交无关（夹角 90°） |
| -1 | 方向完全相反（夹角 180°） |

**核心思想：** 只关注方向是否一致，不受向量长度影响。

### 1.2 数学公式

```
cos_sim = (A · B) / (||A|| × ||B||)
```

三步拆解：
1. **点积：** 对应位置元素相乘后求和
2. **模长：** 各元素平方和开平方根
3. **归一化：** 点积除以模长乘积

### 1.3 直观理解

向量 A = [0.5, 0.5]，向量 B = [0.7, 0.7]：
- B 的每个维度都是 A 的 1.4 倍（长度不同）
- 但方向完全一致（比值相同）
- 余弦相似度 = 1.0

**这就是余弦相似度"剔除长度影响"的含义——它关注的是维度间的比例关系，而非绝对值。**

## 二、向量存储（Vector Store）

### 2.1 InMemoryVectorStore（内存向量存储）

数据存储在内存中，程序重启后丢失。适合开发测试。

**核心操作：**

| 操作 | 方法 | 说明 |
|------|------|------|
| 新增 | `add_documents()` | 添加文档到向量库 |
| 删除 | `delete()` | 按 ID 删除文档 |
| 检索 | `search()` | 按相似度搜索 |
| 检索 | `similarity_search()` | 相似度搜索（Chroma） |

**新增文档时可指定：**
- `documents` —— 文档列表（list[Document]）
- `ids` —— 每条数据的唯一标识符

**检索参数：**
- `query` —— 查询文本
- `search_type` —— 检索类型（"similarity"）
- `k` —— 返回的相似文档数量

### 2.2 Chroma（外部持久化向量存储）

Chroma 是轻量级向量数据库，支持数据持久化到磁盘。

**与 InMemoryVectorStore 的区别：**

| 特性 | InMemoryVectorStore | Chroma |
|------|---------------------|--------|
| 持久化 | 不支持 | 支持（persist_directory） |
| 数据规模 | 小规模 | 中等规模 |
| 性能 | 快（内存操作） | 中等（磁盘 I/O） |
| 适用场景 | 开发测试 | 生产环境 |

**Chroma 额外功能：**
- `filter` —— 按元数据过滤检索结果
- `persist_directory` —— 指定持久化存储路径
- `collection_name` —— 类似数据库表名

### 2.3 检索器（Retriever）

向量存储对象可通过 `.as_retriever()` 转换为检索器对象，检索器是 LangChain 的标准检索接口。

**检索器的特点：**
- 输入：查询字符串
- 输出：`list[Document]`（相关文档列表）
- 可直接参与 `|` 链式调用

**使用检索器的好处：**
- 统一接口，不依赖具体向量存储实现
- 可直接作为 Chain 的组件
- 支持配置检索参数（如 k 值）

## 三、在 RAG 中的完整流程

```
用户查询 → embed_query → 查询向量
                                ↓
文档库 → embed_documents → 文档向量 → 余弦相似度排序 → Top-K 文档
```

1. 所有文档预先通过嵌入模型转为向量并存储
2. 用户查询到来时，将查询转为向量
3. 计算查询向量与所有文档向量的余弦相似度
4. 返回相似度最高的 Top-K 文档作为上下文

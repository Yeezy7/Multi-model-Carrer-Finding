# 中间件机制（Middleware）

## 一、核心概念

中间件是 Agent 执行过程中的钩子函数（Hook），可以在 Agent 执行的不同阶段插入自定义逻辑。类似于 Web 框架中的中间件，用于监控、日志、动态修改行为等。

## 二、中间件类型

### 2.1 before_agent / after_agent

在 Agent 执行前后触发。

**参数：**
- `state: AgentState` —— Agent 的状态记录（包含所有消息）
- `runtime: Runtime` —— 执行过程中的上下文信息

**用途：** 日志记录、执行时间统计、状态初始化/清理。

### 2.2 before_model / after_model

在模型调用前后触发。

**参数：**
- `state: AgentState` —— 当前状态
- `runtime: Runtime` —— 上下文信息

**用途：** 模型调用日志、输入输出监控。

### 2.3 wrap_model_call

包装模型调用，在调用前后插入逻辑。

**参数：**
- `request` —— 模型调用请求
- `handler` —— 实际的模型调用函数

**关键：** 必须调用 `handler(request)` 才能真正执行模型调用。

### 2.4 wrap_tool_call

包装工具调用，在调用前后插入逻辑。

**参数：**
- `request: ToolCallRequest` —— 工具调用请求（包含 tool_call 的 name 和 args）
- `handler` —— 实际的工具调用函数

**返回：** `ToolMessage` 或 `Command`

**用途：** 工具调用监控、日志记录、结果修改、上下文注入。

### 2.5 dynamic_prompt（动态提示词切换）

在每次生成提示词之前，根据上下文动态切换不同的提示词。

**参数：**
- `request: ModelRequest` —— 模型请求（包含 runtime.context）

**返回：** 提示词字符串

**核心机制：** 通过 `request.runtime.context` 读取上下文标记，根据标记返回不同的提示词。

## 三、中间件注册

所有中间件通过列表传给 `create_agent` 的 `middleware` 参数：

```python
agent = create_agent(
    model=chat_model,
    tools=[tool1, tool2],
    middleware=[before_hook, after_hook, tool_hook, prompt_switch]
)
```

## 四、Runtime Context（运行时上下文）

Runtime 是 Agent 执行过程中的共享上下文，可以在不同中间件之间传递信息。

**核心机制：**
- `runtime.context` —— 字典类型的共享数据
- 在一个中间件中设置的值，其他中间件可以读取
- 用于实现跨组件的状态传递

**典型应用：**
```
wrap_tool_call 中设置 context["report"] = True
    ↓
dynamic_prompt 读取 context.get("report", False)
    ↓
根据标记切换提示词
```

## 五、执行顺序

Agent 的完整执行流程：

```
1. before_agent
2. before_model
3. dynamic_prompt（生成提示词）
4. wrap_model_call（模型调用）
5. after_model
6. wrap_tool_call（工具调用，可能多次）
7. 重复 2-6（多轮推理）
8. after_agent
```

## 六、实际应用场景

| 场景 | 中间件 | 说明 |
|------|--------|------|
| 日志监控 | before_agent, after_agent | 记录执行开始/结束 |
| 工具调用追踪 | wrap_tool_call | 记录工具名和参数 |
| 动态提示词 | dynamic_prompt | 根据场景切换不同提示词 |
| 上下文注入 | wrap_tool_call | 在工具调用中修改 runtime.context |
| 模型调用监控 | wrap_model_call | 记录请求参数和响应结果 |

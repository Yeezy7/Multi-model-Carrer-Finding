# 会话记忆管理

## 一、核心问题

LLM 本身没有记忆能力，每次请求都是独立的。要实现多轮对话，需要在每次请求时将完整的历史消息传递给模型。LangChain 通过 `RunnableWithMessageHistory` 机制自动管理历史消息。

## 二、临时会话记忆（InMemoryChatMessageHistory）

### 2.1 机制

历史消息存储在内存中，程序重启后丢失。适合开发测试和短期对话。

### 2.2 使用流程

1. 创建 `InMemoryChatMessageHistory` 对象
2. 将其与 session_id 绑定，存入字典
3. 通过 `RunnableWithMessageHistory` 包装原有 Chain
4. 调用时传入 session_config 指定会话

### 2.3 RunnableWithMessageHistory 的关键参数

| 参数 | 说明 |
|------|------|
| `runnable` | 被增强的原有 Chain |
| `get_session_history` | 通过 session_id 获取历史消息对象的函数 |
| `input_messages_key` | 用户输入在模板中的占位符名 |
| `history_messages_key` | 历史消息在模板中的占位符名 |

### 2.4 调用时的 session_config

```python
session_config = {
    "configurable": {
        "session_id": "user_001"
    }
}
chain.invoke({"input": "问题"}, config=session_config)
```

**关键点：** session_id 不同，历史消息完全隔离。同一个 session_id 下的历史消息会自动累积。

## 三、长期会话记忆（FileChatMessageHistory）

### 3.1 为什么需要

InMemoryChatMessageHistory 在程序重启后历史消息丢失。生产环境需要将历史消息持久化到磁盘。

### 3.2 自定义实现

通过继承 `BaseChatMessageHistory` 类，实现文件存储：

**需要实现的方法：**

| 方法 | 作用 |
|------|------|
| `add_messages(messages)` | 将新消息追加到历史记录 |
| `messages`（property） | 获取历史消息列表 |
| `clear()` | 清空历史消息 |

**消息序列化：**
- `message_to_dict()` —— 单个消息对象 → 字典
- `messages_from_dict()` —— 字典列表 → 消息对象列表
- 以 JSON 格式写入文件

### 3.3 文件存储的优势

| 特性 | InMemory | FileStorage |
|------|----------|-------------|
| 持久化 | 否 | 是 |
| 重启后保留 | 否 | 是 |
| 多进程共享 | 否 | 是 |
| 性能 | 快 | 中等 |

## 四、Chat Prompt 与历史消息的配合

### 4.1 模板设计

```
ChatPromptTemplate:
  - ("system", "你是一个助手")
  - MessagesPlaceholder("chat_history")   ← 历史消息注入位置
  - ("human", "请回答：{input}")
```

### 4.2 数据流

```
用户输入 → RunnableWithMessageHistory 自动注入历史消息
         → ChatPromptTemplate 渲染完整提示词
         → Model 调用
         → 新的回答自动追加到历史消息
```

**关键点：** 用户不需要手动管理历史消息，`RunnableWithMessageHistory` 会自动完成注入和追加。

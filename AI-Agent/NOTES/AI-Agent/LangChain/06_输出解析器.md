# 输出解析器（Output Parser）

## 一、为什么需要输出解析器

ChatModel 的返回类型是 `AIMessage` 对象，而非纯文本。在多组件链式调用中，AIMessage 如果直接传给下一个组件（如另一个 PromptTemplate），会导致类型不匹配。

输出解析器的作用就是在组件之间做**类型转换**——将模型输出解析为下游组件需要的格式。

## 二、StrOutputParser（字符串输出解析器）

### 2.1 功能

从模型输出中提取纯文本内容，统一处理 invoke 和 stream 两种模式。

### 2.2 处理逻辑

| 输入模式 | 输入类型 | 处理方式 |
|----------|----------|----------|
| invoke 输出 | `AIMessage` 对象 | 提取 `.content` 属性 |
| stream 输出 | 逐块 `AIMessageChunk` | 逐块提取 `.content` 并拼接 |

### 2.3 在链中的位置

```
prompt → model → parser
```

将 ChatModel 的 `AIMessage` 转为纯文本字符串，便于后续处理。

### 2.4 关键价值

- LLM 的输出是字符串，不需要 parser
- ChatModel 的输出是 AIMessage，传给下一个 ChatModel 时可能引发类型错误
- **多条链串联时，每经过一个 ChatModel 后建议接一个 parser**

## 三、JsonOutputParser（JSON 输出解析器）

### 3.1 功能

将模型输出的 JSON 字符串解析为 Python 字典对象。

### 3.2 使用场景

- 要求模型以 JSON 格式输出
- 下游组件需要 dict 类型的数据
- 需要对模型输出做结构化处理

### 3.3 在链中的价值

```
prompt(要求JSON输出) → model → json_parser → prompt(接收dict) → model
```

**典型场景：** 第一个模型生成名字（JSON），解析后传给第二个模型分析含义。

## 四、解析器对比

| 解析器 | 输入 | 输出 | 适用场景 |
|--------|------|------|----------|
| StrOutputParser | AIMessage | str | 通用文本输出 |
| JsonOutputParser | AIMessage | dict | JSON 结构化输出 |

## 五、注意事项

- 解析器是链式调用的关键衔接点
- 没有解析器，ChatModel 的输出无法直接传给下一个 PromptTemplate
- 使用 JsonOutputParser 时，提示词中需要明确要求模型输出 JSON 格式

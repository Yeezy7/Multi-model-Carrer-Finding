# 输出解析器（Output Parser）

## 一、为什么需要输出解析器

ChatModel 的返回类型是 `AIMessage` 对象，而非纯文本。在多组件链式调用中，AIMessage 如果直接传给下一个组件，可能导致类型不匹配。

输出解析器的作用就是在组件之间做**类型转换**——将模型输出解析为下游组件需要的格式。

## 二、StrOutputParser（字符串输出解析器）

### 2.1 功能

从模型输出中提取纯文本内容，统一处理 invoke 和 stream 两种模式。

### 2.2 处理逻辑

| 输入模式 | 输入类型 | 处理方式 |
|----------|----------|----------|
| invoke 输出 | `AIMessage` 对象 | 提取 `.content` 属性 |
| stream 输出 | 逐块 `AIMessageChunk` | 逐块提取 `.content` 并拼接 |

### 2.3 在链中的位置

```
prompt → model → parser
```

将 ChatModel 的 `AIMessage` 转为纯文本字符串，便于后续处理。

## 三、解析器的作用

1. **类型转换** — 将消息对象转为字符串
2. **模式统一** — 屏蔽 invoke 和 stream 的返回差异
3. **链的衔接** — 确保下游组件（如另一个模型）获得正确的输入类型
4. **扩展性** — LangChain 还有其他解析器（如 JsonOutputParser、PydanticOutputParser），可根据需要替换

## 四、注意事项

- LLM（非 ChatModel）的输出已经是字符串，不一定需要 StrOutputParser
- ChatModel 的输出若不经过解析，传给下一个模型时可能引发类型错误
- 多条链串联时，每经过一个 ChatModel 后建议接一个解析器

# 提示词工程（Prompt Engineering）

## 一、核心设计原则

提示词工程的目标是通过精心设计的指令，引导 LLM 产生期望的输出。核心原则如下：

| 原则 | 说明 | 示例 |
|------|------|------|
| **角色定义** | 给 AI 一个专业身份，激活对应知识域 | "你是一个金融专家" |
| **任务描述** | 清晰说明任务目标和范围 | "将文本分类为以下类别：..." |
| **格式约束** | 规定输出的具体格式 | "按 JSON 字符串输出" |
| **边界兜底** | 定义异常情况的处理方式 | "不清楚的分类为'不清楚类别'" |
| **缺失值策略** | 信息不全时的处理方式 | "原文未提及" |

## 二、Few-shot 示例驱动

### 2.1 核心思想

通过提供若干组输入-输出示例，让模型理解任务期望。无需微调即可引导模型行为和输出格式。

### 2.2 消息结构模式

```
system: 定义任务 + 分类范围 + 兜底规则
user:   示例输入 1
assistant: 示例输出 1
user:   示例输入 2
assistant: 示例输出 2
...
user:   实际待处理输入
```

示例的作用：
- 展示期望的输出格式和风格
- 提供任务边界参考
- 降低模型理解歧义
- 通常 2-3 个高质量示例即可达到较好效果

## 三、案例一：金融文本分类

**任务：** 将金融文本分为"新闻报道、财务报告、公司公告、分析师报告"四类

**设计要点：**
- System 定义分类列表和兜底标签"不清楚类别"
- 用字典存储示例数据（类别 → 文本）
- 动态构建 messages：逐条添加 user-assistant 示例对
- 对待分类文本，在 messages 后拼接当前问题

**关键设计：** 每条提问都复用同一组示例消息 + 新追加的 user 消息，保证每次请求都有完整的上下文。

## 四、案例二：金融信息抽取

**任务：** 从股市新闻中抽取结构化字段（日期、股票名称、开盘价、收盘价、成交量）

**设计要点：**
- 用 schema 列表定义需要抽取的字段
- 指定缺失值填充方式"原文未提及"
- 要求以 JSON 字符串输出，便于程序解析
- 示例以标注好的 dict 形式存储，动态转为 JSON 字符串

**抽取输出的 JSON 格式：**
```json
{"日期": "2025-06-16", "股票名称": "传智教育A股", "开盘价": "66人民币", "收盘价": "68人民币", "成交量": "123000"}
```

## 五、JSON 在提示词工程中的作用

| 操作 | API | 说明 |
|------|-----|------|
| 序列化 | `json.dumps(obj, ensure_ascii=False)` | Python 对象 → JSON 字符串 |
| 反序列化 | `json.loads(str)` | JSON 字符串 → Python 对象 |

JSON 的作用：
- 要求 AI 以 JSON 输出，结果可直接被程序解析
- 用 JSON 结构定义 schema，让 AI 理解需要抽取的字段
- 模型返回的 JSON 字符串经反序列化后变为结构化数据

## 六、提示词优化常见技巧

1. **明确否定** — 告诉模型不要做什么（"无需其他内容"）
2. **角色扮演** — 让模型扮演某个角色比直接下指令效果好
3. **分步指导** — 复杂任务拆分为多个步骤
4. **格式示例** — 展示期望的输出模板
5. **约束前置** — 先将约束条件放在 system 消息中

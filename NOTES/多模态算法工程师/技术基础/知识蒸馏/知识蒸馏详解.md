## 一、蒸馏是什么：大模型教小模型

### 1.1 一个直觉例子

知识蒸馏（Knowledge Distillation, KD）的核心设定：**一个能力强但笨重的大模型（教师 Teacher）把自己学到的知识"教"给一个能力弱但轻快的小模型（学生 Student）**，让学生的精度尽量逼近教师，同时保留小模型的推理速度和显存优势。

直觉例子：资深教师（大模型）讲解一道难题时，不会只告诉学生"答案是 B"，而是会说明"为什么 C 也沾边、为什么 D 明显不对"。**"答案是 B"对应硬标签，讲解过程对应软标签**——蒸馏的本质就是把教师的"讲解过程"搬给学生。

### 1.2 为什么软标签比硬标签信息量大（核心动机）

硬标签（one-hot）只包含"正确答案是哪一类"这一比特量级的信息；而教师模型输出的**软标签（soft target，各类别的概率分布）**隐含了额外的知识：

1. **类间相似度**：如果模型认为"猫"和"狗"的概率分别是 0.7 / 0.2，而"猫"和"汽车"是 0.7 / 0.01，说明模型学到了"猫与狗更像、猫与车差异大"；
2. **不确定度**：置信度高低反映了样本的难易程度，学生可以"重点学难的样本"；
3. **暗知识（dark knowledge）**：Hinton 论文中的原词，指那些在硬标签里完全不可见、但藏在概率分布尾巴里的信息（比如"猫"和"老虎"的小概率关联）。

> 一句话：**硬标签告诉你"是什么"，软标签告诉你"和什么像、像多少"**，后者是连续值，信息量远大于前者。

### 1.3 蒸馏的通用框架

```text
              ┌────────────────────────────┐
  输入 x ────▶│  教师模型（大，已训练好）   │────▶ 软标签 p^T
              └────────────────────────────┘
              ┌────────────────────────────┐
  输入 x ────▶│  学生模型（小，待训练）     │────▶ 软预测 q^T
              └────────────────────────────┘

  学生总损失 = 硬标签监督(交叉熵) + λ·蒸馏损失(软标签匹配) [+ 特征损失]
```

三个组件缺一不可：

| 组件 | 作用 | 关键设计 |
|------|------|---------|
| 教师 | 提供知识信号 | 准确率高、与下游任务同域 |
| 蒸馏损失 | 学生与教师输出"对齐" | 匹配 logits / 特征 / 关系 |
| 训练数据 | 学生学习的载体 | 通常与教师训练数据同分布 |

### 1.4 为什么知识能"转移"

教师模型学到的本质是输入空间上的**函数关系** $f_T(x)$。如果学生网络容量足够，就可以通过最小化 $f_S(x)$ 与 $f_T(x)$ 的差异，学到相近的函数关系。学生"学会了教师的行为"，而不是"背下了教师的输出"——因此对未见数据也有迁移效果。

## 二、Hinton 温度蒸馏（重点，必考）

### 2.1 论文与核心思想

Hinton, Vinyals & Dean（2015）《Distilling the Knowledge in a Neural Network》提出经典框架：

- 教师输出 logits $z_i$（softmax 之前的原始分数）；
- 直接匹配 logits 方差太大、难训练；直接匹配概率（$T=1$ 的 softmax）又因教师过于自信（概率接近 one-hot）而信息量不足；
- 于是引入**温度 T** 软化概率分布。

### 2.2 温度软化公式（软目标）

用温度 $T$ 重定义 softmax，得到软目标 $p_i^{(T)}$：

$$p_i^{(T)} = \frac{\exp(z_i / T)}{\sum_{j} \exp(z_j / T)}$$

- $T$ 越大，分布越平缓（趋近均匀分布）；
- $T=1$ 时退化为普通 softmax（即硬预测的 soft 版本）；
- $T \to \infty$ 时所有 $p_i \to 1/N$，信息完全抹平；
- $T \to 0^+$ 时退化为 argmax（one-hot）。

```python
# 温度软化的 PyTorch 实现
def softened_softmax(logits, temperature):
    return (logits / temperature).softmax(dim=-1)

teacher_probs = softened_softmax(teacher_logits, T=4.0)  # 软目标
student_probs = softened_softmax(student_logits, T=4.0)  # 学生同温下的预测
```

### 2.3 学生损失：硬标签 CE + 软目标 KL

学生总损失由两部分组成：

$$\mathcal{L} = \mathcal{L}_{hard} + \lambda \, T^2 \, \mathcal{L}_{soft}$$

其中：

$$\mathcal{L}_{hard} = \mathrm{CE}(y, \mathrm{softmax}(z^S)) = -\sum_i y_i \log q_i^{(1)}$$

$$\mathcal{L}_{soft} = \mathrm{KL}(p^{(T)} \| q^{(T)}) = \sum_i p_i^{(T)} \log \frac{p_i^{(T)}}{q_i^{(T)}}$$

- $\mathcal{L}_{hard}$：学生用 $T=1$ 的预测与真实标签 $y$ 计算交叉熵，保证学生不偏离 ground truth；
- $\mathcal{L}_{soft}$：学生用**同温度 $T$** 的软预测 $q^{(T)}$ 匹配教师的软目标 $p^{(T)}$，传输教师的类间知识；
- $T^2$：梯度补偿因子（见 2.5 推导），因为软目标的梯度量级与 $1/T^2$ 成正比；
- $\lambda$：软损失权重，控制"听老师的话"的程度。

> 关键细节（面试常问）：**学生计算软损失的温度必须与教师一致（都用 $T$），而算硬损失时用 $T=1$**。

### 2.4 为什么温度 T 有效：软化分布暴露类间关系

未加热（$T=1$）的教师输出通常极度自信，例如：

```text
T=1  : 猫 0.980  狗 0.015  车 0.003  飞机 0.002
T=4  : 猫 0.520  狗 0.180  车 0.110  飞机 0.090
T=8  : 猫 0.350  狗 0.240  车 0.180  飞机 0.150
```

- $T=1$ 时概率接近 one-hot，"狗 0.015 vs 车 0.003"这种**比值关系被压缩淹没**，学生学不到类间相似度；
- 升温后分布摊开，"猫 0.52、狗 0.18、车 0.11"让学生看到：**猫与狗比猫与车更相似**（狗的概率 > 车的概率），这正是软标签的核心价值；
- 同时软分布更平滑，梯度的方差更小，学生训练更稳定。

**类比**：教师像一位裁判，硬标签只给名次（第 1 名），软标签给了完整得分（第 1 名 98 分、第 2 名 91 分、第 3 名 70 分）——后者显然信息更丰富。

### 2.5 T² 梯度补偿因子的推导（面试加分项）

软损失 $\mathcal{L}_{soft}$ 对学生 logits $z_i^S$ 的梯度（链式求导可得）：

$$\frac{\partial \mathcal{L}_{soft}}{\partial z_i^S} = \frac{1}{T}\left(q_i^{(T)} - p_i^{(T)}\right)$$

**大 T 近似**：当 $T$ 很大时，对 logits 做一阶泰勒展开 $\exp(z/T) \approx 1 + z/T$，softmax 近似为：

$$p_i^{(T)} \approx \frac{1 + z_i^T/T}{N}, \qquad q_i^{(T)} \approx \frac{1 + z_i^S/T}{N}$$

代入梯度：

$$\frac{\partial \mathcal{L}_{soft}}{\partial z_i^S} \approx \frac{1}{T} \cdot \frac{(z_i^T - z_i^S)}{N \cdot T} = \frac{z_i^T - z_i^S}{N \cdot T^2}$$

**结论**：

1. 大 $T$ 下，软损失梯度**与 $1/T^2$ 成正比**——温度越高，梯度越小；
2. 如果不补偿，调大 $T$ 会导致学生学习信号指数级减弱，训练失效；
3. 因此损失前乘 $T^2$（即 $\lambda T^2 \mathcal{L}_{soft}$），使梯度量级与温度无关、保持与 logits 差异成正比；
4. 有趣的是，补偿后梯度 $\propto (z_i^T - z_i^S)$，**大 T 时软目标蒸馏近似等价于直接在 logits 空间做均方误差匹配**（logit matching），这为"蒸馏 ≈ 匹配 logits"提供了理论视角。

### 2.6 温度怎么选（训练 vs 推理）

| 阶段 | 温度 | 原因 |
|------|------|------|
| 训练（蒸馏时） | $T$ 通常取 2 ~ 10（论文用 4、8、20） | 软化分布暴露类间关系 |
| 推理（部署后） | $T=1$ | 学生直接用普通 softmax 输出 |

调温经验：

- **T 过低**（接近 1）：软目标近似硬标签，蒸馏退化为普通训练，类间信息丢失；
- **T 过高**（如 100）：分布趋近均匀，几乎不含信息，且 $T^2$ 放大噪声，训练变慢；
- **教师越自信**（训练集精度极高）：可用更高温度（论文中 MNIST 实验用 $T=20$ 抵消教师的"过度自信"）；学生网络较小时用较低温度（如 $T=4$）；
- **经验法则**：一般从 $T=4$ 起试，看学生验证集精度调 2~10 区间；**温度只影响训练，推理必须用 $T=1$**。

### 2.7 完整训练流程（伪代码）

```python
# Hinton 蒸馏训练循环
for x, y in dataloader:
    teacher_logits = teacher(x).detach()          # 教师冻结，只出 logits
    student_logits = student(x)

    L_hard = CE(student_logits, y)                # T=1 与硬标签
    L_soft = KL(softmax(teacher_logits/T),        # 同温度软目标
                softmax(student_logits/T))
    L = L_hard + lamda * T**2 * L_soft            # T² 补偿

    loss.backward()
    optimizer.step()

# 推理：学生用 T=1
pred = student(x).softmax(-1)
```

## 三、蒸馏的类型：响应 / 特征 / 关系

### 3.1 响应蒸馏（Response-based）：对齐输出 logits / 概率

匹配教师与学生的**最终输出**（logits 或概率），即 Hinton 经典做法，按教师产生方式再细分：

| 子类型 | 教师来源 | 特点 |
|--------|---------|------|
| 离线蒸馏（Offline） | 预先训好的固定大模型 | 最经典、最稳定；两阶段 |
| 在线蒸馏（Online） | 与学生同步训练的同规模模型 | 无需预训练大教师；教学相长 |
| 自蒸馏（Self） | 学生自己（历史版本/EMA） | 无教师成本；训练即蒸馏 |

（三种范式详见第四章。）

**优点**：实现简单、通用性强（任何带 softmax 头的模型都能做）、与任务无关。**缺点**：只对齐输出，丢失了中间层学到的高层特征语义。

### 3.2 特征蒸馏（Feature-based）：对齐中间层特征

核心思想：**中间特征比最终 logits 信息更丰富**——logits 是"压缩后的结论"，特征图是"推理过程"。代表工作是 **FitNets**（Romero et al., 2015）：

- 教师第 $k$ 层输出特征 $f_T(x) \in \mathbb{R}^{d_T}$，学生某一层特征 $f_S(x) \in \mathbb{R}^{d_S}$；
- 学生特征先过一层线性映射 $W_r$ 对齐维度，再做 L2 回归：

$$\mathcal{L}_{hint} = \left\| W_r \, f_S(x) - f_T(x) \right\|_2^2$$

**为什么特征蒸馏信息更丰富**：

1. 特征图携带**空间结构信息**（目标在哪、边缘在哪），logits 只是标量分布；
2. 特征对齐约束了**中间表示空间**，等于让学生继承教师的"思维过程"，而不是只学"结论"；
3. 中间层语义更通用，利于学生学到可迁移的表征（教师的高层特征往往比学生的更成熟）。

**实现注意**：

- 维度对齐：学生特征维度过小时加线性投影 $W_r$（或 1×1 卷积）；
- 空间对齐：特征图尺寸不同需 resize / pooling；
- 特征需归一化（L2 norm 或 LN）后再算距离，否则量级差异会主导损失；
- 选择"哪个层对齐"需要实验：一般对齐靠近输出的高层特征收益最大。

### 3.3 关系蒸馏（Relational）：对齐样本间关系

前面两种都是"逐样本对齐"（per-sample），关系蒸馏对齐的是**样本之间的关系**（pairwise relation），代表工作是 RKD（Park et al., 2019）。核心思想：教师对一批样本"谁和谁像、像多少"的判断，才是真正的结构化知识。

距离关系损失（蒸馏样本间距离矩阵/亲和矩阵）：

$$\mathcal{L}_{RKD-D} = \sum_{(i,j)} \left( d_{ij}^S - d_{ij}^T \right)^2, \qquad d_{ij} = \left\| f_i - f_j \right\|_2$$

角度关系损失（三样本间的夹角结构）：

$$\mathcal{L}_{RKD-A} = \sum_{(i,j,k)} \left( \cos\theta_{ijk}^S - \cos\theta_{ijk}^T \right)^2$$

**优点**：蒸馏的是"样本间的相对几何结构"，与教师的具体表示无关，天然不敏感于维度/尺度的差异（多模态蒸馏里很有用）。**缺点**：需要 batch 内组合样本对，计算量 $\mathcal{O}(B^2)$ / $\mathcal{O}(B^3)$，batch 小时统计不准。

### 3.4 三种类型对比

| 维度 | 响应蒸馏 | 特征蒸馏 | 关系蒸馏 |
|------|---------|---------|---------|
| 对齐对象 | 输出 logits/概率 | 中间特征 | 样本间距离/角度 |
| 信息层次 | 结论 | 推理过程 | 样本间结构 |
| 实现难度 | 低 | 中（维度/层对齐） | 中（样本组合） |
| 计算开销 | 低 | 中 | 高（$O(B^2)$~$O(B^3)$） |
| 代表工作 | Hinton KD | FitNets, AT | RKD |
| 常用场景 | 分类/回归 | 视觉/表示学习 | 度量学习/少样本 |

## 四、训练范式：离线 / 在线 / 自蒸馏

### 4.1 离线蒸馏（Offline KD）：两阶段

```text
阶段1：用大算力训练教师（教师完全固定，训练一次可复用于多个学生）
阶段2：冻结教师 → 前向出软标签 → 训练学生（教师不再更新）
```

- **优点**：教师只推理不出梯度，训练稳定；教师可复用（训一个教师服务多个学生）；实现最简；
- **缺点**：两阶段成本高；教师与学生容量差距大时易出现"教学失效"（见 4.4 容量差距）。

### 4.2 在线蒸馏（Online KD）：师生同训

没有预训练大教师，而是让**两个（或多个）同规模网络同时训练、互相学习**，代表工作 Deep Mutual Learning（DML）：

$$\mathcal{L} = \mathcal{L}_{task}(x, y) + \lambda \left[ \mathrm{KL}(p_a \| p_b) + \mathrm{KL}(p_b \| p_a) \right]$$

- 双方既是教师也是学生，损失**对称**（互相提供软目标）；
- **优点**：不需要大教师和两阶段；多模型集成式的互相监督，精度可超过单模型；
- **缺点**：软目标质量受限于同规模模型，无"大教师天花板"可借力；训练成本翻倍（两个网络都更新）。

### 4.3 自蒸馏（Self-distillation）：自己教自己

学生以**自身的某个版本**为教师，代表工作 DINO（ViT 自监督）：

- DINO 中教师 = 学生参数的**指数移动平均（EMA）**，教师只前向不反传梯度；
- 教师和学生对同一张图的不同裁剪视角（multi-crop）输出特征，学生预测教师的特征：
  $$\mathcal{L} = -\sum_x p_t(x) \log p_s(x)$$
- 因为教师参数"滞后"于学生，天然携带更强的先验知识，**训练即蒸馏，零额外教师成本**。

| 范式 | 教师来源 | 教师是否更新 | 优势 | 劣势 |
|------|---------|-------------|------|------|
| 离线 | 预训练大模型 | 否 | 稳定、可复用、上限高 | 两阶段、成本高 |
| 在线 | 同规模同伴 | 是 | 无需大教师 | 软目标上限低、算力翻倍 |
| 自蒸馏 | 自己/EMA 历史版本 | EMA 更新 | 零成本、稳定 | 无外部知识增益 |

> 面试记忆：**离线蒸馏 = 站在巨人的肩膀上；在线蒸馏 = 互相学习；自蒸馏 = 镜像中的自己。**

## 五、蒸馏损失组合

### 5.1 统一损失公式

实战中常把多种损失叠加（响应 + 特征 + 任务损失）：

$$\mathcal{L} = \alpha \, \mathcal{L}_{hard} + \beta \, \mathcal{L}_{soft} + \gamma \, \mathcal{L}_{feat}$$

| 项 | 内容 | 语义 | 典型取值 |
|----|------|------|---------|
| $\mathcal{L}_{hard}$ | 学生与真实标签的 CE | 保证不偏离 ground truth | 权重固定 $\alpha = 1$ |
| $\mathcal{L}_{soft}$ | 学生与教师软目标的 KL | 传输教师类间知识 | $\beta$ 常取 0.1~10（视温度） |
| $\mathcal{L}_{feat}$ | 中间特征对齐损失 | 传输教师表示能力 | $\gamma$ 常取 0.1~1 |

### 5.2 权重怎么调（经验）

1. **$\mathcal{L}_{hard}$ 永远保留**：$\alpha=1$，它是学生的"底线监督"，去掉会让学生学歪；
2. **$\beta$ 与温度联动**：若用 $T^2$ 补偿因子，$\beta$ 的量级会变大，通常直接按 Hinton 论文取 $\lambda \approx 1$ 后微调；更常见做法是**不乘 $T^2$，而是调 $\beta$**（两派实现都有，面试时说明即可）；
3. **按损失量级而非直觉调权**：先跑一版，打印三个损失的数值，让三个梯度贡献在 $10^{-1} \sim 1$ 量级，再细调；
4. **特征损失用 warmup**：训练初期学生特征没成型，直接大权重对齐特征会抑制分类头学习，前 10% 步数把 $\gamma$ 从 0 线性升到目标值；
5. **网格搜索**：固定 $\alpha=1$，$\beta \in \{0.1, 0.5, 1, 5, 10\}$，$\gamma \in \{0, 0.1, 0.5, 1\}$，按验证集选最优组合；
6. **经验法则**：学生越小、任务越难 → 适当提高 $\beta$（更依赖教师）；数据量大 → 可降低 $\beta$（硬标签已经够多）。

## 六、大模型时代的蒸馏

### 6.1 LLM 蒸馏：从 logits 到序列级蒸馏

大模型场景下，Hinton 式 logits 蒸馏难以直接使用（原因见 6.2），主流做法是**序列级蒸馏（Sequence-level KD, SeqKD）**：让教师生成文本，学生在教师的输出文本上做最大似然训练：

$$\mathcal{L} = -\sum_{t} \log P_S\!\left(y_t^{teacher} \mid y_{<t}^{teacher}, x\right)$$

即：**学生读教师的"答案文本"，学习教师如何组织语言和推理**。变体包括：

- **离线 SeqKD**：教师一次性生成大量文本 → 离线构造蒸馏数据集 → SFT 学生；
- **在线 SeqKD**：训练中动态让教师（或教师 + 学生混合）采样文本做监督；
- **GKD（Generalized KD）**：用**学生自己生成的序列**（on-policy）配教师的打分做反向 KL，缓解 off-policy 暴露偏差。

> 核心差异：小模型时代对齐"概率分布"，大模型时代对齐"生成的文本流"。文本流是分布的可采样近似。

### 6.2 logits 蒸馏在大 LLM 上的可行性问题

为什么不能直接对大 LLM 做 Hinton 式蒸馏：

1. **词表太大**：词表约 100k~150k，每个 token 都要在全词表上算 softmax + KL，单步显存/算力开销巨大（$\mathcal{O}(V)$ 的中间张量 + 两个前向）；
2. **模型太大**：教师（几十 B）+ 学生（几 B）双模型前向，训练显存直接翻倍，小团队根本跑不动；
3. **分布不匹配**：大模型的 softmax 分布极度尖锐，且长序列输出上"分布"的概念退化为逐位置独立建模，KL 对齐在长序列上误差累积；
4. **tokenizer 不一致**：师生词表不同时 logits 空间完全不对齐，需要额外对齐（如 token 映射），复杂度剧增；
5. **收益不匹配**：对大模型而言，压缩瓶颈主要在推理显存/带宽，而序列级蒸馏数据已经够用，没必要付出 logits 对齐的高昂成本。

### 6.3 MiniLLM 与反向 KL：为什么正 KL 不够好

先理清方向约定（面试最容易讲混）：设教师分布 $p_T$、学生分布 $p_S$。

**正向 KL（Forward KL）** $D_{KL}(p_T \| p_S) = \mathbb{E}_{x \sim p_T} \log \frac{p_T(x)}{p_S(x)}$

- 按教师分布采样求期望，**要求学生在教师有概率的所有地方都有概率**（零避免 / mode covering）；
- 后果：学生被迫覆盖教师的长尾（包括大量低质量、幻觉式文本），导致学生输出**过平滑、过于保守、废话多**；
- 并且期望要按 $p_T$ 采样，需要从教师分布采样，开销大且 off-policy（与推理时的学生分布不一致）。

**反向 KL（Reverse KL）** $D_{KL}(p_S \| p_T) = \mathbb{E}_{x \sim p_S} \log \frac{p_S(x)}{p_T(x)}$

- 按**学生自己**的分布采样（on-policy），只惩罚"学生给高概率而教师给低概率"的位置；
- 性质是**零强制 / mode seeking**：学生可以只覆盖教师的一个高概率模式，分布更尖锐、更自信；
- 学生采样自己的输出训练，正好模拟推理时的行为，缓解暴露偏差（exposure bias）。

**MiniLLM**（2023）的做法：学生生成序列前缀（on-policy），用反向 KL 对齐学生的完整序列分布与教师分布，并给 $D_{KL}$ 加上界处理学生采样到教师零概率位置的情况：

$$\mathcal{L} = \sum_{t} D_{KL}\!\left(p_S(\cdot \mid x, y_{<t}) \,\|\, p_T(\cdot \mid x, y_{<t})\right)$$

**效果**：学生输出更"像教师"、更精准、幻觉更少，尤其在小学生 + 大教师场景下明显优于正向 KL。核心一句话：**正 KL 让学生面面俱到（学成"平庸的平均人"），反 KL 让学生抓住要点（学成"教师本人"）。**

### 6.4 为什么用教师生成的数据训练，而不是直接用标注数据

1. **分布一致**：学生推理时生成的文本分布，与教师生成的文本分布更接近；用教师数据训练 = 提前对齐推理时的输入分布（缓解 exposure bias）；
2. **教师有 label 没有的分布**：标注数据（gold label）是 one-hot / 单一参考答案，而教师学到了"对于这个输入，合理回答的分布"——多轮对话、开放问答、长文本场景根本不存在唯一 label，教师分布就是唯一可得的监督；
3. **教师的隐式偏好**：教师经过 RLHF 等对齐后，学会了"什么回答被人类接受"（风格、长度、拒绝方式），这些偏好编码在教师输出里，而原始 label 里没有；
4. **纯数据蒸馏即可用**：当教师不开源时，**只拿教师生成的文本做 SFT 也算蒸馏**（这是最实用的闭源大模型蒸馏手段，如用 GPT-4 输出训练开源小模型）。

### 6.5 多模态蒸馏（重点）

#### 6.5.1 CLIP 蒸馏到小视觉塔：EVA-CLIP

- 背景：CLIP 的图像塔与文本塔做对比学习，图像塔效果上限受限于"无监督标签质量"；
- EVA-CLIP 的做法：用 **EVA（一个大规模掩码图像建模 MIM 模型，ViT-g）的图像自监督特征作为教师**，蒸馏给 CLIP 的图像塔，同时做 CLIP 式图文对比对齐：
  $$\mathcal{L} = \mathcal{L}_{CLIP} + \lambda \left\| f_{student}^{img}(x) - f_{EVA}^{img}(x) \right\|_2^2$$
- 收益：图像塔在**更小的参数下**获得接近甚至超过大模型的视觉特征（自监督大特征 → 对比学习小塔），同时保持与文本塔对齐。

#### 6.5.2 VLM 蒸馏：TinyLLaVA

- 背景：VLM（如 LLaVA）参数量大，边缘设备跑不动；
- TinyLLaVA 的做法：**学生 VLM 学教师 VLM 的回答与推理**。用大教师 LLaVA-1.5-7B 在视觉指令数据上生成回答，再让学生 VLM（小语言模型骨干，如 1.3B~3.1B）在"图像 + 指令 → 教师回答"上做序列级蒸馏 + 视觉指令微调；
- 关键点：蒸馏的是**语言模型的生成分布**（序列级，见 6.1），视觉塔也可以复用教师的视觉编码器（教师视觉塔与小学生共享，只压缩语言部分）；
- 效果：3.1B 参数达到接近 7B 教师的水平，推理速度提升数倍。

#### 6.5.3 SigLIP 2 的自蒸馏思想

- SigLIP 2（Google，2024）在 SigLIP 基础上引入**自蒸馏（self-distillation）**：
  - 每个塔（图像塔/文本塔）都**从自身的教师版本学习**，教师是模型的 EMA（指数移动平均）或固定预训练权重；
  - 自蒸馏目标 + 语言模型辅助监督（cap-desc 重写伪标题）+ 掩码预测目标联合训练；
- 思想与 DINO 一脉相承：**训练过程中模型自己教自己**，教师参数更稳定、信号更一致，起到平滑训练、防止塌缩、增强表征的作用；
- 启示：自蒸馏不需要额外的大教师，是"穷人的蒸馏"，在预算受限的多模态预训练中尤其实用。

#### 6.5.4 多模态蒸馏的模态对齐问题

多模态蒸馏的独特难点：**师生可能在结构上根本不对齐**。

| 不对齐来源 | 例子 | 处理方案 |
|-----------|------|---------|
| 视觉塔 patch size 不同 | 教师 patch 14×14，学生 patch 32×32 | token 数不同，无法逐 token 对齐 |
| 输入分辨率不同 | 教师 448²，学生 224² | token 网格不同，先插值/池化 |
| 特征维度不同 | 教师 d=1024，学生 d=512 | 加线性投影层 $W_r$ |
| tokenizer 不同（VLM 侧） | 教师 Qwen、学生 LLaMA | logits 空间不可比，用序列级蒸馏 |
| 模态对齐（图文） | 教师双塔，学生只用视觉塔 | 对齐视觉塔对文本的响应（如图文匹配 logits） |

针对"token 数不同怎么办"，常用方案（按优先级）：

1. **全局层面对齐**：用 CLS token 或均值池化后的全局特征对齐（token 数无关，最稳）；
2. **特征图插值**：把学生 token 网格双线性插值到教师 token 网格再逐 token 对齐（需 patch 数成比例，否则信息错位）；
3. **注意力图对齐**：对齐每层的 attention map（与 token 数无关、天然对齐空间结构）；
4. **投影对齐**：学生特征过 MLP 映射到教师特征空间，再算距离（FitNets 思路）；
5. **干脆不对齐特征，只做输出级蒸馏**：让学生的最终输出（图文匹配分数/生成文本）对齐教师——实现最简、多模态场景最常用。

> 面试记忆点：**模态对齐问题一句话——"对齐不了维度就对齐分布，对齐不了分布就对齐输出"**。

## 七、蒸馏 vs 量化 vs 剪枝：三种模型压缩手段

| 维度 | 知识蒸馏 | 量化 | 剪枝 |
|------|---------|------|------|
| 本质 | 学知识（训练层面） | 压缩数值表示（精度位数） | 删冗余（结构层面） |
| 是否改变结构 | 学生本身是轻量架构 | 结构不变，精度降低 | 删权重/头/层 |
| 是否要训练 | 需要（重点） | 一般不需要（PTQ），QAT 要 | 结构化剪枝常需微调 |
| 是否需要教师/数据 | 需要教师 + 数据 | 需要少量校准数据（PTQ） | 需要数据做重要性评估 |
| 精度损失 | 最小（知识迁移） | 小（4bit 后开始明显） | 视剪枝比例，大比例损失大 |
| 速度/内存收益 | 取决于学生架构 | 内存按 bit 比例降，速度看硬件 | 直接减少计算量 |
| 与硬件耦合 | 无 | 强（需硬件支持低 bit 算子） | 中 |
| 典型应用 | 大模型 → 小模型 | 大模型直接低 bit 推理 | 大模型瘦身 |
| 可叠加性 | 可与量化/剪枝叠加 | 可与蒸馏叠加 | 可与蒸馏叠加 |

> 三者正交：**蒸馏负责"变小且变好"，量化负责"变小且变快"，剪枝负责"变小且变轻"**。工程上常用"蒸馏出小模型 → 再量化/剪枝"的级联流水线（如小模型 + INT8 量化，精度损失比直接量化大模型小得多）。

## 八、工程实践

### 8.1 什么时候该蒸馏

| 场景 | 是否适合蒸馏 | 说明 |
|------|------------|------|
| 部署资源受限（边缘设备/手机/车机） | ✅ 首选 | 推理显存、延迟双约束 |
| 高并发在线服务 | ✅ 适合 | 小模型吞吐高，QPS 瓶颈 |
| 教师已存在且开源 | ✅ 成本低 | 只需教师推理数据 |
| 需要大规模微调压缩 | ✅ 与 LoRA 等叠加 | 学生也可用 LoRA 训练 |
| 数据量极少 | ⚠️ 谨慎 | 蒸馏同样需要数据，软标签缓解但非万能 |
| 学生任务与教师差异大 | ⚠️ 谨慎 | 领域漂移时教师知识有害 |

### 8.2 教师选择

1. **优先选同任务、同领域、精度更高的模型**——教师的强项必须覆盖学生的目标能力；
2. **不是越大越好（capacity gap）**：教师过强（> 学生 10 倍以上参数）时，软标签过于尖锐/复杂，小学生学习不动甚至比自训更差；缓解办法：提高温度软化、或用中等规模教师（先蒸馏出一个中间模型再蒸馏学生）；
3. **多个教师可以集成**：多个教师的平均软目标比单一教师稳（模型集成 → 蒸馏）；
4. **教师不一定需要"正式"模型**：自蒸馏（EMA）、无监督教师（MIM 特征）、闭源 API 教师（生成数据）都算合法教师。

### 8.3 学生架构设计

- **结构对齐优先**：VLM/LLM 场景，学生尽量与教师同族（同 tokenizer、同模态塔结构），可复用教师 embedding、甚至部分层权重初始化，蒸馏效率翻倍；
- **瘦身优先"减深度"而非"减宽度"**：减少层数（depth）比减宽（width）在蒸馏中通常保留更多能力，且与特征蒸馏的层对齐天然兼容；
- **视觉塔设计**：多模态场景可考虑"学生共享教师视觉塔 + 小语言模型"（TinyLLaVA 路线），或独立小视觉塔（需处理模态对齐，见 6.5.4）；
- **学生不要从零训**：先预训练/预加载学生骨干，蒸馏效率远高于随机初始化。

### 8.4 评测设计（学生 vs 教师 vs 基线对比表）

```text
| 模型                 | 参数量 | 内存 | 时延 | Acc/TaskA | Acc/TaskB | 说明                     |
|----------------------|--------|------|------|-----------|-----------|--------------------------|
| 教师（大模型）       | 7B     | 16G  | 80ms | 92.3%     | 90.1%     | 精度上限/成本基线         |
| 学生（无蒸馏自训）   | 0.8B   | 2G   | 12ms | 85.1%     | 82.4%     | 判断蒸馏的真实增益         |
| 学生（KD 蒸馏）      | 0.8B   | 2G   | 12ms | 89.6%     | 87.2%     | 目标模型                  |
| 学生（KD+INT8 量化） | 0.8B   | 1G   | 8ms  | 88.9%     | 86.0%     | 叠加压缩后的最终部署形态   |
```

评测要点：

1. **必须设"学生无蒸馏基线"**：只有和"同样大小的学生自己训"对比，才能体现蒸馏的价值；
2. **精度 + 效率双表**：精度表配时延/显存/参数量表，单独看精度无意义；
3. **同数据同种子**：蒸馏与非蒸馏学生用同数据、同训练步数对比，避免"多训了数据所以更强"的假象；
4. **看相对损失而非绝对值**：常以"教师精度的损失比例"（如 92% → 89.6%，损失 2.6%）衡量蒸馏保真度；
5. **额外看 OOD / 分布外能力**：蒸馏学生是否继承了教师的泛化能力，还是只"背下"了训练分布；
6. **消融**：对温度 $T$、权重 $\lambda$、是否加特征损失做消融实验，形成可复现的配置记录。

## 九、高频面试问答

**Q1：软标签为什么比硬标签好？**
硬标签（one-hot）只给出"是哪类"；软标签是连续概率分布，编码了类间相似度（"猫和狗近、猫和车远"）、样本难度（置信度）与暗知识。学生从软标签中学到的是"关系结构"而非"答案"，信息量远大于硬标签，且梯度更平滑、训练更稳。

**Q2：温度 T 的作用是什么？T 越高越好吗？**
T 控制 softmax 分布的"软硬程度"：T 大 → 分布摊平，暴露类间相似度；T 小 → 接近 one-hot。不是越高越好：T 过高分布趋近均匀、信息抹平且噪声放大；T 过低退化为硬标签。训练时一般 2~10，推理时必须用 T=1。

**Q3：损失里的 T² 是从哪来的？**
软损失梯度推导得到 $\partial L_{soft}/\partial z_i = (q_i^T - p_i^T)/T$，在大 T 泰勒近似下正比于 $(z_i^T - z_i^S)/(NT^2)$——梯度随 $1/T^2$ 衰减。乘上 $T^2$ 使梯度量级与温度解耦，且大 T 下蒸馏等价于 logits 的均方误差匹配。

**Q4：离线、在线、自蒸馏的区别？**
离线：教师固定，两阶段，最稳最常用；在线：两个同规模模型互教同训，无需大教师；自蒸馏：教师是学生自身的 EMA/历史版本，零教师成本。维度在"教师从哪来、要不要更新"。

**Q5：为什么大模型难做 logits 蒸馏？**
① 词表 100k+，全词表 softmax/KL 显存算力爆炸；② 双模型（几十 B + 几 B）前向训练开销翻倍；③ 长序列分布逐 token 对齐误差累积、师生 tokenizer 不一致时 logits 空间不对齐；④ 大模型更关注推理压缩，序列级蒸馏（教师生成文本 → SFT）已足够且更便宜。

**Q6：正向 KL 和反向 KL 的区别？为什么 MiniLLM 用反向 KL？**
正 KL（教师∥学生）按教师分布采样，零避免、mode covering，学生被迫覆盖教师长尾（含低质量文本），输出过平滑；反 KL（学生∥教师）按学生分布采样（on-policy），零强制、mode seeking，学生只覆盖教师高概率区域，分布尖锐。MiniLLM 用反 KL 让学生的采样即推理行为，输出更精准、幻觉更少。

**Q7：为什么用教师生成的数据训练学生，而不是直接用标注数据？**
① 师生共享"生成分布"（缓解 exposure bias）；② 开放场景无唯一 label，教师分布是唯一监督；③ 教师经对齐后编码了人类偏好（风格/长度），label 里没有；④ 教师不开源时，教师生成数据是唯一可行的蒸馏途径。

**Q8：多模态蒸馏的难点？视觉塔 token 数不一样怎么办？**
难点：模态对齐——师生 patch size、分辨率、特征维度、tokenizer 都可能不同。方案：全局特征（CLS/池化）对齐、特征插值、注意力图对齐（与 token 数无关）、线性投影对齐维度、或直接输出级蒸馏（对齐图文匹配分数/生成文本）。

**Q9：特征蒸馏 vs logits 蒸馏的优缺点？**
logits 蒸馏：简单通用、任务无关，但只对齐"结论"；特征蒸馏：对齐"推理过程"，信息更丰富、对表示学习增益大，但需解决层选择、维度/空间对齐、归一化，实现复杂、对结构差异敏感。

**Q10：蒸馏和量化、剪枝的区别？可以叠加吗？**
蒸馏是训练层面的知识迁移（改变学生架构/分布）；量化压缩数值精度（FP16→INT8）；剪枝删冗余结构。三者正交，工程上"先蒸馏缩小、再量化提速、再剪枝瘦身"是标准级联流水线，叠加后精度损失小于单独粗暴压缩。

## 十、常见误区

- [ ] **误区 1：蒸馏就是让学生拟合教师的 logits**。错——核心是温度软化的概率分布（软目标），且大模型场景已演进为序列级/特征/关系蒸馏；直接拟合 logits 既不稳也不常用。
- [ ] **误区 2：温度 T 越大越好**。T 过高分布趋平，信息消失；T 必须只在训练用、推理回归 T=1。选 T 要看教师自信度与学生容量。
- [ ] **误区 3：教师越大越好**。存在容量差距（capacity gap）：教师过强小学生会"学不动"，必要时用中等教师或调大温度。
- [ ] **误区 4：学生必须与教师同构**。异构蒸馏可行（不同骨干、不同深度），只是对齐成本高；特征蒸馏尤其需要维度/空间对齐。
- [ ] **误区 5：用硬标签微调 = 蒸馏**。没有教师信号的"训小模型"只是普通训练；"学生 + 教师软目标/特征/序列"才是蒸馏。
- [ ] **误区 6：蒸馏后学生一定损失精度**。设计得当的学生可接近甚至超过教师（学生容量匹配时）；且蒸馏可与量化/剪枝叠加互不冲突。

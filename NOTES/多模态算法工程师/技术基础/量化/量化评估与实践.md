# 量化评估与实践：显存账本、多模态敏感性与部署落地

> 本模块索引见 [量化详解](量化详解.md)

## 一、量化质量评估双维度

量化是"用精度换显存/速度"，所以验收必须回答两个问题：**数值上差了多少**、**任务上差了没**。

### 1.1 维度一：数值误差（快速、逐层、定位用）

对每层的权重/激活，比较量化前后张量的差异：

| 指标 | 公式 | 用途 |
| --- | --- | --- |
| 最大绝对误差 | $\max_i \|\hat{x}_i - x_i\|$ | 找"爆点"（离群损坏处） |
| 相对误差 | $\frac{\|x - \hat{x}\|_2}{\|x\|_2}$ | 整体幅度损失 |
| 余弦相似度 | $\frac{x \cdot \hat{x}}{\|x\|\|\hat{x}\|}$ | 方向保持度（>0.99 通常安全） |
| 信噪比 SNR | $10\log_{10}\frac{\|x\|^2}{\|x-\hat{x}\|^2}$ | 单层量化代价量化 |

数值误差**不等于任务掉点**，但能快速定位"哪一层最受伤"（量化后逐层对比，误差最大的层优先处理）。

### 1.2 维度二：任务指标（最终验收，唯一权威）

| 任务 | 指标 | 可接受标准（经验） |
| --- | --- | --- |
| LLM 语言建模 | Perplexity（WikiText-2 / C4） | INT8 +<0.1；INT4 +<1（70B 更小） |
| 通用能力 | MMLU / GSM8K / 零样本 acc | 掉 <1~2% 视为可接受 |
| 图文检索/匹配 | 图文匹配分数、Recall@K | 掉 <0.5~1% |
| OCR / 文档理解 | 字符/单词准确率 | 掉 <1%（视觉细节任务更敏感） |
| 检测/分割 | mAP / mIoU | 掉 <0.5~1%（回归头敏感） |

**验收铁律**：数值误差通过不等于任务通过——**永远以任务指标为准**，数值误差只用来定位。

### 1.3 评估代码思路（可运行）

```python
import torch
import torch.nn.functional as F

torch.manual_seed(0)

def quant_sym(x, bits, per_channel=False):
    """对称量化→反量化（per-tensor / per-channel）"""
    qmax = (1 << (bits - 1)) - 1
    if not per_channel:
        scale = x.abs().max() / qmax
        q = torch.clamp(torch.round(x / scale.clamp_min(1e-12)), -qmax, qmax) * scale
        return q
    scale = x.abs().max(dim=0, keepdim=True).values / qmax   # 每列一个 scale
    q = torch.clamp(torch.round(x / scale.clamp_min(1e-12)), -qmax, qmax) * scale
    return q

def evaluate(orig, quant, label):
    max_abs = (orig - quant).abs().max().item()
    cos = F.cosine_similarity(orig.flatten(), quant.flatten(), dim=0).item()
    rel = ((orig - quant).norm() / orig.norm()).item()
    print(f"{label:22s} max_abs={max_abs:.4f}  cosine={cos:.4f}  rel_err={rel:.4f}")

# 带离群通道的权重矩阵（模拟 LLM 某层）
W = torch.randn(128, 64) * 0.1
W[:, 3] *= 30                     # 离群通道

evaluate(W, quant_sym(W, 8), "INT8 per-tensor")
evaluate(W, quant_sym(W, 8, per_channel=True), "INT8 per-channel")
evaluate(W, quant_sym(W, 4), "INT4 per-tensor")
evaluate(W, quant_sym(W, 4, per_channel=True), "INT4 per-channel")
```

输出（实际运行）：

```text
INT8 per-tensor            max_abs=0.0308  cosine=0.9988  rel_err=0.0484
INT8 per-channel           max_abs=0.0307  cosine=1.0000  rel_err=0.0065
INT4 per-tensor            max_abs=0.5533  cosine=0.9558  rel_err=0.2945
INT4 per-channel           max_abs=0.5533  cosine=0.9936  rel_err=0.1136
```

**结论**：per-channel 对含离群点的权重收益巨大（INT4 rel_err 0.29 → 0.11）——这就是"**掉点先换 per-channel**"的依据。任务级评估（perplexity/acc）用现成工具：LLM 用 `lm-evaluation-harness` 或 `transformers` 自算 PPL，图文用各自的 benchmark。

### 1.4 端到端任务级评估：perplexity 实测（可运行）

用一个小"语言模型"（Embedding + 线性层，在合成马尔可夫序列上训练）演示**量化前后的 PPL 对比**——这就是 LLM 任务级验收的最小闭环：

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)

V = 32                                    # 词表
P = torch.softmax(torch.randn(V, V) * 1.5, dim=1)   # 转移概率
seq = [0]
for _ in range(20000):                    # 采样合成"语言"
    seq.append(int(torch.multinomial(P[seq[-1]], 1)))
seq = torch.tensor(seq)
x, y = seq[:-1], seq[1:]                  # 预测下一个 token

class TinyLM(nn.Module):
    def __init__(self):
        super().__init__()
        self.emb = nn.Embedding(V, 16)
        self.fc = nn.Linear(16, V)
    def forward(self, x):
        return self.fc(self.emb(x))

def train():
    m = TinyLM(); opt = torch.optim.Adam(m.parameters(), lr=1e-2)
    for _ in range(400):
        opt.zero_grad()
        F.cross_entropy(m(x[:8192]), y[:8192]).backward()
        opt.step()
    return m

def ppl(m):
    with torch.no_grad():
        return F.cross_entropy(m(x), y, reduction="mean").exp().item()

def quant_weights(m, bits=8):             # per-channel 量化权重
    q = TinyLM(); q.load_state_dict(m.state_dict())
    with torch.no_grad():
        for name, p in m.named_parameters():
            if "weight" in name and p.ndim == 2:
                qmax = (1 << (bits - 1)) - 1
                scale = p.abs().max(dim=0, keepdim=True).values / qmax
                qp = torch.clamp(torch.round(p / scale.clamp_min(1e-12)), -qmax, qmax) * scale
                dict(q.state_dict())[name].copy_(qp)
    return q

m = train()
print(f"FP16 perplexity: {ppl(m):.3f}")
print(f"INT8 perplexity: {ppl(quant_weights(m, 8)):.3f}")
```

输出（实际运行）：

```text
FP16 perplexity: 11.337
INT8 perplexity: 11.338
```

**结论**：weight-only INT8 对语言建模**基本无损**（PPL +0.001）——这就是"INT8 通常无感"的直接证据。真实 LLM 的验收就是把这个流程换成 LLaMA + 真实数据集。

## 二、显存与速度收益账本

### 2.1 权重显存表（仅权重，不含 KV cache/激活/优化器）

| 模型 | 参数 | FP16 | INT8 | INT4 |
| --- | --- | --- | --- | --- |
| 7B | $7\times10^9$ | **~14 GB** | ~7 GB | ~3.6 GB |
| 13B | $1.3\times10^{10}$ | ~26 GB | ~13 GB | ~6.7 GB |
| 70B | $7\times10^{10}$ | **~140 GB** | ~70 GB | ~35 GB |

（INT4 按 g128 约 4.15 bits/param 计，含 scale 开销。）

**反直觉结论**：70B 的 INT4（35GB）比 7B 的 FP16（14GB）大，但 70B INT4 单卡 A100-80G 就能跑，7B FP16 只够 24G 卡——**量化让"更大更强的模型"在固定显存预算内成为可能**，这比"同模型省内存"更重要。

### 2.2 速度提升机制：带宽瓶颈 → 算术瓶颈

LLM 生成（decode）是 **memory-bound**：每步只算 1 个 token 的 matmul，但要把**全部权重读一遍**。此时瓶颈是显存带宽，不是算力。

$$\text{decode 时间} \approx \frac{\text{权重字节数}}{\text{带宽}} \Rightarrow \text{INT4 比 FP16 快} \approx \frac{14\text{GB}}{3.6\text{GB}} \approx 3\text{倍（理想）}$$

- 实测（A100/H100、g128 INT4）通常 **1.5~2×**：受 kernel 开销、KV cache 读取、剩余 FP16 层拖累，到不了 3×；
- prefill（长序列）是 **compute-bound**：量化收益主要来自 INT GEMM 的 Tensor Core，但精度要求使激活保持 FP16，收益小于 decode；
- 小模型收益低（权重小、带宽占比低）；**大模型 + 小 batch decode 时量化收益最大**。

### 2.3 实测经验范围（LLaMA 类，WikiText-2 PPL）

| 方案 | PPL 变化 | 体感 |
| --- | --- | --- |
| INT8 weight-only | +<0.1 | 无感 |
| INT4 GPTQ/AWQ（7B） | +0.4~0.6 | 下游掉 1~2% |
| INT4 GPTQ/AWQ（70B） | +0.3 左右 | 几乎无感 |
| INT4 激活也量化 | +1~3 甚至更多 | 危险，谨慎 |

**经验法则**：模型越大越耐量化；**权重耐、激活不耐**；掉点出现时优先调"定标方式"而非"降低位宽"。

## 三、KV cache 量化（INT8/FP8 的收益与代价）

- **为什么要量化 KV**：长上下文下 KV cache 常占显存 50%+，且 decode 每步都要读全部 KV（带宽大户）；
- **做法**：K/V 用 INT8/FP8（甚至 INT4）存储，读取时反量化；配合**分组量化 + 通道离群点保护**（对敏感通道单独处理）；
- **收益**：显存与 KV 读取带宽降至 1/2~1/4，长上下文吞吐显著提升；
- **代价**：KV 是"逐 token 累积"的，误差会沿序列长度累积，过长上下文 + 过低 bit 可能伤质量；所以常选 **FP8/INT8**（比权重更保守），INT4 只在显存吃紧时用；
- 量化 KV 是推理中**唯一允许有损**的手段，与 GQA/MQA、PagedAttention 可叠加（详见 [KVCache详解](../KVCache/KVCache详解.md) 与 [KV Cache优化技术](../KVCache/KV%20Cache优化技术.md)）。

## 四、多模态量化敏感性（重点）

### 4.1 视觉塔 vs LLM：谁更耐量化？

| | 视觉塔（ViT/CLIP） | LLM 主干 |
| --- | --- | --- |
| 数据形态 | 连续图像特征（patch 嵌入） | 离散 token 语义 |
| 激活特性 | **幅度大、含高动态范围**，细节敏感 | 有离群点但冗余度高 |
| 权重冗余 | 相对低 | 极高（参数多、鲁棒） |
| 量化敏感性 | **敏感**（细节丢失直接伤图文匹配/OCR） | **耐量化**（weight-only INT8/INT4 掉点小） |

**为什么视觉塔更敏感**：图像特征是**连续细粒度**的，微小的量化噪声会直接抹掉边缘/纹理/文字细节；而 LLM 的高层语义冗余能容忍权重的轻微扰动。实验上常见：**同一模型，LLM 权重 INT8/INT4 几乎无感，视觉塔一量化就掉点**。

数值上直观验证"激活比权重更不耐量化"（同样 INT4，谁掉得狠）：

```python
import torch
import torch.nn.functional as F

torch.manual_seed(0)
def q4(x):
    qmax = 7
    scale = x.abs().max() / qmax
    return torch.clamp(torch.round(x / scale.clamp_min(1e-12)), -qmax, qmax) * scale
def ev(orig, q, label):
    rel = ((orig - q).norm() / orig.norm()).item()
    cos = F.cosine_similarity(orig.flatten(), q.flatten(), dim=0).item()
    print(f"{label:26s} rel_err={rel:.4f}  cosine={cos:.4f}")

w = torch.randn(4096) * 0.5          # 干净的权重（LLM 权重近似）
a = torch.randn(4096) * 0.5
a[::100] *= 20                       # 带离群点的激活（视觉塔特征常见）
ev(w, q4(w), "权重 INT4")
ev(a, q4(a), "激活 INT4(含离群)")
```

输出（实际运行）：

```text
权重 INT4                    rel_err=0.1684  cosine=0.9861
激活 INT4(含离群)               rel_err=0.5104  cosine=0.8601
```

**结论**：同样 4-bit，激活因为含离群点，重构误差比权重高 3 倍、余弦降到 0.86——**这就是"激活不耐量化"的数学根源**，也是多模态部署时视觉塔保持 FP16 的原因。

### 4.2 图文任务的量化验收

| 任务 | 验收指标 | 量化后观察 |
| --- | --- | --- |
| 图文匹配/检索 | 图文匹配分数、Recall@K | 视觉塔量化后明显下降 |
| 图像问答（VQA） | 准确率 | LLM 量化影响小，视觉塔量化影响大 |
| OCR/文档理解 | 字符/单词准确率 | **最敏感**（像素级细节） |

验收流程：FP16 baseline 跑全量 → 量化后跑全量 → 逐项对比；若掉点，用 1.1 的逐层数值对比定位"是视觉塔哪一层在受伤"。

### 4.3 常见做法：混合精度

```text
视觉塔（patchify/视觉 transformer） → FP16（或 FP32 敏感层）
视觉投影层（image projector）       → FP16（桥接层，误差被放大）
LLM 主干                          → INT8 / INT4（weight-only）
输出头 / LM head                   → FP16（输出 logits 敏感）
```

- 好处：把"有限的不确定性预算"花在刀刃上——LLM 大权重省下来的显存远多于视觉塔，所以**先量化 LLM，视觉塔保持高精度**是性价比最高的方案；
- 工程上先跑"全 LLM 量化 + 视觉塔 FP16"→ 掉点再逐个把视觉塔敏感层回 FP32，而不是一上来全量化。

## 五、量化部署全流程示例

### 5.1 通用链路

```text
PyTorch 模型 (FP32/FP16)
   │ ① torch.ao.quantization（PTQ，先在本机验证误差）
   ├─ ② 导出 ONNX（含量化算子） → TensorRT INT8 engine（GPU 部署）
   └─ ③ 导出 GGUF → llama.cpp / Ollama（CPU/Apple 部署）
   └─ ④ 直接用 auto-gptq/autoawq 产出 INT4 → vLLM（LLM 生产）
```

```bash

# ② TensorRT 构建 INT8 engine（首次自动校准）
trtexec --onnx=model.onnx --int8 --calib=calibration.cache --calibData=./calib_data

```

TensorRT 的 INT8 用**对称量化**，权重 scale 取 $\max|W|$、激活 scale 用校准（MinMax/Entropy/Percentile，KL 散度是默认），校准发生在激活上、权重直接取最大值即可（详见 [精度与量化](../TensorRT/精度与量化.md)）。

## 六、量化失败排查（掉点严重）

按概率从高到低逐项排查：

1. **检查离群点**：打印每层激活 `act.abs().max()` 与均值比，出现 >100 量级即离群点作祟（这是视觉塔掉点的头号原因，见四 4.1）；
2. **换 per-channel / per-group**：per-tensor 的共享 scale 被离群值撑大是掉点主因，1.3 已证 per-channel 能把 INT4 rel_err 从 0.29 降到 0.11；
3. **混合精度**：把量化敏感的层（embedding、lm_head、视觉塔、投影层）回 FP16/FP32，其余保持低比特；
4. **增大/修正校准集**：校准集要**覆盖真实业务分布**（不能只拿通用文本）；样本太少或分布漂移会让 scale 严重偏差；
5. **检查溢出/饱和**：确认计算时用 FP16/BF16 反量化而不是 FP32 下溢；对称量化无 zero-point 时注意负不对称分布（改用非对称量化）；
6. **数值定位**：用 1.1 的逐层 evaluate()，找出"量化前后数值误差最大的层"，针对性处理（该层回 FP16 或换算法）；
7. **仍不行**：考虑 QAT（训练成本换精度）或换算法（朴素 RTN → GPTQ/AWQ → 更细 group）。

> **决策顺序**：先 PTQ + per-channel 看任务指标 → 掉点→ 混合精度 → 换校准/算法 → 最后才 QAT。

## 七、高频面试问答

**Q1：量化后怎么验收？**
双维度：数值误差（逐层 max_abs/rel_err/cosine，用于定位）＋ 任务指标（perplexity/acc/mAP/VQA，最终权威）。数值通过不等于任务通过，一切以任务为准。

**Q2：为什么 INT8 几乎不掉点？**
权重分布集中、量化步长小（相对误差 ~0.8%），且 LLM 权重冗余高、对扰动鲁棒；INT8 weight-only 的 PPL 增加 <0.1，远小于任务自身的波动。

**Q3：多模态模型怎么量化？**
混合精度：视觉塔 FP16（对量化敏感）、LLM 主干 INT8/INT4（耐量化）、输出头 FP16。先量化 LLM 省大头显存，视觉塔掉点再逐层回 FP32。

**Q4：perplexity 掉多少可接受？**
INT8 应 <+0.1；INT4 一般 +0.3~0.6（7B），70B 更小；掉 +1 以上就要排查（可能激活也被量化或定标有问题）。下游任务掉 1~2% 通常可接受，超出则处理。

**Q5：掉点严重先查什么？**
先看离群点（激活 max 与均值比）→ 换 per-channel/per-group → 混合精度 → 增大校准集 → 检查溢出。数值逐层定位最快。

**Q6：KV cache 量化收益和代价？**
省显存和带宽（长上下文大头），但误差沿序列累积，所以通常用 FP8/INT8 保守量化；与 GQA/PagedAttention 叠加，是长上下文显存方案之一。

**Q7：校准集为什么要代表业务分布？**
scale 由校准集统计决定，校准集不覆盖真实分布（如业务多是长代码，校准用短文本），量化后 scale 就错——激活范围估计偏了就整体掉点。

**Q8：量化掉点后用 QAT 还是换算法？**
先用"便宜手段"：per-channel、混合精度、换 GPTQ/AWQ（都比 QAT 便宜得多）。只有这些都救不回来（如激活也必须 INT4 的端侧场景）才上 QAT。

## 八、常见误区

1. **"数值误差小 = 任务不掉点"** —— 错。逐层数值误差与任务指标不是线性对应；某些层数值误差小但方向性损坏（如余弦下降）照样掉点，必须跑任务。
2. **"per-tensor 和 per-channel 差不多"** —— 错。只要有权重/激活离群点，per-tensor 的共享 scale 就被撑大，误差成倍放大（1.3 实测 INT4 差 2.6 倍）。
3. **"量化必然掉点"** —— 错。weight-only INT8 基本无感，INT4 在 70B 级也接近无损；掉点通常来自"激活被量化"或"定标方式不对"。
4. **"先量化视觉塔还是 LLM 无差别"** —— 错。视觉塔对量化敏感得多，错误量化视觉塔会直接伤图文匹配/OCR；应优先保持视觉塔 FP16。
5. **"量化只影响显存不影响延迟"** —— 错。decode 是带宽瓶颈，权重位宽直接决定每步读取字节数，INT4 通常带来 1.5~2× 吞吐提升。

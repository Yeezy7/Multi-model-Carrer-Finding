# 学习率调度（Learning Rate Schedule）

> 本模块索引见 [优化器与学习率详解](优化器与学习率详解.md)

## 一、定义与公式

> 优化器决定"怎么走"，调度器决定"走多快"。同一优化器配不同调度，效果天差地别——**大模型训练中，调度策略的重要性不亚于优化器本身。**

### 1.1 Warmup：用小 lr 安全起步

训练初期直接上大 lr 会导致发散或崩溃，原因：

1. **初始参数随机 → 损失曲面初期极陡**：初始梯度范数可能异常巨大，大 lr 一步迈飞；
2. **Adam 二阶矩统计未建立**：$v_t$ 从 0 累积，初期 $\sqrt{\hat v_t}$ 偏小 → Adam 自动把步长放大（见 Adam 子篇 §1.2 偏差校正的推论），与大 lr 叠加 = 更新爆炸；
3. **BatchNorm/分布未稳定**：初期 batch 统计量剧烈漂移，大 lr 放大不稳定；
4. **Transformer 特有**：attention logits 初始就乘 $\sqrt{d_k}$，softmax 分布极端，梯度噪声大。

**三种常见 warmup**（设 warmup 步数 $T_w$，最大学习率 $\eta_{\max}$）：

| 方式 | 公式 | 特点 |
|------|------|------|
| 线性 warmup | $\eta_t = \eta_{\max} \cdot \dfrac{t}{T_w}$ | 最简单、最常用（LLaMA 等） |
| 余弦/平滑 warmup | $\eta_t = \eta_{\max}\cdot \dfrac{1 - \cos(\pi t/T_w)}{2}$ | 起始平滑，斜率连续 |
| 多项式 warmup | $\eta_t = \eta_{\max} \cdot \left(\dfrac{t}{T_w}\right)^{p}$ | $p$ 控制增速（$p=2$ 慢起快落） |

### 1.2 余弦退火（Cosine Annealing）

**思想**：后期参数已在好区域，大 lr 只会震荡跳出；让 lr 从峰值**平滑下降**到最小值：

$$\eta_t = \eta_{\min} + \frac{1}{2}(\eta_{\max} - \eta_{\min})\left(1 + \cos\frac{\pi t}{T}\right)$$

- $T$：总步数，$t$：当前步数（warmup 后从 0 计）；
- $t=0$ 时 $\eta=\eta_{\max}$，$t=T$ 时 $\eta=\eta_{\min}$（常取 $\eta_{\max}/10$ 或 0）；
- **为什么平滑优于阶梯**：学习率突变（StepLR 每 30 epoch ÷10）让损失出现尖峰/震荡；余弦曲线导数连续，后期在极小值附近"细嚼慢咽"；
- **为什么比常数好**：后期大 lr 反复跳出已找到的好区域（训练 loss 震荡不降），余弦自然衰减帮助收敛到更优区域。实测多数任务：余弦 > 常数 > 阶梯。

### 1.3 Inverse Sqrt（Transformer 论文调度）

Vaswani et al. (2017) 原文：

$$\eta_t = d_{\text{model}}^{-0.5} \cdot \min\left( t^{-0.5},\; t \cdot \text{warmup\_steps}^{-1.5} \right)$$

- warmup 阶段（$t < T_w$）：$\eta_t \propto t$ 线性上升；
- decay 阶段：$\eta_t \propto 1/\sqrt{t}$，缓慢衰减、**永不降到 0**；
- 两段在 $t=T_w$ 处拼接（连续但不可导），常记作 $\eta_t \propto \frac{1}{\sqrt{\max(t, T_w)}}$ 形式；
- **适合训练预算不确定/超长训练**：多训一步总能再进步一点；而 cosine 必须预设总步数 $T$。

### 1.4 OneCycle：只循环一次的三段式

1. **上升**：$\eta$ 从 $\eta_{\max}/100$ 线性升到 $\eta_{\max}$（前 30% 预算，即 warmup）；
2. **衰减**：从 $\eta_{\max}$ 线性/余弦降到 $\eta_{\max}/1000$（后 70%）；
3. **动量反向**：上升期 momentum 从 0.95 降到 0.85，下降期升回 0.95（步长大时动量小，防过冲）。

本质是"**大 lr 快速穿越 + 低 lr 精修**"的调度哲学；比固定 lr 收敛快、精度高（fast.ai 标配）。

## 二、数学性质与直觉

### 2.1 warmup 的两个数学根源

- **梯度范数**：初始化随机 → 初期 $\|\nabla L\|$ 可能远大于稳态值；步长 $\eta\|\nabla L\|$ 超出稳定区间（$\eta a < 2$，见 SGD 子篇 §2.3）即发散；
- **Adam 偏差校正**：初期 $\hat v_t$ 被 $1-\beta_2^t$ 校正放大（$t=1$ 时 $v_1$ 只有真实 0.1%），$\eta \cdot \hat m/\sqrt{\hat v}$ 瞬时可被放大到 $\eta\cdot\frac{1-\beta_1}{\sqrt{1-\beta_2}}\approx \eta\cdot 3.2$——warmup 用极小的 $\eta$ 与这个放大对冲。

### 2.2 余弦退火的几何直觉

把训练想象成"先快速定位好区域，再精细逼近最优点"：

- 前半程：lr 还在高位，能跳出坏区域、探索；
- 中段：lr 平滑收缩，逐步收敛；
- 末段：lr → $\eta_{\min}$，相当于在极小值附近做越来越小的修正——**等效于在终点附近做无重启的模拟退火**。导数连续保证 loss 曲线不出现阶梯尖峰。

### 2.3 inv-sqrt 与 cosine 的分工

| 场景 | 选择 | 原因 |
|------|------|------|
| 预算固定（epoch 数已知） | cosine | 能精确规划衰减轨迹到 0 |
| 预算不定 / 语料取之不竭 | inv-sqrt | 永不归零，多训一步多进步一步 |
| 需要快速下降后期精度 | cosine（降到峰值 10%） | 后期小 lr 精修效果好 |

### 2.4 OneCycle 的动量反调原理

lr 大时动量也大 → 速度累积过猛 → 冲过头（等效步长 $\eta/(1-\gamma)$ 爆炸）。OneCycle 在上升期把 momentum 调小（0.95→0.85）对冲大 lr，下降期 lr 变小后再把动量放大帮助精修——**两个超参此消彼长，全程维持"有效步长"基本恒定**。

## 三、源码实现（可直接运行）

### 3.1 手写调度循环：warmup + 余弦退火

不依赖 scheduler 类，直接在 `param_group` 上覆盖 lr——这是理解"调度器原理"的最短路径。损失函数用 $y=(w\cdot x-b)^2$：

```python
import torch
import math

torch.manual_seed(0)
x = torch.linspace(-2, 2, 64)

warmup_steps, total_steps, lr_max = 20, 300, 0.1

def get_lr(t):
    """t: 当前步数 (0 起)。前 20 步线性 warmup, 之后余弦退火到 lr_max/10"""
    if t < warmup_steps:
        return lr_max * (t + 1) / warmup_steps                # 线性 warmup
    tt = t - warmup_steps
    T = total_steps - warmup_steps
    return lr_max / 10 + (lr_max - lr_max / 10) * 0.5 * (1 + math.cos(math.pi * tt / T))

w = torch.tensor(1.5, requires_grad=True)
b = torch.tensor(-0.8, requires_grad=True)
opt = torch.optim.SGD([w, b], lr=lr_max)      # 初始 lr 会被下面覆盖
for t in range(total_steps):
    opt.zero_grad()
    ((w * x - b) ** 2).mean().backward()
    lr = get_lr(t)
    opt.param_groups[0]["lr"] = lr            # 手写调度的核心: 直接改 param_group
    opt.step()
    if (t + 1) % 60 == 0:
        print(f"step {t+1:3d}  lr={lr:.4f}  loss={((w*x-b)**2).mean().item():.2e}")
```

```text
step  60  lr=0.0958  loss=1.64e-10
step 120  lr=0.0750  loss=2.10e-20
step 180  lr=0.0455  loss=4.25e-27
step 240  lr=0.0201  loss=1.61e-30
step 300  lr=0.0100  loss=6.15e-32
```

读表要点：warmup 段（前 20 步）lr 从 0.005 爬升，loss 几乎不动；进入余弦段后 loss 指数级下降，lr 每 60 步减半——**前期稳起步、后期精收敛**。

### 3.2 用 LambdaLR 实现完全相同的调度

```python
import torch
import math

torch.manual_seed(0)
x = torch.linspace(-2, 2, 64)
warmup_steps, total_steps, lr_max = 20, 300, 0.1

w = torch.tensor(1.5, requires_grad=True)
b = torch.tensor(-0.8, requires_grad=True)
opt = torch.optim.SGD([w, b], lr=lr_max)
scheduler = torch.optim.lr_scheduler.LambdaLR(
    opt,
    lr_lambda=lambda t: (
        (t + 1) / warmup_steps
        if t < warmup_steps
        else 0.1 + 0.9 * 0.5 * (1 + math.cos(math.pi * (t - warmup_steps) / (total_steps - warmup_steps)))
    ),   # lambda 返回"乘到初始 lr 上的系数"
)
for t in range(total_steps):
    opt.zero_grad()
    ((w * x - b) ** 2).mean().backward()
    opt.step()          # 顺序: 必须先更新参数
    scheduler.step()    # 再调调度器 (PyTorch 约定)
    if (t + 1) % 60 == 0:
        print(f"step {t+1:3d}  lr={opt.param_groups[0]['lr']:.4f}")
```

```text
step  60  lr=0.0955
step 120  lr=0.0745
step 180  lr=0.0450
step 240  lr=0.0198
step 300  lr=0.0100
```

与 3.1 逐值几乎一致（差异是 1 步的 off-by-one：手写版以"当前步"为自变量，LambdaLR 以"已完成步数 last_epoch"为自变量——两种写法都正确，关键是**调度函数里的 t 语义前后一致**）。

### 3.3 inv-sqrt 调度的数值形态

```python
warmup = 20
def inv_sqrt_lr(t):
    return min((t + 1) ** -0.5, (t + 1) * warmup ** -1.5)

for t in [0, 10, 19, 20, 100, 1000, 10000]:
    print(f"t={t:6d}  lr={inv_sqrt_lr(t):.6f}")
```

```text
t=     0  lr=0.011180
t=    10  lr=0.122984
t=    19  lr=0.223607
t=    20  lr=0.218218
t=   100  lr=0.099504
t=  1000  lr=0.031607
t= 10000  lr=0.010000
```

读表要点：$t=19$ 处到达峰值 0.224（warmup 终点）；此后 $1/\sqrt{t}$ 缓慢衰减——到 10000 步还有 0.01，**永不归零**。这就是"训练预算不定"场景选它的原因。

### 3.4 OneCycle 的 lr 与 momentum 联动

```python
import torch

torch.manual_seed(0)
x = torch.linspace(-2, 2, 64)
w = torch.tensor(1.5, requires_grad=True)
b = torch.tensor(-0.8, requires_grad=True)
opt = torch.optim.SGD([w, b], lr=0.004, momentum=0.9)
scheduler = torch.optim.lr_scheduler.OneCycleLR(
    opt, max_lr=0.1, total_steps=300, pct_start=0.3,
    anneal_strategy="cos", div_factor=100.0, final_div_factor=1000.0,
)
for t in range(300):
    if t in (0, 90, 150, 210):
        pg = opt.param_groups[0]
        print(f"t={t:3d}  lr={pg['lr']:.5f}  momentum={pg['momentum']:.4f}")
    opt.zero_grad()
    ((w * x - b) ** 2).mean().backward()
    opt.step()
    scheduler.step()
pg = opt.param_groups[0]
print(f"t=300  lr={pg['lr']:.7f}  momentum={pg['momentum']:.4f}")
```

```text
t=  0  lr=0.00100  momentum=0.9500
t= 90  lr=0.09999  momentum=0.8500
t=150  lr=0.08059  momentum=0.8694
t=210  lr=0.03815  momentum=0.9119
t=300  lr=0.0000066  momentum=0.9500
```

读表要点：90 步（30%）时 lr 到达峰值 0.1 且 momentum 同时降到 0.85（防过冲）；300 步时 lr 衰减到 $6.6\times10^{-6}$（峰值千分之一）而 momentum 回到 0.95——**lr 与动量反向联动全程可见**。

### 3.5 调度器与优化器的 step 顺序（工程关键）

**规则：`scheduler.step()` 必须在 `optimizer.step()` 之后。** 顺序反了的后果是 lr 提前一步生效（PyTorch 会告警）：

```python
import torch

w = torch.tensor(0.0, requires_grad=True)
opt = torch.optim.SGD([w], lr=0.1)
sched = torch.optim.lr_scheduler.LambdaLR(opt, lr_lambda=lambda t: 0.5 ** (t + 1))
w.grad = torch.tensor(1.0)
sched.step()                          # 错误顺序: 参数还没更新就先调度
print(f"错误顺序: 当前 lr = {opt.param_groups[0]['lr']:.4f}")
opt.step()                            # 这一步用了"下一步"的 lr
print(f"参数被更新: w={w.item():+.4f}  (正确顺序下应为 -0.1)")
```

```text
错误顺序: 当前 lr = 0.0250
参数被更新: w=-0.0250  (正确顺序下应为 -0.1)
```

首次参数更新本该用初始 lr=0.1（得到 w=-0.1），错误顺序下直接用 0.025——**整个 lr 曲线整体偏移一步**，warmup 等精确按步的调度会被系统性扭曲。

### 3.6 何时按 step、何时按 epoch

| 规则 | 说明 |
|------|------|
| 按 **step** 调度 | warmup、cosine、inv-sqrt、OneCycle 等"按步数连续变化"的调度，**必须按 step**；按 epoch 会因数据集大小不同导致曲线错乱 |
| 按 **epoch** 调度 | StepLR（每 N 个 epoch 衰减）等阶梯式调度，可接受按 epoch |
| 大模型预训练 | 几乎全部按 step（一个 epoch 就是几十万步） |
| 微调（SFT/多模态） | 常按 epoch（数据集小），配合 cosine 时按 step 也行 |
| 警告 | 数据集被截断或 batch 变化时，按 epoch 的 warmup 会失真；统一按 step 最稳 |

checkpoint 注意：**保存时必须同时保存 `optimizer.state_dict()` 与 `scheduler.state_dict()`**，否则恢复训练时 lr 从 0 重新开始。

## 四、超参与调参经验

1. **大模型标准组合（背下来）**：AdamW + linear warmup（总步数 1%~3%）+ cosine 到峰值 10%；BERT 用 warmup 10000 步 + 线性衰减；Transformer 原文用 Adam + inv-sqrt；
2. **warmup 长度**：任务越难、batch 越大、lr 峰值越高 → warmup 越长；LLM 常用 2000 步或总步数 1~3%；SFT 用几十~几百步即可；
3. **cosine 终值**：降到峰值 10%（LLM 默认）或 0（部分实现）；微调常降到峰值 1% 以下；
4. **OneCycle 适用**：CV 分类/检测小模型（fast.ai 标配），大模型预训练不用（预算通常动态调整）；
5. **先定 lr 峰值再定调度**：峰值用 LR finder 扫（见总览第十节）；调度形状只影响"怎么从峰值走"，不改变峰值选择；
6. 用 wandb/tensorboard 记录 lr 曲线，检查调度器是否按预期工作（常见 bug：scheduler 忘 step、checkpoint 没存调度器、按 epoch 混用了按步的调度）。

## 五、优缺点

| 调度 | 优点 | 缺点 |
|------|------|------|
| 常数 lr | 简单；收敛后期稳定 | 后期大 lr 震荡不收敛；前期发散风险 |
| warmup + 常数 | 解决起步崩溃 | 后期无精修 |
| **warmup + cosine** | 起步稳 + 后期精修，对峰值 lr 不敏感 | 需预设总步数；训练中途加数据会打乱轨迹 |
| StepLR | 简单、易理解 | lr 突变 → loss 尖峰；需手动选衰减节点 |
| inv-sqrt | 无需总步数、永不归零 | 后期衰减太慢，可能不够精细 |
| OneCycle | 收敛快、精度高、自动管动量 | 需预设总步数；参数多（pct_start 等） |

## 六、与同类对比

| 维度 | StepLR | cosine | inv-sqrt | OneCycle |
|------|--------|--------|----------|----------|
| 是否需要总步数 | 否（按 epoch） | 是 | 否 | 是 |
| lr 曲线 | 阶梯突变 | 连续平滑 | 平滑衰减到 0 之外 | 升-降三角 |
| 动量调度 | 无 | 无 | 无 | **有（反向联动）** |
| 后期行为 | 恒定小 lr | 归零附近精修 | 缓慢持续下降 | 归零 |
| 典型场景 | 老式 CNN | **LLM 标配后半段** | Transformer 原文/长训练 | 小模型快训 |
| 与 warmup 结合 | 少见 | 标配 | 内建（公式自带） | 内建（前 30%） |

## 七、高频面试问答

**Q1：为什么需要 warmup？**
四点：① 初始梯度范数异常大，大 lr 一步迈飞；② Adam 二阶矩从 0 累积，初期 $\sqrt{\hat v}$ 偏小会把步长错误放大（偏差校正的推论）；③ BN/注意力分布未稳定；④ Transformer 的 attention logits 初始极端。用线性/余弦 warmup 小 lr 起步，统计量稳定后再升峰值。

**Q2：warmup + cosine 为什么是大模型标准？**
warmup 对症"起步崩溃"，cosine 对症"后期收敛"——两个问题分别被解决，且对 lr 峰值不敏感（3e-4 或 1e-3 都训得动），被 GPT/LLaMA/Qwen/CLIP 等所有主流模型验证。

**Q3：cosine 和 StepLR 的区别？为什么余弦更好？**
StepLR 阶梯式突变 lr，loss 出现尖峰震荡；cosine 按 $\eta_{\min}+\frac{1}{2}(\eta_{\max}-\eta_{\min})(1+\cos\frac{\pi t}{T})$ 连续平滑下降，后期细嚼慢咽、无突变。实测余弦 > 常数 > 阶梯。

**Q4：inv-sqrt 和 cosine 的适用差异？**
inv-sqrt 永不归零、不需要总步数，适合预算不定/超长训练（Transformer 原文）；cosine 需要预设 $T$，轨迹规划更精细，适合预算固定（现代 LLM 主流）。

**Q5：调度器为什么必须在 optimizer.step() 之后调用？**
否则第一次参数更新就用"下一步"的 lr，整条 lr 曲线偏移一步；warmup 等精确调度会被系统性扭曲（PyTorch 会告警）。恢复训练要同时 load optimizer 与 scheduler 的 state_dict。

**Q6：OneCycle 的三阶段设计？**
前 30% lr 从峰值 1/100 升到峰值（warmup），后 70% 降到峰值 1/1000；同时 momentum 从 0.95 降到 0.85 再升回——大 lr 时用小动量防过冲，小 lr 时用大动量精修。

**Q7：大 batch 训练 lr 怎么调？**
batch ×k 时 lr 可 ×√k~k（梯度噪声方差 $\propto 1/m$），同时 warmup 按比例延长；否则初期步长失稳。这也是大 batch 必须配合调度的原因。

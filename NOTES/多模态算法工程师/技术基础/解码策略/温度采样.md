# 温度采样（Temperature Sampling）

> 本模块索引见 [解码策略详解](解码策略详解.md)

## 一、定义与公式

温度采样在 softmax **之前**用温度 $T$ 缩放 logits：

$$p(v \mid x_{<t}) = \frac{\exp(z_v / T)}{\sum_{v'} \exp(z_{v'} / T)}$$

| 温度 T | 效果 | 数学表现 |
|--------|------|---------|
| $T < 1$ | 分布更锐利（尖锐），更保守 | logits 被放大，softmax 更"硬" |
| $T = 1$ | 保持模型原始分布 | 标准 softmax |
| $T > 1$ | 分布更平坦，更随机 | logits 被压缩，接近均匀分布 |
| $T \to 0$ | **退化为 greedy** | 最大概率趋近 1，等价 $\arg\max$ |
| $T \to \infty$ | 退化为均匀随机 | 每个 token 等概率 |

分布熵随温度单调递增，熵定义：

$$H(p) = -\sum_{v \in V} p(v) \log p(v)$$

## 二、核心原理

### 2.1 温度改变了什么、不改变什么

- **改变**：概率分布的"陡峭程度"。$T<1$ 把 logits 差距放大——好 token 更好、差 token 更差；$T>1$ 把差距缩小——差 token 也有机会被选中；
- **不改变**：token 的相对排序（monotonic）。$\frac{z_a}{T} > \frac{z_b}{T} \iff z_a > z_b$，所以无论 T 取多少，概率最大/最小的 token 身份不变，变的只是头部与尾部的**差距**；
- **不增加信息量**：T 引入的是"随机性"而非"创造性"。T 太大 = 在胡说八道中随机挑词。

### 2.2 极限行为

$$T \to 0: \quad p(v) \to \begin{cases} 1, & v = \arg\max z \\ 0, & \text{otherwise} \end{cases} \qquad T \to \infty: \quad p(v) \to \frac{1}{|V|}$$

实现上 T→0 不会真的除零（会 NaN），工程上用很小的 $T$（如 0.05）近似；T→0 的采样就等价于 greedy。

### 2.3 实践区间

| 任务 | T 建议 |
|------|--------|
| 精确答案（数学、OCR、评测） | $T \to 0$ 或 greedy |
| 翻译/摘要 | 0.3 ~ 0.7 |
| 对话（默认） | 0.7 ~ 1.0 |
| 创意写作 | 0.8 ~ 1.2 |

## 三、源码实现

### 3.1 温度缩放函数与数值演示

```python
import torch

def temperature_softmax(logits: torch.Tensor, T: float) -> torch.Tensor:
    """带温度的 softmax：T=1 是标准 softmax；T 越小分布越尖。"""
    return torch.softmax(logits / T, dim=-1)

logits = torch.tensor([2.0, 1.0, 0.1, -1.0])     # 一个典型 logits
for T in (0.2, 0.5, 1.0, 2.0, 10.0):
    p = temperature_softmax(logits, T)
    H = -(p * p.log()).sum().item()
    print(f"T={T:<5} p={p.double().numpy().round(4).tolist()}  熵 H={H:.3f}")
# T=0.2  p=[0.9932, 0.0067, 0.0001, 0.0]   熵 H=0.041   ← 极尖，接近 one-hot
# T=0.5  p=[0.8619, 0.1166, 0.0193, 0.0021]  熵 H=0.468
# T=1.0  p=[0.6381, 0.2347, 0.0954, 0.0318]  熵 H=0.961   ← 模型原始分布
# T=2.0  p=[0.4512, 0.2737, 0.1745, 0.1007]  熵 H=1.249
# T=10.0 p=[0.288, 0.2606, 0.2381, 0.2133]  熵 H=1.380   ← 接近均匀分布（ln4≈1.386）
```

> **读表结论**：熵随 T 单调上升（$0.041 \to 1.380$，上限 $\ln 4 \approx 1.386$）；token 排序始终不变（第一个永远是概率最大的）；差距从 0.9932:0.0000 收窄到 0.288:0.2133。

### 3.2 手写温度采样循环（玩具分布）

```python
import torch

torch.manual_seed(0)

VOCAB = ["a", "b", "c", "<eos>"]
EOS = 3

def toy_probs(prefix: tuple) -> torch.Tensor:
    """玩具模型：a→b/c 二选一；b 之后倾向重复；c 之后结束。"""
    if not prefix:
        return torch.tensor([1.0, 0.0, 0.0, 0.0])
    last = prefix[-1]
    if last == 0:
        return torch.tensor([0.0, 0.6, 0.4, 0.0])    # b(0.6) c(0.4)
    if last == 1:
        return torch.tensor([0.0, 0.9, 0.0, 0.1])    # 重复陷阱
    return torch.tensor([0.0, 0.0, 0.0, 1.0])        # c → eos

def toy_logits(prefix: tuple) -> torch.Tensor:
    p = toy_probs(prefix)
    return torch.log(torch.where(p > 0, p, torch.full_like(p, 1e-7)))

def temperature_sample(logits: torch.Tensor, T: float) -> int:
    p = torch.softmax(logits / T, dim=-1)
    return int(torch.multinomial(p, 1).item())

def decode(T: float, max_len: int = 10) -> str:
    prefix, tokens = [], []
    for _ in range(max_len):
        v = temperature_sample(toy_logits(tuple(prefix)), T)
        if v == EOS:
            break
        prefix.append(v)
        tokens.append(VOCAB[v])
    return "".join(tokens)

for T in (0.05, 0.5, 1.5):
    print(f"T={T:<5}", [decode(T) for _ in range(5)])
# T=0.05 ['abbbbbbbbb', 'abbbbbbbbb', 'abbbbbbbbb', 'abbbbbbbbb', 'abbbbbbbbb']
#             ← 极低温度 ≈ greedy，必掉进 b 陷阱
# T=0.5  ['ac', 'abbbbbbbb', 'abbbbbbbbb', 'abbbbbbbbb', 'abbbbbbbbb']
#             ← 低温：p(b)=0.69，多数还是进陷阱
# T=1.5  ['ac', 'ac', 'ac', 'ac', 'abbbbbbb']
#             ← 高温：p(b)=0.57，绕开陷阱的比例明显上升
```

### 3.3 与 transformers generate 对比（分数级精确对齐）

```python
import torch
from transformers import GPT2Config, GPT2LMHeadModel

torch.manual_seed(42)
cfg = GPT2Config(vocab_size=100, n_layer=2, n_head=4, n_embd=128, n_positions=64)
model = GPT2LMHeadModel(cfg).eval()
model.config.pad_token_id, model.config.eos_token_id = 0, 0
input_ids = torch.tensor([[1, 2]])
attn = torch.ones_like(input_ids)

T = 0.8
gen = model.generate(input_ids, attention_mask=attn, do_sample=True, temperature=T,
                     top_k=None, top_p=None, max_new_tokens=3,
                     return_dict_in_generate=True, output_scores=True)
logits = model(input_ids, attention_mask=attn).logits[:, -1]
my_probs = torch.softmax(logits / T, dim=-1)
hf_probs = gen.scores[0][0].softmax(-1)
print("与 HF 的分布最大偏差:", (my_probs - hf_probs).abs().max().item())
# 与 HF 的分布最大偏差: 3.7e-09   ← 逐 token 分布数值一致
```

> **对齐原理**：`generate` 的 `output_scores=True` 返回"施加所有 warper 之后"的每步概率；我们只设温度（不设 top_k/top_p）重算，两者应逐 token 数值相等。

### 3.4 固定种子下的端到端复现

```python
import torch
from transformers import GPT2Config, GPT2LMHeadModel

torch.manual_seed(42)
cfg = GPT2Config(vocab_size=100, n_layer=2, n_head=4, n_embd=128, n_positions=64)
model = GPT2LMHeadModel(cfg).eval()
model.config.pad_token_id, model.config.eos_token_id = 0, 0
input_ids = torch.tensor([[1, 2]])
attn = torch.ones_like(input_ids)

T = 0.8
torch.manual_seed(123)
out_my = model.generate(input_ids, attention_mask=attn, do_sample=True,
                        temperature=T, top_k=None, top_p=None, max_new_tokens=6)
torch.manual_seed(123)
out_hf = model.generate(input_ids, attention_mask=attn, do_sample=True,
                        temperature=T, top_k=None, top_p=None, max_new_tokens=6)
print("同种子同输出:", torch.equal(out_my, out_hf))
# 同种子同输出: True   ← 采样策略下固定 seed 即可复现
```

## 四、深入分析

### 4.1 温度与熵的定量关系

3.1 演示了熵 $H$ 从 $0.041 \to 1.380$ 的单调上升。**熵是"确定性"的量化标尺**：评测任务要求低熵（答案确定），对话任务要求中熵（自然），T 就是调节熵的最直接旋钮。

### 4.2 温度解决不了的问题

1. **不截断长尾**：即使 T=1，长尾里概率 $10^{-4}$ 的乱 token 依然有机会被采到（T 只缩放、不置零）。因此温度必须配 Top-K/Top-P 使用；
2. **不防重复**：低温放大重复循环内的 logits 差，反而更容易卡进重复（见 3.2 中 T=0.05 全掉进 b 陷阱）；
3. **与量化的坑**：低温（T<0.5）放大 logits 差值的同时放大量化噪声，量化模型建议温和温度（0.7+）。

### 4.3 温度与采样组合的完整顺序

```text
repetition_penalty → 温度缩放 → top_k → top_p → softmax → multinomial
```

先压已出现 token，再调陡峭度，最后截长尾。每个旋钮解耦、独立调节（详见[重复惩罚](重复惩罚.md)与 [TopK与TopP](TopK与TopP.md)）。

### 4.4 温度与评测的关系

1. **评测要确定性**：VQA/OCR 等评测用 greedy 或 $T \to 0$，同输入同输出、指标可复现；用采样必须固定 seed 且多次取平均；
2. **温度敏感性实验**：VQA 上把温度从 0.2 升到 1.0，accuracy 通常先稳后降——随机性侵蚀精确答案，这是"评测用低温度"的直接证据；
3. **幻觉放大**：多模态评测中的"幻觉"在采样 + 高温下显著放大（低置信区域被随机选中），严谨论文多报告 greedy 结果。

## 五、优缺点

| 优点 | 缺点 |
|------|------|
| 实现极简（除一下、softmax、multinomial） | 不改变 token 排序，只能调"陡峭度" |
| 单参数直觉清晰，连续可调 | 不截断长尾，低概率噪音 token 仍可能被采到 |
| 保留模型原始分布的信息（T=1） | 不解决重复问题，低温反而加重重复 |
| 熵随 T 单调，方便按任务找甜点 | 单独使用时质量不如 Top-P 组合 |

## 六、与同类对比

| 策略 | 调节机制 | 与温度的关系 |
|------|---------|-------------|
| Greedy | 无 | $T \to 0$ 的极限就是 greedy |
| Top-K | 硬截断前 K 个 token | 互补：温度管形状，Top-K 管候选集 |
| Top-P | 累积概率动态截断 | 互补：温度管形状，Top-P 管长尾 |
| Beam Search | 搜索多条路径 | 完全不同维度：温度在分布上做文章，beam 在路径上做文章 |

> **一句话**：温度是"全局形状旋钮"，Top-K/Top-P 是"局部候选裁剪"，两者配合才构成完整的采样管线。

## 七、高频面试问答

**Q1：温度 T 是怎么影响生成的？T=0 会发生什么？**
温度缩放 softmax 前的 logits：$p \propto \exp(z/T)$。T<1 分布变尖（更确定），T>1 变平（更随机），T=0 时退化为 greedy（最大概率趋近 1），T→∞ 退化为均匀随机。T 不改变 token 相对排序，只改变分布陡峭程度。

**Q2：温度改变 token 的排序吗？为什么？**
不改变。$\frac{z_a}{T} > \frac{z_b}{T} \iff z_a > z_b$，除法是单调变换，排序不变；变的只是概率的差距——低温把头部 token 的概率抬得更高。

**Q3：为什么低温会更重复？**
低温放大了循环内 token 的高概率（重复模式在分布里本来就有优势），模型更容易被"吸"进重复循环；同时低温下退出循环的低概率 token 更难被采到。所以防重复不能只靠降温。

**Q4：T=1 和关闭温度（不设置 temperature）一样吗？**
一样。T=1 时 $\exp(z/1)$ 就是标准 softmax，是模型的原始分布。HuggingFace 不传 temperature 时默认 1.0（do_sample=True 下）。

**Q5：温度能解决低概率噪音 token 的问题吗？**
不能。温度只缩放不置零，长尾里概率 $10^{-4}$ 的 token 依然可能被采到；需要 Top-P/Top-K 把长尾裁掉。这也是"温度 + top_p"必须组合的原因。

**Q6：怎么让温度采样可复现？**
固定随机种子。`torch.manual_seed` 后采样序列可复现（3.4 演示）；评测、A/B 实验必须固定 seed 并多次采样取平均。

**Q7：多模态 VLM 的温度设置有什么讲究？**
解码发生在文本空间，温度用法与纯文本 LLM 完全一致；但 VQA/OCR 评测要用 T→0（或 greedy）保证确定性与可复现，幻觉问题在采样+高温下显著放大（低置信区域被随机选中）。

**Q8：温度是不是越大越好？**
不是。T 引入的是"随机性"而非"创造性"：T 过大时分布趋近均匀，高概率的合理 token 与低概率的乱 token 几乎等权，输出会胡言乱语。质量与多样性的甜点通常在 0.7~1.0（对话），需要精确答案时反而要压到 0.2 以下。

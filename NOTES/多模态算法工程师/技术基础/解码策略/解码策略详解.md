## 一、解码问题定义：模型怎么"说"出每一个词

### 1.1 自回归生成的本质

生成模型（GPT/LLaMA/Qwen、多模态的 LLaVA/InternVL 等）本质上是一个**自回归（autoregressive）语言模型**：在生成第 $t$ 个 token 时，模型以上文为条件，输出一个**词表上的概率分布**：

$$p(x_t \mid x_{<t}) = \text{softmax}(z_t) = \frac{\exp(z_t^{(v)} / T)}{\sum_{v' \in V} \exp(z_{t}^{(v')} / T)}$$

其中 $x_{<t}$ 是前 $t-1$ 个 token（对多模态模型还包括视觉特征 $\mathbf{v}$），$z_t \in \mathbb{R}^{|V|}$ 是模型最后一层输出的 logits，$V$ 是词表。

**关键理解**：模型给出的只是一个分布，它并不知道"最终输出哪个词"。模型每步只做一件事——输出一个分布。**解码策略（Decoding Strategy）就是"如何从这个分布中挑出下一个 token"的规则**。

### 1.2 为什么解码策略很重要

1. **相同的模型，不同的解码策略 = 完全不同的输出**：同样的 prompt，greedy 给出"最可能"的答案，采样给出多样化的答案；
2. **质量与多样性的权衡**：解码策略的本质是在"接近最优"与"避免退化"之间取平衡；
3. **评测与业务目标不同**：评测要确定性（reproducible），业务要多样性（不千篇一律）；
4. **生成任务本身的病态性**：自回归是"一步错步步错"（error accumulation），早期一个次优 token 会顺着序列传播放大。

### 1.3 解码策略总览

| 类别 | 策略 | 是否随机 | 确定性 | 代表场景 |
|------|------|---------|--------|---------|
| 贪心类 | Greedy Decoding | 否 | 是 | 评测、VQA 答案 |
| 搜索类 | Beam Search | 否 | 是 | 翻译、摘要 |
| 采样类 | 温度采样 / Top-K / Top-P / Min-P / Typical | 是 | 否 | 对话、创意写作 |
| 约束类 | 结构化约束解码（grammar/JSON） | — | — | 函数调用、Agent |

> **一句话记忆**：`Greedy 是"每次都选最好的"，Beam 是"保留几条路再选"，采样是"按概率掷骰子"`。

## 二、Greedy Decoding（贪心解码）

### 2.1 原理

每一步直接取当前概率分布中概率最大的 token：

$$x_t = \arg\max_{v \in V} p(v \mid x_{<t})$$

直到生成结束符 `<eos>` 或达到最大长度 $L$。整个过程是**前向贪婪**的：每一步只看局部最优，不回溯。

```python
# Greedy Decoding 伪代码
def greedy_decode(model, prompt, max_len):
    tokens = tokenize(prompt)
    for _ in range(max_len):
        logits = model(tokens)[-1]              # 最后一个位置的 logits
        next_token = logits.argmax(dim=-1)      # 取最大概率
        if next_token == EOS:
            break
        tokens.append(next_token)
    return tokens
```

### 2.2 优点

| 优点 | 说明 |
|------|------|
| 实现简单 | 一个 `argmax` 搞定 |
| 确定性 | 同输入同输出，便于评测复现 |
| 速度快 | 无候选扩展，无额外内存 |
| 推理成本低 | 适合批量评测（如 VQA accuracy 计算） |

### 2.3 缺点（关键）

1. **重复（repetition）**：模型天然倾向高频 token，greedy 会把这种倾向放大，产生"我已经说过……我已经说过……"的循环；
2. **多样性差**：永远只走一条路，没有探索；
3. **局部最优 ≠ 全局最优**：每一步选概率最大的 token，不代表整句概率最大。因为第 $t$ 步的最优 token 可能把句子带进一个"低概率分支"，而一个概率稍低但前景更好的 token 才是最优解；
4. **惩罚性缺失**：无长度调节，容易过早结束或过长。

> **必考例子**：设 $p(a)=0.4,\ p(b)=0.35,\ p(c)=0.25$，greedy 选 $a$；但如果 $a$ 之后所有续接概率都很低（如 0.05），而 $b$ 的后续路径都是高概率（0.9），那么 $P("ba...") \gg P("aa...")$，greedy 选错了全局最优路径。

## 三、Beam Search（束搜索）—— 重点中的重点

### 3.1 原理：从一条路到一束路

Beam Search 不再只保留一条最优路径，而是每一步维护 **B 个候选序列**（B 称为**束宽 beam width / beam size**）：

1. 第 1 步：计算所有 token 的概率，保留概率最大的 B 个作为候选；
2. 第 t 步：对当前 B 个候选各自扩展词表的 $|V|$ 个 token，得到 $B \times |V|$ 个新候选；
3. 按**累计得分**排序，保留得分最高的 B 个；
4. 重复直到所有 B 个候选都结束，最终返回得分最高的完整序列。

$$S(y_{1:t}) = \sum_{i=1}^{t} \log p(y_i \mid y_{<i})$$

```text
Beam Search 示例（B=2, 词表 {a, b, <eos>}）:
step1: 所有序列        a(0.4)  b(0.35)  →  保留 a, b
step2: 扩展            aa(0.16) ab(0.24) ba(0.14) bb(0.21)
      →  保留得分最高的 ab(0.24), bb(0.21)
step3: 扩展            aba(0.096) ... abb(0.084) bba(0.126) bbb(0.084)
      →  保留 bba(0.126), aba(0.096) ...
```

### 3.2 束宽 B 的影响

| 束宽 | 质量 | 速度/内存 | 表现 |
|------|------|-----------|------|
| B=1 | 退化为 greedy | 最快 | 质量次优 |
| B=4~8 | 明显提升（翻译/摘要） | 中等 | 工程常用默认 |
| B=16~32 | 边际收益递减 | 慢，内存大 | 高分任务（如竞赛）偶尔用 |
| B→∞ | 理论上逼近全局最优 | 指数级开销 | 不现实（实际是 DFS 指数爆炸） |

**关键结论**：
- B 越大，越接近全局最优，但收益**边际递减**（B=4→8 提升明显，B=32→64 几乎无差）；
- B 越大，重复问题越严重（见 3.4）；
- B 每加一倍，计算量近似翻倍（$O(B \cdot |V| \cdot L)$）。

### 3.3 打分与长度归一化

#### 为什么用 log 概率累加

直接累乘概率 $P = \prod p_i$ 在数值上会下溢（几十个 0.1 连乘就趋近 0），且越长的序列乘积越小。因此实践中用**对数概率累加**：

$$S(y_{1:t}) = \sum_{i=1}^{t} \log p(y_i \mid y_{<i})$$

#### 长度惩罚（Length Penalty）—— 为什么需要

纯 log 概率累加存在**长度偏差（length bias）**：

1. **偏好短序列**：$a \cdot b < a \cdot b \cdot 0.99$ 恒成立？不对——log 后 $S(a,b) = \log a + \log b$，多一个 token 就要多乘一个 $\log p < 0$，总得分一定更小。**所以不加任何处理时，Beam 系统性地偏向短序列**，容易"草草结束"；
2. 但翻译任务里长句子内容更全、质量更高，所以需要**长度归一化**来抵消这种偏差。

标准做法（GNMT，Wu et al. 2017）：

$$\text{score}(y) = \frac{1}{|y|^{\alpha}} \sum_{i=1}^{|y|} \log p(y_i \mid y_{<i})$$

- $\alpha = 1$：均匀长度归一化（HuggingFace `length_penalty` 常见设为 1.0）；
- $\alpha > 0$：鼓励长序列（penalize 短序列）；
- $\alpha < 0$：鼓励短序列；
- 另一种变体：`penalty = 1 + α * (5 + len)^β / (5 + 1)^β`（OpenNMT 风格），更平滑。

> **面试记忆点**：Beam Search 有两个"长度问题"——① 不归一化偏好短句（要加 length penalty 补偿）；② 归一化过头会偏好长句（重复废话），α 要调。

### 3.4 缺点

| 缺点 | 原因 | 缓解 |
|------|------|------|
| **重复严重** | Beam 的 B 条路径高度相似（源自同一父序列），互相"踩同一条路" | 去重（见 3.5）、repetition penalty |
| **多样性差** | 只保留 top-B，低概率但有意思的路径被剪掉 | 多样化 Beam（见 3.5） |
| **长度偏差** | 见 3.3 | length penalty |
| **集束内无差别** | B 条候选可能只是同一句的微小改写，浪费束宽 | diverse beam search |
| **全局最优不保证** | 仍是贪心剪枝的启发式搜索（NP-hard 问题的近似） | 无 |

### 3.5 变体

#### 3.5.1 Diverse Beam Search（多样化束搜索）

思路：把 B 个束分成 G 组，组间施加**互斥惩罚**，强迫各组走不同方向：

$$\text{score}_g(y) = \text{score}(y) + \lambda \sum_{y' \in \text{previous groups}} \Delta(y, y')$$

其中 $\Delta$ 是序列间的差异度量（常用分词重叠/汉明距离），λ 控制多样性强度。效果：B 条候选覆盖更多语义方向，供下游 rerank 选择。

#### 3.5.2 Beam 内的去重

1. **n-gram 去重（`no_repeat_ngram_size`）**：在 Beam 扩展时直接禁止生成与已有输出重复的 n-gram（见第六章）；
2. **候选去重（deduplicate beams）**：如果两条 Beam 生成的 token 序列完全相同（或前缀相同），只保留一条，把省下的束宽让给新方向；
3. **父序列多样性**：确保 B 个 beam 的父亲不集中在同一条路径上。

### 3.6 适用场景总结

| 适合 | 不适合 |
|------|--------|
| 机器翻译（结构对应、句子长度固定） | 开放对话（多样性要求高） |
| 文本摘要（需要忠实提取关键信息） | 创意写作（需要惊喜感） |
| 多模态 captioning（答案明确） | 长文本生成（重复会滚雪球） |
| 结构化任务（得分可比较） | 需要"人味"的生成 |

> **经验法则**：任务的目标是"逼近最优答案"→ 用 Beam；任务是"给出合理且多样的答案"→ 用采样。

## 四、采样类解码（Sampling）—— 重点

### 4.1 温度采样（Temperature Sampling）

#### 原理

在 softmax 之前用温度 $T$ 缩放 logits：

$$p(v \mid x_{<t}) = \frac{\exp(z_v / T)}{\sum_{v'} \exp(z_{v'} / T)}$$

| 温度 T | 效果 | 数学表现 |
|--------|------|---------|
| $T < 1$ | 分布更锐利（尖锐），更保守 | logits 被放大，softmax 更"硬" |
| $T = 1$ | 保持模型原始分布 | 标准 softmax |
| $T > 1$ | 分布更平坦，更随机 | logits 被压缩，接近均匀分布 |
| $T \to 0$ | **退化为 greedy** | $\arg\max$ 一个 token 概率趋近 1 |
| $T \to \infty$ | 退化为均匀随机 | 每个 token 等概率 |

#### 直觉解释

- $T < 1$：把 logits 差距放大，好 token 更好、差 token 更差 → 输出更"确定"；
- $T > 1$：把 logits 差距缩小，差 token 也有机会被选中 → 输出更多样、更有创意；
- 实践中对话模型常用 $T = 0.6 \sim 1.0$；创意任务 $T = 0.8 \sim 1.2$；需要精确答案时 $T \to 0$。

```python
# 温度采样
def temperature_sample(logits, temperature=0.8):
    logits = logits / temperature
    probs = softmax(logits)
    return torch.multinomial(probs, num_samples=1)
```

> **面试记忆点**：温度改变的是"概率分布的陡峭程度"，不改变 token 的相对排序（monotonic），只改变"头部 token 与尾部 token 的差距"。

### 4.2 Top-K 采样

#### 原理

只从概率最高的 K 个 token 中采样（其余 token 概率置零）：

$$\mathcal{V}_t = \{v \in V : \text{rank}(p(v \mid x_{<t})) \le K\}, \qquad p'(v) = \frac{p(v)}{\sum_{v' \in \mathcal{V}_t} p(v')} \quad (v \in \mathcal{V}_t)$$

#### K 固定问题（关键缺陷）

Top-K 的 K 是**固定值**，但不同时间步的概率分布形态差异巨大：

| 分布形态 | 例子 | Top-K 的问题 |
|----------|------|-------------|
| **尖峰分布**（分布很尖） | "1+1=___"，正确答案概率 0.98 | K=50 时混入大量无意义 token，稀释正确概率 |
| **平坦分布**（分布很平） | "继续讲故事……" 后续 500 个 token 概率相近 | K=10 时把所有合理候选都剪掉了 |
| 极端情形 | 尖峰时 K=1 才合理；平坦时 K=500 也不够 | 单一 K 无法同时适配 |

**结论**：Top-K 不自适应——它假设所有时间步的"合理候选数"相同，这是错误的。因此单独使用效果一般，常与 Top-P 叠加。

> 顺带一提：**K 太大会采样到长尾噪音 token**（尤其是分布平坦的中间层），**K 太小会失去多样性**。OpenAI 早期 API 用 top_p=1, top_k=0 意味着"都关闭"。

### 4.3 Top-P 采样 / 核采样（Nucleus Sampling）—— 重点

#### 原理（Holtzman et al., 2019）

动态截断：从概率最高的 token 开始累加，直到累积概率超过阈值 $p$，把这一组 token 作为采样候选集：

$$\mathcal{V}_p = \left\{ v_{(1)}, v_{(2)}, \dots, v_{(k)} : \sum_{i=1}^{k} p(v_{(i)}) \ge p \right\}$$

其中 $v_{(i)}$ 按概率降序排列，$k$ 是最小满足条件的数量。

#### 为什么比 Top-K 自适应（必考）

| 分布 | Top-K 表现 | Top-P 表现 |
|------|-----------|-----------|
| 尖峰分布（1+1=2） | K 固定 → 混入噪音或剪掉对的 | 累积概率很快到 0.95 → 候选集只有 1~2 个 token，精准 |
| 平坦分布（自由续写） | K=10 剪掉合理候选 | 累积到 0.95 需要几十上百个 token → 候选多，保留多样性 |
| 长尾分布 | 可能采到概率 0.0001 的乱 token | 长尾概率小，累加贡献低，被自动排除 |

**一句话**：Top-P 让**候选集大小随分布自适应**——分布尖时候选少、分布平时候选多，永远"只装下累积概率 p 的核（nucleus）"。

#### 工程默认值

- 默认 $p = 0.9 \sim 0.95$（截断低概率尾巴）；
- p 太小 → 多样性降低、接近 greedy；
- p 太大（接近 1）→ 长尾噪音进入候选集。

```python
# Top-P 采样（nucleus sampling）
def top_p_sample(logits, top_p=0.9):
    probs = softmax(logits)
    sorted_probs, sorted_idx = probs.sort(descending=True)
    cumsum = sorted_probs.cumsum(dim=-1)
    mask = cumsum - sorted_probs > top_p      # 超过 p 之后的置零
    sorted_probs[mask] = 0
    probs = sorted_probs.scatter(-1, sorted_idx, sorted_probs)
    probs = probs / probs.sum()
    return torch.multinomial(probs, num_samples=1)
```

> **注意实现细节**：代码里用 `cumsum - sorted_probs > top_p` 而不是 `cumsum > top_p`，这是为了**保证第一个（概率最大的）token 总在候选集里**——即使它的概率已经超过 p。

### 4.4 Min-P 采样（补充）

Min-P（Nguyen et al., 2024）的思路：以**当前最大概率**为基准设置绝对阈值，只保留概率 $\ge \min\_p \times \max\ p$ 的 token：

$$\mathcal{V} = \{v : p(v \mid x_{<t}) \ge \min\_p \cdot \max_v p(v \mid x_{<t})\}$$

- 当分布尖时（max p 大），阈值被抬高 → 候选少（类似小 top-p）；
- 当分布平时（max p 小），阈值降低 → 候选多。
- 相比 Top-P：Min-P 对"分布平滑度"更敏感，在低熵分布下表现更稳定，DeepSeek 等模型官方推荐 `min_p=0.02~0.05` 与 top_p 联用。

### 4.5 典型采样（Typical Sampling，补充）

Typical Sampling（Meister et al., 2023）从信息论出发：人类的自然语言近似于一个"可预测但非完全确定"的过程，最符合人类语言统计规律的 token 往往是**概率略低于最大、但并非最低**的那部分。

$$S(v) = \left| \log p(v) - \sum_{v'} p(v') \log p(v') \right| = \left| \log p(v) + H(p) \right|$$

选择与**分布负熵 $-H(p)$** 差距在阈值 $\tau$ 内的 token 作为候选。效果：避免"过度确定的死板文本"与"过度随机的胡说"两个极端，生成更接近人类写作习惯。在部分任务（如文档风格续写）上表现优于 Top-P，但实现更复杂、默认参数更敏感，目前工程使用不如 Top-P 普遍。

### 4.6 采样四兄弟对比

| 策略 | 核心机制 | 自适应 | 问题/优点 |
|------|---------|--------|----------|
| 温度 T | 缩放 logits | 否（全局固定） | 只调"陡峭度"，不截断长尾 |
| Top-K | 固定前 K 个 | 否（K 固定） | K 不随分布形态变化 → 尖/平场景都别扭 |
| Top-P | 累积概率达 p | 是（候选数动态） | 尖时候选少、平时候选多，**默认首选** |
| Min-P | 相对最大概率的阈值 | 是 | 对分布平滑度敏感，可与 Top-P 叠加 |
| Typical | 与负熵距离 | 是 | 信息论视角，贴近人类语言 |

## 五、重复问题与重复惩罚（Repetition Penalty）

### 5.1 为什么模型容易重复

1. **模型自身倾向**：自回归模型对"高频路径"有偏好，一旦进入重复循环，循环内每个 token 的条件概率都高，模型"自己出不来"；
2. **Beam 放大效应**：Beam 的 B 条路径彼此相似，重复模式会被多条路径同时选中并互相加强（一个重复的 beam 存活率高）；
3. **解码器注意力崩溃**：注意力权重在重复位置失焦（attentional collapse），模型"忘了"前面的内容；
4. **训练目标 mismatch**：训练时用 teacher forcing（真实前缀），推理时用模型自己的输出（自生成前缀），分布偏移导致退化。

### 5.2 Repetition Penalty（重复惩罚）

对**已经出现过的 token** 的 logits 施加惩罚（CTRL 论文提出，Keskar et al., 2019）：

$$\text{logits}(v) = \begin{cases} \dfrac{\text{logits}(v)}{\text{penalty}}, & v \in \text{已生成集合}, \ \text{logits}(v) \ge 0 \\[6pt] \text{logits}(v) \times \text{penalty}, & v \in \text{已生成集合}, \ \text{logits}(v) < 0 \end{cases}$$

- $penalty > 1$：出现过的 token 概率被压低（如 1.05 ~ 1.3）；
- $penalty = 1$：关闭（默认）；
- 正 logits 除以惩罚、负 logits 乘惩罚，是为了**避免在 0 附近跳跃造成的不连续**，同时保证符号翻转（HuggingFace 的实现逻辑）。

### 5.3 No Repeat N-Gram（n-gram 去重）

直接把"已经出现过的 n-gram"设为禁止生成：

- `no_repeat_ngram_size = 3`：任何已生成过的 3-gram，其后续 token 概率直接置零；
- **优点**：硬约束，彻底阻断局部重复；
- **缺点**：
  1. 会把**合理的重复**也禁掉（如"多模态算法工程师"这种合法词组在长文中必然重复）；
  2. 是"硬禁"而非"软惩罚"，可能影响语义连贯性；
  3. n 太大效果差，n 太小（如 2）会破坏语法（"的""了"都会禁）。

### 5.4 其他缓解手段

| 手段 | 原理 | 备注 |
|------|------|------|
| 降低温度 / 提高 top-p | 降低重复概率分布被强化的程度 | 副作用：多样性降低 |
| 增加 prompt 指引 | "不要重复之前的句子" | 软约束，效果不稳定 |
| 长度上限 | 强制结束，防止无限循环 | 治标不治本 |
| contrastive search（对比搜索） | 同时最大化"与历史 token 的差异度"（如 SimCTG） | 新一代解码，重复率低、质量高 |
| **DoLa / 层内对比**（补充了解） | 推理时从不同层输出差异判断是否陷入重复循环 | 高级技巧，面试加分 |

## 六、常用组合策略（工程重点）

### 6.1 标准配置（HuggingFace `generate` 参数）

```python
from transformers import AutoModelForCausalLM

model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-7B-Instruct")

# 生成任务（翻译/摘要/结构化输出）
output = model.generate(
    input_ids,
    max_new_tokens=512,
    num_beams=4,                      # Beam 家族
    length_penalty=1.0,               # 长度归一化
    no_repeat_ngram_size=3,           # 局部去重
    early_stopping=True,
)

# 对话任务（采样家族，业界标配）
output = model.generate(
    input_ids,
    do_sample=True,
    temperature=0.7,                  # 0.6 ~ 1.0
    top_p=0.9,                        # 0.85 ~ 0.95
    repetition_penalty=1.05,          # 轻微防重复
    max_new_tokens=2048,
)
```

**业界默认组合（记熟）**：

$$\boxed{\text{temperature}=0.7 \sim 1.0 \quad + \quad \text{top\_p}=0.9 \quad + \quad \text{repetition\_penalty}=1.05}$$

| 参数 | 作用 | 调整方向 |
|------|------|---------|
| temperature | 控制整体随机性 | 任务越"要准确"越低 |
| top_p | 剪掉低概率长尾 | 0.9 起步，加大 ≈ 增加多样性 |
| repetition_penalty | 防重复 | 1.0~1.3；>1.3 易生硬 |
| max_new_tokens | 防失控 | 按任务定 |
| min_new_tokens / min_length | 防止过早结束 | 结构化任务常用 |

### 6.2 生成任务 vs 对话任务的策略差异

| 维度 | 生成任务（翻译/摘要/代码） | 对话任务（chat/Agent） |
|------|---------------------------|----------------------|
| 目标 | 逼近最优解（忠实、准确） | 多样、自然、有"人味" |
| 默认解码 | **Beam Search**（或 greedy） | **采样（top_p + 温度）** |
| 温度 | 低（0.3~0.7）或关闭采样 | 中高（0.7~1.0） |
| 束宽 | 4~8 | 无（不做 beam） |
| 重复控制 | no_repeat_ngram 常用 | repetition_penalty 常用 |
| 失败模式 | 过短、重复、翻译腔 | 发散、幻觉、答非所问 |

**为什么对话不用 Beam**：对话的"正确答案"不唯一，Beam 会选出最"套路"的那条（平庸），且多条 beam 相似度高、多样性差；采样才能带来自然感。而翻译/摘要的得分可比较（BLEU/ROUGE），Beam 的"逼近最优"属性与评测指标高度契合。

### 6.3 量化对解码的影响（工程坑）

1. **INT8/INT4 量化改变 logits 数值**：量化误差会让 logits 出现微小扰动，导致：
   - **greedy 敏感**：排名边缘的 token 可能被量化噪声"顶掉"（argmax 对微小扰动脆弱）；
   - **采样相对鲁棒**：概率采样对 logits 的绝对误差不敏感，只要分布形态不崩；
   - **top_p 边界敏感**：候选集边界处的 token 是否被包含可能抖动。
2. **温度与量化叠加**：低温（T<0.5）会放大 logits 差值 → 量化噪声被放大 → 建议量化模型用温和温度（0.7+）；
3. **KV Cache 量化**：KV 精度损失会污染 attention 分数，进而改变每一步解码分布，长序列生成时影响累积；
4. **实践建议**：量化模型评测时固定 greedy + 相同 seed 对比；上线前用"量化 vs FP16 输出一致性"指标（如 token 级 F1 或语义相似度）做回归。

## 七、视觉语言生成（VLM）的解码 —— 多模态重点

### 7.1 视觉 token 不参与解码（必考）

VLM（LLaVA、Qwen-VL、InternVL 等）的生成流程：

```text
图像 → Vision Encoder → 视觉特征 → Projector → 与文本 embedding 拼接 → LLM（自回归文本解码）
                                            ↑
                                   视觉 token 只作为"条件"，
                                   生成阶段只输出文本 token
```

**关键结论**：
1. **解码器只有文本解码**：视觉信息通过 cross-attention / 拼接注入，但**输出词表仍是文本词表**，每一步从文本词表采样；
2. **视觉 token 不在词表里**：模型不"生成"像素，视觉分支负责"理解"，LLM 负责"组织语言"；
3. **所有解码策略（greedy/beam/采样）对 VLM 同样适用**，因为解码发生在文本空间；
4. **多帧/视频模型**（如 Qwen2.5-VL）同理：帧的视觉特征压缩后进 LLM，解码仍是文本。

> **面试陷阱**：有人误以为 VLM 是"先生成视觉 token 再生成文本"。实际主流架构中视觉特征是一次性编码（单 pass），不是逐像素自回归生成的。

### 7.2 结构化输出约束：JSON / 函数调用

多模态 Agent / 工具调用场景要求模型输出合法 JSON，解码时有两类方案：

#### 方案一：外校验 + 重试（post-hoc validation）

```text
生成文本 → 解析 JSON → 失败? → 重试（换温度/换 prompt）→ 成功? → 使用
```

| 优点 | 缺点 |
|------|------|
| 实现简单，任何模型可用 | 重试次数不定，延迟不可控 |
| 不依赖解码器内部 | 低质量模型可能一直失败 |
| 可配合 pydantic 等校验库 | 长输出中一个字符错就全废 |

#### 方案二：内约束解码（constrained / grammar-constrained decoding）

在解码的每一步，**用一个有限状态机（FSM）/ grammar 约束合法的下一个 token 集合**，把不符合 JSON schema 的 token 概率直接置零：

$$p'(v) = \begin{cases} p(v) / Z, & v \in \text{FSM 允许集合} \\ 0, & \text{otherwise} \end{cases}$$

- 实现代表：**Outlines**、**Guidance**（微软）、**XGrammar**（字节，Llama.cpp 集成）、`transformers` 的 `GrammarConstrainedLogitsProcessor`；
- **EBNF grammar 描述 JSON/JSON Schema**，编译成确定有限自动机（DFA），生成时逐 token 查表；
- 支持**完整 JSON Schema 约束**（枚举、类型、必填字段、`additionalProperties: false`）。

| 维度 | 外校验重试 | 内约束解码 |
|------|-----------|-----------|
| 一次成功率 | 依赖模型 | 100%（只要 FSM 正确） |
| 延迟 | 可能多次生成 | 单次，但每步多一次 FSM 查表（通常 <5% 开销） |
| 复杂度 | 低 | 中（需 grammar 编译） |
| 业务适用 | 快速原型 | 生产级 API/Agent |
| 风险 | 超时、重试风暴 | FSM 与模型 vocab 不匹配时卡死 |

> **业界趋势**：生产环境（尤其是 Agent 多轮工具调用）基本都转向内约束解码；部分方案还叠加"JSON 修复器"（如 OpenAI 的 response_format + 端侧 repair）。

### 7.3 答案抽取与后处理（VQA 场景）

多模态评测（VQA-v2、GQA、ScienceQA）中，模型输出通常是完整句子，需要抽取出答案并归一化后才能与标注比较：

| 步骤 | 操作 | 例子 |
|------|------|------|
| 答案抽取 | 取最后一个句号/问号后的片段，或按模板抽取 | "答案是一个苹果" → "苹果" |
| 归一化 | 小写、去标点、去掉冠词（a/an/the）、数字统一 | "Apple." → "apple" |
| 同义词映射 | 近义答案统一（"bicycle"/"bike"） | 用固定映射表 |
| 可选分词 | 部分评测按 token 集匹配 | 多词答案 |

**与解码策略的关系**：
- 评测时常用 **greedy**（确定性）→ 输出稳定、归一化流程可复现；
- 用采样时建议固定 seed，否则同一模型同一问题两次输出不同，accuracy 抖动；
- **温度敏感性实验**：VQA 上把温度从 0.2 升到 1.0，accuracy 通常先稳后降（随机性侵蚀精确答案），这是"评测要用低温度/确定性"的直接证据。

### 7.4 多模态场景：贪心 vs 采样

| 场景 | 推荐解码 | 原因 |
|------|---------|------|
| 离线评测（VQA/OCR/图表理解） | **greedy**（或低温度） | 确定性、可复现、指标稳定 |
| 图文对话产品 | 采样（T=0.7, top_p=0.9） | 自然、多样、用户体验好 |
| 图像描述（captioning 评测） | Beam（B=4~8）+ CIDEr 调参 | 评测指标与 Beam 契合 |
| 视觉 Agent（工具调用） | 低温度 + 约束解码 | 稳定输出合法 JSON |
| OCR / 数学公式识别 | greedy 或 T≈0 | 结果必须精确 |

**经验结论**：
1. **评测与上线用不同解码策略是常态**——评测用 greedy 证明"模型能力上限"，业务用采样换取体验；
2. 多模态评测中的"幻觉"在**采样 + 高温**下显著放大（低置信区域被随机选中），所以严谨评测论文多报告 greedy 结果；
3. captioning 评测（BLEU/CIDEr）对多样性不敏感，Beam 反而能刷高分——这也是"评测分数高 ≠ 生成质量高"的原因之一。

## 八、解码质量评估

### 8.1 评测指标与解码策略的关系

| 指标 | 衡量什么 | 与解码策略的关系 |
|------|---------|----------------|
| BLEU | n-gram 精确匹配（翻译） | **Beam 更容易拿高分**（重合度高、长度合理）；采样分数波动大 |
| ROUGE | 召回侧 n-gram（摘要） | 同上，Beam 稳定 |
| CIDEr | 加权 n-gram 一致（caption） | captioning 评测标配，与 Beam/贪心搭配使用 |
| Perplexity（PPL） | 模型对文本的困惑度 | 与解码无关，衡量模型本身；低 PPL ≠ 低重复率 |
| 自重复率（self-BLEU / repetition rate） | 生成文本内部 n-gram 重复程度 | greedy/Beam 显著更高，采样（top_p）更低 |
| 多样性指标（Distinct-n） | 生成集合中不同 n-gram 的比例 | 采样 > Beam > Greedy |
| MAUVE（模型 vs 人类分布距离） | 生成分布与人类分布的散度 | 采样接近人类分布，Beam 偏差大 |

**核心认知**：
- **BLEU/CIDEr 分数高 ≠ 生成质量好**：Beam 可以系统性刷高 n-gram 重合（牺牲多样性），这是"度量驱动的解码陷阱"；
- 高质量评测应该是**指标 + 人工评估 + 多样性指标**三位一体；
- 对话模型评测（MT-Bench、AlpacaEval）用 LLM-as-judge，与解码策略同样敏感——固定解码策略与 seed 是对比实验的基本要求。

### 8.2 解码策略相关的质量 checklist

| 现象 | 可能是解码问题 |
|------|--------------|
| 输出死板、无变化 | 温度过低 / 用了 greedy |
| 输出胡言乱语、不相关 | 温度过高 / top_p 过大 / 长尾 token |
| 疯狂重复同一段 | 没开 repetition_penalty / beam 过大 |
| 输出过短、戛然而止 | beam 长度偏差（没加 length penalty） |
| 输出过长、废话连篇 | length_penalty 过大 / max_new_tokens 未设 |
| 输出全是最高频词 | top_p 太小（退化成 argmax） |

## 九、对比总结表

| 策略 | 确定性 | 多样性 | 速度 | 质量（任务匹配时） | 重复风险 | 适用场景 |
|------|--------|--------|------|-------------------|---------|---------|
| Greedy | 高（恒定） | 最低 | 最快 | 中（局部最优） | 高 | 评测、精确答案 |
| Beam Search | 高（恒定） | 低 | 慢（B 倍扩展） | 高（全局近似最优） | **最高** | 翻译、摘要、captioning |
| 温度采样 | 低（随机） | 随 T 升高 | 快 | 中高（自然） | 中 | 对话、创意写作 |
| Top-K | 低（随机） | 由 K 决定 | 快 | 中（K 不自适应） | 中 | 常作辅助，配 Top-P |
| Top-P | 低（随机） | 自适应 | 快 | **高（核采样）** | 低 | **对话、通用生成默认** |

**选型口诀**：

```text
要确定 → Greedy 或 Beam（低温度）
要最优 → Beam（+ length_penalty + 去重）
要自然 → Top-P + 温度（0.7~0.9 + 0.7~1.0）
要防重复 → repetition_penalty + no_repeat_ngram
要结构 → 约束解码（FSM / grammar）
```

## 十、高频面试问答

**Q1：Beam Search 和 Greedy Decoding 有什么区别？**
Greedy 每步只取当前概率最大的 token，一条路走到底，是局部最优；Beam Search 每步保留 top-B 个候选序列、最终按整体累计 log 概率选最优，是全局最优的近似。Beam 质量更高但更慢、更容易重复；B=1 时 Beam 退化为 Greedy。

**Q2：温度 T 是怎么影响生成的？T=0 会发生什么？**
温度缩放 softmax 前的 logits：$p \propto \exp(z/T)$。T<1 分布变尖（更确定），T>1 变平（更随机），T=0 时退化为 greedy（概率最大的 token 概率趋近 1）。T 不改变 token 相对排序，只改变分布的陡峭程度。

**Q3：Top-P 为什么比 Top-K 好？**
Top-K 的候选数固定，无法适配分布形态；Top-P 动态截断到累积概率 p 的 token 集——分布尖时候选少（精准），分布平时候选多（保留多样性），永远只保留概率质量占比 p 的"核"，且长尾噪音被自动排除。默认 p=0.9~0.95。

**Q4：为什么模型生成容易重复？怎么解决？**
原因：① 模型对高频路径有倾向，重复循环内的条件概率自我强化；② Beam 的多条相似路径互相放大重复；③ 注意力在重复位置失焦；④ 训练（teacher forcing）与推理（自生成）分布不一致。解决：repetition_penalty（软惩罚）、no_repeat_ngram（硬去重）、降低温度、合理控制 beam 大小。

**Q5：为什么评测时通常用 Greedy 而不是采样？**
Greedy 确定性强：同输入必得同输出，评测结果可复现、可对比，不会因为采样随机性造成指标抖动；采样需要固定 seed 且多次取平均，才能近似确定性结果。评测要衡量"模型能力上限"，Greedy/Beam 更合适；业务要体验才用采样。

**Q6：Beam Search 为什么要做长度归一化？**
log 概率累加时每多一个 token 就多乘一个小于 1 的负数（$\log p<0$），总得分必然降低，导致 Beam 系统性偏好短序列、过早结束；长度归一化（除以 $|y|^{\alpha}$）抵消该偏差，α 控制对长句的鼓励程度。不归一化偏好短句，归一化过头偏好长废话。

**Q7：temperature、top_p、repetition_penalty 三个参数一起用时，它们各自管什么？相互作用如何？**
temperature 管整体随机性（logits 缩放）、top_p 管长尾剪枝（候选集大小）、repetition_penalty 管已出现 token 的概率压制。工程上是先做 repetition penalty → 再温度缩放 → 再 top_p 截断 → 最后 softmax 采样（HuggingFace 的 LogitsProcessor 顺序）。三者解耦，可独立调节。

**Q8：多模态模型的解码和纯文本 LLM 有什么区别？**
没有本质区别：VLM 的视觉特征是一次性编码后作为条件注入 LLM，解码仍发生在文本词表空间，greedy/beam/采样策略全部适用。区别在外部：评测时需做答案抽取与归一化（VQA）、结构化任务需 JSON 约束解码、图像 caption 评测用 Beam 刷 CIDEr。

**Q9：JSON 约束解码怎么实现？为什么生产环境优先用？**
用 EBNF grammar（或 JSON Schema）编译成 DFA/FSM，解码时每步只保留"当前状态允许"的 token，把不符合 schema 的 token 概率置零，保证输出 100% 合法。相比"外校验重试"（可能多次生成、延迟不可控），内约束解码单次完成、延迟可预测，是 Agent 工具调用的生产标配。

**Q10：Top-K=50、Top-P=0.9、Temperature=0.7 这三个同时设置时，执行顺序是什么？**
HuggingFace 等框架的执行顺序：先施加 logits processors（repetition_penalty、no_repeat_ngram 等）→ 温度缩放 logits → top_k 截断 → top_p 截断 → softmax → 采样。注意 top_k 先做、top_p 再做，最终候选集是两者交集，再由温度放大后的概率分布决定采样结果。

## 十一、常见误区

1. **误区：Beam Search 找到的一定是全局最优解。**
   不是。Beam 只是启发式剪枝的近似搜索，B 有限时仍可能丢掉最优路径；只有在 B=∞ 时才精确，而那是指数复杂度。B 增大只能降低错过最优的概率。

2. **误区：温度越高越"聪明"，低温度只会得到死板的答案。**
   温度只调概率分布的陡峭程度，不提升模型能力。T>1 引入的是"随机性"而非"创造性"，过高会输出低质量噪音；合适的温度组合（如 0.7~0.9 + top_p）通常在质量与多样性之间最优。

3. **误区：Top-K 和 Top-P 可以互相替代，效果一样。**
   两者机制不同：Top-K 是硬截断前 K 个，Top-P 是动态累积概率截断。在尖峰分布下 Top-K 会混入噪音，在平坦分布下会剪掉合理候选；Top-P 自适应，是更优选择，且两者可以叠加使用。

4. **误区：no_repeat_ngram 越大越好，能彻底解决重复。**
   n-gram 去重是硬约束，会误伤合法的重复（如固定搭配、专有名词、引用），且不解决"语义层面"的重复（换个说法反复说同一件事）；应配合 repetition_penalty 与合理的解码参数使用，而不是一味调大。

5. **误区：评测和线上应该用完全相同的解码策略。**
   通常相反：评测用 greedy/beam 追求确定性与指标可比性（衡量能力上限），线上用采样+约束追求体验与合规。两者目的不同，不必统一——但对比实验必须固定策略与 seed。

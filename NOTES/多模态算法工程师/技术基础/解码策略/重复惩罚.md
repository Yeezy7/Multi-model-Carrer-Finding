# 重复惩罚（Repetition Penalty 与 No Repeat N-Gram）

> 本模块索引见 [解码策略详解](解码策略详解.md)

## 一、定义与公式

### 1.1 Repetition Penalty（软惩罚，CTRL 论文提出，Keskar et al., 2019）

对**已经出现过的 token** 的 logits 施加惩罚：

$$\text{logits}(v) = \begin{cases} \dfrac{\text{logits}(v)}{\text{penalty}}, & v \in \text{已生成集合}, \ \text{logits}(v) \ge 0 \\[6pt] \text{logits}(v) \times \text{penalty}, & v \in \text{已生成集合}, \ \text{logits}(v) < 0 \end{cases}$$

- $penalty > 1$：出现过的 token 概率被压低（常用 1.05 ~ 1.3）；$penalty = 1$ 关闭；
- 正 logits 除以惩罚、负 logits 乘惩罚：**避免在 0 附近跳跃造成的不连续**，同时保证符号翻转（HuggingFace 实现逻辑）。

### 1.2 No Repeat N-Gram（硬约束）

直接把"已经出现过的 n-gram"设为禁止生成：

- `no_repeat_ngram_size = 3`：任何已生成过的 3-gram，其后续 token 概率直接置零；
- 公式化：扫描生成序列 $y_{<t}$ 中所有长度为 $n-1$ 的子串 $g$，若 $g$ 曾出现过且其后继 token 为 $v$，则 $p(v) := 0$。

## 二、核心原理

### 2.1 为什么模型容易重复（概率分布自增强）

1. **概率自增强（核心机制）**：自回归模型的分布由上文决定。一旦生成了重复片段，该片段自身的条件概率极高（高频路径），模型"自己出不来"——重复的 token 概率高 → 被选中 → 成为下文 → 概率更高，形成正反馈循环；
2. **Beam 放大效应**：Beam 的 B 条路径彼此相似，重复模式被多条路径同时选中并互相加强（重复的 beam 存活率高）；
3. **注意力崩溃**：解码器注意力权重在重复位置失焦（attentional collapse），模型"忘了"前面的内容；
4. **训练/推理不一致**：训练用 teacher forcing（真实前缀），推理用模型自己的输出（自生成前缀），分布偏移导致退化。

### 2.2 软惩罚 vs 硬约束

| 手段 | 机制 | 效果 |
|------|------|------|
| repetition_penalty | 已出现 token 的 logits 按比例压低 | 软：重复仍可能发生，只是变难；保留语义连贯 |
| no_repeat_ngram | 已出现 n-gram 的后继直接置零 | 硬：局部重复 100% 阻断；可能误伤合理重复 |

> **记忆点**：软惩罚"降低概率"，硬约束"直接封杀"。工程上两者都常用，硬约束对 Beam 更关键（beam 最容易重复）。

### 2.3 为什么正负 logits 要分开处理

假设已出现 token $v$ 的 logits 为 $+2.0$，惩罚 1.2：
- 统一"除以惩罚"：$2.0/1.2 = 1.67$，概率下降——OK；
- 但如果 logits 是 $-2.0$（本来概率就很低），再乘/除会怎样？两种操作都会把它"抬"向 0（除以 1.2 → -1.67，乘以 1.2 → -2.4）。**对称处理的意义**：正侧下降、负侧也下降（或不放大），且不会在 0 处产生跳跃，保证变换连续。

## 三、源码实现

### 3.1 手写 Repetition Penalty（与 HF 逐位对齐）

```python
import torch

def repetition_penalty_logits(logits: torch.Tensor, generated_ids, penalty: float = 1.2) -> torch.Tensor:
    """对已生成 token 的 logits 施加软惩罚：正侧除以 penalty，负侧乘 penalty"""
    z = logits.clone()
    for t in generated_ids:
        z[..., t] = torch.where(z[..., t] > 0, z[..., t] / penalty, z[..., t] * penalty)
    return z

logits = torch.tensor([5.0, 2.0, -1.0, -3.0])
print("原始  :", torch.softmax(logits, -1).numpy().round(4))
# 原始  : [0.9496 0.0473 0.0024 0.0003]
print("惩罚后:", torch.softmax(repetition_penalty_logits(logits, [0], 2.0), -1).numpy().round(4))
# 惩罚后: [0.6095 0.3697 0.0184 0.0025]
# 解释：token0 的 logits 5.0/2.0=2.5，概率 0.95→0.61；
#       被压下来的概率质量重新分配：token1 0.047→0.370
```

> 注意：惩罚"已出现 token"是把它们的相对地位压低，被压下来的概率质量会**重新分配**给其他 token——比较的是相对排序而非某个 token 的绝对概率。

### 3.2 手写 No Repeat N-Gram（与 HF 逐位对齐）

```python
import torch

def no_repeat_ngram_logits(generated_ids, logits: torch.Tensor, n: int = 3) -> torch.Tensor:
    """禁止所有已出现 n-gram 的后继 token：
    扫描序列中每个长度为 n-1 的前缀，把它真实出现过的后继 token 置 -inf"""
    z = logits.clone()
    if len(generated_ids) < n:
        return z
    for i in range(len(generated_ids) - n + 1):
        nxt = generated_ids[i + n - 1]          # 该 (n-1)-gram 真实的后继
        z[..., nxt] = float("-inf")
    return z

gen_ids = [5, 9, 5, 9, 5]                        # 已生成序列（含重复模式 5,9,5,9）
z = torch.zeros(12)
z_banned = no_repeat_ngram_logits(gen_ids, z, n=3)
print("被禁的 token:", (z_banned == float("-inf")).nonzero().flatten().tolist())
# 被禁的 token: [5, 9]
# 解释：n=3 时检查 2-gram → 后继映射：{5,9}→5（两次）、{9,5}→9（两次），
#       所以 5 和 9 都被禁——已出现的 2-gram 无法再"接上一次"
```

### 3.3 端到端演示：惩罚如何改变生成路径（玩具分布）

```python
import torch

VOCAB = ["a", "b", "c", "<eos>"]
EOS = 3

def toy_logits(prefix: tuple) -> torch.Tensor:
    """玩具模型（logits 权重）：
    - a 之后：b 权重 9 ≫ c 权重 4（b 局部最优）
    - b 之后：仍是 b 权重 9（重复陷阱）——惩罚只能对"已生成的 b"生效"""
    if not prefix:
        return torch.tensor([10.0, 0.0, 0.0, 0.0])
    last = prefix[-1]
    if last == 0 or last == 1:
        return torch.tensor([0.0, 9.0, 4.0, 0.0])
    return torch.tensor([0.0, 0.0, 0.0, 10.0])

def repetition_penalty_logits(logits, generated_ids, penalty):
    z = logits.clone()
    for t in generated_ids:
        z[..., t] = torch.where(z[..., t] > 0, z[..., t] / penalty, z[..., t] * penalty)
    return z

def decode(penalty=1.0, max_len=10):
    """贪心解码 + 重复惩罚：penalty 是唯一变量"""
    prefix, tokens = [], []
    for _ in range(max_len):
        z = repetition_penalty_logits(toy_logits(tuple(prefix)), prefix, penalty)
        v = int(z.argmax())
        if v == EOS:
            break
        prefix.append(v)
        tokens.append(VOCAB[v])
    return "".join(tokens)

print("无惩罚    :", decode(1.0))
# 无惩罚    : abbbbbbbbb   ← b 权重 9 一路碾压，卡死在重复循环
print("penalty=3:", decode(3.0))
# penalty=3: abc           ← 进入 "ab" 后 b 被罚成 9/3=3 < c 的 4，
#                             模型转走 c 分支并正常结束
# 机制要点：第一次选 b 时 b 还没"出现过"，惩罚不影响这一步；
#           一旦 b 进了已生成集合，其 logits 被逐次压低，模型被拖出循环
```

### 3.4 与 transformers 对比（处理器级精确对齐）

```python
import torch
from transformers import GPT2Config, GPT2LMHeadModel
from transformers.generation import RepetitionPenaltyLogitsProcessor, NoRepeatNGramLogitsProcessor

torch.manual_seed(42)
cfg = GPT2Config(vocab_size=100, n_layer=2, n_head=4, n_embd=128, n_positions=64)
model = GPT2LMHeadModel(cfg).eval()
model.config.pad_token_id, model.config.eos_token_id = 0, 0
input_ids = torch.tensor([[1, 2]])
attn = torch.ones_like(input_ids)
z0 = model(input_ids, attention_mask=attn).logits[:, -1]

def repetition_penalty_logits(logits, generated_ids, penalty=1.2):
    z = logits.clone()
    for t in generated_ids:
        z[..., t] = torch.where(z[..., t] > 0, z[..., t] / penalty, z[..., t] * penalty)
    return z

def no_repeat_ngram_logits(generated_ids, logits, n=3):
    z = logits.clone()
    if len(generated_ids) < n:
        return z
    for i in range(len(generated_ids) - n + 1):
        z[..., generated_ids[i + n - 1]] = float("-inf")
    return z

# ① repetition penalty：手写 vs HF 处理器
hf_z = RepetitionPenaltyLogitsProcessor(1.2)(input_ids, z0.clone())
my_z = repetition_penalty_logits(z0, input_ids.flatten().tolist(), 1.2)
print("repetition_penalty 对齐:", torch.equal(hf_z, my_z))
# repetition_penalty 对齐: True

# ② no_repeat_ngram：手写 vs HF 处理器
hf_z2 = NoRepeatNGramLogitsProcessor(3)(input_ids, z0.clone())
my_z2 = no_repeat_ngram_logits(input_ids.flatten().tolist(), z0, 3)
print("no_repeat_ngram 对齐:", torch.equal(hf_z2, my_z2))
# no_repeat_ngram 对齐: True

# ③ 端到端：HF generate 直接带惩罚参数
out = model.generate(input_ids, attention_mask=attn, do_sample=False,
                     repetition_penalty=1.2, no_repeat_ngram_size=3, max_new_tokens=8)
print("端到端生成:", out.flatten().tolist())
# 端到端生成: [1, 2, 2, 2, 75, 75, 75, 24, 24, 24]   ← 惩罚改变了每一步的 argmax
```

## 四、深入分析

### 4.1 惩罚过大的副作用

- `repetition_penalty > 1.3`：输出**生硬、不连贯**——合理的重复（固定搭配、专有名词、引用）也被压掉，模型被迫换词；
- no_repeat_ngram 的 n 太小（2）："的""了""是"这类高频虚词被禁，破坏语法；n 太大（5+）：几乎不触发，失去作用；
- 硬约束会误伤**语义级重复**：换个说法反复说同一件事（"我们讨论了 A……我们再谈谈 A"）n-gram 检测不到——它只认字面 n-gram。

### 4.2 惩罚在 Beam 场景的关键作用

Beam 的 B 条路径源自同一父序列，**重复模式会在多条路径上同时存活**，没有干预时重复被 beam 系统性放大。所以 Beam 场景优先用 `no_repeat_ngram_size=3`（硬阻断）而不是软惩罚；`repetition_penalty` 则更适合采样场景。

### 4.3 惩罚与量化的坑

量化（INT8/INT4）扰动 logits 后，logits 正负边界附近的 token 会被误判（如本来是 -0.01 变 +0.02），导致"该惩罚的没惩罚"；低温 + 高惩罚组合下量化噪声被双重放大，建议量化模型用温和参数。

### 4.4 新一代替代方案

| 方案 | 原理 | 备注 |
|------|------|------|
| Contrastive Search（SimCTG） | 同时最大化"与历史 token 的差异度" | 重复率低、质量高，实现复杂 |
| DoLa / 层内对比 | 从不同层输出差异判断是否陷入重复 | 推理期高级技巧 |

## 五、优缺点

| 手段 | 优点 | 缺点 |
|------|------|------|
| repetition_penalty | 软性、连续可调、保留语义连贯 | 只降概率不保证消除重复；过大生硬 |
| no_repeat_ngram | 硬阻断，局部重复 100% 消失 | 误伤合理重复（固定搭配/引用）；不解决语义重复 |
| 组合使用 | 软硬互补，覆盖两种重复形态 | 参数多，需按任务调 |

## 六、与同类对比

| 手段 | 机制 | 强度 | 适用 |
|------|------|------|------|
| repetition_penalty | logits 缩放 | 软 | 采样场景默认 |
| no_repeat_ngram | 概率置零 | 硬 | Beam/翻译/摘要 |
| 降低温度 | 整体分布变尖 | 软（间接） | 任何场景，代价是多样性下降 |
| prompt 指引 | "不要重复" | 弱 | 软约束，效果不稳定 |
| Contrastive Search | 与历史差异度 | 强 | 新一代，质量与复杂度都高 |

## 七、高频面试问答

**Q1：为什么模型生成容易重复？**
① 概率自增强：重复循环内每个 token 条件概率高，模型出不来；② Beam 的多条相似路径互相放大重复；③ 注意力在重复位置失焦；④ 训练（teacher forcing）与推理（自生成）分布不一致。

**Q2：Repetition Penalty 的公式？为什么正负 logits 分开处理？**
已出现 token 的 logits：正侧除以 penalty、负侧乘以 penalty。分开处理是为了避免在 0 附近跳跃造成的不连续，并保证符号翻转；否则会出现"惩罚反而抬高了负 logits"的不对称现象。

**Q3：Repetition Penalty 和 No Repeat N-Gram 的区别？**
软惩罚：按比例压低已出现 token 的概率，重复变难但不保证消失；硬约束：已出现 n-gram 的后继 token 概率直接置零，局部重复 100% 阻断。前者保留连贯性，后者可能误伤合理重复（如固定搭配在长文中合法重复）。

**Q4：no_repeat_ngram_size 的 n 怎么选？**
n=2 太小，高频虚词（"的""了"）被禁破坏语法；n=3~4 常用；n 太大（5+）几乎不触发。同时要记住它只防"字面 n-gram 重复"，防不了"语义重复"（换说法反复说同一件事）。

**Q5：为什么 Beam Search 更容易重复？怎么解决？**
Beam 的 B 条路径高度相似、源自同一父序列，重复模式在多条路径上同时存活并被加强。解决：no_repeat_ngram（硬阻断）+ repetition_penalty（软惩罚）+ 控制束宽。

**Q6：repetition_penalty 设多大合适？**
1.05~1.3 常见。小于 1.05 几乎无效，大于 1.3 输出生硬不连贯——合理的重复（固定搭配、引用、专有名词）也被压掉，模型被迫换不自然的词。

**Q7：业界对话生成的标配参数是什么？**
temperature=0.7~1.0 + top_p=0.9 + repetition_penalty=1.05。三者解耦：温度管随机性、top_p 管长尾、repetition_penalty 管重复；HuggingFace 执行顺序是 penalty → 温度 → top_k → top_p → 采样。

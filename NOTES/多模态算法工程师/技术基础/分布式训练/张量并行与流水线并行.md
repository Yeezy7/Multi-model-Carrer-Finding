# 张量并行与流水线并行

> 本模块索引见 [分布式训练详解](分布式训练详解.md)

## 一、定义与公式

### 1.1 张量并行（TP）：切权重矩阵本身

数据并行（DP）是"每卡复制一份模型，分不同数据"；**张量并行（Tensor Parallel，TP）是把单个权重矩阵拆开，多卡合作算一次矩阵乘**。对线性层 $Y = XW^{\mathsf{T}}$（$X \in \mathbb{R}^{b\times d_{in}}$，$W \in \mathbb{R}^{d_{out}\times d_{in}}$），有两种切法：

**列并行（column parallel）**——按输出维切 $W$：

$$W = \begin{bmatrix} W_1 \\ W_2 \\ \vdots \\ W_p \end{bmatrix}, \quad Y = XW^{\mathsf{T}} = \Big[\, XW_1^{\mathsf{T}} \;\Big|\; XW_2^{\mathsf{T}} \;\Big|\; \cdots \;\Big|\; XW_p^{\mathsf{T}} \,\Big] = \big[\,Y_1 \,\big|\, Y_2 \,\big|\, \cdots \,\big|\, Y_p\,\big]$$

每卡算自己的 $Y_r = X W_r^{\mathsf{T}}$，输出按特征维**拼接**（或保持分片传给下一层）。

**行并行（row parallel）**——按输入维切 $W$，输入同步切分，输出用 all-reduce 求和：

$$W = \big[\,W_1 \;\big|\; W_2 \;\big|\; \cdots \;\big|\; W_p\,\big], \quad X = \big[\,X_1 \;\big|\; X_2 \;\big|\; \cdots \;\big|\; X_p\,\big], \quad Y = \sum_{r=1}^{p} X_r W_r^{\mathsf{T}} \xrightarrow{\text{AllReduce}} Y$$

推导只需一条等式：矩阵乘对输入维是线性叠加 $XW^{\mathsf{T}} = \sum_r X_r W_r^{\mathsf{T}}$，all-reduce 就是把这个"跨卡部分和"加总。

### 1.2 流水线并行（PP）：按层切模型

**流水线并行（Pipeline Parallel，PP）把模型按层序切成 $p$ 个 stage**，每卡只负责一部分层。为了减少"后段卡干等"，引入 micro-batch 流水：把 batch 切成 $m$ 个微批，相邻 stage 错开一个微批并行推进。设每个微批在单个 stage 耗时 $t$：

- 串行（不流水）总时间：$T_{serial} = m \cdot p \cdot t$；
- 流水总时间：第 1 个微批走完 $p$ 个 stage 需 $pt$，之后每个微批只多 $t$：$T_{pipe} = (m + p - 1)t$；
- **气泡率（bubble ratio）**：

$$\text{bubble} = \frac{T_{pipe} - m\cdot t}{T_{pipe}} = \frac{(m+p-1) - m}{m+p-1} = \frac{p-1}{m+p-1}$$

推导要点：$T_{pipe}$ 里只有 $m\cdot t$ 是有效计算，其余 $(p-1)t$ 是流水"注水/排空"阶段的空闲。$m$ 越大气泡越小，$p$ 越大气泡越大。

### 1.3 三种并行的切分对象一句话

| 并行 | 切什么 | 复制什么 |
| --- | --- | --- |
| DP | 数据 | 完整模型 ×N 份 |
| TP | 权重矩阵内部 | 激活（每卡算一部分输出） |
| PP | 网络层序列 | 激活的切分边界 |

## 二、核心原理

### 2.1 Megatron-LM 的 MLP 布局：column → GELU → row

Transformer 的 MLP 是 $f(X) = \text{GELU}(XW_1)W_2$，Megatron 的切法（$p$ 张卡）：

```
   X (完整)                          H_r (分片)                        Y (完整)
    │                                  │                                  ▲
    ▼                                  ▼                                  │
┌────────────┐   H_r = GELU(X W1_rᵀ) ┌──────────┐   Y_r = H_r W2_rᵀ   ┌──────┐
│ fc1 列并行  │ ───────────────────▶ │  GELU    │ ───────────────────▶ │AllReduce│
│ W1 按输出切  │  输出保持分片，不通信      │ 逐元素， │  本卡部分和            │ 求总和  │
└────────────┘                        │ 无需通信  │                     └──────┘
                                      └──────────┘
```

**省一次通信的设计思想**：列并行的输出天然按特征维分片，如果不 gather，下一步 GELU（逐元素）可继续在分片上算，最后一行并行 + 一次 all-reduce 一次性完成"拼接 + 求和"。若中间 gather 一次再计算，就白白多一轮通信——所以第一层用列、第二层用行，**整个 MLP 只有 1 次 all-reduce**。

### 2.2 Attention 的 TP 布局

- QKV 三个投影：**column parallel**，按 head 维切（每个 head 完整落在单卡上，softmax 无需跨卡通信）；
- out_proj：**row parallel** + 一次 all-reduce；
- LayerNorm 的均值和方差需要跨卡 all-reduce（或按 Megatron 方式切分 norm 权重）。

因此**每个 Transformer 层固定 2 次 all-reduce**（Attention 1 次 + MLP 1 次），通信次数与层数线性、与 TP 度数无关。

### 2.3 TP 的通信特征与适用场景

- 每次 all-reduce 的规模 = $b \times s \times h$（激活大小），**与参数量无关、与激活成正比**；
- TP 组内卡必须频繁全连接通信 → 只适合**单机 NVLink（~900 GB/s）**内、最多 8 卡；
- 跨节点（PCIe/IB）带宽低一个数量级，TP 跨节点会让通信成为绝对瓶颈。

### 2.4 流水线并行：GPipe 与 PipeDream 1F1B

**GPipe（静态两波）**：每个 stage 先连续做完 $m$ 个前向，再做 $m$ 个反向。简单，但每 stage 要同时保留 $m$ 个微批的激活，**显存 O(m)**。

```
stage0: F0 F1 F2 F3 │ B3 B2 B1 B0      （等待 3 个空闲格）
stage1:    F0 F1 F2 F3 │ B3 B2 B1 B0
stage2:       F0 F1 F2 F3 │ B3 B2 B1 B0
stage3:          F0 F1 F2 F3 │ B3 B2 B1 B0
           时间 ────────────────────▶   总时间 (m+p-1) + (m+p-1)，bubble=(p-1)/(m+p-1)
```

**PipeDream 1F1B（one forward one backward）**：反向尽量早做，每个 stage 交替推进前向与反向（"能反传就反传，否则前传"）。bubble 不变，但**显存从 O(m) 降到 O(p)**（激活只需保留最近约 $p$ 个微批），允许更大的 $m$、更小的气泡。

## 三、源码实现

### 3.1 纯 tensor 验证：列并行与行并行的数学等价性

```python
# 直接运行：验证"切分后拼接/求和 == 完整矩阵乘"
import torch

p, bs, in_f, out_f = 4, 2, 8, 16
torch.manual_seed(0)
X = torch.randn(bs, in_f)
W = torch.randn(out_f, in_f)            # 完整权重

# —— 列并行：W 按输出维切 p 块，输出拼接 ——
W_cols = torch.chunk(W, p, dim=0)       # 每块 [out_f/p, in_f]
Y_col = torch.cat([X @ Wc.t() for Wc in W_cols], dim=-1)
assert torch.allclose(Y_col, X @ W.t())

# —— 行并行：W 按输入维切，X 同步切，输出求和（模拟 all-reduce）——
W_rows = torch.chunk(W, p, dim=1)       # 每块 [out_f, in_f/p]
X_rows = torch.chunk(X, p, dim=-1)
Y_row = sum(Xr @ Wr.t() for Xr, Wr in zip(X_rows, W_rows))
assert torch.allclose(Y_row, X @ W.t())
print("列并行/行并行与完整矩阵乘等价 ✓")
# 输出: 列并行/行并行与完整矩阵乘等价 ✓
```

### 3.2 2 进程真实 TP 训练（gloo，CPU 可跑）

```python
# 保存为 tp_mlp.py。运行方式：
#   torchrun --nproc_per_node=2 tp_mlp.py
# （GPU 环境 backend 换 "nccl"；本机无 torchrun 时可用 torch.multiprocessing 起 2 个进程）
import torch
import torch.nn.functional as F
import torch.distributed as dist

class AllReduce(torch.autograd.Function):
    """可微 all-reduce：前向求和，反向时梯度再 all-reduce（通信算子是线性映射，梯度不变式）"""
    @staticmethod
    def forward(ctx, x):
        y = x.clone()
        dist.all_reduce(y, op=dist.ReduceOp.SUM)
        return y

    @staticmethod
    def backward(ctx, grad_output):
        g = grad_output.clone()
        dist.all_reduce(g, op=dist.ReduceOp.SUM)
        return g

def main(rank=0, world=2):
    dist.init_process_group(backend="gloo", rank=rank, world_size=world)
    torch.manual_seed(0)
    bs, in_f, hidden, out_f, shard = 4, 8, 16, 8, 16 // world

    W1_full = torch.randn(hidden, in_f) * 0.1      # 全局权重（仅 rank0 用于验证）
    W2_full = torch.randn(out_f, hidden) * 0.1
    # 各 rank 持有的分片：fc1 切输出维（列并行），fc2 切输入维（行并行）
    W1 = W1_full[rank * shard:(rank + 1) * shard].clone().requires_grad_()   # [shard, in_f]
    W2 = W2_full[:, rank * shard:(rank + 1) * shard].clone().requires_grad_()  # [out_f, shard]
    X = torch.randn(bs, in_f)
    opt = torch.optim.SGD([W1, W2], lr=0.1)

    for step in range(20):
        H = F.gelu(X @ W1.t())                     # ① fc1 列并行：本地算，输出分片
        Y = AllReduce.apply(H @ W2.t())            # ② fc2 行并行：部分和 + 1 次 all-reduce
        loss = (Y ** 2).mean()
        loss.backward()                            # all-reduce 梯度也走一遍 all-reduce
        opt.step()
        opt.zero_grad()

        if step == 0 and rank == 0:                # 与全量计算对比
            W1_g, W2_g = W1_full.clone().requires_grad_(), W2_full.clone().requires_grad_()
            Y_ref = F.gelu(X @ W1_g.t()) @ W2_g.t()
            (Y_ref ** 2).mean().backward()
            assert torch.allclose(Y, Y_ref, atol=1e-5), "TP 输出与全量计算不一致"
            print("验证通过：列并行+行并行输出 == 全量计算")
    if rank == 0:
        print(f"训练完成 loss={loss.item():.4f}")
    dist.destroy_process_group()

if __name__ == "__main__":
    main()
```

```text
运行输出（2 进程 CPU，已验证）：
验证通过：列并行+行并行输出 == 全量计算
训练完成 loss=0.0011
```

### 3.3 GPipe 流水与 bubble 模拟器

```python
# 直接运行：验证 bubble = (p-1)/(m+p-1)，并对比 GPipe 与 1F1B 的激活占用
def simulate(mode, p, m):
    fq = [[('F', k) for k in range(m)] for _ in range(p)]
    bq = [[('B', k) for k in range(m)] for _ in range(p)]
    fi, bi = [0] * p, [0] * p
    done_f, done_b = [set() for _ in range(p)], [set() for _ in range(p)]
    peak, t = [0] * p, 0
    while True:
        f_snap, b_snap = [s.copy() for s in done_f], [s.copy() for s in done_b]
        plan = [None] * p
        for s in range(p):                          # 每 tick 每 stage 至多推进一个事件
            if mode == 'f1b1' and bi[s] < m:        # 1F1B：反传可做就做
                k = bq[s][bi[s]][1]
                if k in f_snap[s] and (s == p - 1 or k in b_snap[s + 1]):
                    plan[s] = ('B', k)
                    continue
            if fi[s] < m:                           # 否则推前向
                k = fq[s][fi[s]][1]
                if s == 0 or k in f_snap[s - 1]:
                    plan[s] = ('F', k)
            if mode == 'gpipe' and fi[s] >= m and bi[s] < m:  # GPipe：前向波完再反传
                k = bq[s][bi[s]][1]
                if k in f_snap[s] and (s == p - 1 or k in b_snap[s + 1]):
                    plan[s] = ('B', k)
        for s in range(p):
            if plan[s] is None:
                continue
            (done_f[s] if plan[s][0] == 'F' else done_b[s]).add(plan[s][1])
            (fi if plan[s][0] == 'F' else bi)[s] += 1
            peak[s] = max(peak[s], len(done_f[s] - done_b[s]))
        if all(fi[s] >= m and bi[s] >= m for s in range(p)):
            break
        t += 1
    total, useful = t + 1, 2 * m
    return total, (total - useful) / total, peak

p, m = 4, 16
for mode, name in [('gpipe', 'GPipe '), ('f1b1', '1F1B  ')]:
    total, bubble, peak = simulate(mode, p, m)
    print(f"{name} p=4 m=16: 总时间={total} bubble={bubble:.2%} "
          f"公式={(p-1)/(m+p-1):.2%} 各stage峰值激活={peak}")
```

### 3.4 3D 并行：DP×PP×TP 分组（64 卡 = 8×2×4）

```python
# 直接运行：给定 DP/PP/TP 度数，算出每个通信组包含哪些全局 rank
def partition_3d(dp, pp, tp):
    """全局 rank 编号布局：rank = dp_idx*(pp*tp) + pp_idx*tp + tp_idx"""
    tp_groups, pp_groups, dp_groups = [], [], []
    for d in range(dp):
        for p in range(pp):
            tp_groups.append([d * pp * tp + p * tp + t for t in range(tp)])
    for d in range(dp):
        for t in range(tp):
            pp_groups.append([d * pp * tp + p * tp + t for p in range(pp)])
    for p in range(pp):
        for t in range(tp):
            dp_groups.append([d * pp * tp + p * tp + t for d in range(dp)])
    return tp_groups, pp_groups, dp_groups

tp, pp, dp = partition_3d(dp=8, pp=2, tp=4)          # 64 卡
print("TP 组示例:", tp[0])     # [0,1,2,3]：组内 all-reduce，NVLink 直连
print("PP 组示例:", pp[0])     # [0,4]：组间传激活，跨 stage 边界
print("DP 组示例:", dp[0][:6], "...")   # 0,8,16,...：数据并行复制组
```

## 四、深入分析：显存 / 通信 / 复杂度数值账本

### 4.1 TP 的通信量：与激活成正比（7B 算例）

设 7B 模型：$h=4096$，$L=32$ 层，序列 $s=2048$，单卡 batch 1，BF16。单次 all-reduce 大小：

$$S = b \times s \times h \times 2\text{B} = 1 \times 2048 \times 4096 \times 2 \approx 16.8 \text{ MB}$$

| 项目 | 公式 | 数值 |
| --- | --- | --- |
| 每层通信 | 2 次 all-reduce × ≈2×S | ≈67 MB |
| 每 step 通信 | 32 层 × 67 MB | ≈2.1 GB |
| NVLink 耗时（900 GB/s） | 2.1 GB / 900 GB/s | ≈2.4 ms |
| 若走 PCIe（50 GB/s） | 2.1 GB / 50 GB/s | ≈43 ms（不可接受） |
| 对比 DP 梯度同步 | ≈2×14 GB | 28 GB / step |

**结论**：TP 通信量比 DP 低一个数量级，但依赖单机 NVLink 的高带宽才"免费"——这就是 TP 不能跨节点的量化原因。且注意 TP 通信量与参数量无关：模型再大、只要激活不变，通信量不变。

### 4.2 PP 的显存账本（7B，4 stage）

| 项目 | 单卡全量 | PP 4 stage 每卡 |
| --- | --- | --- |
| 参数（BF16） | 14 GB | 14/4 = 3.5 GB |
| 梯度 + 优化器状态 | 98 GB | 98/4 ≈ 24.5 GB |
| 中间激活 | 全部层 | 只存自己 stage 的层（且 1F1B 只存约 2p-1 个微批） |
| **合计** | ≈114 GB | ≈30 GB |

PP 的参数/梯度/优化器显存同样除以 stage 数；额外收益是**激活只需保留本 stage 区间**，配合 1F1B 后每个 stage 的激活 = 约 $p$ 个微批，而非全部 $m$ 个。

### 4.3 bubble 数值与权衡

| p | m | bubble |
| --- | --- | --- |
| 4 | 16 | 15.8% |
| 4 | 32 | 8.6% |
| 8 | 64 | 9.9% |
| 4 | 1（无流水） | 75% |

$m$ 越大 bubble 越小，但 micro-batch 过小会稀释单次计算效率（kernel 利用率下降），实际取 $m \ge 2(p-1)$（1F1B 的前提）。

### 4.4 混合并行总账（64 卡：DP8 × PP2 × TP4）

- 每卡参数 = $7B/(PP \times TP) = 7B/8 \approx 875M$（BF16 ≈ 1.75 GB），DP=8 路复制做数据并行；
- 通信分层：TP 组内（4 卡 NVLink）每层 2 次 all-reduce；PP 边界（2 卡间）每微批传一次激活；DP 组（8 卡）每 step 一次梯度 all-reduce；
- Megatron 论文中 512 卡 = DP16 × PP4 × TP8 是典型配置：TP 管单机带宽、PP 管跨机切层、DP 管吞吐。

### 4.5 MoE 专家并行（EP）简述

MoE 的每个 expert 可以放到不同卡上，token 经门控路由到对应卡：$g(x)=\text{softmax}(xW_g)$ 取 top-k，通过 **all-to-all** 把 token 整体搬到目标卡，算完再搬回。EP 的通信量与"被路由的 token 数"成正比，是稀疏模型扩容到万卡的首选（详见模块内 MoE 主题）。

## 五、优缺点

| 并行 | 优点 | 缺点 |
| --- | --- | --- |
| TP | 单层计算提速（矩阵乘被切小）；通信量与参数无关 | 只适合单机 NVLink；卡数上限受层内维度约束（≤ hidden/head）；每层都通信 |
| PP | 通信量极小（只传 stage 边界激活）；切层不切矩阵，任意模型适用 | bubble 空闲；各 stage 负载不均（首尾层计算量不同）；micro-batch 调度复杂 |

## 六、与同类对比

| 维度 | DP | TP | PP | FSDP/ZeRO-3 |
| --- | --- | --- | --- | --- |
| 切分对象 | 数据 | 权重矩阵内部 | 网络层 | 参数/梯度/优化器状态 |
| 单卡显存 | 不降 | ÷TP | ÷PP | ÷卡数（线性） |
| 通信量 | 梯度大小（与参数成正比） | 激活大小（与参数无关） | 最小（边界激活） | 约 DP 的 1.5× |
| 通信拓扑 | 全集群 | 单机 NVLink 内 | 相邻 stage | 全集群 |
| 强项 | 吞吐（数据多） | 单层显存/算力 | 跨节点扩展 | 显存最省、最易用 |
| 弱项 | 显存不降 | 无法跨节点 | bubble 与负载不均 | 通信多、激活未切 |

组合方式：TP 管单机带宽（内部），PP 管跨机（外部），DP 管数据吞吐（最外层），FSDP 可与任意维度组合（如 HybridShard = TP + FSDP）。

## 七、高频面试问答

**Q1：TP 和 PP 的区别？**
TP 切单个权重矩阵（多卡合作算一层），PP 按层切（每卡负责若干层）。TP 通信量大但只在单机 NVLink 内；PP 通信量小（只传边界激活）可跨节点，但有 bubble。一句话：TP 是"层内切"，PP 是"层间切"。

**Q2：为什么 TP 只适合单机？**
TP 每层都要 2 次 all-reduce，通信量与激活成正比（7B 算例 ≈2.1 GB/step）。NVLink 900 GB/s 下约 2.4 ms，换 PCIe（50 GB/s）就变成 43 ms，通信直接成为瓶颈。所以 TP 组永远建在单机内。

**Q3：bubble ratio 怎么算？**
$T_{pipe}=(m+p-1)t$，其中有效工作 $m\cdot t$，$\text{bubble}=(p-1)/(m+p-1)$。推导：第一个微批走完 $p$ 个 stage 耗时 $pt$，之后每个微批只增加 $t$，共 $m+p-1$ 个单位时间，其中 $(p-1)$ 个是注水/排空空闲。$m=16,p=4$ 时约 15.8%。

**Q4：为什么 MLP 第一层用 column 并行、第二层用 row 并行？**
列并行的输出天然按特征维分片，GELU 逐元素运算无需通信，直接作为行并行的分片输入，最后一次性 all-reduce——整个 MLP 只有 1 次通信。若中途 gather 拼接再算，就多一轮全量通信。

**Q5：TP 的通信量为什么与激活成正比而不是参数量？**
all-reduce 传的是"输出激活"（$b\times s\times h$），不是权重。模型参数翻倍但 batch/序列不变时，每层通信量不变。这也是"模型越大 TP 越划算"的原因：显存收益线性增长，通信成本不变。

**Q6：GPipe 和 PipeDream 1F1B 的区别？**
GPipe 静态两波（先全部前向再全部反向），调度简单但每 stage 要保留 $m$ 个微批激活（O(m)）；1F1B 反向尽早执行、前后向交替推进，bubble 相同但激活占用降到 O(p)，可以支撑更大的 $m$ 和更小的气泡。

**Q7：3D 并行怎么排？**
先 TP（单机内 4 卡组），再 PP（跨机按层切，如每机一组 stage），最后 DP 复制。64 卡 = DP8×PP2×TP4：TP 组 [0,1,2,3]，PP 组 [0,4]，DP 组 {0,8,16,...}。rank 编号按 dp_idx×(pp×tp) + pp_idx×tp + tp_idx 排布。

**Q8：什么时候用 PP？什么时候用 TP？**
显存瓶颈且单机放不下 → 先 TP（限单机）再 PP（跨机）；通信瓶颈（带宽低）→ 优先 PP（通信最小）；吞吐不足 → 加 DP；显存仍不够 → 上 FSDP/ZeRO。超大模型（100B+）通常 DP×PP×TP 全上 + FSDP 混合。

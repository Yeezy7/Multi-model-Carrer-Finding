# 多模态分布式训练实践

> 本模块索引见 [分布式训练详解](分布式训练详解.md)
## 一、多模态训练与纯文本训练的差异
### 1.1 资源画像：多模态模型的"三件套"

多模态模型（InternVL、Qwen-VL、LLaVA、BLIP 系列）的权重由三部分组成：

| 组件 | 典型规模 | 显存占用（fp16 参数） | 说明 |
| --- | --- | --- | --- |
| 视觉塔（ViT/CLIP encoder） | CLIP ViT-B 86M ~ InternViT-6B | 0.2 ~ 12 GB | 负责把图像编码成视觉 token 序列 |
| 投影层（MLP/Q-Former） | 几 MB ~ 几百 MB | 可忽略 | 把视觉特征对齐到文本空间 |
| 文本塔（LLM） | 1.5B ~ 70B+ | 3 ~ 140 GB | 生成/理解的主体，常被冻结或低学习率 |

**视觉 token 数量是显存压力的核心来源**：一张 $448\times448$ 的图、patch size 14，会产生 $32\times32=1024$ 个 patch token（加 CLS 共 1025 个），一张普通图 ≈ 8~16 倍于一条 64~128 token 的文本；视频输入（32 帧 × 每帧 200+ token）更可达上万 token。
### 1.2 显存构成：激活与 KV cache 占比陡增

对一次前向+反向，单卡显存 $\approx$ 参数 + 优化器状态 + 激活 + KV cache：

| 组成 | 纯文本 LLM | 图文多模态 | 原因 |
| --- | --- | --- | --- |
| 参数 + 优化器 | 固定 | 多出视觉塔权重 | AdamW 每参数约 12 字节（fp16 参数+fp32 主副本+动量的三份） |
| 激活 | 由文本长度决定 | **由视觉 token 数支配** | 视觉塔注意力 score 矩阵是 $B\times N\times N\times heads$，$N=1025$ 时一张图就是百万级元素 |
| KV cache | 由输入 token 决定 | 视觉 token 占大头 | LLM 端每层对每个视觉 token 都存 K、V |

KV cache 量化示例（fp16、$L$ 层、hidden $d$）：$KV_{\text{cache}} = 2\times2\times L\times d\times N_{\text{tok}}$。32 层、$d=4096$ 的模型，一张 1025 token 的图：$2\times2\times32\times4096\times1025 \approx 0.54$ GB；batch=8 张图即 **4.3 GB 只用于 KV cache**，而 128 token 的文本只占 0.07 GB。同理视觉塔激活约正比于 $M_{\text{act}} \sim B\cdot N\cdot d\cdot \text{层数}$。

**结论**：多模态训练"长在序列上"，显存瓶颈从纯文本的"权重"转移为"激活 + KV cache"，这也决定了并行方案的选择（见第二节）。
## 二、核心原理与选型
### 2.1 并行维度速览

- **数据并行（DDP）**：每卡一份完整模型，各卡算各自 batch 的梯度，每步一次 AllReduce。通信量与参数规模成正比。
- **FSDP（ZeRO-3）**：参数/梯度/优化器状态分片，前向 AllGather、反向 ReduceScatter，单卡显存大幅下降，通信约为 DDP 的 2~3 倍。
- **张量并行（TP）**：把单个大矩阵切到多卡，每层多次小 AllReduce，适合单卡装不下的大权重。
- **流水并行（PP）**：按层切段，卡间流水执行，适合超大模型。
- **序列并行（SP）**：沿序列维度切分（长图/视频场景，见 4.1 第 6 条）。
### 2.2 多模态选型建议（决策表）

| 视觉塔规模 | LLM 规模 | 推荐方案 | 理由 |
| --- | --- | --- | --- |
| < 1B（CLIP ViT-B/L、SigLIP） | ≤ 7B | **DDP 或 FSDP** | 单卡装得下完整模型，数据并行最简单可靠 |
| 1B ~ 4B（ViT-H、SigLIP-4B） | 7B ~ 14B | **FSDP**（激活压力大时视觉塔加 TP/SP） | 权重+激活+KV 逼近单卡，FSDP 按需取回参数 |
| 4B ~ 6B+（InternViT-6B） | 7B ~ 34B | **FSDP + TP/SP 组合** | 视觉塔权重分片 + 长序列维切分，两者叠加吃下"大权重 + 长序列" |
| 大视觉塔 + 70B+ LLM | — | **3D 并行（DP+TP+PP）+ SP** | 双塔都可能超单卡，走 Megatron/ColossalAI 类框架 |
| 冻结视觉塔 | 任意 | DDP + 冻结参数 | 视觉塔不参与梯度同步，开销近似纯文本 DDP |

**选型三原则**：① 序列长 → 优先解决激活/KV（SP、gradient checkpointing）；② 权重超单卡 → 才上 FSDP/TP；③ 视觉塔冻结时 → DDP 就够了，别为显存过度设计。
## 三、源码实现

两个可直接运行的程序（纯 torch，无第三方依赖）：**程序 A** 为完整 DDP 骨架（`DistributedSampler`、`no_sync` 梯度累积、rank 0 保存、`all_gather` 分布式评测）；**程序 B** 为冻结视觉塔 + 只训练投影层/LLM 的变体（见 3.3）。
### 3.1 分布式下的数据加载（重点）
```python
from torch.utils.data import DataLoader, Dataset, DistributedSampler

class ImageTextDataset(Dataset):
    """图文数据集正确写法：
    ① __init__ 只存路径/索引，绝不在初始化里解码全部图像；
    ② 解码+预处理放 __getitem__，由 num_workers 个 worker 进程并行；
    ③ 真实项目统一用 processor（如 AutoProcessor）resize/归一化，保证所有样本形状一致。"""
    def __init__(self, num_samples, img_size=224, seq_len=32, vocab_size=5000, synthetic=True):
        self.img_size, self.seq_len, self.vocab_size = img_size, seq_len, vocab_size
        self.synthetic = synthetic

    def __len__(self):
        return self.num_samples if hasattr(self, "num_samples") else 0

    def __getitem__(self, idx):
        if self.synthetic:
            # 可运行版本：随机数据占位，接口与真实数据完全一致
            pixel_values = torch.randn(3, self.img_size, self.img_size)
            input_ids = torch.randint(0, self.vocab_size, (self.seq_len,))
        else:
            # 生产版本（worker 进程内执行）：
            # pixel_values = processor(Image.open(path))  # 统一尺寸，禁止各样本不同尺寸
            # input_ids = processor(caption)
            raise NotImplementedError("替换为真实图文读取")
        return pixel_values, input_ids

def collate_fn(batch):
    """统一打包。多卡 DDP 下各 rank 的 batch 形状必须一致
    （AllReduce/AllGather 对形状敏感），动态分辨率要在此处 pad 对齐并附掩码。"""
    pixel_values = torch.stack([b[0] for b in batch])   # (B, 3, H, W)，H/W 全局一致
    input_ids = torch.stack([b[1] for b in batch])      # (B, L)
    return pixel_values, input_ids
# DataLoader 关键参数：num_workers=4~16 解码/预处理并行；
# pin_memory=True 拷贝到 GPU 更快；sampler 用 DistributedSampler 按 rank 切分
loader = DataLoader(
    dataset, batch_size=16, sampler=DistributedSampler(dataset, shuffle=True),
    num_workers=4, pin_memory=True, collate_fn=collate_fn, drop_last=True)
```
**大图解码开销**：一张 4K 原图解码 + resize 占几十 ms CPU 时间，GPU 前向只要 1~2 ms；`num_workers` 太少或解码在主进程会被 CPU 拖死。两条出路：
1. 预处理流水线：用 `WebDataset`/LMDB 存已解码缩略图，或离线缩到目标分辨率再存；
2. **缓存特征**：视觉塔冻结时把整库图离线过一遍视觉塔存 `embedding.pt`（BLIP-2 的 Q-Former 阶段就是这么做的），训练时 `__getitem__` 只 load 一个向量，解码开销直接归零。
### 3.2 程序 A：完整多卡图文训练骨架（DDP）
```python
# train_mm_ddp.py —— 多模态图文对比学习训练骨架（可直接运行）
# 运行命令（Linux + 多卡 GPU，NCCL）：
#   torchrun --nproc_per_node=2 train_mm_ddp.py
#   torchrun --nproc_per_node=8 train_mm_ddp.py --amp --freeze-vision
# Mac/CPU 调试：torchrun --nproc_per_node=2 train_mm_ddp.py --backend gloo
import argparse
import random
import time
from contextlib import nullcontext

import numpy as np
import torch
import torch.distributed as dist
import torch.nn as nn
import torch.nn.functional as F
from torch.cuda.amp import GradScaler, autocast
from torch.utils.data import DataLoader, Dataset, DistributedSampler


class VisionTower(nn.Module):
    """迷你 ViT：patch 化 + Transformer，模拟 CLIP/InternViT 视觉塔。
    224x224 图 -> 196 patch token + 1 CLS = 197 token；调大 img_size 即可模拟上千 token。"""

    def __init__(self, img_size=224, patch_size=16, dim=256, depth=4, heads=4):
        super().__init__()
        self.dim = dim
        num_patches = (img_size // patch_size) ** 2
        self.patch_embed = nn.Conv2d(3, dim, patch_size, patch_size)
        self.cls_token = nn.Parameter(torch.zeros(1, 1, dim))
        self.pos_embed = nn.Parameter(torch.zeros(1, num_patches + 1, dim))
        self.encoder = nn.TransformerEncoder(
            nn.TransformerEncoderLayer(d_model=dim, nhead=heads, dim_feedforward=dim * 4,
                                       batch_first=True, norm_first=True),
            num_layers=depth)
        nn.init.trunc_normal_(self.pos_embed, std=0.02)

    def forward(self, x):
        b = x.size(0)
        x = self.patch_embed(x).flatten(2).transpose(1, 2)              # (B, N, D)
        x = torch.cat([self.cls_token.expand(b, -1, -1), x], dim=1)     # (B, N+1, D)
        return self.encoder(x + self.pos_embed)


class TextTower(nn.Module):
    """迷你文本塔：模拟 LLM 端（真实项目换成 Qwen/LLaMA 等 decoder）。"""

    def __init__(self, vocab_size=5000, dim=256, depth=4, heads=4):
        super().__init__()
        self.embed = nn.Embedding(vocab_size, dim)
        self.encoder = nn.TransformerEncoder(
            nn.TransformerEncoderLayer(d_model=dim, nhead=heads, dim_feedforward=dim * 4,
                                       batch_first=True, norm_first=True),
            num_layers=depth)
        self.norm = nn.LayerNorm(dim)

    def forward(self, input_ids):
        return self.norm(self.encoder(self.embed(input_ids)))           # (B, L, D)


class MultimodalModel(nn.Module):
    """视觉塔 + 投影层 + 文本塔三件套（对应 InternVL/Qwen-VL/LLaVA 类架构）。"""

    def __init__(self, vision_tower, text_tower, proj_dim=256):
        super().__init__()
        self.vision_tower = vision_tower
        self.projection = nn.Linear(vision_tower.dim, proj_dim)  # 投影层
        self.text_tower = text_tower

    def forward(self, pixel_values, input_ids):
        vfeat = self.vision_tower(pixel_values)                 # (B, Nv+1, D)
        v = F.normalize(self.projection(vfeat).mean(dim=1), dim=-1)   # 池化+投影
        t = F.normalize(self.text_tower(input_ids).mean(dim=1), dim=-1)
        return v, t

    def compute_loss(self, pixel_values, input_ids, temperature=0.07):
        """InfoNCE 图文对比损失：batch 内 (图, 文) 一一配对，对角线为正样本"""
        v, t = self.forward(pixel_values, input_ids)
        logits = v @ t.t() / temperature                        # (B, B)
        labels = torch.arange(v.size(0), device=v.device)
        return (F.cross_entropy(logits, labels) +              # 图像->文本
                F.cross_entropy(logits.t(), labels)) / 2       # 文本->图像


class ImageTextDataset(Dataset):
    def __init__(self, num_samples, img_size=224, seq_len=32, vocab_size=5000):
        self.num_samples, self.img_size = num_samples, img_size
        self.seq_len, self.vocab_size = seq_len, vocab_size

    def __len__(self):
        return self.num_samples

    def __getitem__(self, idx):
        # 见 3.1：synthetic 随机数据保证开箱即跑；生产环境替换为解码+processor
        return (torch.randn(3, self.img_size, self.img_size),
                torch.randint(0, self.vocab_size, (self.seq_len,)))


def collate_fn(batch):
    return torch.stack([b[0] for b in batch]), torch.stack([b[1] for b in batch])


def evaluate(model, loader, device, rank, world_size):
    """分布式评测：各卡在自己的数据子集上算指标，再 all_gather 到 rank 0 汇总。
    注意：all_gather 要求各卡 tensor 形状一致，评测 DataLoader 必须 drop_last=True；
    若结果异构（如生成文本），改用 dist.all_gather_object。"""
    model.eval()
    accs = []
    with torch.no_grad():
        for pixel, input_ids in loader:
            pixel, input_ids = pixel.to(device), input_ids.to(device)
            v, t = model(pixel, input_ids)                      # DDP forward
            logits = v @ t.t() / 0.07
            label = torch.arange(v.size(0), device=device)
            correct = (logits.argmax(dim=1) == label).float().mean().unsqueeze(0)
            buf = [torch.zeros_like(correct) for _ in range(world_size)]
            dist.all_gather(buf, correct)                       # (world_size,) -> 各卡同步后汇总
            if rank == 0:
                accs.extend([b.item() for b in buf])
    if rank == 0:
        return sum(accs) / len(accs)
    return None


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--backend", default="nccl", help="nccl(Linux+GPU) / gloo(本地调试)")
    parser.add_argument("--epochs", type=int, default=2)
    parser.add_argument("--batch-size", type=int, default=16)
    parser.add_argument("--accum-steps", type=int, default=4, help="梯度累积步数")
    parser.add_argument("--num-workers", type=int, default=4)
    parser.add_argument("--num-samples", type=int, default=2048)
    parser.add_argument("--freeze-vision", action="store_true", help="冻结视觉塔")
    parser.add_argument("--amp", action="store_true", help="fp16 混合精度")
    args = parser.parse_args()

    # ---- 0. 初始化分布式环境（torchrun 自动注入 RANK/LOCAL_RANK/WORLD_SIZE）----
    dist.init_process_group(backend=args.backend)
    rank, world_size = dist.get_rank(), dist.get_world_size()
    if torch.cuda.is_available():
        torch.cuda.set_device(rank)
        device = torch.device("cuda", rank)
    else:
        device = torch.device("cpu")    # gloo 本地调试（Mac/CPU）
    random.seed(42 + rank)
    np.random.seed(42 + rank)
    torch.manual_seed(42 + rank)

    # ---- 1. 模型 + 可选冻结视觉塔 ----
    model = MultimodalModel(VisionTower(), TextTower()).to(device)
    if args.freeze_vision:
        for p in model.vision_tower.parameters():
            p.requires_grad = False     # 冻结：DDP 自动跳过这些参数的梯度同步
    ddp_kwargs = {"device_ids": [rank]} if torch.cuda.is_available() else {}
    model = nn.parallel.DistributedDataParallel(model, **ddp_kwargs,
                                                find_unused_parameters=False)

    # ---- 2. 优化器：只收集 requires_grad=True 的参数（冻结后视觉塔不进优化器）----
    optimizer = torch.optim.AdamW([p for p in model.parameters() if p.requires_grad], lr=1e-4)
    scaler = GradScaler(enabled=args.amp)

    # ---- 3. 数据：DistributedSampler 按 rank 切分；worker 并行解码 ----
    dataset = ImageTextDataset(args.num_samples)
    sampler = DistributedSampler(dataset, num_replicas=world_size, rank=rank, shuffle=True)
    loader = DataLoader(dataset, batch_size=args.batch_size, sampler=sampler,
                        num_workers=args.num_workers, pin_memory=True,
                        collate_fn=collate_fn, drop_last=True)

    # ---- 4. 训练循环 ----
    for epoch in range(args.epochs):
        sampler.set_epoch(epoch)        # 必须：否则每个 epoch 的 shuffle 各卡顺序重复
        model.train()
        t0 = time.time()
        for step, (pixel, input_ids) in enumerate(loader):
            pixel = pixel.to(device, non_blocking=True)
            input_ids = input_ids.to(device, non_blocking=True)

            is_last = (step + 1) % args.accum_steps == 0
            # no_sync：梯度累积的中间步不触发 AllReduce，只有最后一步同步一次
            with model.no_sync() if not is_last else nullcontext():
                with autocast(enabled=args.amp):
                    loss = model.module.compute_loss(pixel, input_ids) / args.accum_steps
                scaler.scale(loss).backward()

            if is_last:
                scaler.step(optimizer)
                scaler.update()
                optimizer.zero_grad(set_to_none=True)

            if step % 20 == 0:
                avg_loss = loss.detach() * args.accum_steps
                dist.all_reduce(avg_loss, op=dist.ReduceOp.AVG)     # 跨卡平均
                if rank == 0:
                    elapsed = time.time() - t0
                    gbs = args.batch_size * world_size * args.accum_steps
                    print(f"[E{epoch} S{step}] loss={avg_loss.item():.4f} "
                          f"throughput={gbs / elapsed:.1f} samples/s (全局)")

        # ---- 5. 保存：仅 rank 0 写盘；barrier 保证写完再继续 ----
        if rank == 0:
            torch.save({"epoch": epoch, "model": model.module.state_dict()},
                       f"mm_ckpt_ep{epoch}.pt")
        dist.barrier()

        # ---- 6. 分布式评测 ----
        eval_dataset = ImageTextDataset(64)
        eval_sampler = DistributedSampler(eval_dataset, num_replicas=world_size,
                                          rank=rank, shuffle=False)
        eval_loader = DataLoader(eval_dataset, batch_size=args.batch_size,
                                 sampler=eval_sampler, num_workers=0,
                                 collate_fn=collate_fn, drop_last=True)
        acc = evaluate(model, eval_loader, device, rank, world_size)
        if rank == 0:
            print(f"[E{epoch} Eval] top1 acc={acc:.4f}")

    dist.destroy_process_group()


if __name__ == "__main__":
    main()
```
### 3.3 程序 B：冻结视觉塔变体（find_unused_parameters 的取舍）

与程序 A 的差异只有三处：
```python
# ① 冻结：先 requires_grad=False，再包 DDP（推荐顺序）
for p in model.vision_tower.parameters():
    p.requires_grad = False
# ② 优化器只收可训练参数（投影层 + LLM）
optimizer = torch.optim.AdamW(
    [p for p in model.parameters() if p.requires_grad], lr=1e-4)
# ③ DDP 包装：已按 ① 冻结则不需要 find_unused_parameters
model = nn.parallel.DistributedDataParallel(model, device_ids=[rank],
                                            find_unused_parameters=False)
```
**`find_unused_parameters` 取舍**：
- DDP 会在反向时检查每个 bucket 是否收到梯度，若某个 `requires_grad=True` 的参数没收到（例如视觉塔输出被 `detach`、或前向里部分分支没走），就报 "Expected to have finished reduction … parameters that were not used in producing loss"；
- 解法三选一：① 规范冻结（`requires_grad=False`，**首选，零开销**）；② 开 `find_unused_parameters=True`（每次反向多一次 autograd 图遍历 + 额外标记开销，训练稍慢，调试期可先开）；③ 构造参数列表——把冻结子模块从 DDP 前向中摘除（如冻结塔输出提前缓存），从根上消除未用参数；
- 工程上常见组合：`requires_grad=False` 冻结 + 暂时开着 `find_unused_parameters=True` 防其他分支漏参数，稳定后再关掉提速。
## 四、深入分析
### 4.1 常见坑与解法（逐条）

**坑 1：视觉塔冻结时 DDP 报"参数未使用"**
原因与三种解法见 3.3。补充一个高频场景：冻结塔时若不设 `requires_grad=False` 而只不传梯度（`detach` 或直接丢弃输出），100% 触发该报错。

**坑 2：不同卡图像尺寸/分辨率不一致导致 batch 打包失败**
- 症状：`torch.stack` 报 shape 不匹配，或各卡 loss 数量级差 10 倍（pad 的 mask 没对齐）；
- 根因：`__getitem__` 返回了不同 `H×W` 的 tensor，`collate_fn` 无法堆叠；
- 解法：所有图过同一个 `processor(resize=..., do_normalize=True)`，保证形状固定；真的要做动态分辨率（如 InternVL 的动态 tiling），在 `collate_fn` 里统一 pad 到 batch 最大分辨率并返回 attention mask，padding 区域在 loss 中置 -inf/忽略。

**坑 3：梯度累积 + DDP 的同步次数控制**
默认每步 `backward` 都触发一次全卡 AllReduce，梯度累积 N 步 = N 次通信。正确做法是前 N-1 步包在 `model.no_sync()` 里，只在最后一步同步：
```python
for step, batch in enumerate(loader):
    is_last = (step + 1) % accum_steps == 0
    with model.no_sync() if not is_last else nullcontext():   # 中间步只攒梯度不通信
        (loss / accum_steps).backward()   # 先除后加，等价于大 batch 的梯度大小
    if is_last:
        optimizer.step(); optimizer.zero_grad(set_to_none=True)
```
注意：BN 统计量在累积过程中只来自局部 batch，多模态模型默认全 LayerNorm/RMSNorm，无此问题。

**坑 4：多卡评测怎么做**
直接"每卡各自算、最后 rank 0 汇总"会漏掉数据：各卡只见到自己的分片。正确流程见程序 A 的 `evaluate`：各卡算局部 batch 的指标 → `dist.all_gather` 同步每个 batch 的结果 → 汇总。要点：
- `all_gather` 要求各卡 tensor **形状一致**，评测 loader 也要 `drop_last=True` 或手动 pad；
- 生成类任务（图文生成、VQA 文本输出）各卡答案长度不同，用 `dist.all_gather_object` 传 Python 对象；
- 评测与训练交错时先 `dist.barrier()` 防止一卡在训练另一卡在评测。

**坑 5：混合精度在视觉塔的数值稳定性**
- fp16 只有 5 位有效指数位（最大 65504），视觉塔激活范围大（大 logits、大位置编码），`softmax` 前溢出为 inf → 梯度 NaN；
- 解法按优先级：① 用 bf16（范围同 fp32，几乎零踩坑，A100/H100 原生支持）；② 必须 fp16 时，LayerNorm/RMSNorm/对比 logits 保持 fp32（`torch.autocast` 默认已自动），并配 `GradScaler`（初始 loss_scale 可调低如 2^10）；③ 观察 `scaler.get_scale()` 频繁减半说明溢出不收敛，改用 bf16 或降学习率；
- 视觉塔权重常保持 fp32 主副本（AdamW 本就有），只让激活走 fp16。

**坑 6：长序列（多图/视频）的序列并行（SP）**
多图/视频输入 token 可达 1 万+，单卡激活爆掉，此时 TP 不够用——因为 attention 计算量 $\propto N^2$，得沿序列维切分：**序列并行（Sequence Parallel）/ 上下文并行（Context Parallel）**。主流实现：Megatron-LM SP（与 TP 组合，对 attention 的 QKV 投影做 all-to-all 切分）、DeepSpeed Ulysses、Ring Attention（分块循环注意力，支持无限序列）。多模态工程里：视频帧打包成超长序列训练时建议先开 SP + gradient checkpointing，再考虑降分辨率。

## 五、优缺点

| 优点 | 缺点 |
| --- | --- |
| 视觉塔小/冻结时 DDP 方案简单可靠，与纯文本 LLM 工程无缝复用 | 激活 + KV cache 被视觉 token 数放大，显存画像复杂、难预估 |
| 决策表清晰：按"视觉塔规模 × LLM 规模"选型，很少需要堆到 3D 并行 | 大视觉塔（6B 级）配小 LLM 时并行粒度别扭，TP/SP 都要定制 |
| 冻结视觉塔 + 缓存特征后训练成本接近纯文本微调 | 多模态数据（图像/视频）解码与预处理是 CPU 瓶颈，需专门治理 |
| 分布式评测 all_gather 模式统一、易复用 | 多卡 shape 一致性约束多（动态分辨率、变长文本），collate 要严格 |
| no_sync 梯度累积兼容，等效大 batch 自由 | bf16 不支持的旧卡上，视觉塔 fp16 数值不稳定是持续的坑 |
## 六、与同类对比

**并行方案横评（多模态视角）**：

| 方案 | 单卡显存 | 通信量 | 多模态适配性 | 典型场景 |
| --- | --- | --- | --- | --- |
| DDP | 每卡全量副本 | 每步 1 次 AllReduce | 视觉塔小/冻结时最省事 | 视觉塔 <1B、LLM ≤7B |
| FSDP | 权重/梯度/优化器分片 | 前向 AllGather + 反向 ReduceScatter（约为 DDP 2~3 倍） | 天然适配"一大一小"双塔，InternVL 首选 | 大视觉塔 4B+ |
| TP | 参数切分到单卡装下 | 每层多次小 AllReduce | 长序列需叠加 SP | 70B+ LLM 端 |
| PP | 每卡一段层 | 仅层边界通信 | 与视觉塔分层划分耦合复杂 | 超大模型，训练稳定性要求高 |
| 3D (DP+TP+PP) | 综合最优 | 综合 | 依赖 Megatron/ColossalAI 框架 | 70B+ 全量训练 |
| 序列并行 SP | 激活按序列维分摊 | all-to-all（每层 2 次） | **多图/视频长序列专属** | 上万 token 输入 |

**与纯文本分布式训练的工程差异**（一句话版）：纯文本调"参数量"，多模态调"序列长度"——同样的卡数，多模态更早撞上激活/KV 墙，更依赖 SP 与 checkpointing，而并行框架本身的选型反而更宽。
## 七、高频面试问答

**Q1：多模态训练怎么分卡？**
看"视觉塔规模 × LLM 规模"：视觉塔小（<1B）或冻结 → DDP/FSDP；视觉塔大（InternViT-6B）→ FSDP + TP/SP；LLM 70B+ → 3D 并行。核心约束是显存画像：激活和 KV cache 由视觉 token 数支配，序列长优先 SP + gradient checkpointing。

**Q2：视觉塔冻结时 DDP 报"参数未使用"怎么办？**
先 `requires_grad_(False)` 再包 DDP（首选，零开销）；若仍有 requires_grad=True 的参数没收到梯度（detach、条件分支），开 `find_unused_parameters=True`（代价：每次反向多一次图遍历，稍慢）或按"构造参数列表"的方式只把可训练子模块放进 DDP 反向路径。注意冻结参数本就不该进优化器。

**Q3：图文数据加载慢怎么办？**
三步走：① `num_workers=4~16` + `pin_memory=True`，解码全移到 worker；② 离线预处理（缩图存储/WebDataset），把大图解码从训练路径挪走；③ 视觉塔冻结时直接缓存全库图像 embedding，训练只 load 向量。定位用 profiler 看 CPU 队列时间。

**Q4：多卡评测怎么做？**
各卡用自己的数据分片算局部指标，`dist.all_gather` 把每个 batch 的指标同步到 rank 0 汇总（形状必须一致，评测 loader 也 `drop_last=True`）；生成类异构输出用 `dist.all_gather_object`；评测前 `dist.barrier()` 对齐阶段。

**Q5：梯度累积和 DDP 怎么配合？**
中间步包 `model.no_sync()` 只攒梯度不通信，最后一步触发一次 AllReduce，把 N 步通信压成 1 次；loss 先除以 `accum_steps` 等价于全局大 batch。同时 `sampler.set_epoch(epoch)` 每轮必须调用。

**Q6：视觉塔用 fp16 为什么容易 NaN，怎么办？**
fp16 指数位只有 5 位，大 logits/激活溢出为 inf。优先换 bf16（范围同 fp32）；必须 fp16 时 LayerNorm/对比 logits 保持 fp32、配 GradScaler、观察 loss_scale 是否频繁减半。

**Q7：一张图上千 token，显存装不下怎么办？**
四个方向按性价比：① gradient checkpointing（激活不存，反向重算）；② 序列并行（沿 token 维切分，Ring Attention 等）；③ 降低视觉 token 数（更大 patch、去冗余 token、视觉压缩层）；④ FSDP 分权重 + 更小 batch + 梯度累积。

**Q8：InternVL 这种大视觉塔（6B）+ 小 LLM 怎么训？**
典型配置：视觉塔 FSDP 分片（前向 AllGather 取回）、LLM 端可 TP/SP，两段独立配置；预训练阶段冻结视觉塔只训投影层，对齐阶段再解冻低学习率微调。

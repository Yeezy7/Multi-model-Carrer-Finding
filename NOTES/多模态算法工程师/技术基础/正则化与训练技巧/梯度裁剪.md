# 梯度裁剪（Gradient Clipping）

> 本模块索引见 [正则化与训练技巧详解](正则化与训练技巧详解.md)

## 一、定义与公式

梯度裁剪指在**反向传播之后、参数更新之前**，对梯度做限制，防止梯度范数过大导致一步更新把参数推出稳定区域（训练崩溃）。

### 1.1 全局范数裁剪（Global Norm Clipping，主流）

把所有参数的梯度拼接成一个向量 $g = [g_1, g_2, \dots, g_n]$，计算全局 L2 范数：

$$\|g\|_2 = \sqrt{\sum_i \|g_i\|_2^2} = \sqrt{\sum_{i,j} g_{i,j}^2}$$

超过阈值时按同一比例缩放所有梯度：

$$g_i' = g_i \cdot \min\left(1, \frac{\text{max\_norm}}{\|g\|_2}\right)$$

**推导**：缩放目标是把范数压到 max_norm。令 $g' = c \cdot g$，要求 $\|g'\|_2 \le \text{max\_norm}$：

$$\|c g\|_2 = c \|g\|_2 \le \text{max\_norm} \Rightarrow c \le \frac{\text{max\_norm}}{\|g\|_2}$$

同时要求不放大梯度（$c \le 1$），所以 $c = \min(1, \text{max\_norm}/\|g\|_2)$。范数超限时整体缩放、不超限时原样不动。

### 1.2 按值裁剪（Value Clipping）

$$\tilde{g}_{i,j} = \text{clamp}(g_{i,j}, -\alpha, \alpha)$$

每个元素独立 clamp 到 $[-\alpha, \alpha]$，只限制单值大小，**丢失了整体范数信息**：个别异常值被截断，但整体范数可能仍然很大（许多元素都接近 $\alpha$ 时）。

| 方式 | 公式 | 特点 |
|------|------|------|
| 全局范数裁剪 | $g' = g\min(1, \frac{M}{\|g\|})$ | **主流**；保持各层梯度相对比例 |
| 按值裁剪 | $g' = \text{clamp}(g, -\alpha, \alpha)$ | 只限单值；破坏层间比例 |
| 逐参数范数裁剪 | 每层独立算范数再缩放 | 会破坏层间梯度比例，不推荐 |

## 二、核心原理

### 2.1 为什么 Transformer 必须做梯度裁剪（必考）

1. **注意力机制本身放大梯度**：attention logits 是 $QK^\top/\sqrt{d_k}$，序列长时 softmax 趋近 one-hot，其梯度幅度随输入幅值增长；深层叠加后梯度范数失控；
2. **偶发大 loss 产生巨大梯度**：难样本、数值异常（如 log(0)）、长尾任务中 loss 尖峰 → 一次 step 就把参数推出稳定区域；
3. **loss 暴涨后的自愈能力**：裁剪后即便出现 outlier loss，更新也被限制在安全半径内，训练能自己"缓过来"（下一 batch 正常）。

> 记忆点：**梯度裁剪不是正则化**——它不改变损失的期望、不提升泛化，是**数值稳定性措施**，让训练"不崩"。

### 2.2 梯度爆炸的机理（可视化）

```python
# 全局范数随"单层梯度放大"的增长示意
import torch

def softmax_grad_scale(seq_len, T=5):
    """softmax 在接近 one-hot 时的梯度幅度随深度累积示意"""
    scale = 1.0
    for _ in range(T):
        scale *= seq_len ** 0.5   # 每层 logit 量级放大（示意）
    return scale

print(softmax_grad_scale(64))   # 64^2.5 ≈ 32768：深 Transformer 梯度量级爆炸
```

### 2.3 裁剪阈值的选择

| 场景 | max_norm 常用值 |
|------|----------------|
| BERT 系预训练/微调 | 1.0 |
| LLM 微调（LLaMA 系） | 1.0 |
| 稳定微调（数据噪声大） | 0.5~1.0 |
| 数据干净的小任务 | 可放宽到 5.0 |

**监控建议**：记录裁剪前的 `total_norm`。若频繁触发裁剪（总被缩到 0.5 以下），说明 lr 偏大或数据有 outlier——应降 lr，而不是一味调大 max_norm。

## 三、源码实现

### 3.1 手写全局范数裁剪（含推导验证）

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

def clip_grad_norm_manual(parameters, max_norm=1.0):
    """手写全局范数裁剪：与 torch.nn.utils.clip_grad_norm_ 等价
    注意：parameters 是生成器，必须先物化成列表再遍历两次"""
    params = [p for p in parameters if p.grad is not None]
    total_norm = 0.0
    for p in params:
        total_norm += p.grad.detach().pow(2).sum().item()   # Σ‖g_i‖₂²
    total_norm = total_norm ** 0.5                          # ‖g‖₂
    clip_coef = max_norm / (total_norm + 1e-6)              # max_norm / ‖g‖
    clip_coef = min(1.0, clip_coef)                         # 超限才缩放
    for p in params:
        p.grad.detach().mul_(clip_coef)                     # g' = c·g
    return total_norm

model = nn.Linear(8, 2)
x, y = torch.randn(4, 8), torch.randn(4, 2)
loss = F.mse_loss(model(x), y)
loss.backward()
n1 = clip_grad_norm_manual(model.parameters(), max_norm=1.0)
print(f"裁剪前范数: {n1:.4f}")              # 如 2.8842
print(f"裁剪后范数: {sum(p.grad.pow(2).sum().item() for p in model.parameters()) ** 0.5:.4f}")  # ≤1.0
```

### 3.2 手写 vs 官方 clip_grad_norm_ 对比验证

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

def make_grads():
    torch.manual_seed(42)                 # 每次构造相同数据与梯度
    m = nn.Linear(8, 2)
    F.mse_loss(m(torch.randn(4, 8)), torch.randn(4, 2)).backward()
    return m

m1, m2 = make_grads(), make_grads()
n_manual = clip_grad_norm_manual(m1.parameters(), max_norm=0.5)
n_off = torch.nn.utils.clip_grad_norm_(m2.parameters(), max_norm=0.5)

g1 = torch.cat([p.grad.flatten() for p in m1.parameters()])
g2 = torch.cat([p.grad.flatten() for p in m2.parameters()])
print(n_manual, n_off)                       # 裁剪后范数一致（如 2.2153 / 2.2153）
diff = (g1 - g2).abs().max().item()
print(f"最大逐元素差异: {diff:.2e}")           # 如 2.98e-08（仅浮点求和顺序差异，可忽略）
```

> **注意**：官方 `clip_grad_norm_` 返回裁剪前的 total_norm；小浮点差异来自求和顺序，可忽略。

### 3.3 官方接口与训练循环中的标准用法

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

model = nn.Linear(8, 2)
opt = torch.optim.AdamW(model.parameters(), lr=1e-3)

def train_step(x, y, max_norm=1.0):
    opt.zero_grad()
    loss = F.mse_loss(model(x), y)
    loss.backward()
    total_norm = torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm)
    opt.step()
    return loss.item(), total_norm

loss_v, norm_v = train_step(torch.randn(4, 8), torch.randn(4, 2))
print(f"loss={loss_v:.4f}, grad_norm={norm_v:.4f}")   # 如 loss=1.23, grad_norm=0.30
```

### 3.4 按值裁剪 clip_grad_value_（何时用）

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

model = nn.Linear(8, 2)
F.mse_loss(model(torch.randn(4, 8)), torch.randn(4, 2)).backward()
# 按值裁剪：只对每个元素 clamp，通常用于"单值异常"而非范数爆炸
torch.nn.utils.clip_grad_value_(model.parameters(), clip_value=0.5)
print(max(p.grad.abs().max().item() for p in model.parameters()))  # ≤ 0.5，如 0.5

# 选型：范数爆炸（Transformer 标配）→ clip_grad_norm_；
#      FP16 下个别元素 inf/NaN 前兆 → clip_grad_value_ 临时止血
```

### 3.5 与 AMP（GradScaler）配合的正确顺序（高频事故）

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
from torch.amp import GradScaler

model = nn.Linear(8, 2)
opt = torch.optim.AdamW(model.parameters(), lr=1e-3)
scaler = GradScaler("cuda")                  # 无 CUDA 环境自动降级为 no-op

def train_step_amp(x, y):
    opt.zero_grad()
    with torch.autocast(device_type="cuda", dtype=torch.float16):
        loss = F.mse_loss(model(x), y)
    scaler.scale(loss).backward()
    scaler.unscale_(opt)                       # ★ 1. 先反缩放（真实梯度）
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)   # ★ 2. 再裁剪
    scaler.step(opt)                           # ★ 3. 再 step
    scaler.update()
    return loss.item()

print(train_step_amp(torch.randn(4, 8), torch.randn(4, 2)))  # 如 1.18
```

> **为什么顺序不能反**：AMP 下梯度被 GradScaler 放大了 scale 倍（如 65536），若直接裁剪，等效 max_norm 被放大了 65536 倍，裁剪形同虚设；必须先 `unscale_` 得到真实梯度再裁。

### 3.6 梯度累积场景

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

model = nn.Linear(8, 2)
opt = torch.optim.AdamW(model.parameters(), lr=1e-3)
accum_steps = 4
opt.zero_grad()
for i in range(accum_steps):
    loss = F.mse_loss(model(torch.randn(4, 8)), torch.randn(4, 2)) / accum_steps
    loss.backward()                           # 梯度累加中不裁剪
torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)  # ★ 累积完成后再裁
opt.step()
print("accum + clip + step 完成")
```

## 四、深入分析

### 4.1 裁剪为什么保持"方向不变"

全局范数裁剪是**乘一个标量** $c \in [0,1]$：梯度方向 $g/\|g\|$ 完全不变，只是步长变小。这保证了：裁剪不改变"优化方向"，只限制"更新半径"——因此是数值稳定措施而非正则（不改变最优解）。

### 4.2 三种裁剪的数学对比

| 方法 | 更新形式 | 保持方向 | 保持层间比例 | 主要用途 |
|------|---------|---------|-------------|---------|
| 全局范数 | $g \cdot \min(1, M/\|g\|)$ | ✅ | ✅ | Transformer/LLM 标配 |
| 按值 | $\text{clamp}(g, -\alpha, \alpha)$ | ❌（非线性） | ❌ | FP16 个别 inf 止血 |
| 逐层范数 | 每层独立缩放 | ✅（层内） | ❌ | 少用，可能层间失衡 |

### 4.3 对损失景观的解释

不妨设参数更新 $\Delta \theta = -\eta g'$，裁剪后 $\|\Delta\theta\| \le \eta \cdot M$。即便当前点处于"悬崖"（loss 剧烈变化区域），每一步最多走 $\eta M$ 距离，参数不会一步跨出稳定区域。这与"信任域"思想同源：裁剪等价于一个简易的信任域约束。

### 4.4 高频故障模式与诊断

| 现象 | 诊断 | 处理 |
|------|------|------|
| total_norm 持续指数级增长 | lr 过大 / 数据有 NaN | 降 lr，查数据 |
| total_norm 频繁 == max_norm | lr 偏大 / outlier 多 | 降 lr，而非加大 max_norm |
| 裁剪后 loss 仍 NaN | FP16 溢出（先 unscale？） | 检查 AMP 顺序、换 BF16 |
| 裁剪后 loss 不降 | 梯度方向本身错（数据错位） | 裁剪治标不治本，查前向/数据 |

## 五、优缺点

| 优点 | 缺点 |
|------|------|
| 一行代码，Transformer/LLM 训练标配 | 不是正则化，不提升泛化 |
| 防止偶发大 loss 一步崩盘，训练自愈 | 频繁裁剪会拖慢收敛（更新被限制） |
| 保持梯度方向与层间比例 | 阈值需监控调参 |
| 与 AMP/梯度累积天然配合 | 掩盖真实问题（lr 过大、数据异常） |

## 六、与同类对比

| 方法 | 限制对象 | 是否改变方向 | 目的 | 关系 |
|------|---------|------------|------|------|
| 全局范数裁剪 | 全部梯度范数 | 否 | 数值稳定 | 基准方法 |
| 按值裁剪 | 单元素幅值 | 是 | 单值止血 | 降级备选 |
| 梯度累积 | 更新频率 | 否 | 显存受限等效大 batch | 与裁剪叠加使用 |
| weight decay / L2 | 参数范数 | 否 | 正则、泛化 | **目标不同**：裁剪防崩、衰减防过拟合 |
| lr 调度 | 更新步长（全局） | 否 | 收敛 | 与裁剪互补：裁剪防单步过冲 |

> **关键区分（面试）**：裁剪限制**梯度**（每步），weight decay 限制**参数**（长期）；裁剪解决"数值崩溃"，L2/weight decay 解决"泛化"。两者目的不同、可叠加。

## 七、高频面试问答

**Q1：梯度裁剪的公式？为什么是 min(1, max_norm/‖g‖)？**
令 $g'=cg$，要求 $\|g'\|_2 \le M$ 且不放大梯度：$c \le M/\|g\|_2$ 且 $c\le1$，故 $c = \min(1, M/\|g\|)$。范数超限整体等比缩放，不超限不动。

**Q2：为什么 Transformer 必须做梯度裁剪？**
attention logits 随序列/深度放大导致梯度范数易爆炸；偶发大 loss（难样本、数值异常）一步就可能把参数推出稳定区。裁剪限制更新半径，让训练"崩了能自愈"。

**Q3：全局范数裁剪和按值裁剪的区别？**
全局范数裁剪整组缩放、保持方向与层间比例（主流）；按值裁剪对每个元素独立 clamp，只限制单值、破坏层间比例（FP16 个别异常止血用）。

**Q4：裁剪应该在什么时候做？与 AMP 的配合顺序？**
backward 后、optimizer.step 前；AMP 下必须**先 unscale 再裁剪再 step**——否则裁剪作用于被放大 65536 倍的梯度，形同虚设。

**Q5：梯度裁剪是正则化吗？**
不是。裁剪不改变损失的期望与最优解，只是限制单步更新半径，是数值稳定性措施；想提升泛化要用 L2/weight decay/dropout。

**Q6：怎么判断 max_norm 设得合不合适？**
监控裁剪前的 total_norm：正常时梯度范数平稳波动、偶尔触发裁剪；频繁触发说明 lr 偏大或数据有 outlier，应降 lr 而非调大 max_norm。

**Q7：梯度累积场景下裁剪的时机？**
累积完成（攒够 N 个 micro-batch）后、optimizer.step 前裁剪一次；不要在每步 micro-batch 里裁剪，否则等效于对小梯度裁剪，大梯度被放掉。

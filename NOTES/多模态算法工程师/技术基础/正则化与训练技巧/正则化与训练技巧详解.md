## 一、过拟合的本质与诊断

### 1.1 什么是过拟合

过拟合（Overfitting）指模型在**训练集上表现好、在未见过的验证集/测试集上表现差**的现象。本质是模型把训练集中的**噪声、个别样本的特异性**也当成规律学进去了，导致学到的函数过于"曲折"，无法泛化。

> 一句话：**过拟合 = 拟合了信号 + 噪声，泛化能力被噪声透支。**

在多模态场景中，过拟合尤其常见于：

1. **数据量小**：微调 LLM/VLM 时常只有几千条图文对；
2. **模型容量大**：预训练大模型的参数量远超任务样本数；
3. **数据分布窄**：训练集只覆盖少量视觉风格/语言模板，验证集一换风格就掉点。

### 1.2 偏差-方差权衡（Bias-Variance Tradeoff）

模型误差可分解为三部分：

$$\text{Error} = \text{Bias}^2 + \text{Variance} + \text{Irreducible Error}$$

| 项 | 含义 | 对应状态 |
|----|------|---------|
| Bias（偏差） | 模型平均预测与真实值的差距 | 欠拟合：模型太弱，学不到规律 |
| Variance（方差） | 不同训练集上学到的模型之间的波动 | 过拟合：模型对训练集太敏感 |
| Irreducible Error | 数据本身的噪声上限 | 无法消除 |

**偏差与方差的矛盾**：模型容量 ↑ → 偏差 ↓ 但方差 ↑；模型容量 ↓ → 方差 ↓ 但偏差 ↑。正则化的本质就是**用可控的偏差增加（约束模型）换取方差的大幅下降**。

| 状态 | 现象 | 手段 |
|------|------|------|
| 高偏差（欠拟合） | 训练/验证 loss 都很高 | 加大模型、加数据、降正则 |
| 高方差（过拟合） | 训练 loss 低、验证 loss 高 | 加正则、加数据、早停、dropout |
| 噪声上限 | 两者都高且无法下降 | 检查数据标注质量 |

### 1.3 训练/验证 Gap 与验证曲线判断

**训练-验证 gap**：训练 loss 与验证 loss 的差距。gap 持续拉大 = 模型在"死记"训练集。

验证曲线的标准判断逻辑：

| 曲线形态 | 诊断 | 处理 |
|----------|------|------|
| 训练 loss 降，验证 loss 也降 | 健康，继续 | 保持当前策略 |
| 训练 loss 降，验证 loss 持平 | 过拟合初期 | 加正则 / 早停 |
| **训练 loss 降，验证 loss 升** | **典型过拟合** | 立即停训，降低容量或加正则 |
| 训练 loss 不降，验证 loss 也不降 | 欠拟合 / lr 太小 / 模型bug | 调 lr、加容量 |
| 训练 loss 震荡不收敛 | lr 过大 / warmup 不足 | 降 lr、加 warmup |

> **经典判据（必背）**：过拟合的三个信号 —— ① 训练 loss 降而验证 loss 升（拐点出现）；② train-val gap 持续扩大；③ 验证集上模型输出置信度极端（如 0.999 且全错）。

### 1.4 过拟合与其他异常的鉴别（面试加分）

| 现象 | 可能原因 | 与过拟合的区别 |
|------|---------|---------------|
| 验证 loss 先降后升 | 过拟合 | —— |
| 验证 loss 一步到位很高 | 数据泄漏 / 预处理不一致 | 从第一个 epoch 就高 |
| 验证 loss 周期性暴涨 | 验证集含 OOD 样本 / eval bug | 周期性而非趋势性 |
| 验证 loss 抖动剧烈 | 验证集太小 / 未固定 eval 种子 | 波动而非趋势性上升 |

**判断过拟合的黄金流程**：先确认训练 loss 在下降（排除欠拟合与 bug），再看验证 loss 是否出现"先降后升"的拐点。**训练 loss 都不降，讨论过拟合没有意义。**

## 二、参数正则化（Parameter Regularization）

### 2.1 L2 正则（权重衰减，Weight Decay）

在损失函数上加上权重平方和：

$$L = L_0 + \frac{\lambda}{2} \|w\|_2^2 = L_0 + \frac{\lambda}{2} \sum_{i} w_i^2$$

梯度更新时多出一项：

$$\frac{\partial L}{\partial w} = \frac{\partial L_0}{\partial w} + \lambda w$$

使用 SGD 更新（学习率 $\eta$）：

$$w_{t+1} = w_t - \eta\left(\nabla L_0(w_t) + \lambda w_t\right) = \underbrace{(1 - \eta\lambda)}_{衰减因子} w_t - \eta \nabla L_0(w_t)$$

**每个 step 都会把权重按 $(1-\eta\lambda)$ 向零方向"缩"一点**——这就是"权重衰减"名字的由来。

#### 为什么小权重泛化好？

1. **函数更平滑**：权重小 → 输出对输入变化的敏感度低 → 决策边界平滑，对输入扰动不敏感；
2. **抑制高次特征**：在多项式拟合视角下，小权重压低高阶项，函数复杂度下降；
3. **解的偏好**：L2 在多个等价解中偏好"范数最小"的那个，防止某些维度过大垄断损失。

> 贝叶斯视角：L2 等价于给权重加**零均值高斯先验** $w \sim \mathcal{N}(0, \sigma^2)$，MAP 估计即带 L2 的损失。

#### L2 正则与 AdamW 的区分（与优化器模块联动，必考）

**问题核心**：L2 正则 + Adam 不等价于权重衰减！Adam 的更新 $\theta \leftarrow \theta - \eta \frac{\hat{m}}{\sqrt{\hat{v}} + \epsilon}$ 中**各项更新量被二阶动量归一化**；若把 $\lambda w$ 加进梯度，梯度也被 $\sqrt{\hat{v}}$ 归一化 → 大权重处衰减被压小、小权重处被放大，**衰减不均匀、与学习率耦合，效果显著变差**。权重衰减（decoupled weight decay）直接把 $(1-\eta\lambda)$ 乘在 $\theta$ 上，**不经过二阶动量归一化**，每个参数按同一比例衰减。

| 方法 | 做法 | 与 Adam 配合 |
|------|------|-------------|
| L2 正则 | 梯度里加 $\lambda w$ | 衰减被 $\sqrt{\hat{v}}$ 扭曲，效果差 |
| 权重衰减 | 更新时直接乘 $(1-\eta\lambda)$ | 衰减均匀，效果好 |

> **记忆点**：AdamW = Adam + 解耦权重衰减。预训练/微调大模型（LLM/VLM）现在全部用 AdamW，几乎不用带 L2 的 Adam。实现上 PyTorch 里 `weight_decay` 参数传 0.01~0.1 即对应 $\lambda$。

### 2.2 L1 正则（稀疏性）

$$L = L_0 + \lambda \|w\|_1 = L_0 + \lambda \sum_{i} |w_i|$$

梯度（次梯度）：

$$\frac{\partial L}{\partial w_i} = \frac{\partial L_0}{\partial w_i} + \lambda \cdot \text{sign}(w_i)$$

特点：

1. **稀疏解**：大量权重被推成**精确的 0**（不是接近 0），可用于特征选择、压缩模型；
2. **对不可微点**：$w_i = 0$ 处用次梯度，实现上阈值收缩（proximal）更常用。

#### L1 vs L2 的几何直觉（菱形 vs 圆，必考）

把损失函数等高线与约束画在二维参数平面上：最优解是等高线与约束区域的**首次相切点**。

- **L2 约束** $\|w\|_2 \le C$：圆形区域，相切点一般在坐标轴上概率为 0（需要切点法线恰好对齐坐标轴），通常只是**缩小**权重、很少到 0；
- **L1 约束** $|w_1| + |w_2| \le C$：菱形区域，**角点**恰好落在坐标轴上，等高线很容易碰到角点 → 该维度权重正好为 0 → 稀疏解。

| 维度 | L1 | L2 |
|------|-----|-----|
| 约束形状 | 菱形（$L_1$ 球） | 圆（$L_2$ 球） |
| 解特性 | 稀疏（权重为 0） | 平滑收缩（权重接近 0 但非 0） |
| 梯度 | 常数（sign），不随大小衰减 | 随权重线性衰减，越接近 0 推得越轻 |
| 典型用途 | 特征选择、稀疏化剪枝 | 默认通用正则 |
| 唯一性 | 非唯一（角点可能多个） | 唯一（凸、平滑） |
| 大模型场景 | 几乎不用（稀疏化收益低） | **默认标配（AdamW weight_decay）** |

> **实际提醒**：大模型训练里 L1 几乎没人用（破坏预训练权重分布、收敛不稳），主流就是 AdamW 的 weight decay + Dropout + 数据增强。L1 主要在传统 ML、稀疏模型（如稀疏 MoE 路由正则化）里出现，面试考理论、工程用 L2。

## 三、Dropout（重点，必考）

### 3.1 原理：随机丢弃神经元，防止"共适应"

训练时每个 forward 以概率 $p$（keep 概率）随机保留神经元，以 $1-p$ 丢弃：

$$r_j \sim \text{Bernoulli}(p), \qquad \tilde{y}_j = r_j \cdot y_j$$

其中 $y_j$ 是第 $j$ 个神经元的输出。本质是**每次训练都在采样一个"瘦子网络"的子结构**。

为什么有效（三条主线，面试必须展开）：

1. **打破共适应（Co-adaptation）**：神经元无法依赖"某个特定神经元总是存在"，被迫各自学到更独立、更鲁棒的特征（注意力头不能互相抄答案）；
2. **隐式集成（Ensemble）**：每个 batch 训练的都是一棵不同的子网络，$2^n$ 个子网共享权重，推理时用全部神经元等价于**几何平均集成**这些子网；
3. **数据增强视角**：随机丢弃等价于对隐藏特征空间做随机扰动，让特征对局部缺失鲁棒。

> 面试一句话总结：**Dropout 通过在训练时随机屏蔽神经元，防止神经元之间"串通"（共适应），迫使网络学到冗余且独立的特征，并在推理时以集成的方式使用所有特征。**

### 3.2 训练与推理行为的差异

| 阶段 | 行为 | 原因 |
|------|------|------|
| 训练 | 随机丢弃神经元 | 引入随机性、防共适应 |
| 推理（eval） | **不丢弃，全部保留** | 确定性输出；保留全部等价于对所有子网络做集成 |

> **工程铁律**：`model.train()` 开 dropout，`model.eval()` 关 dropout；`no_grad` 不管 dropout！推理忘了 `eval()` 会导致结果随机抖动——这是多模态模型部署/评测的经典事故。

### 3.3 Inverted Dropout（为什么缩放 1/(1-p)）

直接丢弃有个问题：训练时输出期望 $E[\tilde{y}] = p \cdot y$，与推理时的 $y$ **不一致**（相差 $p$ 倍），导致训练/推理语义漂移。

**Inverted Dropout**（主流实现）在训练时把保留的输出放大 $1/p$：

$$\tilde{y}_j = \frac{r_j}{p} \cdot y_j, \qquad E[\tilde{y}_j] = \frac{p \cdot y_j}{p} = y_j$$

- 训练时**期望输出与推理时完全一致** → 推理时**不用再缩放**，直接原样前向；

```python
# Inverted Dropout 实现
class InvertedDropout(nn.Module):
    def __init__(self, p=0.5):   # p 为保留概率
        super().__init__()
        self.p = p
    def forward(self, x):
        if self.training:
            mask = (torch.rand(x.shape, device=x.device) < self.p) / self.p
            return x * mask
        return x   # 推理不缩放
```

> 注意表述习惯：有的教程写"丢弃概率 p"，此时缩放系数是 $1/(1-p)$。**结论一致：训练除以保留概率，保证期望不变。**

### 3.4 Dropout 概率的选择

| 位置 | 常见值 | 说明 |
|------|--------|------|
| 输入层/Embedding | 0.1~0.2 | 输入噪声不宜过大，否则丢失信息 |
| 隐藏层（MLP/FFN） | 0.1~0.5 | 越大正则越强，也越阻碍拟合 |
| Attention 矩阵 | 0.0~0.1 | 见 3.6 |
| 预训练 / 微调 | 预训练 0.0~0.1；微调可调大 | 数据越多 dropout 越小；输出层前通常不加（防破坏校准） |

### 3.5 结构化 Dropout：DropBlock 与通道 Dropout

普通 dropout 逐元素独立丢弃，对**卷积网络无效**：卷积的感受野重叠，相邻像素信息可以"补位"，随机丢像素等于没丢。

| 方法 | 丢弃单位 | 原理 | 适用 |
|------|---------|------|------|
| 标准 Dropout | 单个激活值 | 逐元素伯努利 | MLP、Transformer FFN |
| **DropBlock** | 连续矩形块（block） | 丢弃感受野内成片的连续区域，防止信息绕过 | CNN、ViT 特征图 |
| **通道 Dropout** | 整个通道 | 丢弃整个 channel，`[N, C, 1, 1]` 广播 | CNN、ViT（CLIP 视觉塔微调常用） |
| **DropPath** | 整个子层（残差分支） | 以概率丢弃 attention/FFN 分支，训练深层 Transformer 的隐式正则 | ViT、ConvNeXt、Swin |

> DropBlock 的两个超参：块大小（block size）、丢弃率（$\gamma$），keep prob 做线性 warmup；DropPath 等价于"对随机深度网络做集成"，常配 stochastic depth。

### 3.6 Attention Dropout（注意力矩阵上的 Dropout）

对**注意力权重矩阵本身**做 dropout（softmax 之后）：

$$\text{Attn}(Q, K, V) = \text{Dropout}\left(\text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)\right) V$$

作用于 `[batch, num_heads, seq_len, seq_len]` 的注意力概率上，即**随机屏蔽某些 token 之间的注意力连接**。每个位置行的注意力概率和不再为 1（被随机置零并缩放），但期望上仍是 1；作用：**防止注意力分数过于集中于少数 token（注意力坍缩），鼓励注意力分布多样**。推理时同样关闭。

### 3.7 为什么 Attention Dropout 与 FFN Dropout 分开设置（必考）

Transformer 中每个 block 有两个独立 dropout 超参：`attention_dropout`（作用在注意力矩阵/softmax 后）与 `ffn_dropout`（作用在 FFN 隐藏层）。分开设置的原因：

1. **作用对象不同**：注意力 dropout 影响的是**信息路由**（哪些 token 交互），FFN dropout 影响的是**特征变换**（隐藏层表达）；
2. **敏感度不同**：注意力矩阵是概率分布，dropout 过大直接破坏注意力语义（路由混乱），**必须小**（0~0.1）；FFN 隐藏维是冗余的高维表达，dropout 空间大（0~0.5）；
3. **工程惯例**：BERT/ViT 用 `attention_probs_dropout_prob=0.1`、`hidden_dropout_prob=0.1`；LLM 系（LLaMA 等）微调常设 `attention_dropout=0`、`ffn_dropout=0.1`。

| 类型 | 作用位置 | 常用值 | 过大后果 |
|------|---------|--------|---------|
| attention dropout | softmax 后注意力矩阵 | 0~0.1 | 路由断裂、注意力分布被破坏 |
| FFN dropout | FFN 隐藏层激活 | 0.1~0.3（微调） | 拟合不足 |
| embedding dropout | 输入 embedding | 0.1~0.2 | 输入信息丢失 |

## 四、标签平滑（Label Smoothing）

### 4.1 公式

把 one-hot 标签改为"软标签"：真实类别概率 $1-\epsilon$，其余 $K-1$ 类均分 $\epsilon$：

$$q'(k) = \begin{cases} 1 - \epsilon + \frac{\epsilon}{K}, & k = y \\ \frac{\epsilon}{K}, & k \neq y \end{cases}$$

交叉熵损失变为：

$$L = -\sum_{k=1}^{K} q'(k) \log p(k) = -\left[(1-\epsilon)\log p(y) + \frac{\epsilon}{K}\sum_{k\neq y}\log p(k)\right]$$

其中 $K$ 是类别数，$\epsilon$ 是平滑系数（Transformer 中默认 0.1）。

```python
# Label Smoothing 实现（F.cross_entropy 自带 label_smoothing 参数）
loss = F.cross_entropy(logits, targets, label_smoothing=0.1)
```

### 4.2 为什么能防过拟合与校准（校准：calibration）

1. **防止过置信（overconfidence）**：one-hot 下模型为了把正类概率推到 1 会无限增大 logit 差，软标签给了模型"不必全对"的空间，logit 幅值受限；
2. **正则化/软化决策边界**：等价于对 logits 加"类间均匀"先验，让预测分布更平滑，抑制极端输出；
3. **对抗标注噪声**：错误标签的"可信度"被压低，对噪声鲁棒；
4. **改善校准（Calibration）**：softmax 输出与真实正确率更接近（ECE/可靠性图更好），对**多模态检索阈值**、**VQA 置信度过滤**、**RLHF 偏好模型**尤其重要。

### 4.3 Transformer 中的默认值与注意事项

| 模型/场景 | 默认 $\epsilon$ |
|-----------|---------------|
| Transformer (Vaswani et al., 2017) | 0.1（论文明确建议） |
| 图像分类 ResNet 系 | 0.1 |
| 蒸馏场景 | 常与温度缩放配合使用 |

> **记忆点**：BERT/Transformer 系论文默认 label_smoothing=0.1，实现里就是一行参数。

### 4.4 注意事项与边界

1. **对硬任务（噪声大）要谨慎**：平滑过度（$\epsilon > 0.3$）会让模型欠拟合，logits 幅度过小；
2. **推理时无需特殊处理**：软标签只影响训练损失，推理照常 argmax；
3. **对比学习（CLIP 系）不用 label smoothing**：目标是拉近正对、推远负对，标签是"对/不对"的二元关系而非类别分布，平滑定义不清；蒸馏时 teacher 软输出 + 平滑会双重软化，需谨慎。

## 五、数据增强（重点）

> 数据增强是**成本最低、收益最高**的正则化手段：不增加任何参数与推理开销，只增加训练数据多样性。对多模态模型，视觉和文本两侧都要做。

### 5.1 图像增强全家桶

| 方法 | 原理 | 适用/注意 |
|------|------|-----------|
| 水平翻转 | 左右镜像，利用对称先验 | 分类、检测通用；注意：文本、道路标志、人脸不宜 |
| 旋转/仿射 | 旋转、缩放、平移、错切 | 通用；大角度旋转对文字/OCR 不友好 |
| 随机裁剪（ResizeCrop） | 随机裁剪再 resize 到原尺寸 | **多模态双塔标配**（CLIP 用随机裁剪+翻转，因为图-文对尺度对齐） |
| 颜色抖动（ColorJitter） | 随机调整亮度/对比度/饱和度/色相 | 对"颜色敏感"任务（如色盲测试）慎用 |
| **MixUp** | 两张图按 $\lambda \sim \text{Beta}(\alpha,\alpha)$ 线性插值，标签也插值：$\tilde{x}=\lambda x_1+(1-\lambda)x_2$，$\tilde{y}=\lambda y_1+(1-\lambda)y_2$ | 分类通用；**不可用于对比学习**（破坏图-文对应关系） |
| **CutMix** | 把一张图的矩形块贴到另一张图上，标签按面积混合 | 分类、检测；保留局部结构，比 MixUp 更利于细粒度 |
| **RandAugment** | 从增强池随机采 $N$ 个变换、强度 $M$ 随机 | 无学习、零成本 AutoAugment 替代品 |
| **AutoAugment** | 用强化学习/搜索学习"增强策略概率表" | 需搜索成本；效果好但策略与数据集绑定 |

**CutMix 标签**（按面积比例混合）：$\tilde{y} = \frac{|B|}{|x|} y_j + \left(1-\frac{|B|}{|x|}\right) y_i$

> 面试常问：**MixUp vs CutMix** —— MixUp 整图线性混合（图像可能"鬼影"），CutMix 保留局部语义（贴块）；CutMix 在 ImageNet 上更优，且对检测/分割有 soft label 形式的扩展。

### 5.2 文本增强

| 方法 | 原理 | 说明 |
|------|------|------|
| 回译（Back Translation） | 译成另一语言再译回来，生成语义相同的平行文本 | 质量高，成本高（需翻译模型） |
| 同义词替换 | 按词性/语义替换同义词（WordNet 等） | 便宜；注意多义词陷阱 |
| 噪声注入 | 拼写错误、字符替换、方言化 | 适合鲁棒性训练（ASR/OCR 文本） |
| 模板多样化 | 改写提问模板（"这张图里有什么？"→"请描述图片内容"） | **多模态数据（如 VQA 指令数据）必做** |

> 经验：文本增强要**轻**。LLM 已对噪声有先验，过强扰动会学坏语言模型本身；回译在双语可用时质量最高，模板多样化是 VLM 指令数据最有效的"增强"。

### 5.3 多模态特有增强

1. **图文对扰动（Image-Text Pair Augmentation）**：对图做裁剪/翻转时，**文本语义必须保持不变**（不能说"左半边的猫"）；随机裁剪对 CLIP 类模型尤其重要——它迫使模型从局部片段也能匹配文本；
2. **字幕重写（Caption Rewriting）**：用 LLM 把训练集字幕重写为多种风格/粒度（简短、详细、追问式），等价于文本侧多样性增强，是 LLaVA 数据配方的重要一环；
3. **负样本构造（数据采样而非增强）**：难负例挖掘——挑与正对相似的图文对做负样本，迫使模型学到细粒度判别（多模态检索训练核心技巧）；
4. **视频维度**：帧采样、抽帧率随机、时间裁剪（视频图文模型）；**多分辨率**：图像分块缩放（LLaVA AnyRes 切图），把"分辨率"当成增强维度。

> 原则（重要）：**多模态数据增强必须以"不破坏图-文对应关系"为底线。** 图像裁剪不能剪掉文本所指对象；文本改写不能改变图像能表达的内容。破坏对应关系的增强会直接污染对比学习目标。

## 六、EMA（指数滑动平均，重点）

### 6.1 公式

维护一组"影子权重"（shadow weights）$\theta_{ema}$，每个 step 用当前模型参数 $\theta$ 滑动更新：

$$\theta_{ema} \leftarrow \lambda \cdot \theta_{ema} + (1 - \lambda) \cdot \theta$$

- $\lambda$ 为衰减系数，典型 0.99（短期平均）~ 0.999（长期平均），大模型微调常用 0.9999；
- $\theta_{ema}$ 初值取 $\theta_0$；
- **EMA 权重不参与梯度计算，只被"平均"**。

### 6.2 为什么 EMA 权重效果更好

1. **参数空间平均（加权集成）**：相当于对训练轨迹上的多个模型做指数加权平均，是一个隐式的集成，集成模型方差更低、泛化更稳；
2. **平滑损失景观（对噪声梯度的高斯滤波）**：训练后期梯度含噪声，参数在损失景观的"凹坑"里震荡，EMA 加权平均让权重落在**更平坦（flat）的极小值区域**——平坦极小值对扰动不敏感、泛化更好，这是随机权重平均理论的核心直觉；
3. **缓解灾难性遗忘（微调场景）**：EMA 权重保留了旧知识的信息，微调 VLM 时能显著减少"灾难性遗忘"导致的通用能力下降。

> 直观理解：训练中权重像掷骰子一样跳来跳去，EMA 是这些骰子的加权平均；**单点可能踩坑，平均点更接近"真实解"。**
### 6.3 训练与评估时怎么用

**训练流程**：

1. 每个 step 优化器更新 $\theta$ 后，同步更新 $\theta_{ema}$；
2. **评估时用 $\theta_{ema}$，训练时用 $\theta$**（或评估时临时切换，评估完切回）；
3. 通常**只保存 EMA checkpoint**（或两者都存）作为最终发布模型。

```python
class EMA:
    def __init__(self, model, decay=0.999):
        self.model = model
        self.decay = decay
        self.shadow = {k: v.detach().clone() for k, v in model.state_dict().items()}
        self.backup = {}

    def update(self, model):
        for k, v in model.state_dict().items():
            self.shadow[k].mul_(self.decay).add_(v.detach(), alpha=1 - self.decay)

    def apply_shadow(self, model):
        self.backup = {k: v.clone() for k, v in model.state_dict().items()}
        model.load_state_dict(self.shadow)     # 切到 EMA 权重去评估

    def restore(self, model):
        model.load_state_dict(self.backup)     # 评估完切回训练权重
```

**注意事项**：

- EMA 一般不平均 buffer（如 BN 的 running_mean）；微调 VLM 时 LN 无 buffer、无 BN，直接整份 state_dict 平均也没问题；
- **warmup 阶段 $\lambda$ 要小**（或用 `decay = min(decay, (1+step)/(10+step))`），否则早期噪声参数被过分平均；
- 与梯度累积、AMP 兼容（EMA 只关心参数）；推理部署导出 EMA 权重即可。

### 6.4 常用 $\lambda$ 速查

| 场景 | $\lambda$ | 说明 |
|------|-----------|------|
| 短任务（分类微调） | 0.99~0.995 | 平均窗口短 |
| 长任务（预训练/大规模微调） | 0.999 | 常用 |
| LLM/VLM 微调 | 0.999~0.9999 | Qwen/LLaVA 类训练常设 0.9999 |
| 半监督/伪标签 | 0.999~0.9999 | Mean Teacher 类方法核心 |

> **面试记忆**：$\lambda=0.999$ 意味着每个新 step 只把影子权重向当前权重移动 0.1%，等效平均窗口约 $1/(1-\lambda)=1000$ 个 step。

## 七、梯度裁剪（Gradient Clipping）

### 7.1 公式

最常用的是**全局范数裁剪**（PyTorch `clip_grad_norm_`）：

$$\|g\|_2 = \sqrt{\sum_i \|g_i\|_2^2}, \qquad g_i' = g_i \cdot \min\left(1, \frac{\text{max\_norm}}{\|g\|_2}\right)$$

即：整组参数梯度范数超过阈值时，**按同一比例缩放**所有参数梯度；不超过则不动。

```python
# PyTorch 用法：backward 后、step 前
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
optimizer.step()
```

| 方式 | 做法 | 特点 |
|------|------|------|
| 全局范数裁剪 | 所有参数一起算范数，超限整体缩放 | **主流**；保持各层梯度相对比例 |
| 逐参数裁剪 | 每个参数独立 clamp | 会破坏层间梯度比例，不推荐 |
| 按值裁剪（clip_grad_value_） | 每个元素 clamp 到 $[-\alpha, \alpha]$ | 只限制单值大小；对"个别异常值"有效，但丢失范数信息 |

### 7.2 为什么 Transformer 必须做梯度裁剪

1. **梯度爆炸是注意力机制的固有风险**：attention logits 是 $QK^\top/\sqrt{d}$，序列长、logits 大时 softmax 接近 one-hot，其梯度幅度随输入幅值增长；深层叠加后范数失控；
2. **偶发大 loss 会产生巨大梯度**（难样本、数值异常），一次 step 就把参数推出稳定区域 → 训练崩；
3. **loss 暴涨后自动恢复**：裁剪后即便出现 outlier loss，参数更新也被限制在安全半径内，训练能自己"缓过来"。

### 7.3 工程细节

- `max_norm` 常用值：1.0（BERT 系）、1.0~5.0（LLM 微调常用 1.0）、0.5~1.0（稳定微调）；
- **裁剪在 backward 后、optimizer.step 前**；与 AMP 配合时**在 unscale 之后裁剪**（FP16 的梯度必须先反缩放成真实梯度再裁）；
- 可监控裁剪前的 `total_norm`：若频繁触发裁剪（总被缩到 0.5 以下），说明 lr 偏大或数据有 outlier，应降 lr 而非一味调大 max_norm；
- 梯度裁剪**不是正则化**：不影响损失的期望，它是**数值稳定性措施**，让训练"不崩"。

## 八、梯度累积（Gradient Accumulation）

### 8.1 原理与等效 batch

显存装不下大 batch 时，把一次大 batch 拆成 $N$ 个小 batch（micro-batch），**每个 micro-batch 都 forward+backward 但暂不更新参数，累加梯度**，攒够 $N$ 个后统一更新一次：

$$\text{等效 batch size} = \text{micro batch size} \times N$$

```python
accum_steps = 8
optimizer.zero_grad()
for i, batch in enumerate(loader):
    loss = loss_fn(model(batch), target) / accum_steps   # 平均，保证总 loss 尺度一致
    loss.backward()
    if (i + 1) % accum_steps == 0:
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        optimizer.step()
        optimizer.zero_grad()
```

注意点：

1. **loss 要除以 accum_steps**，否则等效 batch 变大时总梯度被放大 $N$ 倍，lr 相当于隐式放大；
2. 等价性：**在数学上精确等价于"一次性大 batch"**（只要 loss 是样本均值形式），梯度是线性可加的；
3. 与真大 batch 的细微差别：BN 统计量（见 8.3）、采样顺序、梯度裁剪时机。

### 8.2 与 AMP（混合精度）的配合

- loss 除以 accum_steps **要在 GradScaler.scale 之前**完成（scale 的是"除完之后"的 loss）；
- 每步照样 `scaler.scale(loss).backward()`；**optimizer.step() 前要 `scaler.unscale_()`（把累计的缩放梯度反缩放）→ 裁剪 → `scaler.step(optimizer)`**；
- 累积期间每步调用 `scaler.update()`（或在每个 micro-batch 后都过一遍 unscale/update 判定），保证 scale 因子随 inf/nan 正确调整。

```python
for i, batch in enumerate(loader):
    with torch.cuda.amp.autocast():
        loss = loss_fn(model(batch), target) / accum_steps
    scaler.scale(loss).backward()
    if (i + 1) % accum_steps == 0:
        scaler.unscale_(optimizer)                       # 先反缩放
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        scaler.step(optimizer)
        scaler.update()
        optimizer.zero_grad()
```

### 8.3 BN 在梯度累积下的注意点

梯度累积下**每个 micro-batch 都会单独更新 BN 的 running stats**（BN 在 forward 时就统计了，跟参数更新时机无关），所以等效 batch 变大**并不会**让 BN 统计量更准——想等效大 batch 的 BN 需用 SyncBN 或把统计也累积；micro-batch 太小（2~4）时 BN 统计噪声大，建议换 LN/GN。对 Transformer/VLM（全是 LN/RMSNorm）**无此问题**。

> 面试点：**梯度累积能等效"参数更新的 batch"，但不能等效 BN 的"统计 batch"**；LR scheduler 的 step 时机见 11.7。

## 九、混合精度 AMP（工程速览）

> 混合精度的基础原理（FP16 数值表示、GradScaler、loss scaling）在 PyTorch 基础模块已有详解，这里只讲训练工程中的关键点。

### 9.1 FP16 vs BF16

| 维度 | FP16 | BF16 |
|------|------|------|
| 指数位 / 尾数位 | 5 / 10 | 8 / 7 |
| 取值范围 | 最大 65504 | **与 FP32 相同（±3.4e38）** |
| 溢出风险 | 高（大数溢出、小数下溢） | 极低 |
| 是否需 loss scaling | 需要 | 不需要 |
| 硬件 | 老 GPU 即可 | Ampere（A100）及以上 |

### 9.2 为什么 BF16 稳（面试加分）

- FP16 只有 5 位指数 → 数值范围窄：激活/梯度超过 65504 直接变 inf，小于 6e-5 下溢为 0；
- **BF16 把指数位扩到 8 位（与 FP32 相同）** → 动态范围与 FP32 一致，**不会溢出**；
- 代价是尾数从 10 位降到 7 位（精度稍差），但对训练来说"范围远比精度重要"（梯度的量级跨度大，而精度损失被优化器的动量/二阶矩吸收）；
- 因此：**A100/H100 训练一律 BF16（无 loss scaling、无 inf 烦恼）；V100/3090 用 FP16 + loss scaling。**

### 9.3 FP16 + GradScaler 的工程要点

- **loss scaling 原理**：FP16 下反向传播的梯度常小于 6e-5（下溢为 0），先把 loss 乘上大数（如 65536），梯度同倍放大到可表示范围，更新前再除回去；GradScaler 自动调整 scale：发现 inf/nan 就丢弃该 step 并把 scale 减半，连续稳定则逐步放大；
- 什么时候容易溢出：长序列（梯度大）、大 lr、FP16 下没开 scaler、把 LN 的归约留在 FP16 里做；
- 技巧：LN/RMSNorm 的 mean/rsqrt 归约用 FP32 计算（LLaMA 等实现如此），归一化层参数保持 FP32；PyTorch 用 `torch.autocast(device_type='cuda', dtype=torch.bfloat16)` 一行切换 BF16。

## 十、训练曲线诊断（重点）

> 训练 90% 的时间在"看曲线"。以下清单按"最可能的 bug"排序。

### 10.1 loss 不降 / 震荡 / 暴涨排查清单

| 现象 | 按序排查 | 典型修复 |
|------|---------|---------|
| **loss 完全不降** | ① lr 太小 ② 数据没对齐（label 错位）③ 模型输出恒值 ④ loss 用错 | lr 从 3e-5 试到 3e-3；打印 logits 人工核对 |
| **loss 涨到 NaN** | ① 梯度爆炸 ② lr 过大 ③ FP16 溢出 ④ 数据里有 NaN ⑤ log(0) | 加梯度裁剪、降 lr、换 BF16、检查输入 |
| **loss 持续上升 / 震荡** | lr 过大或 warmup 缺失，参数被一步推飞；振幅过大则 batch 太小 | 降 lr / 加 warmup / 裁剪 / 加大 batch |
| **loss 降很快但验证不动** | 过拟合 / 模型在死记 | 检查过拟合三信号，加正则 |
| **loss 在某处平台不降** | 局部极小 / scheduler 到期 / 数据量不足 | 换 warm restart、降 lr |

### 10.2 梯度范数监控（plot grad norm 判断 lr）

**梯度范数是最重要的"看不见的曲线"**，每个 step 记录 `total_norm`：

| grad norm 行为 | 诊断 |
|----------------|------|
| 稳定在 $10^{-3}\sim10^{-1}$ 量级 | 健康 |
| 持续指数级增长 | lr 过大 / 梯度爆炸前兆，应立即降 lr |
| 总是触发裁剪（等于 max_norm） | lr 偏大或数据有 outlier |
| 数值极小（$<10^{-6}$）且 loss 不动 | 梯度消失 / 冻结层没解冻 / 初始化问题 |
| 突然 NaN | 数值崩坏，检查 FP16 / 数据 |

> 经验公式：**合适 lr 下，grad norm 应缓慢平稳波动；若 grad norm 一路向上，几乎必然是 lr 太大。** 微调时冻结塔的梯度恒为 0 属正常。lr 过小时 loss 曲线平滑但极慢、grad norm 偏小；lr 过大时 loss 前期下降快但随即震荡/暴涨甚至 NaN。
>
> **LR 扫描（lr finder）**：用小 batch 从头训练，lr 按指数从 1e-6 升到 1e-1，画 loss-lr 曲线，选"loss 下降最快且还没崩溃"处的 lr 作为峰值 lr。这是多模态微调选 lr 的标准做法。

### 10.4 前 100 步 Sanity Check（必做）

1. **过拟合单个 batch**：只喂 1~2 个 batch 反复训练，确认 loss 能降到接近 0（说明前向/反向/loss 链路正确）——这步不通过，后面全白搭；
2. **loss 量级 sanity**：第一 step 的 loss 应与随机初始化模型的期望值接近（如分类 logits 随机时 CE ≈ log(K)）；
3. **grad norm sanity**：第一 step 的 grad norm 有限且非零；
4. **eval 链路**：训练前先用随机权重跑一次 eval，确认指标计算无误；固定种子跑 2 次前 10 步，loss 应一致（排查非确定性操作）。

> 面试点：**"前 100 步 sanity check"是最值钱的训练习惯**——多数训练事故（数据错位、loss 用错、没梯度）在前 100 步内都会暴露，跑一整天再发现是最高代价的错误。

## 十一、训练技巧清单

### 11.1 Warmup（学习率预热）

$$\text{lr}_t = \text{lr}_{\min} + (\text{lr}_{\max} - \text{lr}_{\min}) \cdot \frac{t}{T_{\text{warmup}}}$$

- 目的：预训练权重已在稳定区域，冷启动时 Adam 的一阶/二阶动量还没建立，大 lr 会让第一步更新过大、破坏预训练特征；
- 常用：线性 warmup（数个百分点到 10% 的步数），配 cosine 衰减（LLM 标配）；Transformer 论文用平方根预热 $\text{lr} = d_{\text{model}}^{-0.5} \cdot \min(\text{step}^{-0.5}, \text{step} \cdot \text{warmup\_steps}^{-1.5})$。

### 11.2 LR 衰减（Scheduler）

| 策略 | 公式/行为 | 适用 |
|------|-----------|------|
| Step 衰减 | 每 $S$ 步 ×0.1 | 传统 CNN |
| Cosine | $\text{lr}_t = \frac{1}{2}\text{lr}_{\max}\left(1 + \cos(\pi \frac{t}{T})\right)$ | **LLM/VLM 微调标配** |
| Cosine with warmup | warmup + cosine | LLaMA/Qwen 系微调标准 |
| 循环（Warm Restart） | 周期重开大 lr | 超参搜索、局部极小逃逸 |

### 11.3 Early Stopping 与 Best Model 保存

- **判据**：监控验证指标，当验证 loss **连续 $P$ 个 epoch 不创新低**（patience）即停止；
- 三个停止信号：① 验证 loss 出现上升拐点（过拟合铁证）；② patience 耗尽；③ 训练预算用尽；
- **关键实践：不存"最后一步"的模型，永远存"验证集最好"的 checkpoint**，并在刷新 best 时顺手做一次 eval 日志；多模态评测优先用任务指标（CLIP 用 Recall@K / 分类 acc）而非 loss；与 EMA 配合时 EMA 权重免疫震荡，可放宽 patience。

### 11.4 模型平均：SWA 与 Stochastic Weight Averaging

- **SWA（随机权重平均）**：训练末期，把最后一段（如最后 10% 步）的权重直接算术平均，等价于逼近"平坦极小值"；
- 与 EMA 区别：EMA 是全程指数加权（每个 step 都参与），SWA 只对尾部均匀平均；
- 效果：收敛到更宽的极小值 → 测试提升 + 对损失景观更鲁棒；微调 CLIP 后 SWA 可再提 0.5~1 个点检索指标。

### 11.5 Warm Restarts（循环学习率）

$$\text{lr}_t = \text{lr}_{\min} + \frac{1}{2}(\text{lr}_{\max}-\text{lr}_{\min})\left(1 + \cos\left(\pi \frac{t \bmod T_i}{T_i}\right)\right), \quad T_i \text{ 随周期放大}$$

- 周期性地把 lr 拉高再降，帮助跳出局部极小；常用于超参不佳时的抢救、增量训练、few-shot 微调（周期短）；
- 代价：训练时间变长，LLM 大规模预训练不用（不稳定），微调场景可选。

### 11.6 冻结层分阶段训练（Stage-wise Training）

多模态微调的标准配方：

| 阶段 | 冻结 | 训练 | 典型场景 |
|------|------|------|---------|
| 1 | 视觉塔 + LLM | projector 对齐层 | LLaVA 对齐预训练 |
| 2 | 视觉塔 | LLM + projector | 指令微调（LLaVA-1.5 前） |
| 3 | 无（或 LN 解冻） | 全部或部分 LoRA | 高质量全量微调 |

- 冻结用 `requires_grad=False`，且**跳过其参数的 optimizer 组**（避免 weight decay 白算）；冻结 BN 层要置 eval 模式（无 BN 场景忽略）；
- **经验**：数据少时全解冻会灾难性遗忘 → 视觉塔冻结或只解冻最后几层 + 用 EMA + 小 lr。

### 11.7 梯度累积与 Scheduler Step 时机（易错）

| 组件 | step 时机 |
|------|-----------|
| optimizer.step | 每次累积完成后（每 accum_steps 个 micro-batch） |
| scheduler.step | **与 optimizer 同步**（每 accum 完成一次），不是每个 micro-batch |
| GradScaler.update | 每次 optimizer.step 后 |
| EMA 更新 | 每次 optimizer.step 后（用更新后的参数） |
| 梯度裁剪 | optimizer.step 前，**unscale 之后** |

> 常见 bug：把 scheduler 放在 micro-batch 循环里 step，导致 lr 衰减快了 accum_steps 倍。

## 十二、多模态训练特有技巧

### 12.1 视觉塔冻结/解冻策略

| 策略 | 适用场景 | 说明 |
|------|---------|------|
| 完全冻结 | 数据少（<1w 图文对）、只学对齐 | 视觉特征已被 CLIP 预训练得很好 |
| 只解冻最后几层 | 数据中等 | 微调高层语义、保留底层纹理 |
| 全量解冻（小 lr） | 数据充足、领域差异大 | 医学图、卫星图、漫画等 OOD 领域必须解冻 |
| 解冻 LN 层 | 通用技巧 | 只调归一化层（改分布不改语义），成本低收益好 |

- **判断依据**：视觉特征与目标领域相似度。相似领域（自然图 → 自然图）冻结即可；强 OOD（自然图 → 医学影像）必须解冻，否则学不动领域特征；
- **对比学习场景**（CLIP 微调）：视觉塔与文本塔**解冻程度要对称**，防止一个塔"躺平"（mode collapse）；冻结的视觉塔可预计算图像特征（先编码缓存），大幅省显存。

### 12.2 图像-文本配比（Image-Text Ratio）

- **配比 = 每个 batch 里图文对的比例**，直接影响训练目标分布：对比学习正对质量决定上限，文本多样性不足会退化（只有几种模板，视觉塔学不到语义）；
- **VLM 指令微调**：混入 30%~50% 纯文本数据防语言能力遗忘（LLaVA-1.5 做法）；多数据集混用按比例采样；
- batch 内图像分辨率/长宽比尽量一致（否则 padding 浪费）；**batch 内负例构造**：对比学习负例来自同 batch，batch 越大负例越多——CLIP 用大批量（32K）训练的核心原因之一。
### 12.3 Eval 时预处理一致性（高频事故）

- **训练/推理预处理必须完全一致**：CLIP 系微调时训练用随机裁剪，eval 必须用对应的 resize+center crop；分辨率不一致直接掉点；
- 归一化 mean/std 必须与预训练一致（CLIP 是 `(0.48145, 0.45782, 0.40821)`，不是 ImageNet 的）；
- 文本侧：tokenizer 版本、最大长度、padding 方向一致；验证集用**确定性预处理**（随机增强会让指标带噪且不可复现）；部署时把预处理嵌入模型，避免上线环境不一致。

## 十三、常见误区

1. **"Dropout 开得越大越好"**：dropout 过大会导致欠拟合、训练不稳（attention dropout 过大会破坏路由）。正则强度要匹配数据量：数据多、正则要弱。
2. **"L2 正则 = AdamW 的 weight_decay"**：不是。AdamW 的 weight decay 是解耦衰减，与 L2 加进梯度（再被 Adam 归一化）行为不同。换优化器时必须重新调整 weight_decay。
3. **"梯度裁剪是正则化"**：不是。裁剪不改变期望损失，只防"一步崩盘"，是数值稳定性手段；指望它提升泛化是误解。
4. **"EMA 的 decay 越大越好"**：decay 过大（0.9999+）时 EMA 响应极慢，短任务里 EMA 权重还没追上就结束了；要按训练步数配 decay。
5. **"混合精度 = FP16 + GradScaler 就完事"**：漏了 LN 归约用 FP32、漏了 unscale 后再裁剪、漏了 scheduler/EMA 的时机，都会静默出错或让训练不稳。
6. **"过拟合就堆正则"**：先看数据量/数据质量。加数据、降模型容量、早停往往比堆 dropout 更快更有效；正则只是"缓解"不是"根治"。

## 十四、高频面试问答

**Q1：L1 和 L2 正则的区别？为什么 L1 产生稀疏解？**
L1 加的是 $\lambda\sum|w_i|$，梯度恒为 $\pm\lambda$（不随权重变小而减弱），约束区域是菱形，等高线相切点容易落在坐标轴角点 → 权重精确为 0（稀疏）；L2 加 $\frac{\lambda}{2}\sum w_i^2$，梯度 $\lambda w$ 随权重缩小而变弱，约束是圆形，解只收缩不归零。稀疏性可用于特征选择；L2 更平滑稳定，是大模型默认选择。

**Q2：Dropout 为什么有效？**
三点：① 随机丢弃打破神经元共适应，迫使特征独立冗余；② 每个 batch 训练不同子网络，推理全量等价于子网络集成（隐式集成）；③ 对隐藏特征加噪，类数据增强。工程上配合 inverted dropout 保证训练/推理期望一致。

**Q3：为什么训练和推理时 Dropout 行为不同？**
训练需要随机性来引入正则（丢弃神经元）；推理要求确定性输出且希望用上全部特征（等价于对所有子网络做集成）。PyTorch 靠 `model.train()/model.eval()` 切换；忘记 eval 会导致推理结果随机抖动。

**Q4：inverted dropout 为什么缩放 1/(1-p)（或 1/p）？**
直接丢弃时训练输出期望是 $p \cdot y$，推理是 $y$，训练/推理期望不一致。训练时放大 $1/p$ 后期望恢复为 $y$，推理无需任何补偿，保持两阶段语义一致。

**Q5：EMA 有什么用？为什么比原始权重好？**
EMA 是参数空间的指数加权平均：① 对含噪训练轨迹平滑，等价于多模型隐式集成，方差更低；② 收敛到平坦极小值，对扰动鲁棒、泛化更好；③ 微调场景保留旧知识、缓解灾难性遗忘。评估/发布用 EMA 权重，训练用原始权重，$\lambda$ 一般 0.99~0.9999。

**Q6：梯度裁剪的原理？为什么 Transformer 必须加？**
按全局范数超限等比缩放：$g' = g \cdot \min(1, \text{max\_norm}/\|g\|)$。Transformer 的 attention 梯度幅度大、深模型易梯度爆炸，裁剪把更新限制在安全半径，防止偶发大 loss 一步崩盘。裁剪在 backward 后、step 前；AMP 下要先 unscale 再裁剪。

**Q7：Early Stopping 怎么判断？**
监控验证集指标：验证 loss 出现"先降后升"拐点（过拟合）或连续 patience 轮不创新低即停；配合"始终保存验证集最优 checkpoint"使用，绝不能存最后一步。验证指标优先用任务指标而非 loss。

**Q8：梯度累积的等效 batch 怎么理解？有什么坑？**
把 N 个 micro-batch 的梯度累加后一次性更新，数学上精确等价于 N 倍大 batch（loss 需除以 N）。坑：BN 的 running stats 仍按 micro-batch 更新（统计不等效）；scheduler 每累积完成才 step；AMP 下先除 N 再 scale，step 前先 unscale。

**Q9：Label Smoothing 的作用？Transformer 默认多少？**
把 one-hot 改成 $1-\epsilon$ 与 $\epsilon/K$ 的软标签，防止模型过置信、对标注噪声鲁棒、改善输出校准。Transformer 论文默认 0.1；对比学习（CLIP）不用它（无类别分布）。

**Q10：为什么 BN 在梯度累积下不等效大 batch？**
梯度累积只延迟了参数更新，BN 的 batch 统计在每次 forward 时就完成了，micro-batch 还是小的，统计量噪声不变。需要等效大 batch 统计得用 SyncBN 或自定义累积统计；LN/RMSNorm 无此问题。

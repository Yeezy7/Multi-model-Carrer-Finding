# 混合精度训练实践

> 本模块索引见 [参数精度详解](参数精度详解.md)

## 一、混合精度思想（重点）

### 1.1 为什么"混合"

单精度的两个极端都不行：

| 方案    | 问题                                  |
| ----- | ----------------------------------- |
| 全 FP32 | 显存/带宽/算力都是最差档，大模型放不下、训练太慢       |
| 全 FP16 | ① 值域只有 ±65504，激活/梯度动不动溢出；② 最小正规数 6.1e-5，小梯度直接归零 |
| 全 BF16 | 值域没问题，但尾数只有 7 位（eps≈0.008），权重更新精度不够 |

于是各取所长——**"混合精度"**：计算密集的算子用 FP16/BF16 算（快、省显存），关键数值用 FP32 存（稳）。分工如下：

| 对象       | 精度  | 原因                              |
| --------- | --- | ------------------------------- |
| 主权重（master weights） | FP32 | 优化器更新是逐参小步长，FP16 的 1e-3 精度会毁掉更新 |
| 优化器状态（Adam 的 m/v） | FP32 | 一阶/二阶矩长期累积，精度必须足             |
| 前向/反向 GEMM | FP16/BF16 | 计算量大头，Tensor Core 2× 加速        |
| 梯度（fp16 方案） | FP16（带 scale） | 需要 loss scaling 防下溢（见第二节）     |
| LayerNorm/Softmax 等 | FP32 | 数值敏感算子，保持 FP32（见 5.3）        |

> 一句话：**混合精度 = 用 FP32 存关键量 + 用 FP16/BF16 算矩阵 +（FP16 方案）loss scaling**。

### 1.2 三种主流方案

| 方案          | 计算精度 | 是否需要 scaler | 显存（相对 FP32） | 适用          |
| ----------- | ---- | ----------- | ----------- | ----------- |
| FP16 + AMP   | FP16 | 需要         | ~1/2（激活/梯度也省） | NVIDIA 老卡（V100/A100）必选 |
| BF16 训练     | BF16 | 不需要        | ~1/2        | A100+、长稳训练首选   |
| FP8 训练      | FP8  | 不需要（靠分块量化） | ~1/4        | H100+/DeepSeek 级 |

## 二、数值分析（重点，本模块最核心）

### 2.1 FP16 的表示能力

FP16 结构：1 位符号 + 5 位指数（偏置 15）+ 10 位尾数，关键数值：

- 最大有限值：$65504 = (2 - 2^{-10}) \times 2^{15}$；
- 最小正规数：$2^{-14} \approx 6.1 \times 10^{-5}$（之下进入次正规区，$2^{-24} \approx 5.96 \times 10^{-8}$ 以下只能舍入为 0）；
- 相对精度：$2^{-10} \approx 9.77 \times 10^{-4}$。

```python
import torch
fi = torch.finfo(torch.float16)
print(fi.max, fi.smallest_normal, fi.tiny, fi.eps)
# 65504.0 6.103515625e-05 6.103515625e-05 0.0009765625
# tiny 显示最小正规数；次正规下限为 5.96e-8（2^-24）
```

### 2.2 梯度的下溢问题（数学推导）

训练中梯度分布大致横跨 $10^{-2} \sim 10^{-8}$：靠近输出层的梯度大，越往浅层越小（反向传播连乘权重，见下）。

**为什么小梯度会归零？** 设某梯度 $g = 10^{-8}$，二进制下它落在 FP16 的次正规区（$< 2^{-14}$）。FP16 能表示的最小小数间距是 $2^{-24} \approx 5.96 \times 10^{-8}$，凡是 $g < 2^{-25} \approx 2.98 \times 10^{-8}$ 的值**连半个最小间距都不到，只能舍入为 0**：

$$g = 10^{-8} \xrightarrow{\text{FP16}} 0$$

```python
import torch
g = torch.tensor([1e-2, 1e-4, 6.1e-5, 1e-7, 1e-8, 5e-9])
print(g.half())
# tensor([1.0002e-02, 1.0002e-04, 6.0976e-05, 1.1921e-07, 0.0000e+00, 0.0000e+00])
# 1e-8、5e-9 直接变 0 —— 浅层梯度消失，深层权重停止学习
```
**为什么浅层梯度小？** 反向传播逐层连乘（设权重 $|w| < 1$）：

$$g_l = g_L \cdot \prod_{k=l}^{L-1} w_k \cdot \sigma'(x_k), \quad |g_l| \approx |g_L| \times 0.3^{L-l}$$

30 层网络里 $0.3^{29} \approx 10^{-15}$——即便梯度从不"消失"，FP16 的下溢也会主动把它们清零，因此 FP16 训练**必须** loss scaling。

### 2.3 Loss Scaling 原理（逐步推导）

思路：**在进入 FP16 之前先把所有梯度放大一个常数倍，算完再缩小回来**。

设 loss 为 $L$，缩放因子 $S$（如 $S = 2^{16} = 65536$）：

**第 1 步**：放大 loss

$$\hat{L} = L \cdot S$$

**第 2 步**：放大后的 loss 反向传播，梯度同步放大 $S$ 倍（链式法则的线性性：$g = \partial L/\partial w$ 对所有参数同乘 $S$，梯度之间比例不变）

$$g = \frac{\partial L}{\partial w} \;\Rightarrow\; \hat{g} = S \cdot g$$

**第 3 步**：$\hat{g}$ 在 FP16 中可表示（小梯度 1e-8 × 65536 = 6.6e-4，远超下溢线）；**第 4 步**：unscale 回原尺度（FP32 中做除法）：

```python
import torch
S = 2**16
g = torch.tensor([1e-8, 5e-9, 1e-2])              # 原始梯度（fp32）
g_scaled = (g * S).half()                         # 放大后进 FP16
print(g_scaled)   # tensor([6.5517e-04, 3.2759e-04, 6.5550e+02])
# 原来归零的 1e-8 现在变成 6.55e-4，完整保留

g_back = g_scaled.float() / S                     # unscale 回原尺度
print(g_back)     # tensor([9.9972e-09, 4.9986e-09, 1.0002e-02])
# 误差 ~0.03%，远小于舍入误差的随机性，训练不受影响
```

**为什么不会溢出？** 反过来看上限：FP16 最大值 65504，若 loss 本身 ~O(1)，则最大安全缩放 $S \le 65504 / 1 \approx 2^{16}$。**这就是 GradScaler 默认 init_scale = 65536（2^16）的由来**——放大了能保住的最小梯度，又不至于把正常梯度顶爆。

### 2.4 GradScaler 的完整工作流程

`torch.amp.GradScaler` 把上述过程封装成标准 AMP 流程：

```
scale(loss) → backward → step → update
   │             │        │        │
  loss×S       梯度=S×g  检查inf/nan 调整scale
```

具体每一步：

1. **scale**：`scaler.scale(loss)` 把 loss 乘上当前 scale（fp32 张量操作，不损失精度）；
2. **backward**：放大后的梯度进入 fp16 的 Tensor Core 反向计算，小梯度幸存；
3. **unscale（可选但常用）**：`scaler.unscale_(optimizer)` 把所有梯度除以 scale 转回真实尺度，**梯度裁剪/检查前必须调用**；
4. **step**：`scaler.step(optimizer)` 内部先 unscale、再全参扫描 inf/nan——无溢出则正常更新，有溢出则跳过本次 step（参数不更新，损失可接受）；
5. **update**：`scaler.update()` 根据本次是否有溢出调整 scale（见 2.5）。

### 2.5 Scale 的自动调整策略

| 事件        | 动作                              | 原因                              |
| --------- | ------------------------------- | ------------------------------- |
| 本次有溢出     | scale × backoff_factor（默认 0.5）   | 立刻减小，避免连续溢出               |
| 连续 2000 步无溢出 | scale × growth_factor（默认 2.0）    | 试探更大 scale，让更小的梯度也能活下来    |

默认参数：`init_scale=65536, growth_factor=2.0, backoff_factor=0.5, growth_interval=2000`——**溢出了减半、稳定了每 2000 步翻倍**。溢出后跳过一步的代价（loss 短暂停滞）远小于梯度下溢的长期损害。

## 三、训练循环完整代码（可运行）

> 环境：PyTorch 2.8（CPU 可完整运行；GPU 上把 `device_type="cpu"` 换成 `"cuda"`、`GradScaler(device="cpu")` 换成 `GradScaler()` 即可，逻辑完全一致）。

### 3.1 标准 AMP 训练循环（autocast + GradScaler）

```python
import torch
from torch.amp import autocast, GradScaler

torch.manual_seed(0)
model = torch.nn.Sequential(torch.nn.Linear(32, 64), torch.nn.ReLU(),
                            torch.nn.Linear(64, 1))
opt = torch.optim.SGD(model.parameters(), lr=0.1)
loss_fn = torch.nn.MSELoss()
scaler = GradScaler(device="cpu", enabled=True)   # GPU: GradScaler()
x, y = torch.randn(128, 32), torch.randn(128, 1)

for step in range(3):
    opt.zero_grad()
    with autocast(device_type="cpu", dtype=torch.float16):  # 关键1：autocast 只包前向
        out = model(x)
        loss = loss_fn(out, y)                     # loss 是 fp16
    scaler.scale(loss).backward()                  # 关键2：scale→backward→step→update
    scaler.step(opt)
    scaler.update()
    print(f"step{step}: loss={loss.item():.6f} scale={scaler.get_scale()}")
# step0: loss=1.057275 scale=65536.0
# step1: loss=0.981719 scale=65536.0
# step2: loss=0.948040 scale=65536.0
```

### 3.2 溢出跳过 step 的演示

> 独立可运行：本块自带完整初始化（文档中可视为承接 3.1 继续跑）。

```python
import torch
from torch.amp import autocast, GradScaler

torch.manual_seed(0)
model = torch.nn.Sequential(torch.nn.Linear(32, 64), torch.nn.ReLU(),
                            torch.nn.Linear(64, 1))
opt = torch.optim.SGD(model.parameters(), lr=0.1)
loss_fn = torch.nn.MSELoss()
scaler = GradScaler(device="cpu", enabled=True)
x, y = torch.randn(128, 32), torch.randn(128, 1)

def one_step(inject=False):
    opt.zero_grad()
    with autocast(device_type="cpu", dtype=torch.float16):
        loss = loss_fn(model(x), y)
    scaler.scale(loss).backward()
    if inject:                                    # 人为注入 inf 梯度模拟溢出
        with torch.no_grad():
            model[0].weight.grad[0, 0] = float("inf")
    w_before = model[0].weight[0, 0].item()
    scaler.step(opt)
    scaler.update()
    return w_before, model[0].weight[0, 0].item(), scaler.get_scale()

wb, wa, s = one_step()
print(f"正常步:    w [{wb:.4f} -> {wa:.4f}]  scale={s}")
wb, wa, s = one_step(inject=True)
print(f"溢出步:    w [{wb:.4f} -> {wa:.4f}]  scale={s}  ← 权重未更新，scale 减半")
# 正常步:    w [0.0078 -> 0.0104]  scale=65536.0
# 溢出步:    w [0.0104 -> 0.0104]  scale=32768.0  ← 权重未更新，scale 减半
```

关键观察：**溢出时优化器 step 被跳过（权重没变），scale 从 65536 减半到 32768**。

### 3.3 scale 自动增长演示（2000 步无溢出 → 翻倍）

```python
import torch
from torch.amp import autocast, GradScaler

torch.manual_seed(0)
model = torch.nn.Linear(32, 1)
opt = torch.optim.SGD(model.parameters(), lr=0.1)
scaler = GradScaler(device="cpu", enabled=True)
x, y = torch.randn(128, 32), torch.randn(128, 1)

for step in range(2001):                          # 2001 步全程无溢出
    opt.zero_grad()
    with autocast(device_type="cpu", dtype=torch.float16):
        loss = torch.nn.functional.mse_loss(model(x), y)
    scaler.scale(loss).backward()
    scaler.step(opt)
    scaler.update()

print("2001 步无溢出后 scale:", scaler.get_scale())
# 2001 步无溢出后 scale: 131072.0   ← 65536 × 2（growth_interval=2000 触发）
```

### 3.4 BF16 训练（无需 scaler 的对比）

```python
import torch
from torch.amp import autocast

torch.manual_seed(0)
model = torch.nn.Sequential(torch.nn.Linear(32, 64), torch.nn.ReLU(),
                            torch.nn.Linear(64, 1))
opt = torch.optim.SGD(model.parameters(), lr=0.1)
x, y = torch.randn(128, 32), torch.randn(128, 1)

for step in range(3):
    opt.zero_grad()
    with autocast(device_type="cpu", dtype=torch.bfloat16):
        loss = torch.nn.functional.mse_loss(model(x), y)  # BF16：范围同 FP32，不会下溢
    loss.backward()                               # 无需 scale/unscale
    opt.step()
    print(f"step{step}: loss={loss.item():.6f}")
# step0: loss=1.165386
# step1: loss=1.130322
# step2: loss=1.101483
```

> 同设置 100 步实测对比：fp32=1.305 | bf16=1.115 | fp16+scaler=1.163——三种方案收敛水平相当，BF16 代码最简。

### 3.5 手工 Loss Scaling（展示原理，不依赖 GradScaler）

```python
import torch
torch.manual_seed(0)
model = torch.nn.Linear(8, 1)                     # 主权重保持 FP32
opt = torch.optim.SGD(model.parameters(), lr=0.01)
x, y = torch.randn(64, 8), torch.randn(64, 1)
S = 2.0**16                                       # 手工选 scale

opt.zero_grad()
loss = torch.nn.functional.mse_loss(model(x), y)
(loss * S).backward()                             # 1. 放大 loss（梯度随之放大）
for p in model.parameters():
    p.grad = p.grad / S                           # 2. unscale 回真实尺度（fp32 中做）
opt.step()                                        # 3. 正常更新
print("手工 loss scaling 训练一步完成")
# 手工 loss scaling 训练一步完成
```

GradScaler 做的事情**就是这三行**，只是多了"溢出检测 + 自动调 scale"。

### 3.6 梯度裁剪的正确顺序（高频踩坑）

```python
import torch
from torch.amp import autocast, GradScaler

torch.manual_seed(0)
model = torch.nn.Linear(32, 1)
opt = torch.optim.SGD(model.parameters(), lr=0.1)
scaler = GradScaler(device="cpu", enabled=True)
x, y = torch.randn(128, 32), torch.randn(128, 1)

opt.zero_grad()
with autocast(device_type="cpu", dtype=torch.float16):
    loss = torch.nn.functional.mse_loss(model(x), y)
scaler.scale(loss).backward()
# 错误：直接裁剪——此时梯度还是放大 S 倍，裁剪阈值完全错乱
# torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)   # 实际剪的是 S×g！
scaler.unscale_(opt)                              # 必须先 unscale 回真实梯度
torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
scaler.step(opt)
scaler.update()
print("裁剪-更新完成")
# 实测梯度范数（同上设置）：未 unscale 直接 clip = 94517.5（大 6 万倍，形同虚设）
#                             unscale 后 clip   = 1.526e-05（真实梯度范数）
```

## 四、分布式与混合精度

### 4.1 DDP（Data Parallel）

- **通信时机与精度**：DDP 在 `backward()` 结束时通过 hook 对梯度做 all-reduce，此时梯度**尚未 unscale**（仍是放大后的值）——对 FP16 反而是优点（动态范围更大、更抗下溢）；NCCL 按张量原始 dtype 通信，梯度为 FP16/BF16 时通信量自动减半；
- **溢出检测**：`scaler.step(opt)` 在单进程内检查 inf/nan，结果无需跨卡同步（各卡独立判断，标准做法）。

### 4.2 FSDP（Fully Sharded）

- 主权重（FP32）与优化器状态按 rank 分片，每卡只存 1/N，通信的是 FP16/BF16 的 unshard 权重——**混合精度在 FSDP 下省的不只是单卡显存，而是整体可扩展性**；
- FP32 主权重分片不参与前向，只在 `optimizer.step` 时反序列化到对应 rank，其余时间不占"活"显存；
- 常用配置：`MixedPrecision(param_dtype=bf16, reduce_dtype=bf16, buffer_dtype=bf16)` 通信量再减半。

### 4.3 梯度累积（gradient accumulation）

多个 micro-batch 各自 `scaler.scale(loss_i).backward()` 后梯度累加，最后只做一次 `scaler.step(opt)` + `scaler.update()`——GradScaler 天然支持（unscale 只在 step 时执行一次）。**不要**每个 micro-batch 都 unscale（会破坏累加语义，且重复除 scale）。通信瓶颈场景下梯度用 **BF16 all-reduce**（范围安全）比 FP16 稳。

## 五、常见问题排查

### 5.1 NaN 排查（精度相关部分）

| 症状               | 精度相关的可能原因                                | 对策                              |
| ---------------- | --------------------------------------- | ------------------------------- |
| 训练中突然 NaN，scaler 频繁减 scale | 激活/梯度溢出（fp16 下大 logit、大 loss）            | 检查 `scaler.get_scale()` 是否骤降；加梯度裁剪 |
| loss 直接变 inf        | loss 本身溢出 fp16（MSE 大残差、交叉熵 log 出 0）      | loss 计算保持 fp32；loss 乘小系数           |
| 小学习率下权重不更新       | 梯度下溢为 0（未开 scaling 或 scale 太小）           | 用默认 65536；观察 `torch.isnan(grad).any()` |
| 只在特定层 NaN          | 该层前向在 fp16 下溢出（如 attention 分数未缩放）        | 该模块强制 fp32（黑名单，见 5.3）           |
| 分布式中个别卡 NaN        | 溢出检测/梯度同步顺序不一致                            | 统一在 step 前 unscale；检查梯度累积一致性    |

**通用排查顺序**：`torch.autograd.detect_anomaly()` 定位反向步 → 查前向哪一步值域超 65504（fp16）/448（fp8）→ 检查缩放问题（调小 scale 对比）。

### 5.3 为什么有的层必须 FP32（autocast 的算子策略）

autocast 内部按算子类型分类：

| 类别  | 行为              | 算子（CUDA fp16 策略）                  | 原因                          |
| --- | --------------- | ------------------------------ | --------------------------- |
| 白名单 | 自动 cast 到 fp16/bf16 | matmul、linear、conv、bmm            | 计算密集、有 Tensor Core 加速      |
| 黑名单 | 保持 fp32          | layernorm、softmax、log、exp、pow、求和 | 数值敏感或单点误差会被指数/归一化放大     |
| 透明  | 跟随输入 dtype       | copy、view、cat（同 dtype 时）          | 不改变数值                      |

**为什么 LayerNorm 要 FP32？** 归一化做的是"减去均值、除以标准差"：

$$\hat{x} = \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}}$$

FP16 下 $\mu$、$\sigma^2$ 的舍入误差 ~1e-3（eps=9.8e-4），而它们**直接决定整个通道的输出**——一个 1e-3 相对误差的均值会让所有通道输出偏移 1e-3 量级并在深层放大；FP32 下误差 ~1e-7 可忽略。

**为什么 Softmax 要 FP32？** $\text{softmax}_i = e^{x_i}/\sum e^{x_j}$：logit > ~11 时 $e^{11} \approx 6e4$ 已逼近 fp16 上限，再大直接溢出为 inf，分母变 inf，输出全 NaN。多模态里图文相似度 logit 可到 ±20（见第六节），fp16 softmax 必炸。

```python
# 实测：CPU autocast 下 LayerNorm 保持 fp32、Linear 转 bf16
import torch

ln, lin = torch.nn.LayerNorm(8), torch.nn.Linear(8, 8)
x = torch.randn(2, 8)
with torch.amp.autocast(device_type="cpu", dtype=torch.bfloat16):
    out_ln, out_lin = ln(x), lin(x)
print(out_ln.dtype, out_lin.dtype)   # torch.float32 torch.bfloat16
```

## 六、多模态场景注意

### 6.1 视觉塔的数值敏感性

- CLIP 类双塔里，**视觉塔（ViT）的激活与梯度统计分布和文本塔不同**：图像 patch 特征幅度差异更大、早期层梯度更小，FP16 下更易下溢/溢出；
- **能上 BF16 就上 BF16**——视觉塔在 FP16 下偶发 NaN（CLIP 系社区多次报告）在 BF16 下基本消失（范围同 FP32）；
- 若必须 FP16（V100 等老卡）：视觉塔的 LayerNorm/注意力分数强制 FP32（黑名单或局部 `torch.autocast(enabled=False)` 包裹）+ 梯度裁剪；推理提特征建议固定精度并量化后校准一次输出。

### 6.2 相似度 logits 的数值红线与工程清单

对比损失（InfoNCE）与匹配头（ITM）的 logits 经常达到 ±20：

```python
import torch
logits = torch.randn(4, 1) * 20
print(torch.sigmoid(logits).flatten())
# tensor([1.0000e+00, 1.0000e+00, 9.3174e-05, 1.0000e+00])
# fp32 下 OK；但这些 logits 转 fp16 后为 [17.9, 16.2, -9.3, 13.1]
# ① 精度损失；② 若再过 fp16 softmax 直接溢出 NaN
```

对策与清单：
- 相似度矩阵（logits）与损失计算保持 FP32（`torch.autocast(..., enabled=False)` 或显式 `.float()`）；SigLIP 逐对 logit 用 `F.logsigmoid`，不要 `log(sigmoid(x))`；
- 视觉塔、文本塔统一精度策略（别一个 fp16 一个 bf16，张量相加会 dtype 报错）；注意力 logits 除以 $\sqrt{d_k}$ 后再进 softmax 且该块保持 fp32；
- 图像特征 L2 normalize 在 fp32 做，再转低精度存/比；KV cache 量化推理时复检排序指标。

## 七、高频面试问答

**Q1：为什么需要 loss scaling？**
FP16 最小正规数 6.1e-5、最小次正规 5.96e-8，而梯度分布常到 1e-8 以下，直接进 FP16 会下溢为 0（浅层梯度归零）。把 loss 乘一个大 scale（默认 2^16），梯度同步放大后就能在 FP16 里完整表示，unscale 回 FP32 后再更新权重。

**Q2：GradScaler 具体怎么工作？**
四步：① `scale(loss)` 把 loss 乘 scale；② backward 得到放大后的梯度；③ `step(opt)` 内部 unscale 并全参检查 inf/nan——有溢出就跳过本次 step，否则正常更新；④ `update()` 按结果调整 scale：溢出减半（0.5×），连续 2000 步无溢出翻倍（2×）。

**Q3：BF16 为什么不用 loss scaling？**
BF16 指数 8 位、范围与 FP32 完全相同（最大 3.4e38），不存在下溢/溢出问题，所以不需要放大。代价是尾数只有 7 位（精度约 fp16 的 1/8），所以对精度敏感的关键量仍需 FP32。

**Q4：autocast 和 GradScaler 是什么关系？**
分工不同：autocast 管"算子精度"——决定哪些算子用 fp16/bf16 算（白名单），哪些保持 fp32（黑名单）；GradScaler 管"梯度数值"——防下溢。FP16 方案两者都要；BF16 方案只需 autocast。autocast 不会改参数精度（主权重仍是 fp32），GradScaler 不会改算子精度。

**Q5：混合精度为什么能省显存？**
参数按需：主权重/优化器状态 FP32 保留，参与前向的副本、梯度、激活用 2 字节（fp16/bf16）甚至 1 字节（fp8）——激活常是显存大头，低精度直接减半。FP8 方案权重+激活再减半，整体省 30~40%。

**Q6：为什么 LayerNorm/Softmax 要回退 FP32？**
归一化要算通道级均值/方差，fp16 的 1e-3 相对误差直接传导到所有输出；softmax 的指数在 fp16 下 logit>11 就溢出。这类算子计算量小、数值敏感，保持 fp32 几乎不影响速度。

**Q7：FP16 和 BF16 训练怎么选？**
FP16：精度高（10 位尾数），但要 scaler + 有溢出风险，适合 V100/A100 老卡。BF16：范围大免 scaling、训练更稳（视觉塔尤其明显），适合 A100+ 大规模训练，代价是尾数 7 位。DeepSeek 系大规模训练主流是 BF16/FP8。

**Q8：DDP + AMP 要注意什么？**
① DDP 的梯度 all-reduce 在 backward 时进行，此时梯度是放大后的值（fp16 下更抗下溢，属正常现象）；② 梯度裁剪必须先 `scaler.unscale_(opt)`，否则剪的是放大后的范数（实测 94517 vs 1.5e-5）；③ FSDP 通信量随精度减半；④ 梯度累积时只做一次 unscale/step。

## 八、常见误区

1. **"autocast 会把模型参数转成 fp16"**——不会。参数始终 FP32，只有白名单算子的输入被临时 cast，这也是"混合"的含义；
2. **"BF16 训练不需要任何处理"**——不需要 scaler，但尾数只有 7 位，权重更新/残差路径误差 ~0.8%，深模型仍要保留 FP32 主权重与关键层 FP32；
3. **"混合精度只省参数显存"**——参数只占一部分，**激活**才是大头（省一半），FP8 方案里激活按 FP8 缓存（DeepSeek-V3 的做法）收益更大；
4. **"梯度裁剪直接用就行"**——必须先 unscale_，否则裁剪阈值相对真实梯度放大了 S 倍，等于没剪（实测范数差 6 个数量级）；
5. **"fp16 溢出就调小 scale"**——调小 scale 只是缓解，根因要找溢出点（大 logit、大 loss、未缩放 attention 分数）；且 scale 太小会让小梯度重新下溢，两难时优先保主权重与关键层 FP32。

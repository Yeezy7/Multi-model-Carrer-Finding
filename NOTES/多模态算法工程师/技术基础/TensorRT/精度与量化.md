# TensorRT 精度与量化

> 本模块索引见 [TensorRT详解](TensorRT详解.md)

TensorRT 的核心卖点之一是"同一个模型、多种精度"。从 FP32 一路降到 FP8/INT8，显存与延迟逐级下降，代价是数值误差累积。多模态模型（视觉塔 + LLM）恰是研究"哪种精度损失可接受"的最佳样本：视觉塔对量化敏感，LLM 权重却相当耐量化。本章讲清 FP16 部署、INT8 量化的完整链路、精度评估方法，以及多模态场景的量化经验。

## 一、TensorRT 支持的精度总表

| 精度   | 位宽          | 位结构（符号+指数+尾数） | 相对 FP32 理论加速*    | 精度表现                 | 典型适用                     |
| ---- | ----------- | ------------- | ---------------- | -------------------- | ------------------------ |
| FP32 | 32          | 1+8+23        | 1×（基准）           | 无损失                  | 调试基线、数值敏感的小模型            |
| TF32 | 32 存储、19 有效 | 1+8+10        | ~8×（Tensor Core） | 尾数 10 位，误差 ~1e-3     | Ampere+ 上的训练前向/大矩阵乘      |
| FP16 | 16          | 1+5+10        | ~2×              | 范围 ±65504，相对精度 ~1e-3 | **绝大多数推理的默认选择**          |
| BF16 | 16          | 1+8+7         | ~2×              | 范围同 FP32，精度更低        | Ada+ 训练与推理、需防溢出的场景       |
| INT8 | 8           | 整数（1+7 有符号）   | ~4×              | 依赖校准质量，误差 ~1e-2      | 权重/激活量化，性能优先             |
| FP8  | 8           | E4M3 / E5M2   | ~2×（相对 FP16）     | E4M3 接近 FP16         | Hopper/Blackwell 上的大模型推理 |

> \* 加速比为"理论 Tensor Core 峰值之比"，真实收益取决于层类型与访存瓶颈：小模型、带宽受限层（LayerNorm、非 matmul 部分）加速远低于理论值。任何加速结论必须用第五节的方法做 benchmark 验证。

**精度由 GPU 架构决定"能用哪些"**：

| 架构（代表卡）                    | 可用精度                       |
| -------------------------- | -------------------------- |
| Volta（V100）                | FP32 / FP16 / INT8         |
| Turing（T4）、Ampere（A100、L4） | + TF32 / BF16（A100 有 bf16） |
| Ada（L40S、RTX 4090）         | + BF16 加速、FP8 部分支持         |
| Hopper（H100、H200）          | + FP8（Tensor Core 原生）      |
| Blackwell（B200、GB200）      | + FP4 / 更强 FP8             |

构建引擎时精度通过 `--fp16` / `--int8` / `--tf32` / `--fp8` 等开关指定（见第七节），也可对单个层指定精度（混合精度）。

## 二、FP16 部署（重点）

### 2.1 为什么视觉模型 / LLM 推理默认用 FP16

1. **显存减半**：权重与 KV cache 全部减半，同卡能塞下更大模型、更大 batch、更长上下文；
2. **Tensor Core 原生格式**：从 Volta 起 Tensor Core 的输入就是 FP16，FP32 反而要走"拆分/转换"路径，FP16 是硬件最快通路；
3. **精度损失小**：FP16 有 10 位尾数，相对精度约 $2^{-10} \approx 9.8\times10^{-4}$，而权重集中在 $[-1, 1]$，逐元素舍入误差约 $10^{-4}$ 量级，经 7B 规模模型前向累加后依然远小于任务指标能感知的阈值；
4. **零成本转换**：训练好的 FP32 权重直接 `.half()` 即可部署，不需要校准、不需要重训练。FP16 无法表示的范围（>65504）在权重与常规激活中几乎不会出现（指数位 5 位，最大指数 15，数值上限 $65504 = (2 - 2^{-10}) \times 2^{15}$，详见 [FP16与BF16](../参数精度/FP16与BF16.md)）。

结论：**推理默认 FP16；只有当 FP16 出现精度问题才考虑降级（视觉塔部分回 FP32）或升级（INT8/FP8 省显存）**。

### 2.2 FP16 的数值注意点

FP16 部署失败几乎都发生在"中间激活"，而不是权重：

| 位置                  | FP16 风险                                                     | TensorRT 的处理                                        |
| ------------------- | ----------------------------------------------------------- | --------------------------------------------------- |
| LayerNorm / RMSNorm | 求 mean/var 时平方和累积，FP16 尾数 10 位会丢失小量；输入范数抖动                  | fused LayerNorm kernel 内部用 FP32 累加（plugin 行为，对用户透明） |
| Softmax             | logits 超过 $\ln(65504) \approx 11.09$ 时 $e^x$ 溢出为 inf        | 实现先减最大值（max-subtraction）且内部 FP32 计算，输出再转回 FP16      |
| 视觉塔激活               | ViT/SigLIP 的 patch embedding 输出、注意力 logits、MLP 中间层激活幅度大、分布宽 | 无法完全规避，必要时视觉塔单独用 FP16 混合 FP32 编译                    |
| 分类/匹配头 logit        | 图文匹配、检测头的 logit 可能很大（未归一化）                                  | 让 logit 层跑 FP32（TRT 支持逐层指定精度）                       |

**经验法则**：视觉塔出现掉点先看"激活范围"，而不是盲目换 INT8。把视觉塔的激活范围打印出来（`act.abs().max()`），如果出现 >100 的量级，优先做"视觉塔 FP32/FP16 混合、LLM 用目标精度"的拆分配置。

### 2.3 FP16 与 BF16 的部署选型

- **推理首选 FP16**：Tensor Core 支持历史最长（Volta 起）、精度更高（10 vs 7 位尾数）、生态工具链最成熟；
- **BF16 用于训练与防溢出场景**：指数位与 FP32 相同（$2^{-126} \sim 2^{127}$），训练梯度/中间值不会溢出；Ada+ 的 BF16 Tensor Core 才追上 FP16 速度；
- 部署 LLM 时若权重分布极端（例如某些 MLP 层中间值巨大），BF16 可救急，但通常 FP16 + 逐层混合精度更稳。

## 三、INT8 量化（重点）

### 3.1 量化基础

TensorRT 的 INT8 采用**对称量化**（无零点，硬件实现简单）：

$$x_q = \text{round}\left(\text{clamp}\left(\frac{x}{s}, -128, 127\right)\right), \quad x \approx x_q \cdot s$$

其中 scale $s$ 对权重取 $\max|x_w|$，对激活取校准得到的范围 $T$：

$$s_{\text{weight}} = \frac{\max|W|}{127}, \qquad s_{\text{activation}} = \frac{T}{127}$$

**per-tensor vs per-channel**：per-tensor 一个张量共享一个 scale（默认、实现简单）；per-channel 每个输出通道一个 scale（精度更高，尤其当权重通道间幅度差异大——LLM 常见）。换 per-channel 的代价是 kernel 复杂度和少量额外计算。

### 3.2 PTQ（训练后量化）流程

```
① 准备校准集（几百~几千张代表性样本，覆盖真实业务分布）
   → ② FP32/FP16 前向逐层收集激活分布（直方图）
   → ③ 用校准算法（MinMax / Entropy / Percentile）确定每层 scale
   → ④ 量化权重（取 max|W|）+ 量化激活（用 scale）→ 构建 INT8 engine
   → ⑤ 写出 calibration cache（.calib 文件），下次直接复用
```

关键点：**校准发生在激活上，不发生在权重上**（权重用 $\max|W|$ 直接算即可）；量化误差 = 舍入误差（量化 bin 宽度 $s$）+ 截断误差（超出 $[-127s, 127s]$ 的部分直接丢失）。

### 3.3 三种校准算法对比

| 算法             | 原理                                                    | 优点                                                      | 缺点              | 适用                |
| -------------- | ----------------------------------------------------- | ------------------------------------------------------- | --------------- | ----------------- |
| MinMax         | $s = \max                                             | x_{act}                                                 | /127$，完全不截断     | 实现最简单、速度最快        |
| Entropy（KL 散度） | 对每个候选阈值 $T$，把 FP32 直方图截断/合并成 INT8 直方图，取使 KL 散度最小的 $T$ | **TensorRT 默认（EntropyCalibrator2）**，把量化 bin 分配给信息量最大的区域 | 需要足够多的校准样本、计算稍慢 | 通用首选              |
| Percentile     | 取激活分布的 P99.9（可调）作为截断阈值                                | 天然抗离群点                                                  | 分位点选择靠经验        | 激活存在少量大离群值（视觉塔常见） |

KL 散度的定义（$P$=FP32 直方图，$Q$=INT8 量化后的直方图）：

$$D_{KL}(P \| Q) = \sum_i P(i) \log \frac{P(i)}{Q(i)}$$

直觉：截断会丢信息（减少 $P$ 的支撑集），但 bin 宽度变小让被保留的部分更准——KL 校准就是在"截断损失"与"量化细化收益"之间找最优阈值。

### 3.4 QAT（量化感知训练）简述

QAT 在**训练过程中**插入伪量化算子（fake quant）：前向做"量化→反量化"（$x \to x_q \to x_q \cdot s$，模拟 INT8 误差），反向用直通估计器（STE，$\frac{\partial x_q \cdot s}{\partial x} \approx 1$）让梯度穿过量化层，scale 可作为可学习参数参与训练。

| 对比项 | PTQ | QAT |
| --- | --- | --- |
| 是否需要训练 | 否，只需前向跑校准集 | 是，需要训练/微调 |
| 所需数据 | 几百~几千张 | 训练级数据（通常数万+） |
| 耗时 | 分钟~小时级 | 天级（取决于模型规模） |
| 精度 | 大模型（7B+）通常可接受；小模型/视觉塔可能掉点 | 通常显著优于 PTQ，可逼近 FP32 |
| 工程复杂度 | 低（工具链成熟） | 高（改训练代码、重训/微调） |
| 典型场景 | 生产部署首选（先试 PTQ） | PTQ 掉点不可接受、或本来就是训练流程的一部分 |

**决策顺序**：先 PTQ 看数值误差与任务指标 → 掉点不可接受再上 QAT（或改为视觉塔 FP16 + LLM INT8 的混合方案）。

### 3.5 INT8 在 TensorRT 里的配置

- 命令行：`trtexec --onnx=model.onnx --int8 --calib=calibration.cache --calibData=./calib_images`（首次运行执行校准并写 cache，之后 `--calib` 直接复用）；
- Python：构建 `IInt8EntropyCalibrator2` 实现类并挂到 `builder_config.int8_calibrator`（标准写法见第七节 7.2）；
- 精度控制：`config.set_flag(trt.BuilderFlag.INT8)`；逐层精度用 `layer.precision = trt.float16` + `layer.set_output_type(...)` 实现"大部分 INT8、敏感层 FP16"的混合精度；
- 激活 scale 默认 per-tensor；TRT 8.x+ 支持 per-channel scale 模式（对量化敏感层效果明显）。

## 四、FP8（E4M3 / E5M2）

FP8 是 Hopper（H100）引入的 8 位浮点格式，两种子格式分工明确：

| 格式 | 指数+尾数 | 取值范围 | 相对精度 | 用途 |
| --- | --- | --- | --- | --- |
| E4M3 | 4+3 | $\pm 448$ | 较高（约 1e-2 量级） | **权重与激活**（前向/推理） |
| E5M2 | 5+2 | $\pm 57344$ | 较低（约 1e-1 量级） | 梯度、需要大范围的中间值（训练为主） |

- 为什么 FP8 比 INT8 好：量化误差是**相对的**（浮点按指数缩放），不像 INT8 对小数值固定误差；E4M3 在 LLM 权重上常常无精度损失，无需逐层校准调参；
- 硬件门槛：Hopper 起（H100/H200）Tensor Core 原生支持；Blackwell（B200）进一步强化并下探到 FP4；
- TensorRT 侧：trtexec 用 `--fp8` 标志；TRT-LLM 用 `--use_fp8` 量化权重/激活，且 **KV cache 也能用 FP8**（见 [KVCache详解](../KVCache/KVCache详解.md)）；
- 位结构细节与 FP32 的对应关系详见 [FP8与TF32](../参数精度/FP8与TF32.md)。

**选型一句话**：A100 及以下用 INT8 做性能档；H100+ 直接用 FP8（精度更稳、流程更短）。

## 五、精度评估方法（重点）

量化部署后必须回答两个问题：① 输出数值上差多少？② 任务上差多少？两个都要测，数值误差小是任务不掉点的必要条件但**不是充分条件**。

### 5.1 数值级误差（对模型输出）

在相同输入上对比"参考精度输出"与"量化输出"（用引擎跑）：

$$\text{MaxAbsDiff} = \max_i |x_i - y_i|$$

$$\text{余弦相似度} = \frac{x \cdot y}{\|x\|_2 \|y\|_2}$$

$$\text{相对误差} = \frac{\|x - y\|_2}{\|x\|_2}$$

| 指标 | 经验阈值（FP16 vs FP32） | 经验阈值（INT8 vs FP32） |
| --- | --- | --- |
| MaxAbsDiff（logits） | < 1e-2 | < 1e-1 |
| 余弦相似度（logits） | > 0.9999 | > 0.99 |
| 相对误差 | < 1e-2 | < 5e-2 |

注意：阈值只是经验值，且**逐 token/logit 的数值误差在自回归生成里会累积**，数值指标必须配合任务指标综合判断。

### 5.2 任务级指标

| 任务类型 | 指标 | 常见接受标准 |
| --- | --- | --- |
| 图像分类 | Top-1 accuracy | 降幅 < 0.5% |
| 目标检测 | mAP | 降幅 < 1% |
| 图像分割 | mIoU | 降幅 < 1% |
| 图文检索 | Recall@1 | 降幅 < 1% |
| 图文匹配（ITM） | accuracy | 降幅 < 1% |
| VQA | accuracy | 降幅 < 1% |
| 文本生成（LLM） | 参考答案匹配/人工打分 | 分步对比 + 抽样人工 |

多模态 VLM 还要额外关注：**图像理解类回答的正确率**（量化对视觉细节敏感）与**长上下文的稳定性**（KV cache 量化误差累积）。

### 5.3 benchmark 表格模板（精度 × 延迟 × 显存）

| 精度配置 | 延迟（ms/样本） | 吞吐（样本/s 或 tok/s） | 显存峰值（GB） | MaxAbsDiff | 任务指标（Δ vs FP32） |
| --- | --- | --- | --- | --- | --- |
| FP32（基线） | 8.0 | 125 | 14.2 | — | 基准 |
| FP16 | 4.2 | 238 | 7.3 | 5e-3 | -0.1% |
| INT8（KL 校准） | 2.3 | 435 | 4.1 | 3e-2 | -0.4% |
| INT8（QAT） | 2.3 | 435 | 4.1 | 2e-2 | -0.1% |

上表为示例格式，测试时固定 batch、输入尺寸与预热次数（见模块总篇与 TensorRT-LLM 篇的 benchmark 方法论）。

### 5.4 什么时候接受 INT8、什么时候必须 FP16

**接受 INT8**：任务指标降幅 < 0.5~1%、校准集覆盖真实业务分布、且延迟/吞吐/显存收益显著（比如吞吐 +80% 或显存减半让 batch 翻倍）。

**必须 FP16（或混合精度）**：

- 任务对细节极度敏感（小目标检测、细粒度图像检索、医学影像）——视觉塔掉点肉眼可见；
- 校准集无法覆盖线上分布（线上分布漂移）；
- 输出端精度要求高（分数/数值输出，如匹配分数要用于排序）；
- 模型输出直接参与决策且无兜底。

**通用流程**：FP16 基线 → 试 INT8 全量化 → 看 5.1 + 5.2 → 掉点则"视觉塔 FP16 + LLM INT8"混合 → 仍掉点则 QAT 或维持 FP16。

## 六、多模态模型量化敏感性（重点）

### 6.1 视觉塔 vs LLM：谁更怕量化？

**视觉塔更敏感**，原因有三：

1. **激活范围大、分布宽**：ViT/SigLIP 的 patch embedding、attention logits、MLP 中间层激活动态范围可达 2~3 个数量级，INT8 的 127 个 bin 难以同时覆盖大值和小值；
2. **细节信息密集**：CLS token 与网格化视觉特征携带的是空间细节，量化噪声会抹平细粒度差异——"两张相近的图"在量化后被判定为同一张；
3. **校准脆弱**：视觉塔的输出分布强烈依赖图像内容，校准集偏了就整体漂移。

**LLM 更耐量化**，原因：

1. **权重分布集中**：LLM 权重近似高斯、集中在 0 附近、小权重居多，对称量化误差小；
2. **激活有界结构**：softmax 输出固定在 $[0,1]$，注意力结构对噪声鲁棒；
3. **文本任务的容错**：自回归逐 token 输出，量化误差不必然改变 argmax 的答案。

### 6.2 KV cache 量化

长上下文 + 大 batch 时，KV cache 是显存大头（计算方式见 [KVCache详解](../KVCache/KVCache详解.md)）。KV cache 量化（INT8/FP8）能把这部分显存减半：

- 风险：误差沿序列长度**累积**（第 N 步用到的都是量化过的历史 KV），长上下文（>8k）下掉点更明显；
- 实践：先量化权重（收益大、风险小），再考虑 KV cache；长上下文场景评估时必须用真实长度测试，不能只看短样本；
- TensorRT-LLM 中 `--kv_cache_quant_mode int8/fp8` 或 `--use_fp8_kv_cache` 开启。

### 6.3 多模态量化的经验法则

1. **先量化 LLM 权重**：收益最大、风险最小，是第一步；
2. **视觉塔保持 FP16 或最后量化**：一般"LLM INT8/FP8 + 视觉塔 FP16"是性价比最高配置；
3. **校准集必须含真实业务图像**：用线上分布（而不是 ImageNet 随机图）校准与评估，否则 calibrator 选出的阈值不适用于线上；
4. **先看数值误差再看任务指标**：MaxAbsDiff 超阈值先排查（可能只是某层的截断问题，可逐层混合精度），任务掉点再回退；
5. **每换 GPU 型号必须重新校准/验证**：calibration cache 与算子实现相关，跨卡不保证一致。

## 七、源码实现

> 需 Linux + NVIDIA GPU + CUDA 环境运行（当前开发环境为 macOS，以下为标准可运行示例）

### 7.1 trtexec：INT8 校准 + 构建引擎

```bash
# 首次运行：执行校准（用 --calibData 目录下的图片），生成 calibration.cache，构建 INT8 engine
trtexec --onnx=model.onnx \
        --int8 \
        --calib=calibration.cache \
        --calibData=./calib_images \
        --saveEngine=model_int8.engine

# 二次运行：--calib 命中已生成的 cache，跳过校准直接构建（同一模型/同一数据分布可复用）
trtexec --onnx=model.onnx \
        --int8 \
        --calib=calibration.cache \
        --saveEngine=model_int8.engine

# 对比 FP16 与 FP32 基线
trtexec --onnx=model.onnx --fp16 --saveEngine=model_fp16.engine
trtexec --onnx=model.onnx --saveEngine=model_fp32.engine
```

预期行为：首次输出会打印校准过程与各层 scale 信息；构建完成后打印 engine 的推理延迟统计。校准集放 `./calib_images` 下若干张 JPEG/PNG（建议 500~2000 张）。

### 7.2 Python：Int8EntropyCalibrator2 标准写法

```python
# 需 Linux + NVIDIA GPU + CUDA 环境运行
import os
import glob
import numpy as np
import tensorrt as trt
import pycuda.driver as cuda
import pycuda.autoinit  # 初始化 CUDA 上下文

class Int8EntropyCalibrator2(trt.IInt8EntropyCalibrator2):
    """标准校准器：逐 batch 把校准图像送入网络，收集激活直方图 → KL 选择 scale"""

    def __init__(self, calib_dir, cache_file, batch_size=8, input_shape=(3, 224, 224)):
        super().__init__()
        self.image_paths = sorted(glob.glob(os.path.join(calib_dir, "*.jpg")))
        self.batch_size = batch_size
        self.input_shape = input_shape
        self.cache_file = cache_file
        self.batch_idx = 0
        # 分配一块 device 内存，校准期间反复复用（校准图像直接写进这块内存）
        self.device_input = cuda.mem_alloc(
            trt.volume(input_shape) * batch_size * np.dtype(np.float32).itemsize)
    def get_batch_size(self):
        return self.batch_size

    def get_batch(self, names):
        """返回当前 batch 的 device 内存地址；数据用尽返回 None 结束校准"""
        batch_paths = self.image_paths[self.batch_idx:self.batch_idx + self.batch_size]
        if len(batch_paths) < self.batch_size:
            return None
        data = self._preprocess(batch_paths)          # (N,C,H,W) float32，与线上前处理一致
        cuda.memcpy_htod(self.device_input, data)     # host → device
        self.batch_idx += self.batch_size
        return [int(self.device_input)]               # 返回给引擎的输入内存地址

    def _preprocess(self, paths):
        # 占位实现：resize 到 input_shape、归一化（用 cv2/PIL 实现），与部署前处理必须一致
        return np.zeros((self.batch_size, *self.input_shape), dtype=np.float32)

    def read_calibration_cache(self):
        """命中缓存则直接复用，跳过校准"""
        if os.path.exists(self.cache_file):
            with open(self.cache_file, "rb") as f:
                return f.read()
        return None

    def write_calibration_cache(self, length, cache):
        with open(self.cache_file, "wb") as f:
            f.write(cache)
```

## 八、高频面试问答

**Q1：PTQ 和 QAT 的区别？**
PTQ 不需要训练，用校准集前向收集激活分布选 scale，分钟级完成；QAT 在训练中插入伪量化算子（前向模拟量化误差、反向 STE 直通），scale 可学习，精度更高但需要训练数据和计算。生产流程一般先 PTQ，掉点不可接受再 QAT。

**Q2：校准集怎么选？**
三原则：覆盖真实业务分布（线上图像/请求分布）、数量足够（视觉模型几百~几千张，LLM 几百条文本）、与评估集同分布但独立。校准集偏了就选错 scale，结果比不校准还差。

**Q3：为什么 INT8 量化后掉点不大？**
三层原因：① 权重分布集中（高斯状、小权重多），对称量化误差小；② 8 bit 有 256 个 bin，配合 KL/Percentile 校准把 bin 分给信息量大的区域，截断的只是低信息量的尾部分布；③ 模型有冗余与容错，最终输出是 argmax/softmax 决策，小误差不改变决策。但视觉塔与长上下文场景误差会累积，必须实测。

**Q4：视觉塔和 LLM 哪个更耐量化？为什么？**
LLM 更耐量化：权重分布集中、激活有界（softmax）、任务容错高。视觉塔更敏感：激活范围大（跨 2~3 个数量级）、细节信息密集、校准依赖图像分布。实践上"LLM INT8/FP8 + 视觉塔 FP16"最常见。

**Q5：per-tensor 和 per-channel 量化怎么选？**
per-tensor 简单快、硬件支持好，但通道间幅度差异大时误差大；per-channel 每通道一个 scale，精度好但 kernel 复杂。LLM/视觉塔里幅度不均的层（卷积输出通道、FFN 权重）优先 per-channel。

**Q6：推理为什么默认 FP16 而不是 BF16？**
FP16 尾数 10 位精度更高、Tensor Core 支持更早（Volta vs Ampere）、推理无溢出场景；BF16 的优势是指数位 8 位防溢出，那是训练需求。Ada+ 上 BF16 才追平速度，所以推理生态默认 FP16。

**Q7：FP8 和 INT8 怎么选？**
有 Hopper+ 硬件时优先 FP8：E4M3 是相对精度（浮点），对小数值友好，通常无需精细校准流程；A100 及以下只能用 INT8，需要走完整校准。FP8 还能覆盖 KV cache 量化。

**Q8：calibration cache 是什么？换 GPU 为什么要重新校准？**
cache 是校准结果的序列化（每层的 scale 与量化参数）。scale 依赖网络结构与激活分布，与 GPU 型号强相关（不同架构的算子实现、融合方式不同），所以换卡必须重新校准/至少重新验证。

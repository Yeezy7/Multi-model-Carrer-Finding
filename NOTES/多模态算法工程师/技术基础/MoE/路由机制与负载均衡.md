# 路由机制与负载均衡：MoE 的大脑与天平

> 本模块索引见 [MoE详解](MoE详解.md)

路由（Routing）是 MoE 的"大脑"——它决定每个 token 该由哪些专家处理；负载均衡是它的"天平"——防止少数专家被 token 挤爆。本文讲透路由器的工作原理、数学形式、完整可运行的源码实现，以及从 Switch Transformer 到 DeepSeek-V3 的负载均衡演进。

## 一、定义与公式

### 1.1 路由器的数学形式

路由器（Router / Gate）是一个轻量线性映射：把 token 表示 $x \in \mathbb{R}^d$ 映射为 $E$ 个专家的分数，再用 softmax 归一化成概率：

$$g(x) = \text{Softmax}(W_g \cdot x), \quad W_g \in \mathbb{R}^{E \times d}$$

- $E$：专家数量（Mixtral 每层 8，DeepSeek-V3 每层 256）；
- $g_i(x)$：token $x$ 被分配给专家 $i$ 的概率（门控值）；
- $W_g$ 通常**不带 bias**：否则路由不看 token 内容就会被常数偏置，加剧坍缩（见 [MoE详解](MoE详解.md) 3.2）。

### 1.2 top-k 选择

softmax 概率是"全连接"的（每个 token 对全部 $E$ 个专家都有概率），MoE 的关键在于**稀疏化**——只保留分数最高的 $k$ 个：

$$\text{TopK}(g(x)) = \{i_1, i_2, \dots, i_k\}, \quad \text{s.t. } g_{i_1}(x) \ge g_{i_2}(x) \ge \dots \ge g_{i_k}(x) \ge g_j(x), \ \forall j \notin \text{TopK}$$

- $k$ 称为 top-k 大小（通常 1~8）；
- 稀疏度 $= k/E$：Mixtral 8 选 2 是 25%，DeepSeek-V3 256 选 8 约 3%；
- 被选中的专家参与计算，其余专家输出视为 0（**不计算、不占算力**）。

### 1.3 专家输出：加权求和

一个 token 经过 MoE 层的最终输出 = 被选中专家输出的**概率加权和**：

$$y = \sum_{i \in \text{TopK}(x)} g_i(x) \cdot \text{FFN}_i(x)$$

工程实现里权重通常再在选中集合内归一化一次（保证 $\sum g_i = 1$，输出尺度与密集 FFN 一致）：

$$y = \sum_{i \in \text{TopK}(x)} \frac{g_i(x)}{\sum_{j \in \text{TopK}(x)} g_j(x)} \cdot \text{FFN}_i(x)$$

### 1.4 GShard 的 top-2 公式（第一个工业级 MoE）

GShard（Google，2018）首次提出 **top-2 gating**：每个 token 恰好交给 2 个专家，权重在两个选中专家间归一化：

$$y = \tilde{g}_{p}(x) \cdot \text{FFN}_p(x) + \tilde{g}_{q}(x) \cdot \text{FFN}_q(x), \quad \tilde{g}_i = \frac{g_i(x)}{g_p(x) + g_q(x)}, \quad \{p, q\} = \text{Top2}(x)$$

GShard 的三个配套设计至今仍被沿用：

1. **固定 top-2**（不是阈值）：保证每个 token 的算力开销恒定，方便 batch 调度；
2. **容量约束（capacity）**：每个专家每步最多处理 $\lceil \frac{T \cdot k}{E} \cdot c \rceil$ 个 token，超出的 token 被**重新路由给次优专家**（而非丢弃）；
3. **局部性（local dispatch）**：同一台机器内优先路由，减少跨机 all-to-all 通信。

### 1.5 路由 vs 注意力：为什么不能直接用 attention 当路由

面试常追问"路由器和注意力不都是给 token 打分吗？"——两者打分对象完全不同：

| 对比项 | 注意力（Attention） | MoE 路由（Router） |
| --- | --- | --- |
| 打分对象 | token 对 token（序列内交互） | token 对专家（参数块） |
| 输出 | 加权混合全部 token 的信息 | 选出少数专家做非线性变换 |
| 稀疏性 | 软加权，所有位置都参与 | 硬选择 top-k，其余完全不参与 |
| 参数量 | 无参数（或极小的投影） | 路由器有参数（$W_g$），**会学习** |

注意力解决"**从别的 token 拿信息**"，路由解决"**用哪组参数处理这个 token**"——两者正交，MoE 模型里两个机制共存于每一层。

## 二、核心原理

### 2.1 路由器怎么训练：梯度如何穿过"离散选择"

路由器本质上就是一个普通线性层 + softmax，**通过端到端反向传播学习**。关键问题：top-k 是离散的（argmax 不可导），梯度怎么传回去？

答案：**梯度只穿过被选中专家的输出路径，且只作用于门控概率（不是离散索引）**。

1. 前向时，token 走了专家 $i$ 的 FFN，输出按 $g_i(x)$ 加权；
2. 反向时，损失对门控概率的梯度为：

$$\frac{\partial L}{\partial g_i(x)} = \frac{\partial L}{\partial y} \cdot \text{FFN}_i(x)$$

3. 这个梯度经 softmax 回传，更新 $W_g$ 的参数；同时专家 FFN 本身也收到梯度 $\frac{\partial L}{\partial \text{FFN}_i} = g_i(x) \cdot \frac{\partial L}{\partial y}$；
4. **未被选中的专家梯度为 0**——这就是稀疏训练：每步只更新路由器 + 被激活的专家，其余专家冻结（但"冻结"的是本轮梯度，参数本身每轮都可能被不同 token 选中）。

由此产生的**正反馈循环**：如果一个专家被频繁选中，它收到更多梯度 → 学得更快 → 门控更倾向选它 → 被选中更多。这个循环是 MoE 专家专业化的动力，也是 4.1 节"路由坍缩"的隐患。

### 2.2 top-1 与 top-2：省算力 vs 表达能力的平衡点

| 维度 | top-1（Switch Transformer） | top-2（GShard / Mixtral） |
| --- | --- | --- |
| 每 token FFN 算力 | 1 个专家（最省） | 2 个专家（×2，仍远低于密集） |
| 表达能力 | 单专家决定一切，上限低 | 两个专家互补，接近"和集"能力 |
| 容错性 | 路由选错 = 该 token 全错 | 一个选错还有另一个兜底，更稳 |
| 负载均衡压力 | 每个专家需承接 ~1/E 的 token | 每个专家承接 ~2/E，压力稍小 |
| 训练稳定性 | 对路由噪声敏感，需加 noise | 更稳，Mixtral 直接不加热噪声 |

**为什么 top-2 是"甜点位"而不是 top-4 / top-8？**收益递减：k 增大时表达能力向"全部专家（密集）"收敛，算力却线性增加；同时 k 越大，专家分工越模糊，稀疏激活的意义被稀释。Mixtral 用 top-2 以 25% 的 FFN 算力拿到了接近密集的效果，验证了这一点。DeepSeek-V3 的 top-8 看似特殊，但其专家被切得很细（256 个细粒度专家），激活比例仍只有 ~3%，性质等价于"细粒度专家上的 top-k"。

### 2.3 softmax 门控 vs sigmoid 门控（DeepSeek 的选择）

**softmax 门控**（Mixtral 等）：

- 概率和为 1，专家之间**相互竞争**：一个专家分数抬高，其余专家概率被集体压低；
- 优点：归一化后直接当权重用，输出尺度稳定；
- 缺点：路由信号被"和为一"耦合——为了压低某个专家，所有专家的梯度一起变动；均衡信号与任务信号纠缠，需要额外的 aux loss 才能约束。

**sigmoid 门控**（DeepSeek-V2/V3）：

$$u_i(x) = W_g^{(i)} \cdot x, \qquad p_i(x) = \text{Sigmoid}(u_i(x))$$

- 每个专家概率独立落在 $(0,1)$，**互不竞争**，只按自己的 logit 更新；
- 选择时用 logit 排序选 top-k（$\text{TopK}(u_i(x))$），加权时用 sigmoid 概率归一化；
- 优点：路由更新解耦、训练更稳；更关键的是——**sigmoid 的输出不需要和为 1，给"加 bias 不影响概率语义"留下了空间**，这正是 4.4 节 aux-loss-free 方案的基石。

## 三、源码实现：手写一个小型 MoE 层

下面实现一个完整可运行的小型 MoE（`n_experts=8, top_k=2`），包含：路由器、专家 FFN、top-k 选择与加权、Switch Transformer 式负载均衡损失、capacity 截断。直接复制到任意有 PyTorch 的环境即可运行。

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(42)  # 固定随机种子，保证运行结果可复现


class ExpertFFN(nn.Module):
    """单个专家：两层 FFN（等价标准 Transformer 的 FFN 块）"""
    def __init__(self, d_model, d_ff):
        super().__init__()
        self.w1 = nn.Linear(d_model, d_ff)
        self.w2 = nn.Linear(d_ff, d_model)

    def forward(self, x):
        return self.w2(F.gelu(self.w1(x)))


class MoELayer(nn.Module):
    """手写小型 MoE 层：8 个专家 + top-2 路由 + aux loss + capacity 截断"""

    def __init__(self, d_model, d_ff, n_experts=8, top_k=2,
                 capacity_factor=1.25, aux_alpha=0.01):
        super().__init__()
        self.n_experts = n_experts
        self.top_k = top_k
        self.capacity_factor = capacity_factor
        self.aux_alpha = aux_alpha
        self.gate = nn.Linear(d_model, n_experts, bias=False)  # 路由器 W_g
        self.experts = nn.ModuleList(
            [ExpertFFN(d_model, d_ff) for _ in range(n_experts)])

    def forward(self, x):
        tokens = x.reshape(-1, x.size(-1))          # (T, d)，展平成 token 序列
        T = tokens.size(0)

        # 1) 路由器打分 + softmax 门控
        gate_logits = self.gate(tokens)             # (T, E)，每个 token 对每个专家的分数
        gate_probs = F.softmax(gate_logits, dim=-1) # (T, E)，归一化成概率

        # 2) top-k 选择：每个 token 取分数最高的 k 个专家
        top_probs, top_experts = gate_probs.topk(self.top_k, dim=-1)  # 各 (T, k)
        top_probs = top_probs / top_probs.sum(-1, keepdim=True)       # 权重归一化

        # 3) capacity：每个专家本步最多处理的 token 数
        capacity = int(T * self.top_k / self.n_experts * self.capacity_factor) + 1

        # 4) 负载均衡损失（Switch Transformer 的 aux loss）
        f_i = torch.zeros(self.n_experts)           # f_i: 每个专家实际拿到的 token 比例
        for e in range(self.n_experts):
            f_i[e] = (top_experts == e).float().mean()
        P_i = gate_probs.mean(dim=0)                # P_i: 每个专家的平均门控概率
        aux_loss = self.aux_alpha * self.n_experts * (f_i * P_i).sum()

        # 5) 按专家分发 token：容量截断 -> 专家前向 -> 按门控权重累加
        outputs = torch.zeros_like(tokens)
        used = torch.zeros(self.n_experts, dtype=torch.int64)
        for e in range(self.n_experts):
            idx = (top_experts == e).nonzero()      # 哪些 (token, k槽位) 选中了专家 e
            if len(idx) == 0:
                continue
            token_ids = idx[:, 0]                   # 对应 token 序号
            if len(token_ids) > capacity:           # 超过 capacity 的 token 被丢弃
                token_ids = token_ids[:capacity]
            if len(token_ids) == 0:
                continue
            w = top_probs[idx[:len(token_ids), 0], idx[:len(token_ids), 1]]  # 门控权重
            outputs[token_ids] += self.experts[e](tokens[token_ids]) * w.view(-1, 1)
            used[e] = len(token_ids)

        return outputs.view(x.shape), gate_logits, aux_loss, used


# ---------------- 运行测试 ----------------
model = MoELayer(d_model=64, d_ff=128, n_experts=8, top_k=2)
x = torch.randn(2, 16, 64)              # batch=2, seq=16 -> 共 32 个 token
y, gate_logits, aux_loss, used = model(x)
print("输出形状:", tuple(y.shape))
# 输出: 输出形状: (2, 16, 64)          # 与输入同形，MoE 层不改变 token 维度

print("aux_loss:", round(aux_loss.item(), 4))
# 输出: aux_loss: 0.0102               # 接近理论最小值 α=0.01，说明路由较均衡

print("各专家实际处理 token 数:", used.tolist())
# 输出: 各专家实际处理 token 数: [8, 8, 8, 8, 5, 5, 11, 11]
# 说明: 32 个 token × top-2 = 64 次分发，平均每专家 8 个；容量 11 内的都被处理

print("容量上限:", int(32 * 2 / 8 * 1.25) + 1)
# 输出: 容量上限: 11                   # ceil(32×2/8×1.25)+1 = 11

# 验证梯度能回传到路由器与专家（只有被选中的专家有梯度）
x2 = torch.randn(4, 64)
y2, _, _, _ = model(x2)
y2.sum().backward()
print("路由器有梯度:", model.gate.weight.grad is not None)
# 输出: 路由器有梯度: True             # 路由器的 W_g 通过 top-k 加权路径收到梯度
```

**代码要点解读**：

1. **路由器**就是一行 `nn.Linear(d_model, n_experts, bias=False)`，参数量 $64\times8=512$，占整个层比重可忽略——路由便宜，专家昂贵；
2. **top-k 选择**发生在概率上而不是 logit 上（等价），权重在选中集合内归一化，保证与密集 FFN 输出同尺度；
3. **aux loss 中 $f_i$ 由 argmax 统计得出（不可导），$P_i$ 由 softmax 概率得出（可导）**——损失只会把路由概率往"均匀"方向推，不会干扰专家参数；
4. **capacity 截断**模拟了真实实现中的 token 丢弃：本例容量 11，各专家实际都未超载，故 64 次分发全部完成；
5. 真实框架（如 megablocks、Tutel）用**分组 top-k + 块稀疏矩阵**实现，避免了 Python 循环，但数学完全一致。

## 四、负载均衡（重点）

### 4.1 问题：路由坍缩（Routing Collapse）

不加约束训练 MoE，会观察到**少数专家吸收几乎所有 token**：

- 原因：2.1 节的正反馈——某专家偶尔多收几个 token → 梯度更多 → 更强 → 路由更倾向它 → 良性循环变恶性循环；最终 1~2 个专家承担 90% 以上的计算；
- 后果：
  1. **表达能力退化**：其余专家几乎不更新，白占显存，"稀疏"退化成"一个强专家 + 一群废专家"；
  2. **训练崩溃**：强专家梯度爆炸、弱专家梯度消失，aux loss 数值震荡；
  3. **吞吐损失**：GPU 上专家批次严重不均衡，快专家空转等慢专家。

**注意区分两个概念**：专家"专业分化"是**好事**（不同专家擅长不同 token 子集），分化不一定是坍缩；坍缩的判据是**负载失衡**（分配比例偏离均匀太远），所以负载均衡损失约束的是"分配比例"而非"能力差异"。

### 4.2 负载均衡损失：aux loss 的数学

Switch Transformer（2021）提出了至今最主流的 aux loss：

$$L_{aux} = \alpha \cdot N \cdot \sum_{i=1}^{N} f_i \cdot P_i$$

- $N$：专家数量；$\alpha$：权重系数（约 0.01，太小不均衡、太压抑制任务性能）；
- $f_i = \frac{1}{T}\sum_{t=1}^{T} \mathbb{1}\{\arg\max_j g_j(x_t) = i\}$：**实际分配给专家 $i$ 的 token 比例**（由离散选择统计，不可导）；
- $P_i = \frac{1}{T}\sum_{t=1}^{T} g_i(x_t)$：**专家 $i$ 的平均门控概率**（可导，梯度经由它传播）。

**推导：为什么最小化这个式子等价于均匀分配？**

设路由足够稳定（$f_i \approx P_i$），则由柯西不等式：

$$\sum_{i=1}^{N} f_i P_i \approx \sum_{i=1}^{N} f_i^2 \ge \frac{1}{N}\left(\sum_{i=1}^{N} f_i\right)^2 = \frac{1}{N}$$

等号当且仅当 $f_1 = f_2 = \cdots = f_N = \frac{1}{N}$（**全部专家等量分到 token**）时成立。

两个极端对照：

| 路由状态 | $f_i$ | $L_{aux}$（$\alpha=0.01$） |
| --- | --- | --- |
| 完美均匀 | 全部 $= 1/N$ | $\alpha = 0.01$（最小值） |
| 完全坍缩到 1 个专家 | $f_1=1$，其余 0 | $\alpha N = 0.08$（8 专家时） |

**实现细节**：$f_i$ 不可导（argmax），梯度只通过 $P_i$ 传播。$P_i$ 降低 ⟺ 路由器对所有 token 给出更"平均"的概率分布 ⟺ 选择变得更分散。于是模型在"任务损失"（想集中选最合适的专家）与"均衡损失"（想均匀分配）之间达到平衡，$\alpha$ 就是这个平衡的旋钮。

### 4.3 capacity factor 与 token 丢弃

即使有 aux loss，短时间内某专家仍可能被塞爆（某些 token 群体天然偏好同一个专家）。capacity 机制兜底：

$$\text{capacity} = \left\lceil \frac{T \cdot k}{N} \cdot c \right\rceil$$

- $T$：token 数；$k$：top-k；$N$：专家数；$c$：**capacity factor**；
- $\frac{T\cdot k}{N}$ 是"理想均匀"下每个专家应处理的 token 数；$c$ 是松弛系数（Switch 用 1.25，GShard 用 1.25~2）；
- 实际负载超过 capacity 时：
  - **Switch Transformer**：超出的 token **直接丢弃**（该 token 跳过 MoE 层，残差直连，梯度截断）；
  - **GShard**：超出的 token 重新路由给**次优专家**（不丢信息，但破坏 top-2 语义）；
  - **Mixtral**：不丢弃，允许专家处理更多 token（代价是快专家空转）。

trade-off：$c$ 越大，丢弃越少、信息损失越小，但专家批次越不均衡、算力浪费越多。**capacity 是"正确性"与"吞吐"之间的旋钮**，推理场景（token 到达不可控）通常比训练设得更大。

### 4.4 DeepSeek-V3 的 aux-loss-free 方案

DeepSeek 认为 aux loss 有三个固有缺陷：① 梯度与主任务损失纠缠，路由"被迫均匀"而牺牲性能；② 小模型上易引发训练不稳定；③ 调参繁琐（$\alpha$、容量都要调）。V3 用**专家级 bias + 无 aux loss** 取而代之：

1. **选择分数**：给每个专家一个可学习的 bias $b_i$，路由选择改为
   $$\text{TopK}(u_i(x) + b_i), \quad i = 1 \dots N$$
   bias 只参与"选谁"，不参与"加权"（加权仍用 sigmoid 概率 $p_i$ 归一化）——内容打分与均衡信号**完全解耦**；
2. **动态调整**：每训练 $\Delta$ 步，统计各专家近期负载，按规则更新：
   $$b_i \leftarrow b_i - \gamma \cdot \text{sign}\left(\text{load}_i - \frac{T \cdot k}{N}\right)$$
   超载专家（load 高于均值）的 bias 被压低 → 该专家被选中的概率下降；欠载专家反之。一轮轮调整形成负反馈，把负载拉回均匀；
3. **推理时移除**：$b_i$ 只服务训练期的均衡，推理时从分数中减去，路由回归纯内容驱动；
4. **为什么这样能免 aux loss**：
   - 均衡信号是**显式的控制回路**（定期校正），不依赖隐式梯度，不会与任务梯度冲突；
   - sigmoid 门控的概率相互独立、不必和为 1，加 bias 只平移选择边界、不扭曲概率语义（softmax 下加 bias 会被归一化抵消或扭曲）；
   - 每步只做一次向量加法（$u_i + b_i$），几乎零成本，无需调 $\alpha$。

配套设计：V3 每层 **1 个共享专家 + 256 个细粒度路由专家**（每 token 激活 8 个），共享专家保证"通用知识"不被稀疏选择丢弃，细粒度专家让均衡调节的粒度更细。

### 4.5 多模态场景的负载均衡

多模态（图像/视频 token 与文本 token 混排）给均衡带来新维度（详见 [MoE详解](MoE详解.md) 8.3）：

1. **模态不均衡**：视觉 token 数量远多于文本 token，且分布高度相关（同一张图的 patch 语义相似）——若均衡损失把每个专家拉到 $1/N$，视觉 token 会压过文本 token 的专家空间；实践中通常按模态分组计算均衡损失，或对视觉 token 的 aux loss 降权；
2. **局部过载**：一张高分辨率图的所有 patch 可能偏好同一批专家，造成"突发坍缩"，比纯文本更依赖 capacity 兜底；
3. **视觉 token 压缩**（Pixel Shuffle）直接减少 token 总数，是缓解均衡压力的"上游手段"。

## 五、优缺点

| 优点 | 缺点 |
| --- | --- |
| 路由器参数量极小，稀疏选择零感知开销 | 离散 top-k 不可导，训练依赖软概率近似，调试复杂 |
| 门控加权可端到端训练，无需额外监督 | 路由正反馈天然倾向坍缩，必须配套均衡机制 |
| aux loss 实现简单、效果立竿见影 | aux loss 与任务损失竞争，α 难调，可能损害任务性能 |
| capacity 机制兜底最坏情况 | capacity 过小丢 token（信息损失）、过大浪费算力 |
| bias 路由（DeepSeek）零调参、免 aux loss | 需要周期性校验负载，实现复杂度更高 |
| 稀疏选择让每 token 算力恒定、可预测 | 专家批次不均衡直接拖累 GPU 利用率 |

## 六、与密集 FFN 的对比

| 对比项 | 密集 FFN | MoE 路由层 |
| --- | --- | --- |
| 前向计算 | 全部 token 走同一个 FFN | 每 token 只走 top-k 专家 |
| 参数量 | $2 \times d \times d_{ff}$ | $N$ 倍于密集 FFN + 路由器 $E \times d$ |
| 每 token 算力 | $2 \times d \times d_{ff}$ | $\approx \frac{k}{N} \times$ 密集（+路由开销） |
| 显存 | 与算力成正比 | 与 $N$ 成正比（全部专家常驻） |
| 训练动力学 | 每参数每步都有梯度 | 每步只有被选中的专家有梯度（更稀疏，收敛规律不同） |
| 稳定性风险 | 低 | 路由坍缩、aux loss 震荡、容量溢出 |
| 工程复杂度 | 单次大矩阵乘 | 分组分发、容量管理、通信（EP 下 all-to-all） |
| 表达能力上限 | 受限于参数量 | 受限于"总参 × 路由质量" |

## 七、高频面试问答

**Q1：路由器是怎么训练的？**
路由器就是一个普通线性层 + softmax，通过端到端反向传播训练：token 前向走 top-k 专家的加权输出，反向时梯度经门控概率 $g_i(x)$ 回传更新 $W_g$，同时被选中专家的 FFN 也收到梯度。未被选中的专家本步梯度为 0。top-k 的离散选择不可导，但用概率加权让梯度"绕过去"了。

**Q2：top-1 和 top-2 的区别？**
top-1（Switch Transformer）最省算力，但每个 token 只依赖单个专家，选错即全错，表达能力弱、对路由噪声敏感；top-2（GShard/Mixtral）算力翻倍但远低于密集，两个专家可互补、有容错，表达能力与稳定性更好，是性价比最高的平衡点。

**Q3：负载均衡损失为什么有效？**
$L_{aux} = \alpha N \sum f_i P_i$，其中 $f_i$ 是专家实际分配比例、$P_i$ 是平均门控概率。当路由稳定时 $L_{aux} \approx \alpha N \sum f_i^2 \ge \alpha$，等号仅在 $f_i$ 全部等于 $1/N$（均匀分配）时成立，坍缩时取到最大值 $\alpha N$。梯度只通过可导的 $P_i$ 传播，把路由概率推向平均，从而间接均衡实际分配。

**Q4：capacity factor 是什么？**
每个专家每步最多处理 $\lceil \frac{T\cdot k}{N} \cdot c \rceil$ 个 token 的松弛系数（典型 1.25）。理想均匀下每专家分到 $\frac{Tk}{N}$ 个，$c$ 给突发负载留余量。超容量的 token 在 Switch 中被丢弃（残差直连、梯度截断），在 GShard 中被重路由给次优专家。$c$ 越大信息丢失越少但批次越不均衡、算力越浪费。

**Q5：为什么 DeepSeek-V3 不用 aux loss？**
因为它在选择分数里加专家级 bias $b_i$：选择时用 $\text{TopK}(u_i + b_i)$，加权时仍用 sigmoid 概率，两者解耦；每训练一段距离按负载正负反馈更新 $b_i$（超载减、欠载加），实现显式的均衡控制回路，推理时移除 bias。均衡信号不进入梯度、不与任务损失竞争，因此免 aux loss 且更稳。

**Q6：softmax 门控和 sigmoid 门控的区别？**
softmax 概率和为 1，专家间相互竞争，加权直接、输出尺度稳定，但均衡信号与任务信号纠缠，通常要配 aux loss；sigmoid 每个专家独立输出 $(0,1)$ 概率，互不竞争，给"bias 平移选择边界"留下了空间（DeepSeek aux-loss-free 的前提），但加权时需要额外归一化。

**Q7：被丢弃的 token 的梯度去哪了？**
该 token 在 MoE 层的输出是残差直连（跳过该层），反向时 MoE 层的梯度贡献为 0——它既不训练任何专家，也不训练路由器。因此频繁丢 token 会白白浪费训练信号，capacity 太小会损害模型效果。

**Q8：路由器会带来额外显存/算力开销吗？**
路由器本身只是一个 $E \times d$ 的线性层，相比专家参数可忽略（如 256 专家 × 4096 维 ≈ 1M 参数，占 671B 模型 0.0002%）。真正的额外开销是：① top-k 的排序/选择操作；② 稀疏分发导致专家批次大小不一带来的 GPU 利用率损失；③ 专家并行（EP）下 token 跨卡的 all-to-all 通信。

## 一、为什么需要"对齐"

### 1.1 预训练模型的本质：一个"续写机器"

预训练只做一件事：根据前文预测下一个 token（因果语言建模）。由此带来三个典型缺陷：

- **不会对话**：只会续写，不会"提问-回答"；
- **不遵循指令**：你让它翻译，它可能在续写诗歌；
- **有害内容**：直接续写互联网文本会输出偏见与有毒内容。

预训练目标与人类使用目标之间有一条鸿沟：**能力已经有了，但"听人话"的行为没有**。填平这条鸿沟就是对齐（Alignment）的任务。

### 1.2 对齐的定义与三要素

对齐 = 通过后续训练，让模型的行为与人类意图一致。业界常以 HHH 三要素衡量：

| 要素           | 含义           | 对应训练               |
| ------------ | ------------ | ------------------ |
| Helpful（有用）  | 正确理解并完成任务    | SFT 教行为，RM/DPO 教偏好 |
| Honest（诚实）   | 不知道就说不知道，不编造 | 偏好数据中标注"拒答"样本      |
| Harmless（无害） | 拒绝危险请求       | 安全 SFT 数据 + 偏好数据   |

### 1.3 对齐的量化背景

对齐训练相对预训练是"小成本大回报"：

- InstructGPT：预训练用了 175B 参数 + 数万亿 token；对齐阶段仅 1.3k 条 SFT 演示 + 31k 条偏好标注，就把 GPT-3 变成了可用的"助手"；
- 典型比例：**对齐数据只有预训练数据的百万分之一**，但对用户可感知的行为改变是决定性的；
- 结论：预训练决定"天花板"，对齐决定"用户能用到多少天花板"。

## 二、完整流水线：从预训练到对齐

### 2.1 流水线图

```text
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌────────────────────┐
│  预训练   │ → │  SFT    │ → │   RM    │ → │ RLHF（PPO/GRPO）   │
└─────────┘   └─────────┘   └─────────┘   └────────────────────┘
                                 ↑                │
                                 └───── 或直接走 DPO 路线 ─────┘
```

两条主路线：

- **三阶段路线（InstructGPT / ChatGPT 路线）**：预训练 → SFT → RM（奖励模型）→ RLHF（PPO/GRPO）；
- **两阶段路线（DPO 路线）**：预训练 → SFT → DPO（用偏好数据直接优化，跳过 RM 与强化学习）。

### 2.2 各阶段总表：训练什么、数据是什么、目标是什么

| 阶段                 | 训练什么                  | 数据是什么                        | 目标是什么                   |
| ------------------ | --------------------- | ---------------------------- | ----------------------- |
| 预训练                | 全部权重（数万亿 token）       | 互联网文本（无标注）                   | 学习语言统计规律与世界知识，获得"续写能力"  |
| **SFT**            | 全部权重或 LoRA（几千~几十万条）   | 人工标注的指令-回答对                  | 学会"指令→回答"的行为模式与对话格式     |
| **RM**             | 一个独立打分模型（从 SFT 模型初始化） | 同一问题的多个回答 + 人类偏好排序           | 学会判断"哪个回答更好"，输出标量奖励     |
| **RLHF（PPO/GRPO）** | 策略模型（SFT 模型 + RM 奖励）  | RM 对策略新生成样本的奖励               | 让生成最大化奖励，同时不偏离 SFT 分布太远 |
| **DPO**            | 策略模型（无需 RM）           | 静态偏好对（chosen 好 / rejected 差） | 隐式奖励最大化：提高好回答概率、压低差回答概率 |

### 2.3 一句话记忆

> **预训练给能力，SFT 给行为，RM 给标准，RLHF/DPO 把行为调向标准。**

### 2.4 各阶段数据规模与成本（量级参考）

| 阶段 | 数据规模 | 训练成本占比 | 显存要求（7B 示例） |
| --- | --- | --- | --- |
| 预训练 | 数万亿 token | ~95%+ | 多机多卡（数百 GPU） |
| SFT | 1k~100k 条 | ~1% | 单卡可训（LoRA/QLoRA） |
| RM | 10k~100k 条偏好标注 | ~0.5% | 同 SFT 量级 |
| RLHF | 在线采样 + RM 打分 | ~2%（含反复采样） | 需策略+参考+RM 三份模型 |
| DPO | 10k~100k 条偏好对（静态） | ~1% | 略高于 SFT |

## 三、SFT / RLHF / DPO 的关系与区别

### 3.1 三者关系

- **SFT 是公共前提**：RLHF 与 DPO 都在 SFT 模型之上做偏好优化，跳过 SFT 直接优化偏好，模型连"问答格式"都没有；
- **RLHF 与 DPO 是同一目标的两种实现**：RLHF 显式训练 RM + 强化学习；DPO 隐式学习偏好，论文证明其目标函数是 RLHF 奖励最大化问题的闭式解（无需 RM、无需在线采样）；
- **经验地位**：RLHF（PPO/GRPO）效果上限更高、可迭代奖励，但工程复杂、不稳定；DPO 简单稳定，近年（DeepSeek-R1、Qwen3 等）成为开源社区主流。

### 3.2 对比表

| 维度 | SFT | RLHF（PPO/GRPO） | DPO |
| --- | --- | --- | --- |
| 需要 RM | 否 | 是（先训 RM） | 否 |
| 训练目标 | 极大化回答似然 | 极大化奖励 - KL 惩罚 | 直接优化偏好对概率差 |
| 数据形态 | 单轮问答对 | 策略在线生成 + RM 打分 | 静态偏好对 |
| 训练稳定性 | 稳定 | 差（需 KL 约束、裁剪；GRPO 缓解） | 好（无采样、无 RL） |
| 显存/工程成本 | 低 | 高（策略 + 参考 + RM 三份模型） | 低（略高于 SFT） |
| 效果上限 | 中（学分布不学偏好） | 高（奖励可迭代、可组合） | 中高 |
| 主要风险 | 过拟合、幻觉放大 | 奖励黑客、分布偏移 | 偏好数据质量敏感 |

### 3.3 何时用哪个（决策要点）

- 只想快速让模型"会对话"：**只做高质量 SFT**（LIMA 经验：1000 条即可有强指令遵循）；
- 有高质量偏好数据、需要可控迭代奖励（安全/事实性要求高）：**RLHF**；
- 有偏好数据、想低工程成本获得可比效果：**DPO**（当前默认推荐）；
- 算力受限：SFT(LoRA) → DPO(LoRA) 全流程单卡可跑；RLHF 需要额外训 RM，成本翻倍。

### 3.5 为什么 GRPO 在替代 PPO（工程视角）

- PPO 需要价值网络（Critic）估计优势函数，7B 模型训练时要同时维护策略 + 参考 + 价值三份权重，显存与调参成本高；
- GRPO（DeepSeek 提出）去掉 Critic：对同一问题采样 $G$ 个回答，用组内回答的相对奖励做归一化（$\hat{A}_i = \frac{r_i - \text{mean}(r)}{\text{std}(r)}$）代替价值估计；
- 效果：训练更稳、显存更低，在推理/数学类任务上成为 RLHF 的默认选择。

### 3.4 优缺点

| 方法 | 优点 | 缺点 |
| --- | --- | --- |
| SFT | 简单、收敛快、是公共前提 | 只学"回答分布"不学偏好；幻觉/有害内容无排序信号 |
| RLHF | 效果上限高、奖励可迭代、可多奖励组合 | 工程复杂、不稳定、显存高；RM 误差会放大 |
| DPO | 免 RM、免采样、稳定、显存低 | 偏好数据质量决定上限；覆盖不足时奖励退化 |

## 四、多模态场景下的微调对齐特点

### 4.1 视觉塔冻结是常态

多模态模型（如 LLaVA）由视觉塔（ViT）+ 投影层 + LLM 组成。SFT 阶段惯例：

- **冻结 CLIP ViT**：其表征已在海量图文对上预训练，SFT 数据远不足以重训，且解冻会遗忘 CLIP 能力、显存暴涨；
- 训练面 = **投影层 + LLM**（或 LLM 加 LoRA）；
- 视觉域差异大时（医学/遥感/文档）才给视觉塔加 LoRA。

### 4.2 图文数据配比

- 图像描述数据（caption）教"看图说话"，指令问答数据（QA）教"按指令用图"；
- 经验配比：**描述 : 指令问答 ≈ 1:5 ~ 1:10**；
- 混入 **10%~20% 纯文本数据**做回放，防语言能力退化（灾难性遗忘）。

### 4.3 图文偏好数据（RM/DPO 阶段）

- 偏好对形态：同一张图 + 同一问题 → 好回答 vs 差回答（差回答含幻觉、漏视觉细节、答非图问）；
- 标注成本高，常用自动构造（三步流水线）：① 让多个强模型对同一图文问题各生成回答；② 用幻觉检测器（CLIP 相似度、检测器比对、LLM 裁判）筛出"含幻觉/漏细节"的差回答；③ 配对成 (chosen, rejected) 偏好对，供 DPO/RLHF 使用；
- **多模态 DPO/RLHF 对幻觉抑制尤其有效**（LLaVA-RLHF、RLHF-V 等），因为偏好数据直接提供"哪个回答更忠于图像"的排序信号。

### 4.4 幻觉：多模态对齐的头号问题

- 表现：描述图中不存在的物体/属性（object hallucination）；
- SFT 是数据侧防御（清洗图文不匹配数据、加拒答样本），缓解有限；
- 强手段在偏好优化阶段：DPO/RLHF 直接打压幻觉回答。

### 4.5 多模态对齐路线图（LLaVA 范式）

```text
Stage1 投影层预训练（冻结 ViT 与 LLM，图文对齐）
  → Stage2 SFT（冻结 ViT，训练投影层 + LLM，指令跟随）
  → Stage3 偏好优化（DPO/RLHF，抑制幻觉、对齐偏好）
```

## 六、高频面试问答

**Q1：SFT、RLHF、DPO 分别解决什么问题？**
SFT 教"行为"（指令→回答的格式与模式）；RLHF 与 DPO 教"偏好"（好回答 vs 差回答的排序）。三者是同一流水线的前后阶段：没有 SFT，偏好优化无从谈起；没有偏好优化，模型只会答不会挑。

**Q2：DPO 为什么不需要奖励模型？**
DPO 把 RLHF 的"显式奖励最大化"问题改写为"隐式奖励"的闭式解：偏好对的 log-ratio（好回答概率 - 差回答概率）本身就编码了奖励。因此只需静态偏好数据直接优化策略，跳过 RM 训练与在线强化学习。

**Q3：PPO 和 GRPO 的区别？**
PPO 需要价值网络（Critic）估计优势函数，显存与复杂度高；GRPO（DeepSeek 提出）去掉了 Critic，用**同一问题的多次采样结果互相做组内归一化**来估计优势，显著降低训练成本，是多模态/数学推理对齐的当前主流。

**Q4：SFT 之后为什么还要偏好优化？幻觉为什么 SFT 压不住？**
SFT 只学回答分布，同一问题的"好/差回答"对它没有排序信号，模型会把幻觉回答也当成正确答案学进去；偏好优化直接提供"忠实于图的回答更好"的偏好信号，才能系统性打压幻觉。

**Q5：对齐会损害模型能力吗？**
会（对齐税）：SFT/RLHF 数据分布窄，可能压低通用能力与多样性。缓解：控制训练数据分布（混入通用数据）、KL 约束（RLHF 里限制偏离 SFT）、LoRA 局部更新、对齐数据只占极小比重。

**Q6：为什么很多开源模型只做 SFT 就发布？**
对齐三要素里 SFT 贡献了最大的行为改变（LIMA：1000 条高质量数据即可），而偏好优化成本高、收益边际递减，且小数据 SFT 在多数基准上已足够；偏好优化在幻觉、安全性要求高的场景才显得不可替代。

**Q7：多模态对齐和纯文本对齐的区别？**
数据形态多一个"图"维度：① 视觉塔冻结/LoRA 决策；② 偏好数据必须是图文三元组（图-问题-双回答）；③ 幻觉是多模态特有的对齐目标（忠实于图像）；④ 配比要平衡 caption/QA/纯文本。

**Q8：对齐阶段最常见的失败是什么？**
奖励黑客（RLHF 里模型找到"刷分"捷径而非变好）与偏好数据噪声（DPO 里 chosen/rejected 标错会直接污染策略）；其次是"对齐税"（安全性与多样性下降）。对策：KL 约束、RM 与策略同步迭代、偏好数据做质量清洗与投票去噪。

## 八、常见误区

1. **误区：SFT 数据越多越好。** LIMA 表明质量远大于数量；大量低质量数据会把模型"带偏"，清洗与去重比堆量更重要。
2. **误区：DPO 完全取代 RLHF。** 在需要多奖励组合、在线迭代奖励、安全对齐等场景，RLHF 仍是更强的手段；DPO 是"简单场景的首选"，不是"永远的替代"。
3. **误区：多模态微调必须解冻视觉塔。** 默认冻结 ViT 反而是最优解（省显存、防遗忘）；只有视觉域差异大时才需要 LoRA 微调视觉塔。
4. **误区：对齐只改行为不改能力。** 对齐会带来"对齐税"（安全性与多样性下降、MMLU 类评测波动），需要回放数据与 KL 约束来平衡。
5. **误区：幻觉靠 SFT 就能根治。** SFT 只能数据侧缓解，偏好优化（DPO/RLHF）才是系统性打压幻觉的手段。

# 交叉注意力：Q/K/V 来源不同与多模态应用

> 本模块索引见 [注意力机制专题详解](注意力机制专题详解.md)

## 一、定义与公式

### 1.1 定义：Q 与 K/V 来自不同序列

自注意力中 Q、K、V 都来自**同一个序列**；交叉注意力（Cross-Attention）中 **Q 来自序列 A，K、V 来自序列 B**，公式完全相同：

$$\text{CrossAttn}(Q_A, K_B, V_B) = \text{softmax}\left(\frac{Q_A K_B^\top}{\sqrt{d_k}}\right) V_B$$

逐行展开：第 $i$ 个 query 从序列 B 中检索信息：

$$o_i = \sum_{j=1}^{n_B} \underbrace{\text{softmax}_j\left(\frac{q_i^\top k_j}{\sqrt{d_k}}\right)}_{\text{query i 对 B 中第 j 个位置}的权重} v_j$$

**关键性质**：输出形状由 **Q 的数量** $n_A$ 决定（$\in \mathbb{R}^{n_A \times d_v}$），与 K/V 的数量 $n_B$ 无关——这使"用少量 query 查询大量 key"成为可能。

### 1.2 与自注意力的唯一区别

| 维度 | 自注意力 Self-Attention | 交叉注意力 Cross-Attention |
|------|------------------------|---------------------------|
| Q 来源 | 序列 A（自身） | 序列 A |
| K/V 来源 | 序列 A（同源） | **序列 B（不同源）** |
| 矩阵形状 | $n \times n$（方阵） | $n_A \times n_B$（可非方阵） |
| 用途 | 建模序列内部依赖 | 两序列信息交互 |
| 参数量 | Q/K/V/O 四组投影 | 相同（四组投影） |

> 面试记忆点：**公式、模块、参数三者完全一样，区别只在"喂进去的是什么"**——把同一份特征同时喂给 Q/K/V 就是自注意力；把另一份特征喂给 K/V 就是交叉注意力。实现上只需注意 K/V 的输入维度可以不同于 Q。

### 1.3 典型场景（按 Q 的角色分类）

1. **Decoder Cross-Attention**（NMT、T5、BART）：Q = decoder 当前 token，K/V = encoder 输出——解码器"问"编码器；
2. **瓶颈注意力**（Q-Former/BLIP-2、Perceiver、Flamingo）：Q = 固定数量的**可学习 query**，K/V = 视觉特征——把任意多的图像 patch 压缩成固定数量 query；
3. **多模态检索/对齐**（跨模态 attention）：Q = 文本 token，K/V = 图像 patch（或反之）。

## 二、核心原理

### 2.1 交叉注意力的本质："提问-检索"协议

Q 是"问题"（要什么信息），K 是"索引"（信息在哪），V 是"答案"（信息是什么）。交叉注意力让 A 序列主动查询 B 序列——**信息流向由 Q 的一侧发起，K/V 一侧不主动**。

### 2.2 为什么多模态用交叉注意力（BLIP-2 路线）

LLaVA 路线把图像 patch 直接拼进序列做全局 self-attention；BLIP-2 用 32 个 query 做交叉注意力瓶颈。选择后者的四个原因：

1. **瓶颈 = 省算力 + 信息蒸馏**：固定 32 个 query 强制模型把"对本任务有用的视觉信息"提取出来，而不是把所有 patch 无差别送入 LLM；
2. **分辨率解耦**：query 数固定，换更高分辨率、加视频帧，送入 LLM 的 token 数不变；
3. **冻结视觉塔友好**：交叉注意力的梯度只更新 query 侧，视觉编码器（冻结 ViT）可以不动；
4. **语义对齐**：query 是"文本导向的问题"，比 patch 拼接更能显式表达"文本想从图像里找什么"。

### 2.3 Q-Former 内部结构（BLIP-2）

```text
                 ┌─────────────────────────── 冻结 ViT ───────────────────────────┐
                 │  图像 patch 特征 [n_p, 768]                                     │
                 └───────────────┬──────────────────────────────┬─────────────────┘
                                 │ K, V                         │ K, V
┌────────────────────────────────┴──────────────┐   ┌───────────┴─────────────────┐
│ 可学习 query [32, 768]  →→ 自注意力 →→ 交叉注意力 →→ FFN                       │
└───────────────────────────────────────────────┴───────────────────────────────────┘
                              ↓ 输出 [32, 768]
                      线性投影后拼入 LLM 输入
```

Q-Former 每层交替做：① query 之间的**自注意力**（32 个 query 互相通信，避免信息重复）；② query 对图像 patch 的**交叉注意力**；③ FFN。名字由来：Querying Transformer——用 query 去查询图像。

## 三、源码实现

### 3.1 通用的交叉注意力 nn.Module

```python
import math
import torch
import torch.nn as nn

class CrossAttention(nn.Module):
    """交叉注意力：Q 来自 query 序列，K/V 来自 key 序列（维度可以不同）"""
    def __init__(self, d_query, d_key, h):
        super().__init__()
        self.h = h
        self.d_k = d_query // h
        self.W_q = nn.Linear(d_query, d_query)          # Q 投影：query 侧维度
        self.W_k = nn.Linear(d_key, d_query)            # K 投影：key 侧维度（可不同）
        self.W_v = nn.Linear(d_key, d_query)            # V 投影
        self.W_o = nn.Linear(d_query, d_query)

    def forward(self, query, key, value, mask=None):
        B, n_q, _ = query.shape
        n_k = key.shape[1]
        q = self.W_q(query).view(B, n_q, self.h, self.d_k).transpose(1, 2)  # [B, h, n_q, d_k]
        k = self.W_k(key).view(B, n_k, self.h, self.d_k).transpose(1, 2)    # [B, h, n_k, d_k]
        v = self.W_v(value).view(B, n_k, self.h, self.d_k).transpose(1, 2)
        scores = (q @ k.transpose(-2, -1)) / math.sqrt(self.d_k)            # [B, h, n_q, n_k]
        if mask is not None:
            scores = scores.masked_fill(mask == 0, float('-inf'))
        out = torch.softmax(scores, dim=-1) @ v                             # [B, h, n_q, d_k]
        out = out.transpose(1, 2).contiguous().view(B, n_q, -1)
        return self.W_o(out)
```

### 3.2 与自注意力的等价性验证

```python
torch.manual_seed(0)
d_model, h = 64, 4
x = torch.randn(2, 16, d_model)
cross = CrossAttention(d_model, d_model, h)          # 自注意力只是交叉注意力的特例：
self_attn = CrossAttention(d_model, d_model, h)      # Q = K = V = 同一份特征

with torch.no_grad():
    for a, b in zip(cross.parameters(), self_attn.parameters()):
        b.copy_(a)

y_self = self_attn(x, x, x)                          # 自己查自己 = 自注意力
y_cross = cross(x, x, x)                             # 相同输入下输出一致
print(torch.allclose(y_self, y_cross, atol=1e-6))    # True
print(y_self.shape)                                  # [2, 16, 64]
```

### 3.4 Q-Former 最小实现（BLIP-2 核心）

```python
class QFormerBlock(nn.Module):
    """一个 Q-Former 层：query 自注意力 → query 对图像的交叉注意力 → FFN"""
    def __init__(self, d_model, h):
        super().__init__()
        self.self_attn = CrossAttention(d_model, d_model, h)      # query 互看
        self.cross_attn = CrossAttention(d_model, d_model, h)     # query 查图像
        self.ffn = nn.Sequential(nn.Linear(d_model, 4 * d_model),
                                 nn.GELU(),
                                 nn.Linear(4 * d_model, d_model))
        self.n1 = nn.LayerNorm(d_model)
        self.n2 = nn.LayerNorm(d_model)
        self.n3 = nn.LayerNorm(d_model)

    def forward(self, queries, image_feats):
        q = self.n1(queries + self.self_attn(queries, queries, queries))
        q = self.n2(q + self.cross_attn(q, image_feats, image_feats))
        return self.n3(q + self.ffn(q))

class QFormer(nn.Module):
    """最小 Q-Former：n_query 个可学习 query，把任意多图像 patch 压缩成固定 token"""
    def __init__(self, d_model, h, n_query=32, n_layers=3):
        super().__init__()
        self.queries = nn.Parameter(torch.randn(n_query, d_model))   # 可学习 query
        self.layers = nn.ModuleList([QFormerBlock(d_model, h) for _ in range(n_layers)])

    def forward(self, image_feats):
        B = image_feats.shape[0]
        q = self.queries.unsqueeze(0).expand(B, -1, -1)   # [B, 32, d_model]
        for layer in self.layers:
            q = layer(q, image_feats)
        return q                                          # [B, 32, d_model]

torch.manual_seed(0)
image_feats = torch.randn(2, 196, 64)     # 2 张图，每张 196 个 patch（14×14）
qf = QFormer(64, h=4, n_query=32, n_layers=2)
out = qf(image_feats)
print(out.shape)                          # [2, 32, 64]：图像被压缩成 32 个 token
# 更高分辨率（如 784 个 patch）输入，输出仍然是 [2, 32, 64]——分辨率解耦
```

### 3.5 Decoder 交叉注意力（encoder-decoder）

```python
# 机器翻译式用法：decoder 当前位置的 query 查询 encoder 的全部输出
torch.manual_seed(2)
enc_out = torch.randn(2, 50, 64)      # encoder 输出（源语言，50 个 token）
dec_in  = torch.randn(2, 1, 64)       # decoder 当前步（已生成 1 个 token）

dec_cross = CrossAttention(64, 64, h=4)
step_out = dec_cross(dec_in, enc_out, enc_out)
print(step_out.shape)                 # [2, 1, 64]：每步只产出 1 个位置
# 自回归时逐 token 调用，Q 侧只有当前 token，K/V 侧是整个 encoder 输出
```

## 四、复杂度与显存分析

### 4.1 复杂度公式

交叉注意力分数矩阵为 $n_q \times n_k$：

$$\text{FLOPs} = O(n_q \cdot n_k \cdot d), \qquad \text{中间显存} = O(n_q \cdot n_k)$$

**计算量由 query 数量主导**（$n_q \ll n_k$ 时是关键优势）。

### 4.2 数值示例（BLIP-2）

| 输入 | token 数 | 注意力矩阵 | 说明 |
|------|---------|-----------|------|
| 224px 图像（16×16 patch） | 196 | $32 \times 196$ | Q-Former 内 |
| 336px 图像 | 441 | $32 \times 441$ | patch 翻倍，矩阵只大 2.25 倍 |
| 1K 分辨率 | 4096 | $32 \times 4096$ | 送入 LLM 的仍是 32 token |
| 8 帧 336px 视频 | 3528 | $32 \times 3528$ | 帧数翻倍也不怕 |

对比"拼接后 self-attention"（LLaVA）：224px 时 $196 \times 196$，336px 时 $441 \times 441$（5 倍），且随 patch 数**平方**增长——这是交叉注意力"分辨率解耦"的数学根源。

### 4.3 KV cache 视角

- encoder-decoder 中 encoder 侧 K/V 缓存一次、全序列复用（相当于天然共享的 KV cache）；
- Q-Former 中图像侧 K/V 也只需计算一次，多个 LLM 步/多个 query 复用；
- 训练时 Q 侧梯度回传**不经过**冻结的视觉塔（只更新 query 与投影），大幅省训练开销。

## 五、优缺点

| 优点 | 缺点 |
|------|------|
| 输出 token 数与 $n_q$ 解耦，分辨率/长度可扩展 | 需要额外的 K/V 前向（视觉特征要单独过一遍投影） |
| 天然信息瓶颈，强制蒸馏关键信息 | 信息有损：patch 细节可能被 query 平均掉 |
| 不修改冻结的视觉塔，训练成本低 | 额外一层模块（比直接拼接多一组参数） |
| 可解释性好：每个 query 对应图像不同区域 | query 数量是超参数，需要调 |
| 适合"查询式"交互（问答、检索、对齐） | 相比自注意力少一次全局交互（query 间只靠自注意力层） |

## 六、与同类对比

| 维度 | 交叉注意力（BLIP-2 路线） | 拼接后 Self-Attention（LLaVA 路线） |
|------|--------------------------|-----------------------------------|
| token 数 | 固定 32，与分辨率解耦 | patch 全进序列（336px ≈ 441+） |
| 计算量 | 随 $n_q$ 增长（$32 \times n_k$） | 随 $n_k^2$ 增长 |
| 信息 | 有损压缩（蒸馏） | 全量保留 |
| 视觉塔 | 冻结友好 | 需联合训练/适配层 |
| 可解释性 | 32 个 query 各自对应区域 | attention map 大而杂 |
| 代表 | BLIP-2、InstructBLIP、Flamingo | LLaVA、Qwen-VL（部分） |

| 场景 | Q 是什么 | K/V 是什么 |
|------|---------|-----------|
| Encoder-Decoder（NMT/T5） | decoder token | encoder 输出 |
| Q-Former/BLIP-2 | 可学习 query（32 个） | 冻结 ViT 的 patch 特征 |
| Flamingo | LLM 的文本 token | 视觉特征（gated cross-attn） |
| Perceiver | 可学习 latent | 任意模态输入 |
| 检索/对齐（跨模态） | 文本 token | 图像 patch（或反之） |

## 七、高频面试问答

**Q1：交叉注意力和自注意力的本质区别？**
公式、参数、实现完全相同，唯一区别是 **Q 和 K/V 是否同源**：自注意力三者来自同一序列（$n \times n$ 方阵，建模内部依赖）；交叉注意力 Q 来自序列 A、K/V 来自序列 B（$n_q \times n_k$，可非方阵，建模两序列交互）。把同一个 x 同时喂给 Q/K/V，交叉注意力模块就变成了自注意力。

**Q2：为什么 Q-Former 用 32 个 query 而不是直接拼接图像 patch？**
① 瓶颈设计：32 个 query 强制模型蒸馏"对本任务有用的视觉信息"，计算量从 $O(n_k^2)$ 降到 $O(32 \cdot n_k)$；② 分辨率解耦：query 数固定，分辨率/帧数变化不改变送入 LLM 的 token 数；③ 冻结视觉塔：梯度不回流 ViT，训练便宜；④ 语义对齐：query 是文本导向的问题，可解释性好。

**Q3：交叉注意力的计算量由谁主导？**
由 query 数量 $n_q$ 主导：FLOPs $= O(n_q n_k d)$。Q-Former 中 $n_q=32$、$n_k$ 是 patch 数，所以图像分辨率翻倍只是 K/V 侧线性增长，总体可控。

**Q4：decoder 的交叉注意力每步怎么算？**
Q 是当前步（或已生成前缀）的 decoder 表示，K/V 是整个 encoder 输出（缓存复用）。每生成一个 token 只算一次 $1 \times n_k$ 的注意力，历史 K/V 不用重算——这是 encoder-decoder 高效的原因之一。

**Q5：cross-attention 能替代 self-attention 吗？**
不能。两者建模的信息不同：自注意力建模单序列内部结构（句法、指代），交叉注意力建模两序列间的映射。Transformer 中通常组合使用：decoder 先做 masked self-attention 建模已生成内容，再做 cross-attention 从 encoder 取外部信息。对纯因果建模（GPT 系）不需要交叉注意力。

**Q6：BLIP-2 相比 LLaVA 的 token 压缩有什么代价？**
信息有损：32 个 query 是"蒸馏器"，patch 级细节（小物体、精细纹理）可能丢失；且多了一层模块。所以需要强任务导向的 query 训练（ITC/ITM/ITG 三阶段）。LLaVA 全量保留 patch 信息但计算贵、训练贵。两者各有取舍，Qwen-VL 等新模型开始混合使用。

**Q7：视频里交叉注意力怎么用？**
把 T 帧的所有 patch（如 $T \times 196$）全部作为 K/V，32 个 query 跨帧查询——计算量 $O(32 \cdot T \cdot 196)$，线性于帧数，因此视频长度几乎不影响送入 LLM 的 token 数。这是 Q-Former 视频版（VideoBLIP 等）能处理长视频的原因。

## 一、注意力的一般形式

### 1.1 Attention(Q, K, V) 的标准定义

注意力机制的输入是三个向量组（矩阵）：查询 $Q$、键 $K$、值 $V$，输出是对 $V$ 的**加权求和**：

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right) V$$

逐 token 展开：对第 $i$ 个查询 $q_i$，先算它与所有键的**兼容性分数**（score），再归一化成权重，最后加权求和：

$$e_{ij} = \text{score}(q_i, k_j), \qquad \alpha_{ij} = \frac{\exp(e_{ij})}{\sum_{j'} \exp(e_{ij'})}, \qquad o_i = \sum_j \alpha_{ij} v_j$$

- 行 $i$ 表示查询 $q_i$ 的注意力分布（对每个键分配多少权重）；
- $\alpha_{ij} \geq 0$ 且 $\sum_j \alpha_{ij} = 1$（softmax 保证）；
- 输出 $o_i$ 是"按照注意力权重混合后的值向量"，维度与 $v_i$ 相同。

### 1.2 记忆检索的类比：注意力 = 加权查询

注意力本质是**基于内容的软性键值检索（content-based soft key-value retrieval）**，与数据库查询 / 人脑记忆检索同构：

| 概念 | 数据库类比 | 人脑类比 |
|------|-----------|---------|
| $Q$（Query 查询） | SQL 查询条件 | 你脑海中的"问题" |
| $K$（Key 键） | 记录的索引字段 | 记忆的"标签" |
| $V$（Value 值） | 记录的内容 | 记忆本身的内容 |
| score$(q,k)$ | 条件匹配程度 | 问题与标签的关联强度 |
| softmax | 归一化为概率 | 唤起概率 |
| 输出 | 检索到的内容混合 | 回忆起的混合印象 |

关键性质：**注意力是"软"的**——不是只取最匹配的那一个值（硬查询），而是所有值按权重混合。权重由 Q 与 K 的匹配度决定，值的具体内容（V）不影响权重。这就是"注意力 = 加权查询"：**Q 提问、K 决定问谁、V 提供答案**。

### 1.3 Soft Attention vs Hard Attention

| 维度 | Soft Attention | Hard Attention |
|------|---------------|----------------|
| 权重形式 | 连续权重 $\alpha_{ij} \in [0,1]$，每个 key 都有贡献 | 离散选择，只能选中 1 个（one-hot）或采样 |
| 公式 | $o_i = \sum_j \alpha_{ij} v_j$ | $o_i = v_{j^*}$，$j^* = \arg\max_j e_{ij}$ 或按 $e_{ij}$ 采样 |
| 可微性 | 全程可微，端到端 BP 训练 | 采样不可微，需 REINFORCE 等技巧或 Gumbel-softmax |
| 信息利用 | 全量利用，稳健但"不聚焦" | 聚焦但信息有损、训练方差大 |
| 现状 | **主流**（Transformer 全系） | 基本被淘汰（图注意力、老式 captioning 用过） |

> 面试记忆点：soft attention 的代价是"注意力被摊薄"（许多无关节点的权重分散了注意力预算），这也是后面 sparse/linear attention 想解决的问题之一。

### 1.4 三种角色各司其职

- **Q**：来自当前需要生成/理解的位置（decoder 当前 token、多模态中的 text query）；
- **K**：提供"可被匹配"的地址信息（被检索位置的标识）；
- **V**：真正的内容信息（被检索位置承载的信息）。

> Q、K、V 只是三个向量，**角色由"是谁映射出来的"决定**，而不是向量本身。同一组向量既可以是 Q 也可以是 K/V（自注意力中三者同源）。

## 二、经典注意力变体

### 2.1 Additive Attention（Bahdanau, 2015）

最早用于 NMT 的注意力（RNN 编码器-解码器），打分函数为：

$$e_{ij} = v^\top \tanh(W_1 q_i + W_2 k_j)$$

- $W_1, W_2$ 分别把 Q、K 投影到同一隐藏空间，加和过 $\tanh$ 后用向量 $v$ 压缩成标量分数；
- 可训练参数：$W_1, W_2, v$（所以也叫 **MLP attention / concat attention**）；
- 时间复杂度 $O(n \cdot d)$（逐对计算），无法矩阵化加速，所以也被称为"**non-multiplicative**"的打分。

**与 Dot Product Attention 的对比**：

| 维度 | Additive (Bahdanau) | Dot Product (Luong) |
|------|--------------------|--------------------|
| 打分公式 | $v^\top \tanh(W_1q + W_2k)$ | $q^\top k$（或 $q^\top W k$） |
| 参数 | $W_1, W_2, v$（额外参数） | 无（或多一个 $W$） |
| 计算 | 逐元素加/乘 + tanh，**不可批量矩阵化** | 纯矩阵乘，GPU/TPU 友好 |
| 表达能力 | 理论上更灵活（非线性） | 只有线性交互 |
| 复杂度 | $O(n \cdot d)$ 常量更大 | $O(n \cdot d)$ 常量极小 |
| 实际 | 老模型（RNN 时代） | **现代 Transformer 唯一选择** |

> 结论：Transformer 抛弃 Bahdanau 的核心原因不是表达能力，而是**矩阵化**——dot product 可以整体写成 $QK^\top$ 一次 GEMM，Additive 无法用 Tensor Core 高效实现。

### 2.2 Dot Product / Scaled Dot Product（Luong, 2015）

Luong 提出三种打分方式：

| 名称 | 公式 | 说明 |
|------|------|------|
| dot | $e_{ij} = q_i^\top k_j$ | 无参数，最简单 |
| general | $e_{ij} = q_i^\top W k_j$ | 中间学一个 $d_q \times d_k$ 矩阵（可视为学习缩放空间） |
| concat | $e_{ij} = v^\top \tanh(W[q_i;k_j])$ | 就是 Bahdanau 形式 |

Transformer 采用 **scaled dot product**：

$$\text{score}(q,k) = \frac{q^\top k}{\sqrt{d_k}}$$

### 2.3 为什么必须除以 $\sqrt{d_k}$（必考推导）

假设 $q, k$ 是 $d_k$ 维、各分量独立且零均值单位方差（LN 之后近似成立）：

$$\text{Var}(q^\top k) = \sum_{t=1}^{d_k} \text{Var}(q_t k_t) = d_k$$

即内积的方差随维度 $d_k$ **线性增长**。若不缩放：

1. $d_k$ 越大，分数绝对值越大；
2. softmax 对极大差值非常敏感：$\frac{e^{100}}{\sum e^{e_{ij}}}$ 会把概率推向 one-hot；
3. one-hot 化的分布梯度 $\approx 0$，**训练时梯度消失、饱和**。

除以 $\sqrt{d_k}$ 后方差恢复为 1，softmax 保持"温和"的分布，梯度流畅：

$$\text{Var}\left(\frac{q^\top k}{\sqrt{d_k}}\right) = \frac{d_k}{d_k} = 1$$

> 面试记忆点：$\sqrt{d_k}$ 是**方差归一化**，不是防溢出（溢出只是表象）。这层理解与归一化专题的动机一脉相承。

### 2.4 自注意力 / 交叉注意力 / 掩码自注意力

三者公式相同，**区别只在 Q、K、V 的来源**：

| 类型 | Q 来源 | K/V 来源 | 用途 |
|------|--------|---------|------|
| 自注意力 Self-Attention | 自身序列 | 自身序列（同源） | 建模序列内部依赖：BERT、GPT、ViT 每层 |
| 交叉注意力 Cross-Attention | 序列 A | 序列 B | 两序列交互：decoder 读 encoder 输出、Q-Former 读视觉特征 |
| 掩码自注意力 Masked Self-Attention | 自身序列 | 自身序列，但**只能看左侧**（因果） | 自回归生成：GPT/LLaMA 每层 |

掩码的形式：在 softmax 前把不允许的位置分数置为 $-\infty$：

$$e_{ij} = \frac{q_i^\top k_j}{\sqrt{d_k}} + M_{ij}, \qquad M_{ij} = \begin{cases} 0 & j \leq i \\ -\infty & j > i \end{cases}$$

- 因果掩码保证 token $i$ 只依赖 $\{0, \dots, i-1\}$，从而可以流式自回归生成；
- 掩码对**梯度**同样生效（未见过位置的梯度为 0），训练时 teacher forcing 下模型天然满足因果性。

> 深入：交叉注意力的 Q 通常远少于 K/V（如 Q-Former 的 32 个 query 对几千个图像 patch），此时矩阵形状是 $[32, \text{num\_patches}]$，计算量由 Q 的数量主导——这正是"瓶颈设计"省算力的原理（见第五章）。

### 2.5 多头注意力 Multi-Head Attention（MHA）

将 $d_{model}$ 拆成 $h$ 个头，每个头在自己的子空间独立做注意力，最后拼接再投影：

$$Q_i = QW_i^Q, \quad K_i = KW_i^K, \quad V_i = VW_i^V$$

$$\text{head}_i = \text{Attn}(Q_i, K_i, V_i), \qquad \text{MHA}(Q,K,V) = \text{Concat}(\text{head}_1, \dots, \text{head}_h) W^O$$

其中每个头的维度 $d_k = d_v = d_{model} / h$。

**为什么切头？**

1. **多子空间并行**：单头只能学一种相似度度量；多头让不同头在不同的投影子空间里捕捉不同类型的依赖；
2. **计算量不变**：$h$ 个头总参数量 = 单头在 $d_{model}$ 维上的参数量（$Q K^\top$ 整体 $O(d_{model}^2)$ 不变），等于"免费获得多种关系建模"；
3. **长距离 + 多粒度**：不同头天然分工，互不干扰；
4. **正则化效果**：拼接前的独立注意力提供隐式的多样性约束。

**可解释性研究：不同头学到不同模式**

| 头的位置 | 学到的模式 |
|---------|-----------|
| 浅层（低层） | 局部/句法模式：相邻词、依赖关系、位置模式（如 attention 到前一个词或固定位置） |
| 中层 | 共指消解、主谓一致等句法-语义混合 |
| 深层（高层） | 语义模式：长距离核心实体、跨句依赖、任务相关模式（多模态中：文本 token 关注对应图像区域） |

实验观察（BERT 分析工作）：

- 部分头是**位置头**（几乎不看内容，只按偏移量找 token，例如"看前一个词"）；
- 部分头是**语法头**（动词找主语、名词找修饰语）；
- 部分头是**罕见词头**（专门关注 rare token，实现"copy"机制）。

**head 数量与 $d_k$ 的关系**

- 约束：$d_k = d_{model} / h$，$h$ 必须整除 $d_{model}$；
- 固定 $d_{model}$：$h$ 越大 → 每个头维度越小 → 单头容量下降，但头数多提供更多模式；
- 经验折中：$d_k = 64$ 左右（原版 Transformer 8 头 × 64），太大单头饱和、太小单头欠拟合；
- 常见配置：BERT-base $h=12, d_k=64$；ViT-B $h=12$；LLaMA-7B $h=32, d_k=128$；LLaMA-70B $h=64$。

> **QK 交互是逐头独立的**（每头 $d_k$ 维内积），头间信息只能通过最后的 $W^O$ 混合——这是 GQA/MLA 等改造的理论基础（头内结构可以共享而不改变 QK 交互语义）。

## 三、高效注意力（面试重点中的重点）

### 3.1 为什么标准注意力"贵"

以序列长度 $n$、头维度 $d$ 计算：

1. **时间**：$QK^\top$ 是 $O(n^2 d)$，$n$ 平方增长；
2. **显存**：$S = QK^\top$ 是 $n \times n$ 矩阵，**必须完整写入显存（HBM）** 再读回来做 softmax，$O(n^2)$ 中间显存（序列 64K 时 $S$ 就有 16GB+ @FP16）；
3. **带宽**：现代 GPU 上 attention 是**访存受限（memory-bound）**问题——$O(n^2)$ 次 HBM 读写的耗时远超计算本身。

> 在长序列场景，瓶颈不是 FLOPS 而是 **HBM 带宽**。一切高效注意力（FlashAttention、sparse、linear）本质上都是在减少 HBM 访问或减少参与计算的元素。

### 3.2 FlashAttention v1（2022，Dao et al.）

**核心思想：IO 感知（IO-aware）的分块计算 + online softmax**，让整个 attention 在一个 kernel 内完成，$n\times n$ 矩阵**从不落盘 HBM**。

**（1）Tiling（分块）**

把 $Q, K, V$ 按行切成 $B_r \times d$、$B_c \times d$ 的块，逐块载入片上 SRAM（fast but small），在 SRAM 内完成块间的 $Q_i K_j^\top$、softmax、加权求和，结果累加到 $O$ 块中，最后一次性写回 HBM。SRAM 是有限的（A100 约 20MB），块大小由 SRAM 容量决定。

**（2）Online softmax（流式 softmax）**

标准 softmax 需要两趟（先求行最大值 $m$ 和分母 $l$，再算 $\exp(s - m)$）。分块后必须**单趟完成**，因此维护每行的**running max $m_i$ 和 running sum $l_i$**：

处理第 $t$ 个块时：

$$m_i^{(t)} = \max\left(m_i^{(t-1)}, \max_j s_{ij}^{(t)}\right)$$

$$l_i^{(t)} = l_i^{(t-1)} \cdot e^{m_i^{(t-1)} - m_i^{(t)}} + \sum_j e^{s_{ij}^{(t)} - m_i^{(t)}}$$

$$o_i^{(t)} = o_i^{(t-1)} \cdot e^{m_i^{(t-1)} - m_i^{(t)}} / \tilde{l}_i^{(t)} + \sum_j \alpha_{ij}^{(t)} v_j$$

- 新块的最大值可能让旧块的概率贡献被重缩放（乘以 $e^{m_{old} - m_{new}}$）；
- 全部块处理完后，输出 $o_i = o_i^{(T)} / l_i^{(T)}$；
- 数值上与标准 softmax **逐位等价（up to rounding）**，因为只是把减最大值和除分母的时机拆开了。

**（3）Backward 不存 $S$：重计算（recomputation）**

标准实现 forward 存 $S$ 或 $P$ 供 backward 用（$O(n^2)$）。FlashAttention 的 backward **不存注意力矩阵**，只用 $O(n)$ 的 $m, l$（row max/sum）重新算出 $S = QK^\top$ 再算梯度，用**额外的 FLOPs 换省掉的 HBM 带宽**——在访存受限场景下这个交换是赚的。

**收益量化**：

| 指标 | 标准 attention | FlashAttention v1 |
|------|---------------|-------------------|
| 中间显存 | $O(n^2)$（$S, P$ 落盘） | $O(n)$（只存 $O$ 和 $m, l$） |
| HBM 访问 | $O(n^2)$ 量级 | 每个 $Q/K/V$ 元素被读 $O(1)$ 次 |
| FLOPs | 基准 | **略增**（backward 重算） |
| 端到端速度 | 基准 | 训练快 2~4 倍（长序列更多） |
| 数值 | 基准 | 数学等价 |

> 记忆点：**FlashAttention 不省 FLOPs、不减复杂度（仍是 $O(n^2)$），省的是 HBM 访问和中间显存**，因此长序列提速明显（长序列时注意力占比高），短序列提升有限。

### 3.3 FlashAttention v2（2023）

v1 的已知问题：

1. 仅在 batch 和 head 维度并行，**序列维度没有并行**（一个 block 内串行）；
2. backward 重计算增加了额外 FLOPs；
3. 大量非矩阵运算（rescale、max 更新）与矩阵运算混排，Tensor Core 利用率不足；
4. block 大小限制导致 head 维度小时并行度差。

v2 的改进：

| 改进 | 内容 |
|------|------|
| 序列维并行 | 把序列（row）也切分给不同 thread block，**更大的并行度**（尤其 head 数少的长序列） |
| 减少非矩阵运算 | 不再在每个块更新时除一次 $l$，而是**最后统一除一次**；running max 更新也精简——把 rescale 次数降到每行仅 1 次 |
| 更优的线程分配 | 一个 warp 计算一个 row 的整个块，减少 SRAM 同步与 bank conflict |
| backward 优化 | 消除不必要的 rescale（利用已经存好的 max），减少重计算开销 |
| 数值稳定性 | 将 $-\infty$ 处理为 $-1000$ 级别常数，避免 NaN（支持 causal mask 的精细处理） |

**效果**：v2 相比 v1 再快约 2 倍，相比标准实现长序列可快 6~9 倍，且仍是**数学等价**（只是求值顺序不同，不做任何近似）。

### 3.4 为什么 FlashAttention "数学上严格等价"

等价性成立的关键：softmax 对行内每个元素**减去同一常数不影响结果**：

$$\text{softmax}(s_i) = \frac{e^{s_i - m_i}}{\sum_j e^{s_j - m_i}}, \qquad \forall m_i \in \mathbb{R}$$

FlashAttention 全程只是：

- 把"最大值的选取"从提前一步（标准做法）改为**边算边更新**；
- 把分母 $l$ 的求和**分块累加**（加法结合律）；
- 把最终归一化推迟到最后。

以上全部是**线性重排**，不改变任何数学结果，只改变浮点舍入的顺序（误差在 FP32 累加下可忽略）。因此：

> FlashAttention 不是近似方法（与 Performer、稀疏注意力本质不同），它是"**用工程手段消除访存瓶颈的精确实现**"，可以被任何数值敏感的下游任务直接替换。

### 3.5 Sparse Attention（稀疏注意力）

思想：人为限定每个 query 只能看部分 key，把 $O(n^2)$ 降到 $O(n \cdot w)$（$w$ 为平均可见范围）。

**典型模式**：

| 模式 | 定义 | 复杂度 | 代表 |
|------|------|--------|------|
| Sliding window（固定窗口） | token $i$ 只看 $[i-w, i]$ | $O(nw)$ | Mistral SWA、Longformer |
| Strided（跳跃） | token $i$ 看 $j \equiv i \pmod{s}$ 的位置 | $O(nw)$ | Sparse Transformer (OpenAI) |
| Global（全局） | 少数 token（[CLS]、句首）看所有位置，全体也被它们看 | $O(nw)$ | Longformer、BigBird |
| Random（随机） | 每层随机选 $w$ 个位置 | $O(nw)$ | BigBird |

**组合模式（Longformer 的 sliding + global）**：绝大多数 token 用滑动窗口（局部建模），少数 **global token**（如 [CLS]、每段首个 token）保留全序列视野（长距离建模），弥补窗口的盲区。

**为什么大模型几乎不用稀疏注意力？**（面试高频）

1. **硬件不友好**：不规则/跳跃的访问模式无法高效映射到 Tensor Core 的稠密矩阵乘，实际 wall-clock 提速远小于理论值；
2. **实现复杂**：每个 pattern 要专门写 kernel，与 FlashAttention 的分块优化冲突（如 causal 下的窗口需要特殊处理）；
3. **质量损失**：固定模式是启发式的，长程依赖若落在窗口外则完全丢失，训练质量下降（有研究表明稀疏 attention 训练出的模型困惑度更高）；
4. **FlashAttention 的崛起**：同样的 $O(n^2)$ 显存问题被 FlashAttention 用更少的 HBM 访问解决了，在它支撑的范围内 dense 更优；
5. 长序列的终极方案转向了**线性 attention / 状态空间模型（Mamba）**或 **MLA 压缩**，而非手工稀疏模式。

### 3.6 Linear Attention（Performer, 2021）

**思路**：把 softmax 注意力中的指数核拆成两个特征映射的内积，从而把 $QK^\top V$ 的结合顺序从"先 $QK^\top$（$O(n^2)$）"改为"先 $K^\top V$（$O(n)$）"。

标准 softmax 核：$A_{ij} = \frac{e^{q_i^\top k_j}}{\sum_{j'} e^{q_i^\top k_{j'}}}$，分子是核函数 $e^{q^\top k}$。

**FAVOR+（Fast Attention Via positive Orthogonal Random features）**：用随机特征近似核

$$e^{q^\top k} \approx \mathbb{E}_\omega\left[\phi(q)^\top \phi(k)\right]$$

其中随机特征（trigonometric，保证非负）：

$$\phi(x) = \frac{1}{\sqrt{m}} \cdot e^{\frac{\|x\|^2}{2}} \cdot \left[\sin(\omega_1^\top x), \cos(\omega_1^\top x), \dots, \sin(\omega_m^\top x), \cos(\omega_m^\top x)\right]$$

$\omega_i \sim \mathcal{N}(0, I_{d})$ 是随机投影，$m$ 是特征维度（超参数，常取 $m \approx d$）。

**线性化的关键一步**——改变结合顺序：

$$O = D^{-1} \left[\phi(Q) \left(\phi(K)^\top V\right)\right], \qquad D = \text{diag}\left(\phi(Q) (\phi(K)^\top \mathbf{1}_n)\right)$$

计算顺序：先算 $\phi(K)^\top V$（$m \times d$）再左乘 $\phi(Q)$（$n \times m$），复杂度：

$$O(n \cdot m \cdot d) \quad \text{而非} \quad O(n^2 \cdot d)$$

**为什么效果有损失**：

1. **随机特征近似误差**：核近似是蒙特卡洛估计，误差 $\sim O(1/\sqrt{m})$，$m$ 取大会变贵，精度天然有上限；
2. **注意力分布失去尖锐性**：线性化把"点积之后归一化"改成了"归一化之外的线性平均"，难以表达 sharp 的 one-hot 式注意力，对"精确拷贝/检索"类任务（如翻译、复制、算术）明显退化；
3. **方差问题**：$e^{q^\top k}$ 的指数增长难以被有限维随机特征稳定捕捉，长序列训练数值不稳；
4. **工程不成熟**：后续被状态空间模型（Mamba）与 gated 架构（RWKV）在"线性建模序列"上超越。

### 3.7 Multi-Query（MQA）/ Grouped-Query Attention（GQA）

**动机：KV cache 显存爆炸**

自回归推理时，每生成一个 token 都要把历史 token 的 K、V 保存下来（供后续 attention 使用），这叫 **KV cache**。其显存：

$$\text{KV cache} = 2 \times L \times n_{layers} \times h \times d_k \times \text{seq\_len} \times \text{bytes}$$

以 70B 模型、$L=80, h=64, d_k=128$、序列 8192、FP16 为例：$2 \times 80 \times 64 \times 128 \times 8192 \times 2$ bytes $= 17.2$ GB——**比模型本身还大**，长上下文推理的主要瓶颈。

**MQA（Multi-Query Attention, 2019）**：所有 head **共享同一组 K、V**，只有 Q 保持多头：

- KV cache 降为原来的 $1/h$；
- 存储从 $L \times h \times d_k$ 变成 $L \times 1 \times d_k$；
- 代表模型：Falcon、PaLM（部分层）。

**GQA（Grouped-Query Attention, 2022）**：折中方案——$h$ 个 Q 头分成 $g$ 组，**每组共享一组 K、V**：

- $h : g$ 比例（32 头 8 组 → 每个 Q 组 4 头共享 1 组 KV）；
- KV cache 降为 $1/(h/g)$，即 $g/h$；
- $g=1$ 退化为 MQA，$g=h$ 退化为 MHA；
- 代表模型：**LLaMA2-70B（GQA）、LLaMA3 全系（GQA）、Mistral-7B（GQA）**。

| 维度 | MHA | GQA | MQA |
|------|-----|-----|-----|
| Q 头数 | $h$ | $h$ | $h$ |
| KV 头数 | $h$ | $g$（$g \mid h$） | $1$ |
| KV cache | 基准 $C$ | $C \cdot g/h$ | $C / h$ |
| 质量 | 基准 | 接近 MHA（轻微损失） | 有可感知损失（小模型明显） |
| 训练成本 | 基准 | 略降（KV 投影少了） | 更降 |
| 使用 | LLaMA1、GPT-2 | LLaMA2/3、Mistral、Qwen | Falcon、PaLM |

**为什么 GQA 而不是 MQA？**：MQA 的 KV 太"窄"（单头信息容量不足），大模型上质量损失明显；GQA 用 $g$ 组 KV 保留足够容量，同时把 cache 压到 $1/(h/g)$。$h:g$ 的经验值：32 头 8 组、64 头 8 组（LLaMA2-70B）、8 头 8 组（LLaMA3-8B，h=32, g=8）。

> 面试记忆点：**GQA 省的是推理时的显存和访存带宽（KV cache），不改训练时的计算复杂度**（训练时 QK^T 仍是全量）；它让"大批次 × 长上下文"的推理吞吐成为可能。

### 3.8 Sliding Window Attention（SWA，Mistral-7B）

**定义**：每个 token 只 attend 到它前面的 $W$ 个 token（causal + 窗口）：

$$\text{Attention}_i = \text{softmax}\left(\frac{Q_i K_{[i-W, i]}^\top}{\sqrt{d_k}}\right) V_{[i-W, i]}$$

- 复杂度从 $O(n^2)$ 降到 $O(nW)$；
- KV cache 从 $O(n)$ 降到 $O(W)$ 每层。

**窗口的"滚动"与信息传播（层间滑动）**：

- 单层：token 只能看到 $W$ 步之内的信息；
- 多层堆叠：第 $l$ 层能触及 $l \cdot W$ 步范围的信息（**等效感受野 $O(L \cdot W)$**，$L$ 为层数）；
- **滚动（rolling）技巧**：相邻层使用**偏移不同**的窗口（例如第 $2k$ 层窗口起点 $i-W$，第 $2k+1$ 层起点 $i-W+W/2$），让高层窗口能"看到"低层窗口的边缘 token，信息像传送带一样逐层传播——这就是"**层间滚动的窗口滑动**"；
- Mistral-7B：$W=4096$、32 层、全部 SWA，等效感受野远超 4096。

**SWA 与 GQA 的关系**：Mistral 同时用 SWA（减注意力计算量）+ GQA（减 KV cache 显存），二者正交。

## 四、DeepSeek 的 MLA（Multi-head Latent Attention）思想简述

### 4.1 动机

GQA 只是"**减少 KV 的 head 数**"，但 KV 仍是"每个 token 一组向量"；MLA（DeepSeek-V2, 2024）更进一步：把 KV **压缩到一个低维潜向量**，KV cache 的瓶颈从"头数"变成"潜维度"。

### 4.2 核心思想：压缩 KV 到潜变量

训练/前向时，K、V 并不直接由 $x$ 投影得到，而是先投影到低维潜空间 $c$（$d_c \ll h \cdot d_k$），再用上投影矩阵恢复到多头形状：

$$c = W_{DK} x, \qquad k = W_{UK} c, \qquad v = W_{UV} c$$

- $W_{DK} \in \mathbb{R}^{d_c \times d_{model}}$：下投影（压缩，把每个 token 的 KV 压成 $d_c$ 维潜向量）；
- $W_{UK}, W_{UV} \in \mathbb{R}^{h \cdot d_k \times d_c}$：上投影（展开回 $h$ 头）；
- **推理时只需缓存 $c$（每 token 每层 $d_c$ 维），而不是 $h$ 组 K、V**；
- 配合 K 的 RMSNorm 与 **解耦 RoPE**（位置编码单独加一小段向量，避免 RoPE 与低秩压缩冲突）。

### 4.3 为什么省显存

| 方案 | 每 token 每层 KV cache 大小 |
|------|---------------------------|
| MHA | $h \times d_k$（如 $64 \times 128$） |
| GQA（8 组） | $g \times d_k$（$8 \times 128$） |
| MLA | $d_c$（DeepSeek-V2 为 512） |

DeepSeek-V2 报告：相比 MHA，**KV cache 减少约 93.3%**；配合 GQA 式共享 + 潜压缩，推理吞吐大幅提升（2.5 倍+），训练成本也因 KV 投影变小而下降。

> 面试记忆点：MLA 是"**KV 的线性低秩压缩 + 推理时只存压缩态**"，与 GQA 的"砍头数"是两条不同路线；MLA 也被 DeepSeek-V3、Qwen 后续架构演进沿用（Qwen3-Next 等）。面试中讲清"下投影压缩、上投影还原、只存 $c$"即可。

## 五、多模态中的注意力

### 5.1 Cross-Attention：BLIP-2 Q-Former 的核心

Q-Former 是一个轻量 Transformer，输入是一组**可学习的 query 向量**（如 32 个，768 维），内部交替做：

1. **自注意力**（query 之间互相交互，保证 32 个 query 的信息不重复——每个 query 负责图像的不同方面）；
2. **交叉注意力**（每个 query 作为 $Q$，attend 到冻结的 ViT 输出图像 patch 特征 $K, V$）；
3. FFN。

$$\text{Query}: Q \in \mathbb{R}^{32 \times 768}, \qquad \text{Image}: K, V \in \mathbb{R}^{n_p \times 768}$$

交叉注意力把"**任意多的图像 patch**"压缩成"**固定 32 个 query 表示**"——这是 Q-Former 名字的由来（Querying Transformer：用 query 去查询图像）。

**训练阶段**：前两个阶段（ITC/ITM/ITG）query 扮演信息瓶颈；第三阶段 query 经过线性投影后拼入 LLM 的输入。

### 5.2 为什么视觉侧用 Cross-Attention 而不是"拼接后 self-attention"？

| 维度 | 拼接后 Self-Attention（LLaVA 路线） | 交叉注意力瓶颈（BLIP-2 路线） |
|------|----------------------------------|------------------------------|
| token 数 | 图像 patch 全部进序列（336px ≈ 576 tokens） | 固定 32 个 query，与图像分辨率解耦 |
| 计算量 | 与 patch 数平方增长 | 只随 query 数增长，patch 再多也不怕 |
| 压缩能力 | 无（信息全量保留，也全量计算） | 强（query 被迫蒸馏关键信息） |
| 融合粒度 | 所有 token 统一交互 | 文本侧主动"查询"图像 |
| 可解释性 | attention map 大而杂 | 32 个 query 各自对应图像不同区域，易分析 |
| 训练成本 | 高（576×576 的 attention 矩阵） | 低（32×576） |
| 代表 | LLaVA、Qwen-VL（部分版本） | BLIP-2、InstructBLIP、Flamingo |

本质原因：

1. **瓶颈 = 省算力 + 信息蒸馏**：32 个 query 强制模型把"图像里对本任务有用的信息"提取出来，而不是把所有 patch 无差别送入 LLM；
2. **分辨率解耦**：query 数固定，换更高分辨率图片、加视频帧，都不改变送入 LLM 的 token 数；
3. **冻结视觉塔友好**：交叉注意力不反向传播到冻结的 ViT（或只浅层微调），避免大规模视觉训练；
4. **语义对齐**：query 是"文本导向的问题"，比 patch 拼接更能显式表达"文本想从图像里找什么"。

### 5.3 视频 / 多帧的时间注意力

视频是三维网格：$T$ 帧 × $H$ 高 × $W$ 宽。**全 3D 注意力**（把所有时空 patch 拉平做 self-attention）复杂度 $O((THW)^2)$，不可行。主流做法是**分解（factorized）时空注意力**：

| 方案 | 做法 | 复杂度 |
|------|------|--------|
| 全 3D | 时空 patch 全拉平 | $O((THW)^2)$，不可行 |
| 空间+时间分解（TimeSformer） | 每帧内先做空间自注意力，再跨帧做时间自注意力 | 空间 $O(T \cdot (HW)^2)$，时间 $O(HW \cdot T^2)$，$T$ 和 $HW$ 各自远小于 $THW$ |
| 交替式（Video Swin） | 3D 窗口内先空间后时间，窗口可移位 | 线性于 token 数 |
| 3D 卷积 + 注意力混合（ViViT） | 3D 卷积提取 tubelet + 分解 attention | 线性于 token 数 |
| 全时程统一 attention（Q-Former 视频版） | 所有帧 patch 作为 K/V，query 跨帧查询 | 计算由 query 数主导 |

**直觉**：视频中相邻帧高度相似，空间内关系与时间上的运动变化是两种不同规律，用两轮小注意力近似一轮大注意力，在几乎不掉点的情况下把复杂度从平方降到两个线性的和。

### 5.4 视觉 token 的 attention 计算量问题

视觉输入打 patch 后 token 数膨胀得很快：

| 输入 | 典型 token 数 |
|------|--------------|
| 224×224 图像（16×16 patch） | 196 |
| 336×336 图像 | 441 |
| 1K 分辨率图像 | 4096 |
| 8 帧 336px 视频 | 3528 |
| 1 分钟视频（1fps） | 数万 |

self-attention 的 $O(n^2)$ 让高分辨率/视频输入成本爆炸。常用缓解手段：

1. **瓶颈交叉注意力**（Q-Former/Perceiver）：让固定数量 query 去查任意多 patch；
2. **窗口注意力**（Swin/ViT 分层）：局部窗口内 self-attn + 跨窗口移位；
3. **token 合并/池化**（token merging、分辨率自适应）：多层间逐步减半 token；
4. **MLA/线性注意力** 路线同样适用于视觉长序列。

> 面试记忆点：多模态里"**图像/视频 token 数量**"是 attention 计算量的真正瓶颈，架构设计的本质是对"视觉 token 数"做压缩——Q-Former 压缩、Swin 分窗、TokenMerging 裁剪。

## 六、注意力图的可视化与可解释性

### 6.1 Attention Map 怎么读

注意力矩阵 $A \in \mathbb{R}^{n_q \times n_k}$，行 = 查询（"谁在看"），列 = 键（"看谁"）：

- 第 $i$ 行 = 查询 $i$ 的注意力分布（每行 softmax 和为 1）——看**某一帧/某 token 对什么感兴趣**；
- 第 $j$ 列 = 键 $j$ 被谁关注——看**某个对象被谁注意**（"被关注度"）；
- 横轴拉伸 = 查询，纵轴 = 键（或反之），常见图例：

| 可视化对象 | 观察内容 |
|-----------|---------|
| 文本 × 文本 | 句法/共指/长距离依赖 |
| 图像 patch × 文本 query | 语言指代的视觉区域（定位、VQA） |
| 图像 × 图像 | 区域间语义关联（部件-整体） |
| 时间帧 × 时间帧 | 运动跟踪、帧间对应 |

**多模态 attention map 的典型读法**：把文本 token 的注意力权重叠加回图像像素（按 patch 位置展开 + 平滑），得到"**注意力热力图**"（如 GradCAM 类似物），可以验证模型"看图说话时是否真的在看对的地方"——这也是评估幻觉的一个侧面手段。

### 6.2 Head 层面的可解释性结论

- **低层头**：位置/句法（看相邻 token、固定偏移）；
- **高层头**：语义/共指/长距离；
- **多模态头**：文本与图像的对应关系往往集中在少数几个"对齐头"上（如跨模态注意力中某几个头专门负责指代消解）；
- **注意力 ≠ 重要度**：attention 权重是"信息混合的比例"，不是"决策贡献度"（attention 可以是 0 也照样推理）。要解释重要度需用梯度/扰动法（如 attention rollout、integrated gradients）。

### 6.3 Head Pruning（头部剪枝）研究

核心结论（Michel et al., 2019；Voita et al., 2019）：

1. **大部分 head 可剪**：对很多任务，剪掉 50%~80% 甚至更多的 head，性能几乎不掉；
2. 少数任务是"**critical head 依赖**"型：一旦剪掉某几个关键头（如共指头、罕见词头），性能骤降——说明注意力存在功能冗余与功能专化并存；
3. 可解释性头（位置头、语法头）不一定等于任务关键头；
4. **实践启示**：剪 head 可省显存/计算（比剪 FFN 容易），但大规模模型上收益不如 GQA 等结构化改造；真正的价值在于**理解了多头注意力为什么可行**——因为多头 = 冗余的候选模式池，训练会自动挑选/组合。

## 七、注意力分数上的温度

### 7.1 训练温度（attention softmax temperature）

在 softmax 前引入温度参数 $\tau$：

$$\alpha_{ij} = \frac{\exp(e_{ij}/\tau)}{\sum_{j'} \exp(e_{ij'}/\tau)}$$

- $\tau < 1$：分布更尖锐（对高分键更集中，接近 hard attention）；
- $\tau > 1$：分布更平滑（各键权重更均匀）；
- Transformer 默认 $\tau = 1$（缩放系数 $\sqrt{d_k}$ 等价于固定温度）。

对比学习（CLIP/SigLIP）中的 $\logits / \tau$：这里的 $\tau$ 是可学习参数（如初始 0.07），作用同样是调节 softmax 锐度——**注意它与注意力温度的位置不同（在 logits 相似度上，而不是 attention 分数上）**。

### 7.2 解码温度（sampling temperature）

生成时对**输出词汇 logits** 施加的温度：

$$p(w) = \text{softmax}(\text{logits}/T)$$

- $T \to 0$：贪心（概率趋于 one-hot）；
- $T = 1$：标准分布；
- $T > 1$：分布变平，采样更随机、更多样；
- $T < 1$：分布变尖，采样更保守。

### 7.3 两者必须区分

| 维度 | 训练温度（attention $\tau$） | 解码温度（sampling $T$） |
|------|---------------------------|------------------------|
| 作用对象 | attention 权重分布 | 输出词表概率分布 |
| 位置 | 注意力 softmax 之前 | 生成采样之前 |
| 是否可学习 | 可（对比学习）或固定 | 推理超参数，不可学习 |
| 影响 | 注意力聚焦/发散程度 | 生成多样性/保守性 |
| 何时用 | 训练/前向 | 仅推理 |

> 面试易混点：有人把"注意力温度调高让模型更关注"和"解码温度调高让输出更多样"混为一谈——**一个作用在隐藏表示空间的混合比例上，一个作用在最终输出分布的采样上**。

## 八、各变体对比总结表

| 变体 | 计算复杂度 | 额外显存（注意力矩阵/KV cache） | 数值等价/近似 | 质量损失 | 代表模型 |
|------|-----------|-------------------------------|--------------|---------|---------|
| Scaled Dot Product（MHA） | $O(n^2 d)$ | $O(n^2)$（S/P）+ KV cache 基准 | 精确 | 无 | 原版 Transformer、BERT、ViT |
| FlashAttention v1/v2 | $O(n^2 d)$（FLOPs 不变） | **$O(n)$**（注意力矩阵不落盘） | **精确** | 无 | GPT-3/4 训练、LLaMA 训练 |
| Sparse（sliding/strided/global） | $O(nw)$ | $O(nw)$ | 精确（但剪掉了边） | 中（长程依赖丢失） | Longformer、BigBird、Sparse Transformer |
| Performer（Linear） | $O(nmd)$ | $O(nm)$ | **近似**（随机特征） | 较高（检索/拷贝任务明显） | Performer、Linear Transformer |
| MQA | $O(n^2 d)$ | KV cache ÷ $h$ | 精确 | 中（单 KV 容量不足） | Falcon、PaLM（部分层） |
| GQA | $O(n^2 d)$ | KV cache ÷ $(h/g)$ | 精确 | 轻微（大模型可忽略） | **LLaMA2/3、Mistral、Qwen2** |
| SWA（Mistral） | $O(nW)$ | KV cache $O(W)$/层 | 精确（剪窗口边） | 轻微（配合多层滚动） | Mistral-7B |
| MLA（DeepSeek） | $O(n^2 d)$ | KV cache → $d_c$（低秩潜变量） | 精确（低秩近似） | 轻微 | DeepSeek-V2/V3 |

> 三句话总结：
> 1. **要精确且长序列** → FlashAttention（先做这个，任何 $n^2$ 场景都该默认开启）；
> 2. **要省推理显存** → GQA（大模型事实标准）；**要更省** → MLA；
> 3. **手工稀疏/线性近似**在大模型时代基本退场（硬件不友好 + 质量损失），被 FlashAttention + GQA/MLA 的组合取代。

## 九、高频面试问答

**Q1：FlashAttention 的原理是什么？为什么快？**
三个要点：① IO 感知：把 Q/K/V 分块载入 SRAM（tiling），一个 kernel 内完成 attention，$n\times n$ 的 $S$ 和 $P$ 从不写回 HBM，省掉 $O(n^2)$ 的中间显存和读写；② online softmax：维护 running max $m$ 和 running sum $l$，单趟完成归一化，数学上与标准 softmax 等价；③ backward 重计算：不存 $S$，用 $O(n)$ 的 $m,l$ 重算梯度。由于 attention 是访存受限任务，HBM 访问大幅减少 → 端到端快 2~4 倍（v1）、6~9 倍（v2）。

**Q2：FlashAttention v2 比 v1 改进在哪？**
① 在序列维度上并行（v1 只在 batch/head 并行），head 少的长序列并行度更高；② 减少非矩阵运算：rescale 从每块一次改为最后统一一次，提升 Tensor Core 利用率；③ 更优的 warp 分配与 backward 优化，消除多余 rescale 与同步开销。v2 在 v1 基础上再快约 2 倍。

**Q3：FlashAttention 为什么数学等价？**
softmax 减同一常数结果不变（减 max 只是数值技巧）；把分母求和分块累加、归一化推迟到最后一刻，全部是线性重排。不改变任何数学结果，只改变浮点舍入顺序，因此不是近似方法，可无风险替换标准实现。

**Q4：GQA 和 MQA 的区别？为什么大模型用 GQA 而不是 MQA？**
MQA 所有 Q 头共享一组 KV（cache 降为 1/h），但 KV 容量不足，质量损失大；GQA 把 $h$ 个 Q 头分成 $g$ 组、每组共享一组 KV，cache 降为 $g/h$，容量够、质量接近 MHA。大模型（LLaMA2/3、Mistral）选 GQA 是因为它在"省显存"与"保质量"之间取得平衡：既有 $h:g$ 可控的压缩率（如 32:8），又不像 MQA 那样单组 KV 表达力不足。

**Q5：为什么 MQA/GQA 能省显存？省的是哪部分显存？**
推理自回归时每层每个 token 的 K、V 都要缓存（KV cache），大小与 head 数成正比：$2 \times L \times h \times d_k \times n$。MQA/GQA 让多个 Q 头**共享同一组 KV**，KV 头数从 $h$ 降到 1 或 $g$，cache 相应降为 $1/h$ 或 $g/h$。省的是推理期显存与访存带宽（同时提高吞吐），训练计算量基本不变。

**Q6：Performer（FAVOR+）为什么是线性复杂度？**
用正随机特征 $\phi(x) = \frac{1}{\sqrt m}e^{\|x\|^2/2}[\sin(\omega^\top x), \cos(\omega^\top x)]$ 近似核 $e^{q^\top k} \approx \phi(q)^\top\phi(k)$，于是 $A V = D^{-1}\phi(Q)(\phi(K)^\top V)$：先算 $m \times d$ 的 $\phi(K)^\top V$ 再左乘 $\phi(Q)$，复杂度 $O(nmd)$ 而非 $O(n^2d)$。代价是随机特征近似误差、注意力分布不尖锐，检索/拷贝类任务质量明显下降。

**Q7：Cross-Attention 用在什么时候？为什么多模态要用？**
两序列交互时：机器翻译的 decoder 读 encoder 输出、T5/BART 编解码、Q-Former 的 query 查图像 patch、Flamingo 的 LLM 读视觉特征。多模态用 cross-attn 的核心是"**固定数量、任务导向的 query 主动查询视觉信息**"：token 数可控（与分辨率解耦）、计算量小、天然形成信息瓶颈、且不修改冻结的视觉塔。而 LLaVA 式"拼接后 self-attn"把所有 patch 混进序列，token 多、计算大、但信息无损失。

**Q8：为什么 dot product attention 要除以 $\sqrt{d_k}$？**
若 $q,k$ 各分量独立零均值单位方差，内积方差为 $d_k$，随维度线性增长。不缩放时分数绝对值大，softmax 趋于 one-hot 饱和，梯度消失。除以 $\sqrt{d_k}$ 把方差恢复为 1，保持温和分布与流畅梯度。

**Q9：Bahdanau（Additive）和 Luong（Dot Product）注意力的本质区别？**
打分函数不同：Bahdanau 用可学习 MLP $v^\top\tanh(W_1q+W_2k)$，表达力强但无法矩阵化，RNN 时代用；Luong 用 $q^\top k$（或 $q^\top Wk$），纯矩阵乘、GPU 友好，Transformer 时代用。淘汰 Bahdanau 的主要原因是工程（矩阵化/Tensor Core），不是表达能力。

**Q10：为什么大模型主流用 GQA/MLA，而不是稀疏注意力？**
① 稀疏模式（sliding/strided/global）不规则访问，Tensor Core 用不上，理论提速实现不了；② 固定启发式模式会漏掉窗口外的长程依赖，训练质量下降；③ FlashAttention 已用"省 HBM 访问"解决 $O(n^2)$ 显存问题，dense 在可达长度内更优；④ 推理瓶颈主要是 KV cache，而稀疏 attention 不减 KV cache（窗口内历史照样要存），GQA/MLA 才直击推理显存痛点。

**Q11：MLA 为什么省显存？**
把每层每个 token 的 KV 先下投影成低维潜向量 $c$（$d_c=512$），推理只缓存 $c$，需要时用 $W_{UK}, W_{UV}$ 上投影还原多头 K/V。KV cache 从"每 token 每层 $h \times d_k$"降到"$d_c$"，DeepSeek-V2 相对 MHA 省约 93.3%。这是对"KV 的线性低秩压缩"，与 GQA"砍 KV 头数"是不同路线。

**Q12：怎么判断 attention map 里模型"看对地方了"？**
把文本 token 的注意力权重按 patch 位置映射回图像像素画热力图，观察高权重区域是否落在语义相关物体上；同时可检查注意力是否集中在 [CLS]/分隔符等位置头、是否出现"只看固定偏移"的退化模式；还要注意 attention 高 ≠ 决策重要（需配合梯度类归因验证）。

## 十、常见误区

1. **"FlashAttention 减少了 FLOPs / 复杂度"**：错。FLOPs 略增（backward 重计算），复杂度仍是 $O(n^2)$，省的是 **HBM 访问次数和中间显存**。它通过减少访存让同样 FLOPs 跑得更快。

2. **"多头注意力参数量是单头的 $h$ 倍"**：错。$d_{model}$ 固定时把特征切成 $h$ 段，Q/K/V 投影总参数量与单头等价（$W^O$ 也把 $h \cdot d_k$ 拼回 $d_{model}$）。多头是"并行子空间建模"，不是参数翻倍。

3. **"attention 权重可以直接当解释 / 剪掉低权重头无害"**：attention 是信息混合比例，不是因果贡献（权重低也可能承载关键信息）；剪头研究显示大部分头可剪，但少数 critical head 剪掉会崩，且剪头结论与任务相关。

4. **"除以 $\sqrt{d_k}$ 是为了防止数值溢出"**：溢出只是副作用，真正原因是**方差归一化**——防止 $d_k$ 增大导致分数方差 $\propto d_k$ 使 softmax 饱和、梯度消失。

5. **"稀疏注意力省 KV cache"**：错。KV cache 存的是**历史 KV**，sliding window 仍要缓存窗口内全部 KV；稀疏只省 attention 计算量。省 KV cache 的是 GQA/MQA/MLA（共享或压缩 KV）。

6. **"温度 $\tau$ 越小注意力越发散"**：反了。attention 温度 $\tau < 1$ 让分布更尖锐（更聚焦），$\tau > 1$ 更平滑；解码温度 $T > 1$ 才让输出更多样——两个温度作用对象完全不同。

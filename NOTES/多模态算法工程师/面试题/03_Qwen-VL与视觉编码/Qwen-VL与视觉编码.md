# Qwen-VL 与视觉编码

## 一、模型链路

### 3.1 `[面经]` Qwen-VL 的图像输入大致经历哪些步骤？

- **答案**：图像经过预处理和视觉编码器得到视觉特征，再经连接层映射成视觉 Token，与文本指令共同送入语言模型。
- **原因**：视觉编码器和 LLM 的特征维度、语义分布及 Token 形式不同，需要中间映射。
- **关键点**：分辨率处理；Patch 划分；视觉 Token 数；多图或视频拼接。
- **追问**：视觉 Token 数主要由哪些因素决定？

### 3.2 `[面经]` Vision Encoder、Projector 和 LLM 分别负责什么？

- **答案**：Vision Encoder 提取视觉表示，Projector 完成模态空间映射，LLM 负责跨模态理解、推理和文本生成。
- **原因**：模块职责分开后可以复用预训练视觉和语言能力，并通过不同冻结策略控制训练成本。
- **关键点**：特征维度；语义信息；训练阶段；梯度流。
- **追问**：Projector 过弱或过强分别有什么问题？

### 3.3 `[面经]` 为什么高分辨率输入能提升文档理解？

- **答案**：高分辨率能保留更多小字体、表格线和局部细节，从而改善 OCR、字段抽取和图表理解。
- **原因**：固定低分辨率会把细粒度文字压缩掉，LLM 后续无法恢复已经丢失的视觉信息。
- **关键点**：信息收益；Token 增长；显存与延迟；动态分辨率权衡。
- **追问**：高分辨率一定比低分辨率好吗？

### 3.4 `[简历]` Dynamic Resolution 和 Visual Token Pruning 的区别是什么？

- **答案**：Dynamic Resolution 主要调整输入图像或区域的分辨率，Token Pruning 主要在视觉特征序列阶段删除低价值 Token。
- **原因**：前者决定“看多细”，后者决定“保留多少”，二者可以串联但优化位置不同。
- **关键点**：输入侧 vs 特征侧；信息损失形式；对 OCR 和视频任务的影响。
- **追问**：两个模块同时使用时如何避免重复压缩？

### 3.5 `[面经]` 视觉 Token 太多会带来什么问题？

- **答案**：会增加上下文长度、Prefill 计算、KV Cache 显存和首 Token 延迟，也可能稀释文本指令与关键视觉证据。
- **原因**：Transformer 注意力和序列长度强相关，多图和视频会进一步放大成本。
- **关键点**：Token 预算；压缩比例；质量-延迟曲线；长上下文限制。
- **追问**：如何确定 Token 保留预算？

## 二、位置与视频扩展

### 3.6 `[基础]` 多图输入时如何避免图像之间的信息混淆？

- **答案**：为不同图像设置明确的边界、图像索引和空间/时间标记，并在指令中明确引用对象。
- **原因**：多张图共享序列时，模型需要知道视觉 Token 属于哪一张图以及图像之间的关系。
- **关键点**：图像占位符；时间戳；坐标；跨图关系。
- **追问**：多图推理错误如何定位？

### 3.7 `[面经]` 视频为什么不能简单当作很多张图片？

- **答案**：视频还包含时间顺序、动作变化、持续时间和跨帧关系，单独理解每帧容易丢失事件边界和运动信息。
- **原因**：视频任务需要回答“何时发生”和“如何变化”，不仅是“画面里有什么”。
- **关键点**：采样策略；时间编码；跨帧聚合；长视频成本。
- **追问**：如果没有专门的视频编码器，如何增强时序建模？

### 3.8 `[场景]` 如何定位 VLM 是视觉编码不足还是语言推理不足？

- **答案**：构造分层测试：纯识别、OCR、区域定位、视觉关系、需要常识的推理题，并对比原图、裁剪图和文本描述输入。
- **原因**：不同测试可以隔离感知和推理能力；如果文本描述输入正常而原图失败，更可能是视觉链路问题。
- **关键点**：控制变量；错误类型；跨模型对比；可视化注意力或 Token。
- **追问**：注意力图能否直接证明模型看到了正确区域？

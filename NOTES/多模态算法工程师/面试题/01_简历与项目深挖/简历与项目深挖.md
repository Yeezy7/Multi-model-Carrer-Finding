# 简历与项目深挖

## 一、长视频时序检索与高效多模态理解

### 1.1 `[简历]` 请介绍这个长视频项目解决了什么问题？

- **答案**：项目解决长视频冗余帧多、视觉 Token 数量大、文本相关事件难定位的问题，采用“全局粗检索 → 候选片段细采样 → 帧内 Token Pruning”的三级流程。
- **原因**：直接把全视频送入 VLM 会带来上下文过长、Prefill 慢和无关信息干扰，因此先缩小时间范围，再压缩视觉表示。
- **关键点**：文本 Query 驱动；Temporal Importance Score；Visual Token Pruning；效果与延迟共同评估。
- **追问**：为什么不直接均匀采样更多帧？

### 1.2 `[简历]` Temporal Importance Score 如何设计？

- **答案**：将 Query-Frame 跨模态相关性、相邻帧特征变化和 Scene Change 等信号融合成时间重要性分数，再召回 Top-K 时间窗口。
- **原因**：只用语义相似度可能漏掉动作变化，只用场景变化又可能召回与 Query 无关的镜头，融合能兼顾语义和时序变化。
- **关键点**：各分量归一化；权重可在验证集调节；Top-K 后保留时间邻域。
- **追问**：如何避免相邻窗口重复召回？

### 1.3 `[简历]` Uniform Sampling、Temporal Retrieval 和 Retrieval + Token Pruning 如何比较？

- **答案**：统一模型、数据和推理配置，只改变视频输入策略，比较 Temporal F1、视觉 Token 数和端到端延迟。
- **原因**：否则无法判断收益来自采样策略还是模型、硬件和 batch 配置变化。
- **关键点**：简历结果是 Temporal Retrieval 将 F1 从 41.8% 提升到 45.1%；加入 Token Pruning 后为 44.5%，Token 减少 30.5%，延迟从 3.92 秒降到 3.13 秒。
- **追问**：为什么 Token Pruning 后 F1 会下降？

### 1.4 `[简历]` Visual Token Pruning 如何避免删掉关键区域？

- **答案**：结合 Patch-Query 相关性、视觉区域重要性和保留比例进行筛选，并设置最低保留数或关键区域保护策略。
- **原因**：单纯按注意力或相似度裁剪，可能删除小目标、文字和动作变化等低面积但高价值信息。
- **关键点**：分层压缩；保留全局 Token；按任务做阈值；用子集评测验证信息损失。
- **追问**：如何做 Token Pruning 的消融实验？

### 1.5 `[简历]` 如果要求进一步降低长视频推理延迟，你会怎么做？

- **答案**：先拆分解码、特征提取、检索、Prefill 和 Decode 的耗时，再针对瓶颈优化缓存、批处理、并行化和 Token 数量。
- **原因**：端到端延迟不一定由 VLM 本身决定，视频解码和数据搬运也可能成为瓶颈。
- **关键点**：离线缓存视觉特征；异步解码；动态 Top-K；KV Cache；FP16/量化；分阶段 benchmark。
- **追问**：如何保证延迟优化不牺牲关键事件召回率？

## 二、复杂文档多模态理解与结构化信息抽取

### 1.6 `[简历]` 请介绍文档理解项目的整体链路。

- **答案**：以 Qwen3-VL 为基础，构造文档 QA、KIE 和图表理解数据，通过 QLoRA 多任务 SFT，并用 Dynamic Resolution 和困难样本增强提升复杂文档能力。
- **原因**：文档任务同时受视觉分辨率、版面结构、OCR 质量和领域数据影响，只调模型或只加分辨率都不够。
- **关键点**：DocVQA、ChartQA、KIE；全局页面 + 局部细节区域；Task Sampling；ANLS/F1。
- **追问**：为什么要同时保留全局页面和局部裁剪？

### 1.7 `[简历]` Dynamic Resolution 解决了什么问题？

- **答案**：根据文字、表格和图表区域的信息密度，对关键区域进行高分辨率裁剪，同时保留全局页面作为版面上下文。
- **原因**：固定分辨率会让小字体和密集表格缩小丢失；只裁局部又会丢掉页面结构和跨区域关系。
- **关键点**：区域检测或启发式选择；分辨率预算；全局与局部输入融合；延迟评估。
- **追问**：区域选择错误会造成什么问题？

### 1.8 `[简历]` QLoRA 为什么适合这个文档项目？

- **答案**：QLoRA 以低比特量化冻结基座模型，再训练 LoRA 低秩适配器，在显存有限时完成领域多任务适配。
- **原因**：文档项目需要尝试多种数据配比和增强策略，QLoRA 能降低训练成本并减少全量微调的显存压力。
- **关键点**：量化基座；LoRA 注入线性层；训练适配器；验证过拟合和量化误差。
- **追问**：QLoRA 的量化误差如何评估？

### 1.9 `[简历]` DocVQA、ChartQA 和 KIE 的指标为什么不同？

- **答案**：DocVQA 常用 ANLS 衡量文本答案相似度，ChartQA关注图表问答准确性，KIE 通常按字段级 Precision、Recall、F1 评估。
- **原因**：文本编辑距离、数值推理和结构化字段匹配的错误形式不同，不能用单一指标覆盖。
- **关键点**：指标与任务目标一致；报告整体和困难子集；保留失败样本分析。
- **追问**：为什么不能只报告平均分？

### 1.10 `[简历]` 文档模型出现 OCR 错误时，如何定位问题？

- **答案**：把链路拆成图像质量、区域裁剪、视觉识别、文本生成和结构化解析五段，分别构造样本并记录错误类型。
- **原因**：最终字段错误可能来自图像模糊，也可能来自模型推理或 JSON 解析，必须先定位责任环节。
- **关键点**：低清、旋转、压缩、表格跨页、数字混淆；按字段和版面切片评估。
- **追问**：OCR 外接工具和端到端 VLM 如何选？

## 三、实习项目：检测与视频行为

### 1.11 `[简历]` YOLO 项目中你如何处理小目标和复杂背景？

- **答案**：从数据清洗、尺度增强、困难样本回溯、Hard Negative、输入分辨率和阈值调优几方面协同优化。
- **原因**：小目标漏检通常不是单一模型结构问题，数据分布、特征分辨率和后处理都会影响结果。
- **关键点**：按场景统计漏检；区分远小目标、遮挡和低照度；验证集保持独立。
- **追问**：什么时候应该改模型结构而不是继续加数据？

### 1.12 `[简历]` 如何将单帧目标检测扩展为作业行为判定？

- **答案**：将检测结果转成带时间戳的器具状态，再通过状态机或时序规则校验“断电 → 验电 → 接地”等操作顺序。
- **原因**：单帧检测只能回答“看到了什么”，不能判断操作是否按流程发生。
- **关键点**：目标置信度过滤；状态转移；超时和缺失处理；误检回滚。
- **追问**：如果检测结果抖动，状态机如何稳定？

### 1.13 `[简历]` RTSP 实时推理 Pipeline 如何设计？

- **答案**：包括视频解码、帧采样、预处理、模型推理、结果解析、时序判定和告警输出，并用队列或线程解耦各阶段。
- **原因**：串行处理会让解码、推理和展示互相阻塞，实时系统需要控制缓存和丢帧策略。
- **关键点**：端到端延迟；吞吐；队列长度；关键帧保留；断流重连。
- **追问**：实时性和完整性发生冲突时如何取舍？

## 四、论文与研究能力

### 1.14 `[简历]` HVA-CLIP 的核心贡献如何用一句话说明？

- **答案**：通过层次化视觉-语义对齐增强 CLIP 在零样本异常检测中的细粒度异常感知能力。
- **原因**：零样本异常检测依赖图文语义匹配，单一全局特征容易忽略局部异常区域。
- **关键点**：异常类别泛化；全局与局部对齐；零样本设置；与 CLIP 基线比较。
- **追问**：零样本异常检测和监督检测的主要差异是什么？

### 1.15 `[简历]` 你的实验如何证明改动确实有效？

- **答案**：固定数据划分和训练配置，设置基线，逐项加入模块做消融，并同时报告主指标、效率和困难子集结果。
- **原因**：只报告最终最好结果无法说明收益来自哪个模块，也无法体现效果和成本的权衡。
- **关键点**：单变量对比；重复实验；统计波动；失败案例；复杂度变化。
- **追问**：如果主指标提升但线上延迟变差，你如何决策？

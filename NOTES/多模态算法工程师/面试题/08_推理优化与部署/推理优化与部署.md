# 推理优化与部署

## 一、性能分析

### 8.1 `[基础]` 模型参数量、显存和推理延迟有什么区别？

- **答案**：参数量是权重数量，显存还包括激活、KV Cache 和临时空间，推理延迟是一次请求的耗时。
- **原因**：参数量相同的模型可能因输入长度、精度、算子实现和硬件不同而有不同延迟和显存。
- **关键点**：权重显存；激活显存；KV Cache；Prefill/Decode。
- **追问**：为什么视觉 Token 增加会显著影响首 Token 延迟？

### 8.2 `[简历]` 你的项目如何定位端到端延迟瓶颈？

- **答案**：将延迟拆成视频解码、预处理、视觉编码、检索、Token 压缩、Prefill、Decode 和后处理，逐段计时。
- **原因**：只测模型 forward 无法解释真实服务延迟，优化方向可能被误判。
- **关键点**：同步/异步；GPU/CPU；数据搬运；P50/P95；端到端指标。
- **追问**：为什么不能只看平均延迟？

### 8.3 `[场景]` Prefill 和 Decode 分别是什么？

- **答案**：Prefill 处理已有的完整输入上下文并建立 KV Cache，Decode 基于 Cache 逐 Token 生成输出。
- **原因**：多模态输入通常让 Prefill 成本很高，长回答则可能让 Decode 成为主要瓶颈。
- **关键点**：输入长度；输出长度；KV Cache；批处理策略。
- **追问**：Visual Token Pruning 主要优化哪一阶段？

## 二、量化与 TensorRT

### 8.4 `[面经]` FP16、BF16 和 INT8 如何选择？

- **答案**：FP16 适合多数 GPU 推理，BF16 动态范围更大，INT8 显存和计算更省但需要校准并关注精度损失。
- **原因**：不同任务和硬件对动态范围、吞吐、算子支持和误差敏感度不同。
- **关键点**：硬件支持；校准集；敏感层；精度-延迟曲线。
- **追问**：为什么不能简单把所有层都量化？

### 8.5 `[基础]` TensorRT 的主要优化方向有哪些？

- **答案**：图优化、算子融合、精度转换、内存复用、Kernel/Tactic 选择和动态 shape 配置。
- **原因**：推理引擎需要针对固定模型、输入范围和硬件生成高效执行计划。
- **关键点**：ONNX 导出；engine 构建；workspace；profile；Plugin。
- **追问**：ONNX 能导出但 TensorRT 构建失败，如何排查？

### 8.6 `[场景]` 量化后精度下降如何定位？

- **答案**：先对比逐层输出和整体指标，检查校准集覆盖、激活范围、异常层和算子精度，再对敏感层保留更高精度。
- **原因**：量化误差往往集中在少数激活分布异常或对精度敏感的层。
- **关键点**：逐层误差；校准数据；混合精度；回归样本。
- **追问**：PTQ 和 QAT 什么时候分别使用？

## 三、服务化与视频流

### 8.7 `[简历]` RTSP 视频流服务如何保证稳定性？

- **答案**：处理断流重连、解码异常、帧队列积压、显存释放、超时和结果回传，并对关键指标做监控。
- **原因**：视频服务的故障不仅来自模型，也来自网络、解码器、队列和资源泄漏。
- **关键点**：丢帧策略；背压；心跳；超时；进程隔离。
- **追问**：队列积压时是丢旧帧还是丢新帧？

### 8.8 `[场景]` 如何设计多模态模型推理服务？

- **答案**：API 层接收请求，预处理服务统一图像/视频格式，推理 Worker 批处理或并发执行，结果层做结构化校验和监控。
- **原因**：将输入处理、模型执行和业务结果解耦，便于扩容、降级和定位问题。
- **关键点**：请求队列；动态 batch；超时；模型版本；灰度发布。
- **追问**：GPU 不足时如何降级？

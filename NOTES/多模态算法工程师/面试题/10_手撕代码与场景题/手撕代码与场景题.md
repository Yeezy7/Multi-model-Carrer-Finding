# 手撕代码与场景题

## 一、Python / PyTorch

### 10.1 `[手撕]` 手写 Top-K 选择并说明复杂度。

- **答案**：若只需要 Top-K，可维护大小为 K 的小根堆，遍历一次数据，复杂度 `O(N log K)`，空间 `O(K)`。
- **原因**：不必对全部 N 个元素排序；当 K 远小于 N 时更高效。
- **关键点**：重复值；空输入；K 超界；稳定性。
- **追问**：如果需要按分数降序输出，如何处理堆内元素？

### 10.2 `[手撕]` 如何计算一个 PyTorch 模型的可训练参数量？

- **答案**：遍历模型参数，筛选 `requires_grad=True` 的参数并累加 `numel()`。
- **原因**：`numel()` 返回参数元素总数，能正确处理矩阵、偏置和多维张量。
- **关键点**：总参数 vs 可训练参数；共享参数去重；单位换算。
- **追问**：LoRA 模型应该统计哪些参数？

### 10.3 `[手撕]` 如何实现带 mask 的 Softmax？

- **答案**：将无效位置填充为负无穷，再减去最大值后做指数归一化，避免数值溢出。
- **原因**：负无穷位置 Softmax 后接近 0，减最大值能提高指数计算稳定性。
- **关键点**：维度；全无效行；dtype；广播。
- **追问**：为什么要先减最大值？

### 10.4 `[手撕]` 如何实现一个滑动窗口平均？

- **答案**：维护窗口和，右端加入新元素，左端移出旧元素，每次用窗口和除以窗口长度，复杂度 `O(N)`。
- **原因**：避免每个窗口重复遍历 K 个元素，将复杂度从 `O(NK)` 降为线性。
- **关键点**：窗口不足 K；边界；浮点误差；流式输入。
- **追问**：如果要计算中位数，数据结构如何变化？

## 二、系统设计

### 10.5 `[场景]` 设计一个长视频文本检索系统。

- **答案**：离线抽帧和特征缓存，在线对 Query 编码并召回候选窗口，再局部采样、Token 压缩并调用 VLM。
- **原因**：把高成本视觉编码和低频处理前置，在线只处理与 Query 相关的候选内容。
- **关键点**：召回率；时间窗口；缓存；延迟；结果可解释性。
- **追问**：新增视频后如何增量更新索引？

### 10.6 `[场景]` 设计一个文档结构化抽取服务。

- **答案**：上传与权限校验 → 文档解析 → 页面/区域切片 → 检索 → VLM 抽取 → Schema 校验 → 证据和结果入库。
- **原因**：分层流程便于处理超长文档、局部细节、输出格式和失败重试。
- **关键点**：页码坐标；异步任务；幂等；人工复核；字段置信度。
- **追问**：如何支持百万级文档？

### 10.7 `[场景]` 线上多模态模型延迟突然升高，如何排查？

- **答案**：先看请求输入长度、视觉 Token、队列等待、GPU 利用率、显存、模型版本和下游服务，再做分阶段对比。
- **原因**：延迟升高可能是数据分布变化、资源拥塞或服务链路故障，不能直接归因于模型。
- **关键点**：P50/P95；分桶；火焰图；回滚；限流。
- **追问**：GPU 利用率低但延迟高说明什么？

### 10.8 `[场景]` 多模态模型效果和成本冲突时如何决策？

- **答案**：先明确业务硬指标，再画效果-Token-延迟-显存曲线，选择满足质量下限的最低成本方案。
- **原因**：工程最优解不是单纯追求最高准确率，而是满足 SLA 和预算的综合最优。
- **关键点**：质量下限；降级策略；缓存；模型路由；灰度验证。
- **追问**：如何设计按请求难度的模型路由？

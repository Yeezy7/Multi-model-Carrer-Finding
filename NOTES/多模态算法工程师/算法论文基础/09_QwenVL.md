# Qwen-VL 系列：从固定分辨率到原生任意分辨率（2023 → 2025）

> 本笔记覆盖通义千问视觉语言模型家族的完整技术演进：Qwen-VL（2023）→ Qwen2-VL（2024）→ Qwen2.5-VL（2025.01）→ Qwen3-VL（2025）。核心线索有两条：**视觉输入怎么变成 LLM 能读的 token 序列**（分辨率策略 + token 压缩），以及**位置信息怎么在 3D 世界（时间×高×宽）里编码**（M-RoPE 家族）。面试被问"动态分辨率怎么做""M-RoPE 是什么""视觉 token 怎么压缩"时，本文是完整答案。

---

## 一、一句话解释与系列演进总览

### 1.1 一句话解释

> **Qwen-VL 系列 = 阿里通义的视觉语言模型家族，核心竞争力是把"任意分辨率/任意长宽比的图像与视频"无损地变成 token 喂给 LLM，并用 3D 位置编码（M-RoPE）让 LLM 真正感知空间布局与时间顺序。**

三代半的演进可以浓缩成四句话：

1. **Qwen-VL（2023）**：把 OpenCLIP 的 ViT-bigG 当眼睛、单层 cross-attention 当"翻译官"，把视觉 token 压成固定 256 个——解决了"有视觉能力"，但分辨率固定 448；
2. **Qwen2-VL（2024）**：扔掉固定分辨率，发明 **Naive Dynamic Resolution**（动态分辨率）与 **M-RoPE**（3D 位置编码）——解决了"看得清"，文档/OCR 能力大幅跃升；
3. **Qwen2.5-VL（2025.01）**：把 ViT 的全局注意力换成 **Window Attention**，给 token 合并器加"动态预算"，时间轴对齐绝对时间——解决了"看得快、看得久、看得准时间"；
4. **Qwen3-VL（2025）**：视觉塔换 **SigLIP-2 架构**、位置编码升级 **Interleaved-MRoPE**、引入 **DeepStack** 多级特征注入与文本时间戳，上下文拉满 256K（可扩 1M）——解决了"看得懂、想得深、记得久"。

### 1.3 三条演进主线（记忆框架）

```text
主线一 分辨率：固定 224/448  → 动态分辨率（切 sub-image）→ 原生分辨率 + 窗口注意力
主线二 位置编码：绝对 PE    → 2D-RoPE（ViT 内）→ M-RoPE 3D（LLM 内）→ Interleaved-MRoPE

```

## 二、Qwen-VL（第一代，2023）：用 Cross-Attention 打开视觉大门

> 第一代是"验证范式"的模型：**冻结视觉塔 + 重采样器压缩 + LLM 生成**。它证明了"不用训视觉塔也能做出能看图、能定位、能读文字的 VLM"，代价是分辨率固定、token 固定、没有时空建模。理解这一代的关键是它的**位置编码体系**——论文里最容易被一笔带过、面试却最爱深挖的地方。

### 2.1 架构总览

Qwen-VL 由三部分组成，总参数量 9.6B：

| 组件 | 参数量 | 初始化 | 说明 |
|------|--------|--------|------|
| LLM | 7.7B | Qwen-7B | 语言底座，中英双语 |
| 视觉编码器 | 1.9B | OpenCLIP ViT-bigG | patch 14，阶段 1/3 冻结 |
| 位置感知 VL Adapter | 0.08B | 随机初始化 | 单层 cross-attention 重采样器（Re-Attention） |

```text
图像(224/448²) ──> ViT-bigG (patch 14) ──> 256/1024 个 patch token
                                                │
                     位置感知 VL Adapter（单层 Cross-Attention，256 个可学习 query）
                     ★ 2D 绝对位置编码注入 Q-K 对（核心设计）
                                                │
                                      固定 256 个视觉 token
                                                │
                                     Qwen-7B LLM（文本侧 1D RoPE）生成
```

**三个组件的分工**：
- **ViT-bigG**：把图像变成 patch token（只做"像素 → 特征"，不含语言信息）；
- **VL Adapter**：把可变数量的 patch token 压成固定 256 个，同时保住空间位置（"翻译官 + 位置保险丝"）；
- **LLM**：把视觉 token 当"特殊单词"接进文本序列，做统一的 next-token 预测。

### 2.2 组件一：视觉编码器 ViT-bigG（OpenCLIP 预训练，冻结）

| 属性       | 值                                                  |
| -------- | -------------------------------------------------- |
| 出处       | OpenCLIP 预训练的 ViT-bigG                             |
| 参数量      | 1.9B（远超 Qwen2 自研的 675M）                            |
| Patch    | 14×14                                              |
| 输入分辨率    | 阶段 1 用 224×224；阶段 2/3 用 448×448                    |
| Patch 数量 | 224 → $16\times16=256$ 个；448 → $32\times32=1024$ 个 |
| 位置编码     | **可学习绝对位置编码**（OpenCLIP 自带，448 时按 224 的权重插值扩展）      |
| 冻结策略     | 阶段 1 训练、阶段 2 训练、阶段 3 冻结                            |

> **数字澄清（面试易错）**：网上流传"448 个 token 压到 256 个"是**错误说法**——448 是**分辨率（像素）**不是 token 数。正确事实：448×448 输入产生 1024 个 patch token（$(448/14)^2$），重采样后压到 256 个（**4 倍压缩**）；224×224 输入产生 256 个 patch，重采样后仍是 256 个（不压缩，只重排列信息）。

### 2.3 组件二：位置感知 VL Adapter（Re-Attention 重采样器）

**为什么需要重采样**：patch token 数量随分辨率变化（256 或 1024），而 LLM 的序列位置有限、batch 内还需要统一形状。直接全量喂 LLM 序列不可控，所以必须压到**固定长度**。

**结构**：单层 cross-attention，用 256 个可学习 query 从图像 patch 中抽取信息：

$$\text{Attn}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d}}\right) V$$

- $Q \in \mathbb{R}^{256 \times d}$：256 个**可学习 query 向量**（每个 query 相当于"我要从图像里提取哪类信息的模板"）；
- $K, V \in \mathbb{R}^{N \times d}$：来自 ViT 的图像 patch 特征（$N=256$ 或 $1024$）；
- 输出恒为 256 个 token，**与输入分辨率无关**——这是"固定 256 token"的来源。

**为什么叫 "Re-Attention"**：它本质是"再注意力"——先让 ViT 做过自注意力，再用一层跨注意力把结果**重新组织**成固定数量、保留位置的 token。命名强调"又一次注意力"而非"新的编码器"。

### 2.4 位置编码体系（本篇重点：Qwen-VL 的三层位置编码）

Qwen-VL 里位置信息**分三层**处理，每一层解决不同问题。面试讲位置编码，把这三层讲清楚就赢了。

```text
第一层（ViT 内部）：可学习绝对位置编码（2D 网格位置）
    ↓ 作用：让 patch token 之间能区分"上/下/左/右"
第二层（VL Adapter 内）：2D 绝对位置编码注入 Q-K 对 ★ 本模型最大创新
    ↓ 作用：压缩到 256 token 时不丢空间布局 → 定位能力来源
第三层（LLM 内部）：文本 1D RoPE，视觉 token 只占普通序列位置
    ↓ 作用：保证视觉 token 与文本 token 能混在一起生成
```

#### 2.4.1 第一层：ViT 内部的可学习绝对位置编码

ViT-bigG 是 OpenCLIP 预训练的，自带**可学习绝对位置编码**：每个 patch 网格位置一个可学习向量（224 时 16×16=256 个位置向量，448 时按 224 的位置编码**双线性插值**成 32×32=1024 个）。

- 作用：patch 与 patch 之间的自注意力能感知"谁在谁旁边"；
- 局限：它是**图像内部的编码**，只保证"图内空间感"，信息出了 ViT 就不管用——所以第二层必须接力。

#### 2.4.2 第二层：2D 绝对位置编码注入 Q-K 对（核心设计）

**问题**：cross-attention 压缩的本质是"加权求和"：$o = \sum_i \alpha_i v_i$。如果 K 不带位置信息，query 只能按"内容像不像"去加权——它无法区分"左上角的猫"和"右下角的猫"，**压缩后空间信息会被加权求和抹平**。那模型就只知道"有只猫"，不知道"猫在哪"，更无法画框。

**解法（论文原话）**：*"we inject the 2D position information into the query-key pairs, avoiding the loss of spatial position information during the compression"*——把 2D 绝对位置编码**同时加到 Q 和 K 上**（所以叫"注入 query-key pair"，是加到 Q、K 两者上，不是只加一边，更不是"加到 pair 之外"）：

$$\tilde{Q} = Q + \text{PE}_{2D}, \qquad \tilde{K} = K + \text{PE}_{2D}$$

注意力分数变成：

$$\alpha_{q,k} = \text{softmax}\left(\frac{\tilde{Q}\tilde{K}^\top}{\sqrt{d}}\right) = \text{softmax}\left(\frac{QK^\top + Q\cdot\text{PE}^\top + \text{PE}\cdot K^\top + \text{PE}\cdot\text{PE}^\top}{\sqrt{d}}\right)$$

展开后可以直观看到位置的作用：
- $QK^\top$：内容相似度；
- $Q\cdot\text{PE}^\top$ 与 $\text{PE}\cdot K^\top$：**query 与"某个位置的 patch"的匹配度**（query 可以问"这个位置的 patch 里有什么"）；
- $\text{PE}\cdot\text{PE}^\top$：位置与位置的交互（相对空间距离）。

**直觉比喻**：没有位置编码的压缩 = "把一桌菜打成糊装进 256 个罐子，吃的时候不知道哪罐是哪个位置的菜"；加了 Q-K 位置注入 = "每个罐子都带坐标标签，还能记住菜原本摆在桌子的哪个区域"。**注意力权重里隐式编码了空间关系**，256 个压缩 token 因此保留了布局信息。

**这就是 Qwen-VL 能做视觉定位（referring / bounding box）的根基**——它也是 Adapter 被称为"位置感知（position-aware）"的原因。

#### 2.4.3 第三层：LLM 内的 1D RoPE（视觉 token 只占序列位置）

压缩后的 256 个视觉 token 被 `<img>`/`</img>` 包起来、插进文本序列，在 LLM 里和其他文本 token 一样**只按序列顺序编号**（Qwen-7B 的 1D RoPE）：

```text
序列:  [<img> | v_1 | v_2 | ... | v_256 | </img> | 这 | 张 | 图 | 里 | 有 | 什 | 么 | ？]
RoPE:    0     1     2     ...   256    257    258   259  ...
```

- 作用：视觉 token 和文本 token 共享同一套位置编号，能无缝混合做自回归生成；
- 局限：**序列位置 ≠ 空间位置**。第一层/第二层的位置信息在进入 LLM 前已经"浓缩"进 token 的内容里了，LLM 侧没有显式的 2D/3D 坐标概念。

#### 2.4.4 三层位置编码的后果总结

| 能力                 | 由哪层提供             | 表现           |
| ------------------ | ----------------- | ------------ |
| 图内空间感（patch 间相对位置） | 第一层（ViT 绝对 PE）    | 视觉塔特征正确      |
| 压缩后仍能定位（画框、指代）     | 第二层（Q-K 位置注入）     | grounding 能力 |
| 图文混合生成             | 第三层（1D RoPE 统一编号） | 对话/生成正常      |
| 视频时间先后             | **三层都没有**         | 时间感知弱（见 2.7） |

> **预告对比**：Qwen-VL 的三层方案是"各管一段"；Qwen2-VL 用 **M-RoPE** 把时间/高/宽三维位置直接编码进 LLM 的旋转位置里（见第三节），视觉塔内改 2D-RoPE——**位置编码从"分层接力"变成"统一 3D"**，这是两代最本质的架构差异之一。

### 2.5 三阶段训练

| 阶段          | 数据                                              | 分辨率     | 冻结策略                              |
| ----------- | ----------------------------------------------- | ------- | --------------------------------- |
| 阶段 1 预训练    | 清洗后 14 亿图文对（LAION 等，77.3% 英文 / 22.7% 中文）        | 224×224 | **冻结 LLM**，训练 ViT + Adapter（5 万步） |
| 阶段 2 多任务预训练 | 细粒度标注：字幕、VQA、定位（image-caption-box 三元组）、OCR、交错图文 | 448×448 | **全部解冻**（ViT 低学习率）                |
| 阶段 3 指令微调   | 350K 指令数据（Chat 格式）                              | 448×448 | **冻结 ViT**，训练 LLM + Adapter       |

冻结策略的三点讲究：
1. **阶段 1 冻结 LLM**：先把"图像 → 视觉 token"这条路打通（否则 LLM 收到的视觉 token 是噪音，梯度互相干扰）；
2. **阶段 2 全解冻**：多任务数据（尤其定位三元组）让视觉塔与 LLM 充分对齐——这也是位置感知真正被训出来的阶段；
3. **阶段 3 冻结 ViT**：指令数据量小（350K），冻结视觉塔防止特征漂移与过拟合。

### 2.6 输入输出接口：为定位而生

- 特殊 token：`<img>`/`</img>` 包裹视觉 token 序列，`<box>`/`</box>` 标记检测框，`<ref>`/`</ref>` 标记被指代的对象；
- 框坐标归一化到 $[0, 1000)$，文本化为 `(x_tl, y_tl), (x_br, y_br)`（左上、右下角点）；
- **位置用文本 token 表达**：模型输出 `<box>(256,145),(672,512)</box>` 这样的字符串，无需专门的坐标输出头——这是"用语言完成定位"的设计，Qwen2-VL 沿用至今。

### 2.7 能力与局限（为什么必须被第二代取代）

**能力**：图文对话、视觉定位（ref/box）、OCR 阅读、中英双语、交错图文输入。

**局限**：

1. **固定分辨率（224→448）**：448×448 对文档、小字 OCR 依然不够清晰；
2. **固定 256 token**：高分辨率图像信息被过度压缩（1024 patch → 256 token），细节丢失；
3. **没有时间维位置编码**（对应 2.4 的第三层缺陷）：视频只能抽帧后**拼成一张复合大图**输入（帧间无时间位置），模型感知不到"先后顺序"与"时间间隔"，跨帧推理、时间戳定位基本不可用；
4. **ViT 阶段 1/3 冻结**：视觉表示与 LLM 对齐不充分，可训练性低于 Qwen2-VL 的全参数方案。

## 三、Qwen2-VL（第二代，2024）：动态分辨率 + M-RoPE（面试重点）

> 这是全系列最重要的一代：**Naive Dynamic Resolution** 和 **M-RoPE** 两个创新奠定了后两代的基础，几乎所有 Qwen 系面试题都从这里出。

### 3.1 架构与模型家族

| 模型 | 视觉编码器 | LLM | 总参数 | 定位 |
|------|-----------|-----|--------|------|
| Qwen2-VL-2B | 675M | 1.5B | 2B | 端侧 |
| Qwen2-VL-7B | 675M | 7.6B | 8B | 性价比主力 |
| Qwen2-VL-72B | 675M | 72B | 72B | 旗舰，对标 GPT-4o |

**注意：三个尺寸共用同一个 675M ViT**——视觉计算开销不随 LLM 规模增长。ViT 使用 patch 14，去掉了绝对位置编码，改用 **2D-RoPE**（这是动态分辨率的前提：没有固定序列长度的绝对位置假设）。

### 3.2 Naive Dynamic Resolution（朴素动态分辨率）

#### 3.2.1 动机：固定分辨率的三大问题

1. **文档/OCR 场景失效**：小字在 448×448 下模糊不可读；
2. **极端长宽比失真**：横版全景图/竖版截图被 resize 后内容被压扁；
3. **token 浪费**：简单图被强制放大到固定分辨率，白耗算力。

#### 3.2.2 算法流程（五步）

```text
输入：任意分辨率原图 (H, W)，token 预算 max_pixels
  ↓
① 等比缩放：保持长宽比，使 H×W ≤ max_pixels
    缩放因子 s = min(1, √(max_pixels / (H·W)))
  ↓
② 对齐网格：H' = round_to_multiple(s·H, 28)，W' = round_to_multiple(s·W, 28)
    为什么是 28？patch 14 × 合并 2 = 28（合并后每个 token 覆盖 28×28 像素）
  ↓
③ 切分 sub-image：超过 448×448（= 32×32 patches）就切成多个 sub-image，逐个编码
  ↓
④ 分别过 ViT：每个 sub-image 独立得到 patch 特征
  ↓
⑤ 合并 + 拼接：每个 sub-image 的 2×2 patch 合并为 1 个 token，按左上→右下顺序拼回一条序列
    每张图以 <|vision_start|> 开始、<|vision_end|> 结束
```

关键参数（论文 + 开源配置）：

| 参数 | 值 | 含义 |
|------|-----|------|
| 缩放对齐单位 | 28（= patch 14 × merge 2） | 缩放后 H、W 均为 28 的倍数 |
| sub-image 上限 | 448×448（32×32 patches） | 大图切成若干 sub-image |
| 单图 token 上限 | 16384（7B/72B 默认 max_pixels = 16384×28×28） | 决定 GPU 显存峰值 |
| 单图 token 下限 | 4（min_pixels = 4×28×28） | 小图至少放大到 4 个 token |

#### 3.2.3 token 数计算公式

设缩放后尺寸为 $H' \times W'$（均为 28 的倍数），则进入 LLM 的视觉 token 数为：

$$N_{\text{tok}} = \frac{H'}{28} \times \frac{W'}{28} = \frac{H' \cdot W'}{784}$$

例如：224×224 → $\frac{224}{28}\times\frac{224}{28} = 8 \times 8 = 64$ 个 token（加上首尾 2 个特殊 token 共 **66 个**，论文原文数据）；448×448 → 16×16 = 256 个。

#### 3.2.4 不同长宽比的 sub-image 切分示例

| 原图              | 缩放后（对齐 28）            | sub-image 数量      | 合并后 token 数 |
| --------------- | --------------------- | ----------------- | ----------- |
| 224×224 方形      | 224×224               | 1                 | 64          |
| 336×224         | 336×224（12×8 个 28-格）  | 1                 | 96          |
| 896×560         | 896×560（32×20）        | 2（各 32×16 与 32×4） | 640         |
| 1600×900 横版     | 约 1120×644 → 1120×644 | 4 左右              | 约 920       |
| 3000×1200 长文档截图 | 缩放至预算内再切              | 若干                | ≤ 16384     |

切分顺序固定为**行优先（row-major）**，且每个 sub-image 的 token 在 M-RoPE 中保留其全局网格坐标——切分是"空间分区"而不是"各自独立"，LLM 依然能感知每个 sub-image 在整图中的位置。

#### 3.2.5 消融结论（论文 3.3.1）

- 固定分辨率没有一个值能在所有 benchmark 上同时最优，动态分辨率平均 token 更少、效果最稳；
- 适当提高 min_pixels（把小图放大）能提升 InfoVQA、OCRBench 等感知类任务；
- **但 min_pixels 过大反而损害 OCRBench**：大量极小图被过度放大，脱离训练分布（OOD）。

### 3.3 M-RoPE（Multimodal RoPE，3D 位置编码）

#### 3.3.1 背景：1D RoPE 的局限

标准 RoPE 把位置编码进 token 间的**相对角度**：对第 $i$ 对频率维度，位置 $m$ 处旋转角为 $\theta_i \cdot m$，其中 $\theta_i = b^{-2i/d}$（通常 $b=10000$）。它只有**一根时间轴**，无法表达"图像里第几行第几列"或"视频第几帧"。

#### 3.3.2 核心思想：把位置拆成三维

M-RoPE 把每个 token 的位置表示成三元组：

$$p = (t, h, w)$$

- $t$：时间轴（视频帧序 / 多图序号 / 图片内恒为常数）；
- $h$：高度轴（行坐标）；
- $w$：宽度轴（列坐标）。

位置编码由三个轴的分量组合而成（论文表述为"把旋转嵌入分解为 temporal、height、width 三个分量"）：

$$\mathrm{M\text{-}RoPE}(t, h, w) = \mathrm{Rot}_t(t) \circ \mathrm{Rot}_h(h) \circ \mathrm{Rot}_w(w)$$

实现上（开源模型配置 `mrope_section`）：每个 head 的维度被**分组**，不同分组使用不同轴的 position id 计算旋转角。Qwen2-VL-7B 配置为 `mrope_section = [16, 24, 24]`（head_dim=128，旋转频率对共 64 对：前 16 对用时间 id，中间 24 对用高度 id，后 24 对用宽度 id）。

#### 3.3.3 三种模态的 position id 分配规则

| 输入 | 时间 id t | 高度 id h | 宽度 id w |
|------|-----------|-----------|-----------|
| 文本第 i 个 token | i | i | i |
| 图像 token（第 r 行第 c 列） | 固定常数 | r | c |
| 视频第 f 帧、第 r 行第 c 列 | f | r | c |

**关键点**：
1. 文本用 $(i, i, i)$，三维退化为 1D——M-RoPE 在纯文本上与标准 RoPE **完全等价**；
2. 图片内所有 token 的时间 id 相同（图片是"单帧"）；
3. 多模态拼接时，**每种模态的编号从前一种模态最大 position id +1 开始**——避免不同模态位置冲突；
4. **位置 id 数值变小**：图像/视频不再按"整体序列绝对位置"编号，而是按局部坐标编号，这让 16K 训练长度的模型能外推到 80K 推理长度（论文 Figure 5 验证：训练上限 16K token，推理 80K 依然稳健）——这是 M-RoPE 除"空间感知"外的第二个隐藏收益。

#### 3.3.4 消融结论（论文 3.3.2）

M-RoPE vs 1D-RoPE：下游任务全面更优，**尤其视频类 benchmark 提升显著**（视频需要时间轴感知）；文本能力不降（因退化为 1D）。

### 3.4 视觉 token 压缩：2×2 卷积 + MLP

ViT 输出的 patch 特征先做**空间合并**再进 LLM：

```text
ViT 输出:  H_p × W_p 个 patch token（patch 14，每个 1280 维）
    ↓ 2×2 分组（等价 2×2 卷积，stride 2）
    每个 2×2 的 patch 特征拼接成 4×1280 维
    ↓ MLP 投影到 LLM 隐藏维（Qwen2-VL-7B 为 3584）
    得到 (H_p/2) × (W_p/2) 个视觉 token
```

- **压缩比固定 4×**（2×2 → 1）；
- 一张 224×224 图：$16\times16=256$ 个 patch → 64 个 token；
- 视觉 token 数量 = $\frac{H'}{28} \times \frac{W'}{28}$，与动态分辨率公式自洽；
- 为什么还要压？**4× 压缩 ≈ 4× 更少的前向计算与 KV cache**，而 2×2 邻域信息高度冗余，几乎无损。

### 3.5 视频统一建模

- 视频按 **2 FPS** 抽帧；
- 引入**时域卷积（depth=2 的 3D 卷积）**：连续帧的 3D 时空 tube 一起过卷积（而非逐帧 2D patch），**2 帧合并为 1 个时间步**（`temporal_patch_size=2`），不增加序列长度就能处理更多帧；
- 为统一训练，**单张图片被视为 2 个相同帧**（满足时域卷积的输入结构）；
- 每个视频的总 token 数上限 16384（训练时动态调帧分辨率）；
- 图像和视频走**同一套**视觉编码器与 M-RoPE——"图像即 1 帧视频，视频即 T 帧图像"。

### 3.6 训练配置

| 阶段 | 数据量 | 训练对象 | 说明 |
|------|--------|---------|------|
| 阶段 1 预训练 | 约 600B token | 视觉编码器对齐（图文对/OCR/分类） | ViT 用 DFN 预训练权重初始化，绝对 PE 换 RoPE-2D |
| 阶段 2 大规模预训练 | 再加约 800B token | 全部参数解冻 | 交错图文、VQA、多任务；累计 1.4T token |
| 阶段 3 指令微调 | 指令数据 | 冻结 ViT，训练 LLM | ChatML 格式，含图像问答/文档/多图对比/视频/Agent |

训练细节：**只对文本 token 计算 loss**（图像 token 无监督目标）；知识截止 2023 年 6 月；支持中英之外的韩日法德意俄越阿等多语种 OCR。

## 四、Qwen2.5-VL（2025.01）：看得快、看得久、看得准时间

### 4.1 本代三个关键词

1. **Window Attention**：把 ViT 的全局注意力换成局部窗口注意力——解决高分辨率下的计算爆炸；
2. **动态 FPS + 绝对时间对齐**：把 M-RoPE 的时间轴从"帧序号"升级为"真实时间"——解决视频时间定位；
3. **动态 token 预算的合并器**：token 压缩从"固定 4×"升级为"可按预算动态合并"。

### 4.2 Window Attention（大 ViT 的局部注意力）

高分辨率下 ViT 全局注意力的复杂度是 $O(N^2)$（$N$ 为 patch 数），原生分辨率输入会直接算不动。Qwen2.5-VL 的重构方案：

| 设计 | 值 |
|------|-----|
| ViT 结构 | hidden 1280、32 层、16 heads、patch 14（**从零训练**，DataComp 等初始化） |
| 窗口大小 | **112×112（= 8×8 个 patch）** |
| 全局注意力层 | 仅 4 层：第 {7, 15, 23, 31} 层 |
| 其余 28 层 | 窗口注意力，区域不足窗口尺寸时不补零、保持原分辨率 |
| 归一化/激活 | RMSNorm + SwiGLU（与 Qwen2.5 LLM 对齐） |

**复杂度分析**：窗口注意力每个 patch 只与窗口内 8×8 个 patch 交互，复杂度与 patch 数**线性**；仅 4 层全局注意力负责跨区域信息流通。代价是局部信息交换受限，由少数全局层弥补。

### 4.3 Visual Token Merger（视觉 token 合并器）

延续 2×2 分组 + 2 层 MLP 的压缩范式，但强调**动态性**：

- 默认单图 token 范围 **4 ~ 16384**（对应 `min_pixels = 4×28×28`，`max_pixels = 16384×28×28`）；
- 通过设置 `min_pixels` / `max_pixels` 或直接指定 `resized_height/width`（自动对齐 28），可以在**精度与成本之间任意调节** token 预算；
- 视频侧同样支持（帧分辨率按总 token 预算动态调整）。

```text
ViT 特征 (任意 H_p × W_p)
   → 2×2 邻域特征拼接（concat）
   → 2 层 MLP 投影到 LLM 维度
   → token 数 = H_p/2 × W_p/2（由像素预算反向决定）
```

### 4.4 绝对时间对齐（MRoPE 时间轴升级）

Qwen2-VL 的时间 id 是"帧序号"——不知道两帧之间隔了多久，1 FPS 与 30 FPS 采样的视频帧间 id 差都是 1。Qwen2.5-VL 的做法：

- **时间 id 直接对齐绝对时间**：按帧的真实时间戳分配时间 id，**帧间 id 间隔反映真实时间流速**；
- 配合**动态 FPS 训练**（训练时按不同采样率抽样），模型学会"1 秒 = 多少 id 间隔"，从而感知运动速度；
- 视频定位数据用"秒"和"时:分:秒:帧（hmsf）"两种格式标注，模型可输出**秒级时间戳**。

### 4.5 文档解析（Omni-Document Parsing）

- 从"识别文字"升级为"解析整页文档"：表格、图表、公式、乐谱、手写体、多栏版面；
- 输出结构化 **HTML 标签**（如 `<table>`、`<img>` 描述），保留版面布局信息；
- 配合原生分辨率，票据、报表的结构化抽取（JSON 输出）成为主打能力。

### 4.6 Agent 能力

- 移动端/桌面端/Web 截图理解 + UI 元素定位（框/点双格式 + 绝对坐标 JSON）；
- 动作空间统一为 function call，多步轨迹数据合成 + 推理过程标注，支撑"看屏幕→决策→操作"闭环。

### 4.7 训练数据（规模翻三倍）

| 阶段 | token 量 | 序列长度 | 训练对象 | 数据构成 |
|------|---------|---------|---------|---------|
| 阶段 1 视觉预训练 | 1.5T | 8192 | 仅 ViT | 图像字幕、知识、OCR、纯文本 |
| 阶段 2 多模态预训练 | 2T | 8192 | ViT + LLM | 交错图文、VQA、视频、定位、Agent |
| 阶段 3 长上下文预训练 | 0.6T | 32768 | ViT + LLM | 长视频、长 Agent 轨迹、长文档 |
| 合计 | **约 4.1T**（vs Qwen2-VL 的 1.4T） | — | — | 长视频 >30 分钟专门合成字幕 |

## 五、Qwen3-VL（2025）：多模态大模型的新上限

### 5.1 模型家族：密集 + MoE，双思维模式

| 模型 | LLM 部分 | 架构 | 定位 |
|------|---------|------|------|
| Qwen3-VL-2B / 4B / 8B / 32B | Qwen3 密集 | 密集 | 边缘到主流 |
| Qwen3-VL-30B-A3B | MoE（30B 总参，3B 激活） | 稀疏 | 性价比 |
| Qwen3-VL-235B-A22B | MoE（235B 总参，22B 激活） | 稀疏 | 旗舰，原生 256K 上下文 |

每个尺寸都有 **Instruct（非思维）** 与 **Thinking（思维）** 两个版本：Thinking 版在推理时输出长思维链（CoT），非思维版直接作答，用户按场景切换（对应 Qwen3 LLM 的"思考/不思考"双模式）。

### 5.2 视觉编码器：SigLIP-2 架构 + 32× 像素压缩

- 视觉塔基于 **SigLIP-2 架构**继续用动态分辨率训练（官方默认 SigLIP2-SO-400M 级，小模型用 300M 级）；
- patch 从 14 升级到 **16**，`spatial_merge_size=2`，`temporal_patch_size=2`——每个视觉 token 覆盖 $16 \times 2 \times 16 \times 2 = 1024$ 像素，即 **32× 像素压缩**；
- 官方处理器默认单图 token 预算 **256~1280**，视频 256~16384（含 2× 时域压缩）；
- 新增 **Qwen3-ViT**（自研 CLIP 预训练版本，消融中全面优于 SigLIP-2 基线）。

> **注意（面试纠正项）**：社区一度流传"Qwen3-VL 的视觉塔升级到 6B 参数"——**官方技术报告与开源 config 均显示视觉塔为 SigLIP-2 架构（约 4 亿参数级），6B 说法不成立**。真正的规模增长在 LLM（MoE 235B）与训练数据（~1T token × 多阶段）。

### 5.3 Interleaved-MRoPE：修复频率失衡

Qwen2 系的 M-RoPE 把维度**按块**分配给 t/h/w（如 `[16,24,24]`），低频/高频带在三个轴上分布不均，长视频场景下频谱有偏。Qwen3-VL 的修复：

- **频率交错分配（interleaved）**：t/h/w 分量在嵌入维度上交替排布（配置 `mrope_interleaved: true`，`mrope_section: [24, 20, 20]`），保证每条轴在低频与高频带都被均匀覆盖；
- 收益：长距离时序建模显著改善，长视频 benchmark 提升；
- 附带好处：interleaved 位置 id 增长更慢，同等长度下需要的缩放因子更小（1M 扩展只需 factor 2~3，而非标准 RoPE 的 4）。

### 5.4 DeepStack：多级 ViT 特征注入 LLM

```text
ViT 第 8 层特征 ──┐  (专用 merger 投影)
ViT 第 16 层特征 ──┼──> 直接加到 LLM 第 1~3 层的 hidden state（残差相加）
ViT 第 24 层特征 ──┘
```

- 受 DeepStack 启发，但**不是**把多尺度输入堆起来，而是从 **ViT 中间层（第 8/16/24 层）** 抽取特征；
- 浅层特征保细节（纹理/小字），深层特征保语义——low-level 到 high-level 全覆盖；
- **不增加序列长度**（只是往已有 token 上做残差注入），在 InfoVQA、DocVQA 等细粒度任务上稳定涨点（消融：AVG 74.7 → 76.0）。

### 5.5 文本时间戳：放弃位置编码式时间

Qwen2.5-VL 用"时间 id 对齐绝对时间"存在两个问题：(1) 长视频产生过大且稀疏的时间 id，损害长时序；(2) 需要在各种 FPS 下均匀采样，数据构造昂贵。Qwen3-VL 改为：

- 每个视频时间片段前插入**显式文本时间戳 token**（如 `<3.0 seconds>`，训练时同时用秒与 HMS 两种格式）；
- 用文本 token 表达时间，模型直接学会"读表"而不是"猜间隔"；
- 代价：上下文长度小幅增加，但视频定位/密集字幕更准、训练更省。

### 5.6 长上下文：256K 原生，1M 可扩

| 能力 | 数值 |
|------|------|
| 原生训练上下文 | 256K（S3 阶段 262144 序列长度） |
| 视频理解 | 30 分钟视频 needle-in-a-haystack **100%**（256K 内） |
| 1M 外推 | YaRN 扩展到 1M（约 2 小时视频），准确率 99.5% |
| 纯文本 | 多项文本 benchmark 超过同规模纯文本底座 |

| 阶段 | 目标 | 训练参数 | token 预算 | 序列长度 |
|------|------|---------|-----------|---------|
| S0 | 视觉-语言对齐 | **仅 MLP merger**（ViT 与 LLM 冻结） | 67B | 8192 |
| S1 | 多模态预训练 | 全部 | ~1T | 8192 |
| S2 | 长上下文预训练 | 全部 | ~1T | 32768 |

后训练三阶段：(i) **长思维链 SFT**（12M+ 合成 CoT 样本冷启动）；(ii) **知识蒸馏**（强教师模型）；(iii) **强化学习**（含答案正确率奖励、可调思维预算）。损失函数改为**平方根归一化的逐 token 损失**（$\mathcal{L} \propto -\frac{\log p}{\sqrt{N}}$），更好平衡文本与多模态 token 的梯度贡献。

## 七、训练流程：预训练 → SFT → 对齐

### 7.1 通用范式

Qwen 系统一采用**"视觉-语言预训练 → 指令微调（SFT）→ 人类偏好对齐"**三级流水线（Qwen3-VL 在预训练里再细分出 S0~S3 四阶段）：

```text
阶段 A 预训练（图文对齐）
  ├─ 目标：让视觉 token 与文本 token 语义对齐（next-token prediction，只监督文本）
  ├─ 数据：图文对、OCR、交错图文文档、视频字幕、知识图谱图像
  └─ 策略：先只训连接器/视觉塔（对齐）→ 再全参数解冻（能力）→ 逐步拉长序列
阶段 B 指令微调（SFT）
  ├─ 目标：让模型听懂指令、输出对话/框/JSON/HTML
  ├─ 数据：ChatML 指令数据（VQA、文档、多图、视频、Agent 轨迹、长 CoT）
  └─ 策略：冻结视觉塔（Qwen-VL/Qwen2-VL 阶段 3）或全参微调（Qwen3-VL 后训练 SFT）
阶段 C 对齐（RM/DPO/RL）
  ├─ 目标：对齐人类偏好，降低幻觉、提升可用性（Qwen3-VL 论文明确：RL 阶段）
  ├─ 奖励：答案正确率奖励（Reward Model）、格式/安全奖励
  └─ 可选：DPO/GRPO 等偏好优化 + 思维预算控制
```

### 7.2 各代训练规模对比

| 维度 | Qwen-VL | Qwen2-VL | Qwen2.5-VL | Qwen3-VL |
|------|---------|----------|------------|----------|
| 预训练 token | 14 亿图文对（阶段 1） | 1.4T（600B+800B） | 4.1T | ~2T+（S1/S2 各 ~1T） |
| 序列长度 | 固定短序列 | 8192 | 8192→32768 | 8192→32768→262144 |
| 阶段数 | 3 | 3 | 3 | 4 预训练 + 3 后训练 |
| 对齐手段 | 无（仅 SFT） | 无（仅 SFT） | SFT | SFT + 蒸馏 + **RL** |

### 7.3 数据构成金字塔

```text
底部（预训练主体）：弱标注图文对、网页交错图文、OCR 图文 —— 量最大
中部（能力数据）：  VQA、定位（框/点/区域）、图表/文档解析、数学
顶部（对齐数据）：  指令对话、长思维链 CoT、GUI Agent 轨迹、多语言 OCR —— 质最高
```

数据质量策略：清洗（去噪、去水印）、合成（OCR 引擎渲染、Agent 轨迹合成）、知识蒸馏（教师模型重写 caption/CoT）、配比控制（文本：视觉 ≈ 保证语言能力不退化）。

## 八、推理：图像如何变成输入序列

### 8.1 单图：占位符替换

```text
ChatML 消息:  user: <|vision_start|><|image_pad|><|vision_end|> 这张图里有什么？

处理流程:
1. 图像 → 缩放/切分/对齐（见 §3.2）
2. 每个 sub-image 过 ViT + 合并器 → token 序列
3. 用真实视觉 token 替换 <|image_pad|> 占位符
4. 序列头尾加 <|vision_start|> / <|vision_end|>（Qwen3-VL 用 <|image_pad|> 计数占位）
5. 与文本 token 拼接 → M-RoPE position id 分配 → LLM 前向
```

### 8.2 多图

- 多张图按出现顺序各自编码、顺序拼接，**每张图独立** `vision_start/vision_end` 包裹；
- M-RoPE 中：多图的时间 id 递增（第 2 张图时间 id = 第 1 张 +1），即"多图 = 多帧视频"；
- Qwen3-VL 支持给图加序号前缀（`Picture 1: ...`），便于"对比第 1 张和第 3 张"这类指代。

### 8.3 视频

```text
视频 → 按 2 FPS 抽帧（Qwen3-VL 可配 fps/num_frames）
    → 相邻 2 帧构成一个时域 patch（temporal_patch_size=2，3D 卷积处理）
    → 帧分辨率按 token 预算动态调整（总 token ≤ 上限）
    → Qwen3-VL：每个时间片段前插入文本时间戳 token（如 <3.0 seconds>）
    → M-RoPE：时间 id 按帧序/绝对时间递增，h/w 按帧内坐标
```

### 8.4 显存权衡（工程要点）

| 场景 | token 占用 | 对策 |
|------|-----------|------|
| 长文档截图 | 最高 16384 | 调低 max_pixels、按页切图 |
| 长视频 | 每帧×帧数，增长快 | 降低 FPS、降帧分辨率（Qwen3-VL 用 total_pixels 限制） |
| 多图对比 | 每图独立预算 | 单图预算下调（如 256~1280） |
| 超长上下文 | 256K 原生 / 1M YaRN | 需 flash-attention + 稀疏/分页 attention 工程 |

| 维度 | Qwen2-VL | LLaVA-1.5 / NeXT | InternVL (1.5/2) | MiniCPM-V (2.0/2.5) |
|------|----------|------------------|------------------|---------------------|
| 视觉塔 | 自研 ViT 675M（patch 14） | CLIP ViT-L/14@336 | InternViT-6B（patch 14） | SigLIP-400M / 自研 ViT（patch 14） |
| 连接方式 | 2×2 卷积 + MLP（4× 压缩） | MLP 投影（不压缩） | **Pixel Shuffle**（s² 倍下采样，4×/16×） | Q-Former 式 resampler / perceiver |

| 动态分辨率 | **原生分辨率 + sub-image 切分** | 1.5 无 / NeXT anyres 2×2 切块 | 448×448 tile 动态网格 | 2.5 起 anyres 切块 |
| 位置编码 | **M-RoPE（3D）** | 绝对 PE / 无 | 2D-RoPE（ViT 内） | 1D RoPE |
| 视频 | 2 FPS + 3D 卷积，统一建模 | 无原生视频 | 支持（抽帧） | 支持（抽帧） |

**一句话差异记忆**：
- **Qwen2-VL**：唯一做"原生分辨率 + 3D 位置编码"的（动态分辨率最彻底）；
- **LLaVA**：最简 MLP 连接，靠数据与多尺度切块补足，无 token 压缩；
- **InternVL**：6B 大视觉塔 + pixel shuffle 高效压缩；
- **MiniCPM-V**：小参数量路线，视觉塔 + 重采样器，主打端侧与中英。

## 十、局限与代价

### 10.1 高分辨率显存开销

- 动态分辨率允许大图输入，但 **token 峰值可达 16384**，KV cache 与 attention 计算随 token 数线性/平方增长；显存上限由"最坏情况"决定，batch 内打包困难；
- 切 sub-image 的边界（窗口/位置编码在 tile 边缘的表现）仍是细节问题；
- 对策：降预算、flash-attention、按需二次缩放。

### 10.2 视频 token 成本

- 1 分钟视频按 2 FPS = 120 帧，即使每帧低分辨率也轻松上万 token；时长 30 分钟视频接近 256K 上下文上限；
- 抽帧即丢信息：高运动、快速翻页场景仍会漏事件；
- 3D 卷积/时域 patch 压缩虽省 token，但帧间高频运动信息被平均化。

### 10.3 幻觉

- 与所有 VLM 一样存在**物体/属性/计数幻觉**（尤其小物体、遮挡、极端光照）；
- 细粒度计数、复杂空间关系（前后遮挡）依旧不稳；
- 长视频中"首尾帧效应"——模型倾向依据早期/后期帧作答，中间帧被遗忘。

### 10.4 其他

- 坐标定位基于 [0,1000) 文本化框，**像素级精度有限**（依赖 token 网格）；
- 多图跨图推理（"A 图中物体在 B 图的位置"）仍弱；
- 多语种不平衡（中文/英文强，小语种 OCR 弱）；
- 训练成本高：Qwen3-VL 预训练约 2T+ token，非一般团队可复现。

## 十一、常见误区

**误区 1：Qwen-VL 的 resampler 是"448 个 token 压成 256 个"。**
错。448 是**第二阶段的分辨率**。准确说法：448×448 时 ViT 输出 1024 个 patch（$(448/14)^2$），重采样器压缩到固定 256 个；224×224 时 256→256 不压缩。

**误区 2：Qwen-VL 的位置编码就是"文本的 1D RoPE"。**
不准确。Qwen-VL 是**三层位置编码体系**：ViT 内部可学习绝对 PE（图内空间感）+ VL Adapter 把 2D 绝对 PE 注入 Q-K 对（压缩后仍可定位，这是它叫"位置感知"的原因）+ LLM 侧 1D RoPE（图文混合生成）。三层缺一不可，真正被面试深挖的是第二层。

**误区 3：Qwen-VL 的"位置编码注入 query-key pair"是指"加在注意力输出上/只加在 value 上"。**
错。是**同时加到 Q 和 K 上**（所以叫 pair）：$\tilde{Q}=Q+\text{PE}_{2D}$、$\tilde{K}=K+\text{PE}_{2D}$，注意力分数里展开出 $Q\text{PE}^\top + \text{PE}K^\top + \text{PE}\text{PE}^\top$ 三个位置项，隐式编码空间关系，支撑 grounding。

**误区 2：Qwen3-VL 的视觉塔是 6B 参数。**
错。官方技术报告与开源 config 均显示视觉塔基于 **SigLIP-2 架构**（默认 SO-400M 级，约 4 亿参数，patch 16）。"6B 视觉塔"是社区流传的错误说法；Qwen3-VL 的规模提升主要在 LLM（MoE 235B-A22B）与训练数据。

**误区 3：动态分辨率 = 多尺度训练 / 简单地把图缩放到几个固定档位。**
不完全是。Qwen2-VL 是**连续原生分辨率**：保持长宽比 + 对齐 28 网格 + 超限切 sub-image，token 数是分辨率的连续函数，而非预设的几个档位（LLaVA-NeXT 的 anyres 才是指定网格切块）。

**误区 4：M-RoPE 就是"三个独立的 RoPE 拼在一起"。**
不准确。M-RoPE 是**一个**旋转编码在维度分组上的分解：不同维度组用 t/h/w 各自的 position id 计算旋转角（Qwen2-VL-7B 为 `[16,24,24]` 分组），文本退化为 $(i,i,i)$ 与 1D RoPE 等价；且位置 id 数值小、利于长度外推。

**误区 5：Qwen2-VL 的 ViT 是冻结的。**
分阶段。阶段 1 主要训 ViT、阶段 2 全解冻、阶段 3 冻结 ViT 只训 LLM——"冻结"只是最后一个阶段的策略，且与 Qwen-VL（阶段 1/3 冻结、只训 adapter）不同。

**误区 6：视觉 token 压缩越多越好。**
不对。2×2 合并是"几乎无损"的邻域冗余压缩；但过度压缩（如固定 256 token 承载 1M 像素图）会丢失小字细节。Qwen2.5-VL 起用动态预算就是在精度与成本间显式权衡。

## 十二、高频面试问答

**Q1：Qwen2-VL 的动态分辨率具体怎么实现？**
保持长宽比缩放使总像素 ≤ max_pixels，H/W 对齐到 28 的倍数（patch 14 × 2×2 合并），超过 448×448 就切成多个 sub-image 各自过 ViT，再把合并后的 token 按行优先拼回一条序列；token 数 = H'·W'/784，默认上限 16384。

**Q2：为什么对齐单位是 28 而不是 14？**
合并器把 2×2 的 patch（14×14 像素）合并为 1 个 token，因此每个视觉 token 覆盖 28×28 像素；若只对齐 14，合并后可能出现半格、无法整数拼接。

**Q3：M-RoPE 和标准 RoPE 的区别？**
标准 RoPE 只有 1D 位置；M-RoPE 把位置拆成 (t, h, w) 三维，维度分组后分别用三个轴的 position id 计算旋转角。文本 token 用 (i, i, i)（等价 1D RoPE），图像用 (常数, 行, 列)，视频用 (帧, 行, 列)；多模态拼接时各模态从上一模态最大 id +1 起算，位置 id 数值小、外推能力强（16K 训练可外推到 80K）。

**Q4：视觉 token 是怎么合并压缩的？**
Qwen2-VL：ViT 输出后把空间相邻 2×2 的 patch 特征做 2×2 卷积/拼接，再过 MLP 投影到 LLM 隐藏维，token 减少 4 倍；Qwen2.5-VL 升级为可配预算的动态合并；Qwen3-VL 把 patch 提到 16，加时域 2 帧合并，单 token 覆盖 32×32×2 像素。

**Q5：为什么要动态分辨率？固定高分辨率不行吗？**
文档、OCR、细粒度识别要求小字清晰，固定 448 或 336 会模糊；固定 1344 又对小图浪费。动态分辨率让 token 数随信息量自适应：大图多 token 保细节、小图少 token 省算力，且保持长宽比不畸变。论文消融也证明没有任何固定分辨率能全 benchmark 最优。

**Q6：Qwen2.5-VL 的 Window Attention 是怎么设计的？为什么能提速？**
ViT 32 层中只有第 {7,15,23,31} 层用全局注意力，其余 28 层用 8×8 patch（112×112 像素）窗口注意力；复杂度从 O(N²) 降为 O(N·w²)（w 为窗口内 patch 数，线性于 N）；RMSNorm + SwiGLU 与 LLM 对齐，ViT 从零训练。

**Q7：为什么 Qwen3-VL 用文本时间戳而不是 M-RoPE 时间 id？**
Qwen2.5-VL 把时间 id 对齐绝对时间后，长视频会产生过大、稀疏的时间 id，且要求各 FPS 均匀采样、数据昂贵。Qwen3-VL 改为在视频片段前插入 `<3.0 seconds>` 这类文本 token，模型"读时间"更直接，长视频与视频定位更稳，代价仅是上下文略增。

**Q8：Qwen3-VL 的 DeepStack 是什么？为什么不增加序列长度？**
从 ViT 第 8/16/24 层抽取多级特征，经专用 merger 投影后**直接加到 LLM 前 3 层对应位置的 hidden state**（残差注入），不新增 token、不涨上下文；浅层保细节、深层保语义，InfoVQA/DocVQA 显著受益。

**Q9：Qwen3-VL 为什么敢用 6B 视觉塔？（纠正版）**
Qwen3-VL 并没有 6B 视觉塔——官方视觉塔基于 SigLIP-2 架构（约 400M）。如果被追问"为什么不把视觉塔做得更大"，可答：视觉塔与 LLM 的参数比（约 1:10 到 1:200）说明瓶颈在 LLM 侧的跨模态推理与记忆，且 400M 视觉塔 + DeepStack 多级特征已覆盖细粒度需求，增大视觉塔的边际收益低于增大 LLM。

**Q10：Qwen2-VL 和 Qwen2.5-VL 在视频能力上的本质区别？**
三点：① 时间建模从"帧序号"变成"绝对时间"（能感知速度并秒级定位事件）；② 采样从固定 2 FPS 变成动态 FPS 训练（任意采样率都稳）；③ 窗口注意力让更高帧率/更长时间成为可能（可理解 1 小时以上视频）。

**Q11：一个 1920×1080 的图在 Qwen2-VL 里大概变成多少 token？**
按默认 max_pixels=16384×784：先等比缩放（1080p 约 1.1M 像素，几乎不用缩），对齐 28 后 H'=1080 附近 → 约 1064×1904（28 倍数取整），token ≈ (1064/28)×(1904/28) ≈ 38×68 = 2584 个，切成若干 448² 的 sub-image 编码。

**Q12：Qwen 系怎么解决"训练只监督文本 token"带来的对齐问题？**
预训练阶段只对文本计算 next-token loss（视觉 token 无监督目标）；通过阶段化训练（先对齐后全量微调）与多样数据（OCR/定位/交错图文）让视觉编码器学到与文本语义一致的表征；Qwen3-VL 再加 DeepStack 多级融合与平方根归一化损失平衡两种 token 的梯度贡献。

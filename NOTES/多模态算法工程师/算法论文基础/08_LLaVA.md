# LLaVA：视觉塔 + MLP 投影 + LLM 的多模态指令微调范式

> 本笔记详解 LLaVA（Large Language and Vision Assistant）系列：LLaVA（2023，NeurIPS 2023 Oral）、LLaVA-1.5（2023.10）、LLaVA-NeXT（即 LLaVA-1.6，2024）。LLaVA 用最简单的架构（CLIP 视觉塔 + 单层 Linear 投影 + Vicuna/LLaMA LLM）配合 GPT-4 生成的指令数据，以极低成本实现了与 BLIP-2、InstructBLIP 等复杂模型相当甚至更强的视觉对话能力，成为后续几乎所有开源 VLM（Qwen-VL、InternVL、MiniCPM-V 等）的基线范式。面试被问"开源 VLM 是怎么做的"，LLaVA 是绕不开的第一站。

## 一、一句话解释

> **LLaVA = CLIP 视觉塔（冻结）+ 简单 MLP 投影层 + Vicuna/LLaMA 大语言模型，用 GPT-4 生成的图文指令数据（LLaVA-Instruct-158K）做视觉指令微调（Visual Instruction Tuning），以极低的训练成本获得强大的视觉对话能力。**

拆开看四个要素：

| 组成 | 具体选择（LLaVA-1） | 具体选择（LLaVA-1.5） | 作用 |
|------|-------------------|----------------------|------|
| 视觉塔 | CLIP ViT-L/14@336（冻结） | CLIP ViT-L/14@336（可选微调） | 把图像编码成 patch 特征序列 |
| 投影层 | 单层 Linear：1024 → 512 | 两层 MLP（Linear + GELU + Linear）：1024 → 4096 | 把视觉特征对齐到 LLM 词嵌入空间 |
| LLM | Vicuna-7B/13B | Vicuna-1.5-7B/13B（LLaMA-2 底座） | 语言理解与生成、遵循指令 |
| 指令数据 | LLaVA-Instruct-158K（GPT-4 生成）+ ShareGPT | LLaVA-Instruct-665K + 公共 SFT 数据 | 教模型"看图说话 + 对话" |

> **历史定位**：BLIP-2 用 Q-Former（一个复杂的可学习桥接模块）对齐视觉与语言；LLaVA 反其道而行——只用一个 Linear 层就完成了视觉 → 语言的对齐，并证明了"视觉塔 + 投影 + LLM"这个最简范式在**足够的指令数据**下就能追平甚至超越复杂桥接方案。LLaVA 的贡献主要在**数据**而非**架构**。

---

## 二、动机：它解决什么问题

### 2.1 痛点一：现有桥接方案太复杂

在 LLaVA 之前，将视觉接入 LLM 的主流方案是 BLIP-2 的 Q-Former（见 07_BLIP2）：

| 方案 | 桥接方式 | 参数量 | 复杂度 |
|------|---------|--------|--------|
| BLIP-2 | Q-Former（可学习 query + 交叉注意力，两阶段预训练） | 约 180M（Q-Former） | 高：需专门的预训练阶段、多目标损失 |
| Flamingo | Perceiver Resampler + 门控交叉注意力 | 门控机制复杂 | 高：每层都要插入交叉注意力 |
| LLaVA | 单个 Linear / 两层 MLP | 0.3M~6M（投影层） | 极低：一个线性变换 |

**LLaVA 的核心假设**：视觉塔（CLIP）经过大规模图文对比预训练后，其 patch 特征已经和文本语义高度对齐；Q-Former 等复杂模块做的工作，本质上只是"特征变换 + 降维"，而这件事实质上可以用一个简单的线性/MLP 投影完成——**瓶颈不在投影层的能力，而在数据**。

### 2.2 痛点二：缺少高质量的视觉指令数据

2023 年初，多模态对话领域的数据问题：

- **图文对数据**（CC3M、SBU 等）只含**一句**简单描述，没有"对话"、"推理"、"多轮问答"的形态；
- **纯文本指令数据**（ShareGPT、Alpaca 等）非常丰富，但**没有图像**，模型无法学会"看图说话"；
- 人工标注高质量视觉指令数据成本极高（每张图要写多轮对话 + 复杂推理，几乎不可规模化）。

**LLaVA 的解法**：利用 GPT-4 的能力，从 COCO 图像**自动生成**指令数据——先让 GPT-4 写描述，再把描述作为"辅助输入"让 GPT-4 扮演用户/助手生成对话与推理。这就是 LLaVA-Instruct-158K 的由来（详见第四节）。

### 2.3 痛点三：验证"对齐预训练 + 指令微调"两阶段范式的价值

LLaVA 之前的 VLM 大多在"预训练阶段就训练多模态"（如 Flamingo 在图文对数据上大规模预训练）。LLaVA 明确提出：

1. **阶段一（特征对齐预训练）**：只用简单的图文描述对，训练投影层，让视觉特征"住进"LLM 的词嵌入空间；
2. **阶段二（端到端指令微调）**：用高质量的图文指令数据，同时训练投影层和 LLM，让 LLM 学会"理解视觉指令并回答"。

这个范式后来成为 LLaVA-1.5、Qwen-VL、InternVL 等几乎所有开源 VLM 的标准训练流程。

## 三、架构详解（重点）

### 3.1 整体结构

```text
┌─────────────┐     ┌──────────────┐     ┌─────────────┐     ┌─────────────────────┐
│   图像       │     │  视觉塔       │     │  投影层       │     │  LLM                │
│ (336×336)   │ ──► │ CLIP ViT-L/14 │ ──► │ Linear/MLP   │ ──► │  Vicuna / LLaMA-2   │
│             │     │   (冻结)      │     │              │     │  (LLaVA-1.5 可微调)  │
└─────────────┘     └──────────────┘     └─────────────┘     └─────────────────────┘
                          │                     │                      ▲
                     576 个 patch token   576 × 4096 特征     与文本 token 拼接后
                     (无 [CLS])           (与 LLM 词嵌入同维)  一起过 Transformer
```

### 3.2 视觉塔：CLIP ViT-L/14@336

| 属性 | 值 | 说明 |
|------|-----|------|
| 模型 | CLIP 的 ViT-L/14 | OpenAI CLIP 系列，图文对比预训练 |
| Patch 大小 | 14 × 14 | 每个 patch 嵌入 1024 维 |
| 输入分辨率 | 336 × 336 | 论文发现 336 分辨率显著优于 224 |
| Patch 数量 | 336/14 = 24，24 × 24 = **576 个** | 关键数字，面试常考 |
| [CLS] token | **丢弃不用** | 只取 576 个 patch 特征 |
| 冻结与否 | LLaVA-1 完全冻结；LLaVA-1.5 可选微调 | 冻结省显存、防灾难性遗忘 |

**为什么不用 [CLS] token？** CLIP 的 [CLS] 聚合了全局图像信息（单向量），适合图文匹配/检索；但 VLM 生成需要**空间细粒度**的信息（"左上角的猫是什么颜色"），必须保留每个 patch 的位置信息。所以全部 patch token 送入投影层，位置编码由 ViT 自带。

### 3.3 投影层：从 Linear 到 MLP

**LLaVA-1 的投影层**（单层 Linear）：

$$W_p : \mathbb{R}^{1024} \to \mathbb{R}^{512}$$

$$h_v = W_p \cdot z_v$$

其中 $z_v \in \mathbb{R}^{1024}$ 是视觉塔输出的 patch 特征，$h_v$ 是投影后的视觉 token（维度等于 LLM 的隐藏层/词嵌入维度 512，Vicuna-7B 的隐藏维是 4096，但 LLaVA-1 用 Vicuna-13B 的 512 维嵌入？——注意：LLaVA-1 投影到 512 维是因为当时实验显示效果相当，且省显存）。

**LLaVA-1.5 的投影层**（两层 MLP，论文实证更好）：

$$\text{MLP}(z_v) = W_2 \cdot \text{GELU}(W_1 \cdot z_v + b_1) + b_2$$

| 版本 | 结构 | 输入维 | 输出维 | 效果 |
|------|------|--------|--------|------|
| LLaVA-1 | Linear | 1024 | 512 | 基线 |
| LLaVA-1.5 | MLP（Linear-GELU-Linear） | 1024 | **4096** | 各任务提升约 2~4 个点 |

输出维度 4096 = Vicuna-1.5 / LLaMA-2-7B 的词嵌入维度，保证视觉 token 与文本 token 可以直接拼接。

> **面试记忆点**：投影层本质是"把 1024 维的 CLIP 视觉特征映射到 LLM 的词嵌入空间"。为什么这么简单的 MLP 就够用？因为 CLIP 预训练已经让视觉特征与文本语义对齐，MLP 只是做一个"坐标系变换"。

### 3.4 LLM：Vicuna / LLaMA-2

| 版本 | LLM 底座 | 规模 | 说明 |
|------|---------|------|------|
| LLaVA-1 | Vicuna-7B / 13B | 7B / 13B | Vicuna 基于 LLaMA-1，经 ShareGPT 对话数据 SFT |
| LLaVA-1.5 | Vicuna-1.5-7B / 13B | 7B / 13B | Vicuna-1.5 基于 LLaMA-2 |
| LLaVA-NeXT | Vicuna-1.5-7B/13B、Mistral-7B、Yi-34B | 7B~34B | 支持不同底座 |

LLM 承担：语言理解、指令遵循、知识推理、生成。**视觉信息通过投影层以"伪 token"形式注入**，LLM 本身不知道 token 是视觉的还是文本的——这正是"LLM 是多模态大脑"的设计哲学。

### 3.5 视觉 token 数量计算（重点数字）

$$N_{\text{visual}} = \left(\frac{336}{14}\right)^2 = 24^2 = 576$$

- 分辨率 336，patch 14，得到 24×24 = 576 个 patch；
- **576 个视觉 token** 是 LLaVA 系列最常被考到的数字；
- 对比：BLIP-2 用 32 个 query token，LLaVA 用 576 个，视觉信息粒度高得多；
- 代价：LLM 输入序列变长，自回归计算量随之增大（见 LLaVA-NeXT 的 anyres 部分）。

### 3.6 两种输入模式（训练/推理）

LLM 的输入由视觉 token 与文本 token 拼接而成，对应两种模式：

| 模式 | 输入构成 | 掩码处理 | 用于 |
|------|---------|---------|------|
| 多模态对话 | [视觉 token × 576] + [用户文本 token] + [助手回答 token] | 只对助手回答计算 loss，其余位置 loss 置零 | 阶段二指令微调 |
| 纯文本对话 | 无视觉 token，仅文本 | 同上 | 防止灾难性遗忘（与 ShareGPT 数据混合训练） |

**掩码（masking）原理**：交叉熵损失只作用在"助手回答"的位置上：

$$\mathcal{L} = -\sum_{t \in \mathcal{T}_{\text{assistant}}} \log p_\theta(x_t | x_{<t})$$

其中 $\mathcal{T}_{\text{assistant}}$ 是助手回答 token 的索引集合。图像 token、用户指令 token 的位置不参与 loss 计算——这让模型只学习"如何回答"，而不会尝试"理解后模仿"图像/指令的生成。

## 四、数据构造：LLaVA-Instruct-158K（重点）

### 4.1 核心思想：用 GPT-4 造数据

人力标注视觉指令太贵，而 GPT-4（多模态版）具备强大的图像理解 + 指令生成能力。LLaVA 的思路分为两步：

1. **为每张图先生成"符号化描述"**：把 COCO 图像的**位置标注**（bounding box、类别）和**属性标注**转换为文本描述，例如：
   ```text
   Human: 用语言描述这张图的视觉内容。位置信息用 [x1, y1, x2, y2] 表示。
   <图像 1>: 有两个男人坐在沙发上。<box>5, 3, 54, 95</box> 中的人穿黑色衬衫…
   ```
   用文本形式表示图像，让 GPT-4（文本版）也能"看见"图像；
2. **基于符号化描述生成三类指令数据**：让 GPT-4 扮演"用户（提问者）+ 助手（回答者）"，对每张图生成对话。

### 4.2 三类指令数据

LLaVA-Instruct-158K 包含约 158K 条（58K 对话 + 23K 详细描述 + 77K 复杂推理）：

| 类型 | 形态 | 数量 | 示例 |
|------|------|------|------|
| 对话（Conversation） | 多轮问答，问答交替 | 58K | 问"这个场景里有什么？"答"两个男人坐在沙发上聊天"……连续 3~5 轮 |
| 详细描述（Detailed Description） | 一段长文本详细描述图像 | 23K | "这是一张室内客厅的照片，沙发上坐着两个男人，茶几上有杂志……" |
| 复杂推理（Complex Reasoning） | 需要常识/逻辑/多步推理的问答 | 77K | 问"这些人的情绪可能是什么？为什么？"答"他们看起来很开心，因为面带微笑且相互对视……" |

三类数据的**难度递进**：对话（感知）→ 描述（组织语言）→ 推理（知识 + 逻辑），共同教会模型"看"+"说"+"想"。

### 4.3 训练时三种模态的 token 位置（核心考点）

LLaVA 训练样本由**三种模态**组成，对应三类 token 位置：

```text
<|im_start|>user
[视觉 token × 576] 这是什么？图中的男人在做什么？
<|im_end|>
<|im_start|>assistant
两个男人正坐在沙发上聊天，穿着休闲服装。
<|im_end|>
```

| 模态 | 内容 | token 位置 | 是否计算 loss |
|------|------|-----------|--------------|
| 图像 | 576 个视觉 token（投影后） | 序列最前 | 否 |
| 人类指令 | 用户问题文本 token | 视觉 token 之后 | 否 |
| AI 回答 | 助手回答文本 token | 序列末尾 | **是**（唯一的监督信号） |

> **为什么只有 AI 回答计算 loss？** 与纯文本 LLM 的 SFT 完全一致：模型只需学会"对给定的输入输出正确的回答"。若让图像/指令位置也计算 loss，等于让 LLM 学习"生成图像特征"和"复述用户问题"，毫无意义且浪费梯度。

### 4.4 混合纯文本数据：ShareGPT

除了 158K 图文指令数据，LLaVA 还混合了 **ShareGPT**（约 40K 真实用户与 ChatGPT 的对话）进行训练：

- **目的 1（防遗忘）**：LLM 只学图文指令会逐渐遗忘纯语言能力（数学、代码、常识问答）；
- **目的 2（保对话质量）**：ShareGPT 数据让模型保持流畅、自然的多轮对话风格；
- 具体做法：训练时把图文样本与纯文本样本**按比例混批**，纯文本样本没有视觉 token，损失只在回答位置计算。

## 五、训练两阶段（重点）

### 5.1 阶段一：特征对齐预训练（Projector Pretraining）

| 配置 | 值 |
|------|-----|
| 数据 | **558K 图文描述对**（CC3M 清洗后的子集，每张图一句话描述） |
| 冻结 | 视觉塔 ✅ 冻结；LLM ✅ 冻结 |
| 训练 | **只训练投影层**（LLaVA-1：Linear；LLaVA-1.5：MLP） |
| 目标 | 让投影层把 CLIP 视觉特征映射到 LLM 词嵌入空间 |

**阶段一的损失**：仍然是最普通的文本生成交叉熵（next-token prediction），监督信号是图片对应的描述文本：

$$\mathcal{L}_1 = -\sum_{t \in \text{caption}} \log p_\theta(x_t | x_{<t}, \text{visual tokens})$$

**阶段一的产出**：训练好的投影层。此时 LLM 没有任何视觉理解能力，只是投影层的输出从"随机噪声"变成了 LLM 认识的形式——**特征对齐完成**。

### 5.2 阶段二：端到端指令微调（End-to-End Instruction Tuning）

| 配置 | 值（LLaVA-1） | 值（LLaVA-1.5） |
|------|--------------|-----------------|
| 数据 | LLaVA-Instruct-158K | LLaVA-Instruct-665K + 公共 SFT 数据 |
| 冻结 | 视觉塔 ✅ 冻结 | 视觉塔 ❌ 可微调（论文实验：微调更好） |
| 训练 | 投影层 + LLM | 视觉塔 + 投影层 + LLM（全参数） |
| 数据形式 | 图文对话 + 纯文本对话混合 | 同左，数据量更大 |

**阶段二的损失**：与阶段一同为交叉熵，但监督信号从"描述句子"升级为"对话回答"：

$$\mathcal{L}_2 = -\sum_{t \in \mathcal{T}_{\text{assistant}}} \log p_\theta(x_t | x_{<t})$$

### 5.3 为什么要两阶段？（核心面试题）

| 观点 | 论证 |
|------|------|
| 直接端到端训练会发生什么 | 投影层从零随机初始化，视觉特征进 LLM 是"乱码"；LLM 会试图强行拟合乱码，梯度混乱，训出的模型看不懂图 |
| 阶段一的价值 | 先让投影层学会"把视觉特征翻译成 LLM 的语言"，此时 LLM 权重不动，梯度只修正投影层，任务简单、稳定收敛 |
| 阶段二的价值 | 在特征已经对齐的基础上，让 LLM 学习"如何根据视觉信息遵循指令"，训练目标从"翻译"升级为"对话" |
| 类比 | 先教翻译官学外语词汇（阶段一），再教他做同声传译（阶段二）——顺序颠倒则两头都学不好 |

> **LLaVA-1.5 的改动**：在阶段二解冻视觉塔（CLIP ViT-L/14@336 的最后一层全连接层，LoRA 或全量微调均可），让视觉特征进一步适配指令微调任务，VQAv2 等任务提升明显。

### 5.4 训练配置（论文参考值）

| 超参数 | LLaVA-1 | LLaVA-1.5 |
|--------|---------|-----------|
| 优化器 | AdamW | AdamW |
| 学习率（投影层/LLM） | 2e-5 | 2e-5 / 2e-4（视觉塔 2e-6） |
| 训练轮数 | 3 epoch（阶段二） | 1 epoch |
| 批大小 | 128（阶段二） | 128 |
| 训练成本 | 8×A100（约 8 小时） | 8×A100（约 20 小时，665K 数据） |
| 精度 | FP16/BF16 | BF16 + gradient checkpointing |

> **训练成本是 LLaVA 的招牌卖点**：整套训练在 8 张 A100 上不到一天，约 2 万美元级别（当时），相比之下 GPT-4 级别的训练成本不可同日而语。

## 六、LLaVA-1.5：相对 LLaVA-1 的改进

### 6.1 改进清单

| 改进点 | LLaVA-1 | LLaVA-1.5 | 效果 |
|--------|---------|-----------|------|
| 投影层 | 单层 Linear | **两层 MLP（GELU）** | 视觉特征表达力更强 |
| 视觉塔 | CLIP ViT-L/14@336 | **CLIP ViT-L/14@336 + 可选微调** | 分辨率提升 + 阶段二解冻视觉塔 |
| 视觉塔微调 | 全程冻结 | 阶段二解冻（最后 1/2 层或全量） | VQAv2、GQA 等提升 2~4 分 |
| LLM | Vicuna-7B/13B | **Vicuna-1.5（LLaMA-2 底座）** | 更强的语言底座 |
| 指令数据 | LLaVA-Instruct-158K | **LLaVA-Instruct-665K + 公共 SFT** | 数据量 4 倍+ |
| 纯文本数据 | ShareGPT（40K） | ShareGPT + VQA 等公共 SFT 数据 | 语言能力不退化 |
| 高分辨率 | 336（固定） | **336 + 双塔（anyres 的前身）** | 支持更高分辨率输入 |
| 训练 | 两阶段 | 两阶段（结构不变） | 范式稳定 |

### 6.2 LLaVA-Instruct-665K 组成

| 数据来源 | 数量 | 类型 |
|---------|------|------|
| 原 158K（GPT-4 生成） | 158K | 对话/描述/推理 |
| GPT-4V 扩充（对话 + 推理） | 约 400K | 对话 + 推理 |
| 其他视觉指令数据 | 约 100K | VQA 类、字幕类 |
| ShareGPT 等纯文本 | 约 40K | 纯文本对话 |

### 6.3 高分辨率支持（LLaVA-1.5 的过渡方案）

LLaVA-1.5 在 336 基础上引入**双分辨率分支**：输入图缩放两份（224 与 336），分别过视觉塔再融合，以缓解高分辨率带来的 token 爆炸。这个思路在 LLaVA-NeXT 中被系统化为 anyres（任意分辨率切图）。

## 七、LLaVA-NeXT（LLaVA-1.6）：任意分辨率

### 7.1 核心改进：AnyRes（任意分辨率切图）

LLaVA-NeXT 的视觉输入处理：

```text
输入图像（任意分辨率）
  ├─ 全图缩放：resize 到 336×336（全局视图，一个"概览"）
  └─ 网格切图：将图像切分成 2×2、1×2、2×3、3×4… 的网格，
              每个网格单独 resize 到 336×336 送入视觉塔
                 ↓
  全局视图 token + 各网格 token 全部拼接 → 输入 LLM
```

| 属性 | 细节 |
|------|------|
| 切图数量 | 最多 6 个网格（2×3 或 3×2）+ 1 个全局视图 |
| 单图 token 数 | 最多 7 × 576 = **4032 个视觉 token**（576 全局 + 6×576 网格） |
| 分辨率范围 | 336 ~ 672（等效），支持超长图（如 1:2 的竖版海报） |
| 动态 token | 按图像纵横比动态决定网格划分，token 数随图像变化 |
| 网格大小选择 | 与图像纵横比最接近的预设组合（如 16:9 → 2×3 网格） |

### 7.2 数学视角：为什么切图能"看清"细节

单分辨率 336 输入下，一个 14×14 patch 覆盖原图 $336/14 = 24$ 像素的**方形区域**。若原图是 1000×1000 的高清图，resize 到 336 后一个 patch 覆盖原图约 $1000/24 \approx 42$ 像素——**小物体/小文字直接被压没**。

切图后，每个网格单独 resize 到 336，网格内一个 patch 只覆盖 $336/24 = 14$ 像素的原图区域：

$$\text{等效分辨率} = 336 \times \max(\text{rows}, \text{cols}) \approx 336 \times 2 \sim 336 \times 3$$

- 2×3 切图 ≈ 672×1008 等效分辨率；
- 细粒度信息（小物体、OCR、图表细节）大幅保留。

### 7.3 代价与对策

| 问题 | 说明 | LLaVA-NeXT 对策 |
|------|------|----------------|
| 计算量爆炸 | 4032 个视觉 token 的注意力开销远超 576 | 使用支持更长序列的 LLM 底座（Mistral-7B 原生 8K 上下文、Yi-34B 支持更长） |
| 训练显存 | 更多 token 意味着更大激活 | gradient checkpointing、BF16、序列打包（packing） |
| 推理速度 | token 多 → 预填充慢 | 视觉 token 的 KV cache 一次计算，后续增量生成 |

### 7.4 数据与底座升级

| 改进 | 内容 |
|------|------|
| 更好的 SFT 数据 | 新增大规模多模态 SFT 混合数据（约 100 万级），包括 OCR、图表、文档理解 |
| 更长的训练 | 两个阶段：先用大规模数据预训练对齐，再指令微调 |
| 多底座 | Vicuna-1.5、Mistral-7B、Yi-34B 三个版本 |
| 效果 | 在 MMMU、MathVista、DocVQA、ChartQA 等基准上大幅超越 LLaVA-1.5，**对标商业 VLM**（GPT-4V 的 80%~90% 水平） |

### 7.5 LLaVA 全系列对比

| | LLaVA（2023.4） | LLaVA-1.5（2023.10） | LLaVA-NeXT（2024.1） |
|--|-----------------|----------------------|----------------------|
| 投影层 | Linear | MLP | MLP |
| 视觉塔 | CLIP ViT-L/14@336（冻结） | CLIP ViT-L/14@336（可微调） | CLIP ViT-L/14 多尺度 |
| 分辨率 | 336 | 336 | 任意（336~672+） |
| 视觉 token | 576 | 576 | 576 ~ 4032 |
| 指令数据 | 158K | 665K | 约 100 万级混合 |
| LLM | Vicuna-7B/13B | Vicuna-1.5-7B/13B | Vicuna/Mistral/Yi-34B |
| 定位 | 范式验证 | 性能优化 | 对标商业 VLM |

## 八、推理流程

### 8.1 端到端推理文字版

```text
1. 输入图像（336×336；LLaVA-NeXT 为全局 + 网格多尺度）
2. 图像 → CLIP ViT-L/14 → 576 个 patch 特征（每个 1024 维）
3. 丢弃 [CLS]，576 个 patch 特征 → 投影层（Linear/MLP）→ 576 个 4096 维视觉 token
4. 文本指令 → tokenizer → 文本 token 序列
5. 拼接：[视觉 token × 576] + [用户指令 token] → 一次性送入 LLM
6. LLM 自回归生成回答：
      p(x_t | x_{<t}) → 采样下一个 token → 追加到序列 → 循环
7. 直到遇到 <EOS> 或达到最大长度，输出完整回答
```

### 8.2 公式化描述

第 $t$ 步生成的 token $x_t$ 的条件分布：

$$p(x_t | x_{<t}, \mathbf{Z}_v) = \text{softmax}\left(W_{\text{lm}} \cdot h_t\right)$$

其中：

- $\mathbf{Z}_v = [\text{MLP}(z_v^{(1)}), \dots, \text{MLP}(z_v^{(576)})]$ 是投影后的视觉 token 序列；
- $h_t$ 是 LLM 第 $t$ 步的隐藏状态；
- $W_{\text{lm}}$ 是语言模型头（输出词表概率）。

> 整个推理过程与纯文本 LLM **唯一的区别**：输入序列前多了 576 个（或更多）由图像编码而来的伪 token。

### 8.3 三种推理能力

| 能力 | 输入 | 输出 |
|------|------|------|
| 视觉问答（VQA） | 图 + 问题 | 短回答 |
| 详细描述 | 图 + "请详细描述" | 长段落 |
| 多轮对话 | 图 + 多轮问题 | 每轮回答（视觉 token 每轮重复输入） |

## 九、对比表：LLaVA vs BLIP-2 vs Qwen-VL

| 维度 | LLaVA-1.5 | BLIP-2 | Qwen-VL |
|------|-----------|--------|---------|
| 发表 | 2023.10 | 2023.1 | 2023.9 |
| 视觉塔 | CLIP ViT-L/14@336 | ViT-g/14（EVA-CLIP 变体） | 自研 ViT（约 675M） |
| 桥接方式 | **MLP 投影层**（最简） | Q-Former（query + 交叉注意力） | 单层 Linear 交叉注意力 + resize 压缩 |
| 桥接参数量 | 约 6M | 约 180M | 轻量 |
| 视觉 token 数 | 576 | **32**（固定 query） | 256（4×4 压缩到 32×4） |
| LLM | Vicuna-1.5-7B/13B | Flan-T5 / OPT | Qwen-7B |
| 预训练数据 | 558K（阶段一）+ 665K 指令 | 129M 图文对 | 1.4B 图文对 |
| 训练成本 | 约 2 万美元（8×A100 一天级） | 高（大数据预训练） | 高（大规模预训练） |
| 两阶段 | 是（对齐 → 指令微调） | 是（Q-Former → 桥接微调） | 是（预训练 → SFT） |
| 指令微调数据 | GPT-4 生成（665K） | InstructBLIP 微调 | 自建指令数据 |
| 高分辨率 | 336（NeXT 支持 anyres） | 224/364 | 448（原生支持） |
| 代表性基准 | VQAv2 80.0+ | VQAv2 约 65（BLIP-2 Opt-2.7B） | VQAv2 约 79 |
| 定位 | **极简范式 + 数据驱动** | 高效桥接（对齐优秀、生成一般） | 全栈自研（视觉塔 + LLM） |

**关键结论**：

1. **连接方式**：BLIP-2 的 Q-Former 用 32 个可学习 query 压缩视觉信息（信息有损但 token 少）；LLaVA 用全量 576 patch token + 简单投影（信息无损但 token 多）；Qwen-VL 折中（token 压缩到 256）。
2. **数据策略**：BLIP-2 靠 129M 图文对大规模预训练；LLaVA 只靠 558K 对齐 + 665K 指令数据——**LLaVA 证明指令数据质量比图文对数量更重要**。
3. **成本**：LLaVA 全流程训练成本比 BLIP-2/Qwen-VL 低一到两个数量级，且效果后来居上。

## 十、局限

### 10.1 分辨率与细节

| 局限 | 说明 |
|------|------|
| 固定分辨率 | LLaVA-1/1.5 固定 336 输入，高分辨率图像细节（小字、小物体）被压缩丢失 |
| 切图计算量 | LLaVA-NeXT 的 anyres 切图后最多 4032 个视觉 token，显存和推理延迟大幅上升 |
| 无原生任意分辨率 | 相比 Qwen2-VL 的原生动态分辨率，anyres 是"切图 + 拼接"的近似方案 |

### 10.2 幻觉（Hallucination）

LLaVA 系列存在显著的**物体幻觉**问题：模型可能"看到"不存在的物体（如图中没有杯子却说有杯子）。原因：

- 指令数据由 GPT-4 生成，本身带有少量幻觉噪声；
- 训练目标（next-token prediction）偏向流畅的文本延续，而非严格的视觉核实；
- 视觉 token 粒度（576 个）对细粒度存在性判断仍不足。

### 10.3 语言与任务覆盖

| 局限 | 说明 |
|------|------|
| 英文为主 | 指令数据（ShareGPT、LLaVA-Instruct、公共 SFT）以英文为主，中文/多语能力弱 |
| 基准饱和 | VQAv2 等经典基准接近饱和，区分度下降 |
| 知识局限 | 视觉推理深度依赖 LLM 底座的知识边界 |

### 10.4 架构层面

- 视觉塔与文本塔**分别预训练再桥接**，视觉特征与语言特征存在系统性 gap（相比原生多模态训练）；
- 全量 patch token 使长上下文成本高，对超长文档/视频等场景不友好；
- 与 BLIP-2 的 32 个 query 相比，LLaVA 的 576 token 在**效率**上处于劣势（靠 LLM 规模弥补）。

## 十一、高频面试问答

**Q1：LLaVA 和 BLIP-2 的核心区别是什么？**
连接方式：BLIP-2 用 Q-Former（32 个可学习 query + 交叉注意力，两阶段预训练），压缩性强但信息有损；LLaVA 用最简单的 MLP 投影，把全部 576 个 patch token 直接映射到 LLM 词嵌入空间。数据上 LLaVA 用 GPT-4 生成的 158K/665K 指令数据做端到端微调，成本远低于 BLIP-2 的 129M 图文对预训练，效果却更好——证明"简单的连接 + 高质量指令数据"足以追赶复杂桥接方案。

**Q2：为什么投影层用单层 Linear（或两层 MLP）就够，不需要 Q-Former？**
因为 CLIP 视觉塔已经通过大规模图文对比预训练把视觉特征对齐到文本语义空间，patch 特征"离语言很近"。投影层只需要做维度变换（1024 → 4096）和轻微非线性调整，不需要额外的信息压缩与选择。Q-Former 的"信息选择"能力在任务简单时是冗余的，LLaVA 的实验证明了这一点。

**Q3：视觉 token 太多会怎样？**
token 多 → 信息粒度细（看得清），但 LLM 的注意力是 O(n²)，序列变长后显存与计算量平方级增长，且 LLM 的上下文窗口可能放不下。LLaVA 用 576 个 token 是"够用"的平衡点；LLaVA-NeXT 切图后最多 4032 个 token，必须配合长上下文 LLM 和序列打包技巧。BLIP-2 用 32 个 query 则是反方向的选择（效率优先、信息有损）。

**Q4：为什么两阶段训练是必要的？直接端到端不行吗？**
阶段一让投影层学会"把视觉特征翻译成 LLM 的语言"（只训投影层，任务简单稳定）；阶段二再训练 LLM 学会"看视觉信息回答指令"。若一开始就端到端，随机初始化的投影层给 LLM 输入的是"乱码"，LLM 会强行拟合乱码导致梯度混乱、收敛困难。类比：先学词汇再学翻译，顺序不能颠倒。

**Q5：什么是视觉指令微调（Visual Instruction Tuning）？**
把指令微调（Instruction Tuning）从纯文本扩展到多模态：用"图像 + 用户指令 → AI 回答"的样本训练 LLM，让其学会根据视觉内容遵循指令。监督信号只有 AI 回答部分（其余位置掩码）。LLaVA 是这一范式的开创者，它证明：只需约 158K 条 GPT-4 生成的视觉指令样本，就能让冻结视觉塔 + 简单投影 + Vicuna 具备接近 GPT-4V 的对话能力。

**Q6：LLaVA 的数据是怎么生成的？**
两步：先把 COCO 图像的位置/属性标注转成符号化文本描述，再让 GPT-4（文本版）基于描述扮演"用户 + 助手"生成三类数据——对话（58K）、详细描述（23K）、复杂推理（77K），合计 158K。LLaVA-1.5 扩充到 665K（加入 GPT-4V 生成的更多对话/推理样本 + 公共 SFT 数据）。

**Q7：LLaVA-1.5 相比 LLaVA-1 的四个关键改进？**
① 投影层：Linear → 两层 MLP（GELU），输出维度 512 → 4096；② LLM 底座：Vicuna → Vicuna-1.5（LLaMA-2）；③ 数据：158K → 665K 指令数据 + 公共 SFT；④ 训练：阶段二解冻视觉塔（可选微调），进一步对齐视觉特征。四项改进合计在 VQAv2 等基准上提升约 10+ 分。

**Q8：LLaVA-NeXT 的 anyres 是怎么实现的？优缺点？**
把输入图缩放成全局视图（336）并按纵横比切成最多 6 个网格，每个网格单独 resize 到 336 过视觉塔，视觉 token 最多 7×576 = 4032 个。优点：等效分辨率提升到 336×N，小物体/OCR/图表细节保留；缺点：token 数量爆炸导致计算量大、推理慢，需要长上下文 LLM + 显存优化技巧。

**Q9：LLaVA 训练时三种模态的 token 分别在哪里？为什么只有回答算 loss？**
序列 = 视觉 token（576 个，最前）+ 用户指令 token + AI 回答 token（最后）。掩码规则：只有 AI 回答位置计算交叉熵。原因：模型的任务是"根据输入生成回答"，图像和指令是输入条件，监督信号只有回答；其他位置算 loss 会让模型去学无意义的"生成图像特征/复述问题"。

**Q10：LLaVA 的局限有哪些？怎么改进？**
① 分辨率固定/切图计算量大 → 动态分辨率、原生多尺度视觉塔（Qwen2-VL）；② 幻觉 → 视觉核实机制、RLHF 对齐、更高分辨率视觉塔；③ 英文为主 → 加入多语指令数据；④ 视觉塔与 LLM 分开预训练的语义 gap → 联合预训练（如 InternVL 的 ViT+LLM 交替训练）。

## 十二、常见误区

**误区 1：LLaVA 的架构创新是核心。**
错。LLaVA 的架构（CLIP + Linear/MLP + Vicuna）几乎没有创新，核心贡献是：① 证明最简连接范式可行；② 提出用 GPT-4 自动构造视觉指令数据；③ 确立"对齐预训练 + 指令微调"两阶段范式。面试答"LLaVA 的创新在数据"是加分回答。

**误区 2：视觉 token 越少越好。**
不对。token 少 → 效率高但信息有损（BLIP-2 的 32 query 在细粒度任务上吃亏）；token 多 → 看得清但代价大。LLaVA 选择 576 全量 patch 是为了信息无损，NeXT 甚至切图到 4032。token 数量是效率与信息量的权衡，不是单调最优。

**误区 3：阶段二只需要训练 LLM。**
不完整。LLaVA-1 阶段二训练投影层 + LLM；LLaVA-1.5 阶段二甚至解冻视觉塔（全参数微调），三者联合优化。视觉塔冻结只是 LLaVA-1 的选择，不是范式必需。

**误区 4：LLaVA 的 158K 数据都是人工标注的。**
错。158K 全部由 GPT-4 基于 COCO 图像自动生成（位置标注转文本 → GPT-4 生成三类指令），人工只负责构造 prompt 模板和清洗。这正是 LLaVA 成本低的根本原因。

**误区 5：LLaVA 的投影层输出是 LLM 的词嵌入。**
严格说不完全对。投影层的目标是让视觉特征**分布接近** LLM 词嵌入空间（数值范围、维度一致），但视觉 token 与真实词嵌入不完全等价——LLM 在阶段二会学出对视觉 token 的专门处理方式。说"投影到 LLM 的词嵌入空间"是常用的直观表述。

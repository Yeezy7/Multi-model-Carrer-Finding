# 电商商品理解：CLIP 相似度 + VLM 结构化抽取 + 规则融合

> 本模块索引见 [行业应用案例详解](行业应用案例详解.md)

## 一、任务定义

电商多模态的四个核心子任务：

| 子任务 | 输入 | 输出 | 典型模型 | 一句话评估 |
| --- | --- | --- | --- | --- |
| 图文一致性校验 | 商品图 + 标题/卖点 | 一致/不一致（含原因） | CLIP 微调 + VLM + 规则 | 准确率、按错误类别拆解 |
| 属性抽取 | 商品图 + 标题 | JSON：颜色/材质/款式/数量 | VLM（结构化输出） | 字段级准确率 |
| 以图搜图 | query 图 | 相似商品列表 | 双塔 embedding + 索引 | 召回@K |
| 同款识别 | 两张商品图 | 是否同款 | 图对相似度模型 + VLM 复核 | 同款判别准确率 |

**为什么"图文一致性"是电商最痛的场景**：

1. **货不对板直接亏损**：主图与描述不一致 → 用户退货，平台承担逆向物流与信任损失；
2. **2C 场景错误代价外溢**：模型误判会直接变成客诉，不像内部工具可以慢慢迭代；
3. **难点真实存在**：平台审核只能查"违禁"，查不了"图文是否对得上"——这天然需要跨模态理解，是多模态面试最常问的业务题之一。

## 二、技术方案：三层架构

```
                       ┌──────────────────────────────────────────┐
                       │  商品主图 z_I = E_img(I)                  │
                       │  标题文案 z_T = E_txt(T)                  │
                       │  s = sigmoid(λ · cos(z_I, z_T) + b)      │
   ┌───────────────┐   └──────────────────┬───────────────────────┘
   │  第一层 CLIP   │   s ≥ τ_high → 一致        │ s < τ_low → 不一致
   │  图文对齐打分   │   τ_low ≤ s < τ_high ──────┘（边界样本，继续下一层）
   └───────────────┘
                    ▼
   ┌───────────────┐   prompt: "请提取商品属性，输出 JSON：
   │  第二层 VLM    │   {color, count, material, style}"
   │  属性抽取      │   → 图侧属性 A_I = {…}, 文侧属性 A_T = {…}
   └───────────────┘
                    ▼
   ┌───────────────┐   颜色冲突 / 数量不一致 / 款式冲突 / 材质互斥
   │  第三层 规则校验 │   命中任一 → 判"不一致"（置信度 0.95）
   └───────────────┘   未命中且 s ≥ τ_high → "一致"
                    ▼
   ┌──────────────────────────────────────────────┐
   │ 输出：{consistent: bool, score, reasons,      │
   │        attrs_img, attrs_txt, confidence}      │
   └──────────────────────────────────────────────┘
```

### 2.1 第一层：图文对齐打分（CLIP/SigLIP 微调）

- **为什么必须微调**：开源 CLIP 在 LAION 自然图上训练，商品图（白底、多角度、光线单一）是明显域漂移；不动模型直接打分，同类商品的分数可能低于跨类商品；
- **打分形式**：图像与文本经编码器得到归一化向量，余弦相似度映射到概率：
  $$s = \sigma\left(\lambda \cdot \frac{z_I^\top z_T}{\|z_I\|\|z_T\|} + b\right), \qquad s \in (0,1)$$
  其中 $\lambda$（温度）与 $b$（偏置）在微调时学出；也可以用 SigLIP 的逐对损失直接训 sigmoid 头；
- **阈值校准**：训练时用 ROC 曲线选阈值，线上再按业务代价微调（详见第四节）：
  - $\tau_{high}$：高于它直接判"一致"（低风险）；
  - $\tau_{low}$：低于它直接判"不一致"；
  - 两者之间的**边界样本**才花成本走第二层。

### 2.2 第二层：VLM 属性抽取

- **为什么 CLIP 不够**：CLIP 回答"像不像"，回答不了"哪里不像"——无法定位是颜色还是款式出了问题，也无法处理计数这类 CLIP 天然盲区；
- **做法**：把主图与标题拼进 prompt，要求输出受限 JSON：
  ```
  你是一个电商商品属性抽取器。请根据商品图和标题，输出：
  {"color": "颜色", "count": "数量", "material": "材质", "style": "款式"}
  只输出 JSON，不要解释。
  ```
- **工程要点**：
  1. **schema 约束**：解码时用正则 JSON 解析 + 受限词表（枚举值用 logits 过滤），防止模型输出"米白偏粉"这类不可比字符串；
  2. **空值处理**：某属性图上可见但文里没写 → 该属性不参与比对（缺省不算冲突），避免误杀；
  3. **成本意识**：VLM 单次调用是 CLIP 的几十倍，所以只对边界样本调用。

### 2.3 第三层：规则与模型融合

- **规则是确定性的**：属性是枚举值，冲突判断零成本、零幻觉，且可解释——这是纯模型做不到的：
  | 规则 | 判据 | 例子 |
  | --- | --- | --- |
  | 颜色冲突 | $A_I^{color} \ne A_T^{color}$ | 图=蓝色 vs 文=红色 |
  | 数量不一致 | $A_I^{count} \ne A_T^{count}$ | 图=1 件 vs 文=2 件 |
  | 款式冲突 | $A_I^{style} \ne A_T^{style}$ | 图=连衣裙 vs 文=牛仔裤 |
  | 材质互斥 | 白名单外组合 | 真丝 vs 涤纶（手工维护互斥表） |
- **融合决策**（本文第六节 demo 的完整实现）：
  1. 规则命中 → **不一致**（置信度最高，0.95）；
  2. 无冲突 且 $s \ge \tau_{high}$ → **一致**；
  3. 无冲突 且 $s \le \tau_{low}$ → **不一致**（分数低到没商量）；
  4. 其余 → **待人工复核**（置信度 = $1 - 2|s - 0.5|$，越接近 0.5 越需要人看）。

### 2.4 三层成本与覆盖

| 层级 | 单次成本量级 | 覆盖样本 | 角色 |
| --- | --- | --- | --- |
| CLIP 打分 | CPU，~10ms | 100% | 粗筛，挡住大部分简单样本 |
| VLM 抽取 | GPU，~400ms | 10%~15% | 边界样本精细化 |
| 规则校验 | 免费 | 全部 | 确定性兜底 |

## 三、数据构造

### 3.1 正负样本

- **正样本**：真实一致商品（主图 + 正确标题），来源：业务沉淀、标注；
- **负样本**：
  1. 真实负样本：业务中发现的货不对板（线上回流，价值最高）；
  2. 构造负样本：把 A 商品的图配上 B 商品的标题（保证描述可读、真实存在，否则模型学"乱文"这种假信号）。

### 3.2 hard negative 构造（重点）

hard negative = 模型最容易判错的负样本。构造手段按难度递进：

| 手段 | 例子 | 为什么难 |
| --- | --- | --- |
| 同商品不同图 | 同款不同角度/光线/滤镜 | CLIP 的分数天然很高，因为语义完全一致 |
| 相似描述不同商品 | "红色连衣裙" vs "红色半身裙" | 共享颜色+品类词，仅一个属性不同 |
| 近似色 | "酒红" vs "正红"、"藏青" vs "深蓝" | 颜色阈值处易混淆 |
| 数量陷阱 | 1 件 vs 2 件装 | CLIP 对计数不敏感，只能靠规则层 |
| 场景/背景干扰 | 同款衣服换不同背景 | 模型容易偷看背景而不是主体 |

- **配比经验**：hard negative 占负样本 50%~70%，并保证与正样本比例接近（否则模型退化成"判负"刷指标）；
- **损失加权**：对 hard negative 提高权重：$L = \sum_i w_i \cdot \text{BCE}(y_i, \hat y_i)$，$w_i$ 按难度分档（1.0 / 1.5 / 2.0）。

### 3.3 图文不一致分类体系

评测与错误分析都按此五分类展开：

| 类别 | 例子 | 主要拦截层 | 难度 |
| --- | --- | --- | --- |
| 颜色 | 图=蓝色，文=红色 | 规则（VLM 抽取后比对） | 简单 |
| 数量 | 图=1 件，文=2 件装 | 规则（CLIP 盲区） | 简单 |
| 款式 | 连衣裙 vs 半身裙 | 规则 + CLIP | 中 |
| 场景/背景 | 室内实拍 vs 文案写"户外" | CLIP 相似度 | 难 |
| 品牌 | 图=无标 A 货，文=正品大牌 | VLM（图文双侧品牌识别） | 难 |

分类体系的价值：**错误分析的骨架**——线上 badcase 先归到五类，再按占比排序投入资源（见第四节）。

## 四、评测设计

### 4.1 指标

- 二分类主指标：准确率、一致类精确率 $P$、召回率 $R$、F1：
  $$F1 = \frac{2PR}{P + R}, \qquad P = \frac{TP}{TP+FP}, \qquad R = \frac{TP}{TP+FN}$$
- 业务上"不一致"样本占比低（通常 <10%），**别只看准确率**：全判"一致"也有 90%+ 准确率；
- 附加指标：属性字段抽取准确率（每属性一个）、人工复核率（越低越省钱）。

### 4.2 错误案例分类

| 错误类型 | 典型场景 | 改进方向 |
| --- | --- | --- |
| 同款不同图误判 | 光线差异大被 CLIP 判低分 | 数据增强、换域 hard negative |
| 数量类冲突漏判 | CLIP 分数高、VLM 没抽到数量 | 强化数量属性 prompt、规则兜底 |
| 场景类误判 | 背景换得离谱被放行 | 增加场景维度 hard negative |
| 空值误杀 | 图有属性、文没写被当冲突 | 缺省属性不参与比对 |

### 4.3 阈值选择：ROC 与代价矩阵

- 在验证集上画 ROC，遍历 $\tau$ 得 $(\text{FPR}(\tau), \text{TPR}(\tau))$；
- 最优阈值由业务代价决定：
  $$\tau^* = \arg\min_\tau \left[ c_{FN} \cdot \text{FN}(\tau) + c_{FP} \cdot \text{FP}(\tau) + c_{human} \cdot \text{Human}(\tau) \right]$$
  其中 $\text{Human}(\tau)$ 是落入 $[\tau_{low}, \tau_{high})$ 需要人工复核的比例；
- 直觉：**误判"一致"（FN）代价 = 用户收货后投诉退货；误判"不一致"（FP）代价 = 白白拦下好商品**。电商通常让 FP 略多（宁可多审不放过），再通过人工复核吸收。

## 五、多模态检索：以图搜图与同款识别

### 5.1 两级架构：索引召回 + 模型精排

```
query 图 → 图像 embedding → 向量索引 top-K（FAISS/HNSW, K≈100~500）
                                        ↓
                          候选集 → 精排（同款判别模型 / VLM 逐对复核）
                                        ↓
                              top-N 结果 + 相似度分数
```

- **召回**：余弦相似度 $sim = \cos(z_q, z_c)$，向量库（FAISS/Milvus）负责近似最近邻，毫秒级；
- **精排**：索引召回的是"视觉相似"，不等于"同款"——同款还要看款式、材质、品牌细节，用专门训练的同款判别模型或 VLM 复核；
- **embedding 训练**：以图搜图用对比学习（InfoNCE）微调，正样本对 = 同款不同图，负样本 = 不同款但视觉相似（构造同 3.2 的 hard negative）。

### 5.2 为什么索引召回后还要 VLM 复核

| 环节 | 回答的问题 | 例子 |
| --- | --- | --- |
| 向量召回 | "长得像吗" | 白底红色连衣裙照片相似 → 召回 |
| VLM 复核 | "是同一个商品吗" | 召回的高仿/同款不同材质 → 剔除 |

检索与一致性是同一套能力的两种用法：一致性判断图文是否一致，同款识别判断图图是否一致——**共享 embedding 与 VLM 层，是简历里值得写的复用点**。

## 六、源码实现：图文一致性判断最小 demo

> 纯 Python 可运行：模拟 CLIP 打分（第一层）+ VLM 属性 JSON 解析（第二层）+ 规则校验融合（第三层），输出结构化结论 JSON。

```python
import json
import random
import re

COLOR_WORDS = ["红", "蓝", "白", "黑", "绿", "黄", "紫", "粉", "酒红", "藏青"]
STYLE_WORDS = {"连衣裙": "连衣裙", "半身裙": "半身裙", "T恤": "T恤",
               "衬衫": "衬衫", "牛仔裤": "牛仔裤"}
MATERIAL_WORDS = {"棉": "棉", "真丝": "真丝", "羊毛": "羊毛", "聚酯": "聚酯"}


def vlm_extract(text: str) -> dict:
    """第二层：模拟 VLM 从图文描述中抽取结构化属性 JSON（按关键词匹配）"""
    attrs = {}
    for c in COLOR_WORDS:
        if c in text:
            attrs["color"] = c
            break
    m = re.search(r"(\d+)\s*件", text)
    if m:
        attrs["count"] = int(m.group(1))
    for w, v in STYLE_WORDS.items():
        if w in text:
            attrs["style"] = v
            break
    for w, v in MATERIAL_WORDS.items():
        if w in text:
            attrs["material"] = v
            break
    return attrs


def clip_score(img: dict, txt: dict, seed: int) -> float:
    """第一层：模拟微调后 CLIP 的图文对齐打分（0~1）

    真实场景中该分数来自模型前向；这里用属性重叠度 + 噪声模拟，
    并故意让它"看不见数量"——与真实 CLIP 对计数不敏感的现象一致。
    """
    rng = random.Random(seed)
    keys = list(set(img) | set(txt))
    matched = sum(1 for k in keys if k in img and k in txt and img[k] == txt[k])
    ratio = matched / max(1, len(keys))
    s = 0.30 + 0.62 * ratio + rng.uniform(-0.04, 0.04)
    return round(min(0.97, max(0.05, s)), 3)


def rule_check(img: dict, txt: dict) -> list:
    """第三层：逻辑规则校验，返回冲突原因列表（确定性、零成本）"""
    reasons = []
    if "color" in img and "color" in txt and img["color"] != txt["color"]:
        reasons.append(f"颜色冲突: 图={img['color']} vs 文={txt['color']}")
    if "count" in img and "count" in txt and img["count"] != txt["count"]:
        reasons.append(f"数量不一致: 图={img['count']} vs 文={txt['count']}")
    if "style" in img and "style" in txt and img["style"] != txt["style"]:
        reasons.append(f"款式不一致: 图={img['style']} vs 文={txt['style']}")
    return reasons


def fuse(img: dict, txt: str, seed: int, tau_high=0.72, tau_low=0.45) -> dict:
    """三层融合主流程：CLIP 打分 -> VLM 抽取 -> 规则校验 -> 决策"""
    txt_attrs = vlm_extract(txt)
    s = clip_score(img, txt_attrs, seed)
    reasons = rule_check(img, txt_attrs)

    if reasons:
        decision, conf = "不一致", 0.95  # 规则冲突是确定性的，置信度最高
    elif s >= tau_high:
        decision, conf = "一致", round(s, 3)
    elif s <= tau_low:
        decision, conf = "不一致", round(1 - s, 3)
    else:
        decision, conf = "待人工复核", round(1 - 2 * abs(s - 0.5), 3)

    return {
        "clip_score": s,
        "图片属性(图侧VLM)": img,
        "文本属性(文侧VLM)": txt_attrs,
        "规则冲突": reasons,
        "结论": decision,
        "置信度": conf,
    }


if __name__ == "__main__":
    cases = [
        ({"color": "红", "count": 1, "style": "连衣裙", "material": "棉"},
         "红色棉质连衣裙 一件 纯棉舒适", 1),
        ({"color": "蓝", "count": 1, "style": "连衣裙", "material": "棉"},
         "红色棉质连衣裙 一件 纯棉舒适", 2),
        ({"color": "红", "count": 1, "style": "连衣裙", "material": "棉"},
         "红色连衣裙 2件装 纯棉", 3),
        ({"color": "红", "count": 1, "style": "连衣裙", "material": "棉"},
         "红色雪纺连衣裙 夏季新款 透气显瘦", 4),
        ({"color": "红", "count": 1, "style": "连衣裙", "material": "棉"},
         "蓝色牛仔裤 一条 纯棉", 5),
    ]
    for img, txt, seed in cases:
        print(json.dumps(fuse(img, txt, seed), ensure_ascii=False, indent=2))
        print("-" * 60)
```

**demo 要点回顾**：三层各自解决一个问题——CLIP 层拦"大方向不一致"（case 5）、规则层拦"属性级冲突"（case 2/3，含 CLIP 盲区计数）、边界层送人工（case 4）。真实项目只需把 `clip_score` 换成模型前向、`vlm_extract` 换成 VLM 服务调用。

## 七、高频面试问答

**Q1：为什么不用纯 CLIP 做图文一致性？**
① CLIP 是全局相似度，回答不了"哪里不一致"，无法给出可解释的冲突原因；② 对属性互换、计数、同款不同图不敏感（case 3 里数量冲突时分数仍高达 0.74）；③ 阈值附近样本无法细分。VLM 提供结构化属性、规则提供确定性，三层各司其职。

**Q2：图文不一致分几类？**
五类：颜色、数量、款式、场景/背景、品牌。分类体系服务错误分析——线上 badcase 按类别占比排序，资源投给占比最高的类别。

**Q3：hard negative 怎么构造？**
同商品不同图（光线/角度/滤镜）、相似描述不同商品（共享多个属性词）、近似色、数量陷阱、场景干扰。配比上 hard 占负样本 50%~70%，配损失权重分档（1.0/1.5/2.0）。构造原则：**负样本必须"读起来像真的"**，不能靠乱文。

**Q4：三层怎么融合？**
规则命中直接判不一致（确定性，置信度最高）；无冲突按 CLIP 分数二分：$s \ge \tau_{high}$ 判一致、$s \le \tau_{low}$ 判不一致、中间送人工。规则是最高优先级，模型分数只在无规则冲突时生效。

**Q5：阈值怎么定？**
ROC 曲线上按业务代价矩阵选点：误判一致（FN）= 退货客诉，误判不一致（FP）= 误拦好商品。代价不对称时用 $\arg\min_\tau (c_{FN}\text{FN} + c_{FP}\text{FP} + c_{human}\text{Human})$，电商通常多送人工复核来吸收 FP。

**Q6：以图搜图为什么要 VLM 复核？**
向量召回回答"长得像"，同款还要看款式/材质/品牌细节；高仿与同款不同材质在 embedding 空间很近，用 VLM 逐对复核做"是同一个商品吗"的最终裁决。

**Q7：VLM 属性抽错了怎么办？**
三层防御：① 受限词表 + schema 约束（枚举值过滤，防"米白偏粉"这类不可比输出）；② 空值不算冲突（缺省不参与比对，防误杀）；③ 属性级置信度 + 规则校验结果不置信时自动转人工，不信任模型单点结论。

**Q8：不一致样本占比很低，训练怎么办？**
重采样 + 损失加权（$L = \sum w_i \text{BCE}$），hard negative 拉高难度；评测禁止只看准确率（全判一致也有 90%+），必须看 F1 与错误分类。

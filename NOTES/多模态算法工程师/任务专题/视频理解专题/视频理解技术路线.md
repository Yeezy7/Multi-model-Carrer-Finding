# 视频理解技术路线：从抽帧到视频 LLM

> 本模块索引见 [视频理解专题详解](视频理解专题详解.md)

## 一、概述：视频建模 = 图像建模 + 时间建模

视频的原始形态是每秒 24~30 帧的图像序列。任何视频理解方法都要回答同一个问题：**怎么把时间维度用起来**。按"时间信息进入模型的方式"，所有方法分三条路线：

1. **帧级聚合**：时间不进入模型结构，只在池化时"平均"一下；
2. **时空建模**：时间进入卷积核或注意力矩阵，模型结构感知帧间关系；
3. **视频 LLM**：时间进入位置编码（M-RoPE），模型结构复用图像 VLM，LLM 负责时序推理。

而在建模之前，所有路线都要先解决第一步——**抽帧**：把 30fps 的原始视频变成模型吃得了的输入。本文按"抽帧 → 三条路线 → 时序定位任务 → 源码 → 选型"的顺序展开。

## 二、抽帧策略：第一道 token 关卡

### 2.1 四种主流策略

| 策略 | 做法 | 优点 | 缺点 | 适用场景 |
| --- | --- | --- | --- | --- |
| 均匀采样（Uniform） | 按固定间隔取帧，如 2fps 或每 N 帧取一帧 | 实现简单、时间覆盖均匀、可控性好 | 关键瞬间可能落在采样间隙被漏掉 | 大多数视频 LLM（Qwen2.5-VL 默认 2fps） |
| 随机采样（Random） | 训练时在时间轴上随机抽帧 | 等价数据增强，覆盖不同时刻 | 推理时不可用（需确定结果） | 训练阶段的通用策略 |
| 关键帧采样（Keyframe） | 选内容变化最大的帧（帧差/光流最大） | 信息密度高，跳过长片段"静止画面" | 变化大 ≠ 语义重要（抖动、切镜干扰） | 视频封面、摘要、检索粗排 |
| 镜头切分（Shot Boundary） | 先检测镜头切换点，每个镜头内再各采几帧 | 贴合叙事结构，语义完整 | 需要额外的切分模型/算法 | 影视/长视频理解、事件检测 |
| 动态 FPS（Dynamic FPS） | 运动剧烈处加密采样、静止处稀疏采样 | 在固定 token 预算内最大化信息量 | 采样位置不可预期，实现复杂 | 长视频 LLM（InternVideo2.5、LLaVA-Video 等） |

### 2.2 公式视角

均匀采样第 $k$ 个采样帧的原始帧号：

$$t_k = \left\lfloor \frac{k \cdot T_{total}}{N_{sample}} \right\rfloor, \quad k = 0, 1, \dots, N_{sample}-1$$

关键帧采样按帧间变化量排序取 top-N：

$$\text{score}(t) = \|x_{t} - x_{t-1}\|_2, \quad \text{关键帧} = \text{top-}N(\{\text{score}(t)\}_{t=1}^{T})$$

### 2.3 选型直觉

- **动作均匀的任务**（慢动作、演讲）：均匀采样即可；
- **事件稀疏的任务**（安防、直播切片）：关键帧/镜头切分信息密度更高；
- **长视频**：先动态 FPS 粗采 → 模型定位到可疑区间 → 再对该区间细采（两阶段"草稿 + 精读"）。

### 2.4 工程要点（面试加分项）

1. **训练/推理一致性**：训练随机采样、推理均匀采样，会导致分布漂移——推理前务必用"与训练相同的间隔"校验一遍效果；
2. **缓存帧特征**：同一个视频被多次请求（审核、检索）时，视觉塔的帧特征可以离线缓存，省掉重复过塔的成本——这是线上视频服务最常见的优化；
3. **关键帧不是越多越好**：关键帧集中在镜头切换处，连续抽取会得到大量"几乎相同"的帧，通常先切分镜头、每个镜头内再按内容挑 1~3 帧；
4. **时间戳与采样绑定**：凡是输出时间戳的任务（时序定位、指代），必须记录"每帧对应的原始秒数"，抽帧不是丢弃信息而是带坐标取样。

## 三、路线一：帧级聚合（图像模型的直接扩展）

### 3.1 流程

视频拆成 $T$ 帧，逐帧过**共享权重**的图像模型 $f$，得到 $T$ 个帧特征，再聚合成视频级特征 $v$：

$$v = \text{Pool}\big(\{f(x_t)\}_{t=1}^{T}\big), \quad f(x_t) \in \mathbb{R}^{d}$$

聚合方式从简单到复杂：

1. **Mean-pool / Max-pool**：$\frac{1}{T}\sum_t f(x_t)$，最简单，丢掉全部时序关系；
2. **加权池化（NetVLAD 类）**：按注意力权重加权求和 $v = \sum_t \alpha_t f(x_t)$，关键帧自动获得更高权重；
3. **Transformer 聚合（late fusion 的完备版）**：把 $T$ 个帧特征放进一个小 transformer，帧与帧之间通过 attention 互相"看"——此时时间信息通过注意力隐式进入模型。

### 3.2 典型早期方法

- **多帧 CNN + 池化**（2015~2018 的图像时代标配）：每帧 VGG/ResNet 特征 → 时序池化 → 分类头；
- **NetVLAD（2016）**：把帧特征"聚类-残差-池化"，把视频变成长度固定的向量，用于视频检索；
- **动作识别的 Late Fusion**：双流思想之前的主流，效果被 3D 卷积全面压制。

### 3.3 为什么被超越

帧级聚合在结构上"看不见时序"：把帧顺序打乱，池化结果几乎不变（mean-pool 完全不变）→ **运动、顺序、事件边界三类信息全部丢失**。它只适合"视频里有没有这个物体/场景"这类退化任务。

## 四、路线二：时空建模（把时间卷进结构里）

### 4.1 3D 卷积与 SlowFast

**3D 卷积**把 2D 卷积核多一个时间轴：$W \in \mathbb{R}^{k_t \times k_h \times k_w}$，在连续 $k_t$ 帧上滑动，显式建模局部运动。I3D（2017）的关键技巧是**膨胀初始化**：把 2D 卷积核沿时间轴复制成 3D，直接加载 ImageNet 预训练权重，解决了 3D 模型"从零学"的难题。

**SlowFast（2019）**用双路径解决"运动与语义所需帧率不同"的矛盾：

- **慢路径（Slow path）**：低帧率（如 4fps）、高通道（$\beta = \frac{1}{8}$ 通道数的 8 倍，即通道多）、捕捉空间语义与物体外观；
- **快路径（Fast path）**：高帧率（如 32fps）、低通道（$\beta = \frac{1}{8}$，即慢路径的 1/8）、捕捉时间运动；
- **横向连接**：快路径把运动信息同步给慢路径。

设计直觉：**语义变化慢但重要（低帧率够用，配大通道），运动变化快但不复杂（高帧率必要，配小通道）**——帧率与通道数按信息密度互补分配，相同算力下比单一路径更有效。

数学上，记慢路径输入帧数为 $T$、通道数 $C$，快路径采样率为 $\tau$ 倍（如 $\tau=8$）、通道数为 $C/\beta$（如 $\beta=8$）：

$$C_{slow} = C, \quad T_{slow} = T; \qquad C_{fast} = \frac{C}{\beta}, \quad T_{fast} = \tau T$$

两路径计算量之比：$\text{cost}_{fast} \approx \frac{\tau}{\beta} \cdot \text{cost}_{slow}$（$\tau=\beta=8$ 时快路径与慢路径计算量相当），总成本只比单慢路径贵约一倍，却同时拿到"高分辨率语义 + 高时间分辨率运动"两类信息。

### 4.2 时空 Transformer：TimeSformer 的注意力分解

把视频展平成 $T \times N$ 个时空 patch token（$T$ 帧、每帧 $N$ 个 patch），朴素做法是让注意力在全部 $TN$ 个 token 上做：

$$\text{复杂度} = O((TN)^2 d)$$

Token 一多就爆炸。TimeSformer（2020）把注意力分解成两步：

1. **空间注意力（Spatial Attention）**：每帧内部，patch 之间互看（时间维度不跨）；
2. **时间注意力（Temporal Attention）**：每个 patch 位置，跨 $T$ 帧互看（空间维度不跨）。

$$\text{复杂度} = O\big(N^2 \cdot T \cdot d\big) + O\big(T^2 \cdot N \cdot d\big)$$

以 $T=8, N=196$（8 帧、每帧 14×14=196 patch）为例：

| 方案 | 复杂度（以 patch 对计） | 相对倍数 |
| --- | --- | --- |
| 全时空联合注意力 | $N^2 T^2 = 196^2 \times 8^2 = 2{,}459{,}904$ | ×7.7 |
| TimeSformer 分解 | $N^2T + T^2N = 196^2\times 8 + 8^2\times 196 = 319{,}872$ | ×1 |

**分离假设**：空间关系主要在帧内、时间关系主要沿 patch 位置对应关系展开——损失少量长程时空交互，换来数量级的复杂度下降，是视频 transformer 的标配设计。

### 4.3 VideoMAE：掩码重建，把冗余变成监督信号

VideoMAE（2022）把 MAE 的掩码自编码搬到视频：随机遮住 **90% 的时空 patch**，让解码器从可见 patch 重建整段视频。

- 视频冗余性（见总览 3.2）极高，90% 遮挡后任务仍有信息量，**掩码本身就是数据增强**；
- 重建需要理解运动与外观（遮住的 patch 要"猜"出下一时刻长什么样）→ 学到时序表征；
- 训练后只用编码器，丢弃解码器，作为下游动作分类/定位的预训练。

对比图像 MAE（遮 75%）：视频能遮更多，正是"相邻帧高度相似"这一冗余的量化体现。

## 五、路线三：视频 LLM（当前主流，重点）

### 5.1 整体流程

```
原始视频(30fps)
   │  ① 抽帧（默认 2fps，见第二节）
   ▼
T 帧图像序列
   │  ② 视觉塔（CLIP / Qwen2.5-VL 视觉编码器）逐帧提特征
   ▼
T 组视觉 token（每帧 ≤ 若干 token，见 5.3）
   │  ③ M-RoPE：把 (帧号, 高, 宽) 三维位置编码加进每个 token
   ▼
视频 token 序列 ⊕ 文本指令（拼成一条序列）
   │  ④ LLM 自回归生成：分类/问答/描述/时间戳
   ▼
输出文本
```

### 5.2 M-RoPE：时间轴进位置编码（本路线最关键创新）

LLM 里 token 的先后顺序由位置编码决定。图像 VLM（如 LLaVA）用 1D 位置编码给"展平的图"排位置；但视频有多帧，如果只按"展平顺序"编码，模型无法区分"这是第 1 帧的左上角"和"第 10 帧的左上角"。

M-RoPE（Multimodal RoPE，Qwen2-VL 提出）把 RoPE 的位置拆成三维：

$$\text{RoPE}(t, h, w) = \mathcal{R}_{\text{time}}(t) \cdot \mathcal{R}_{\text{height}}(h) \cdot \mathcal{R}_{\text{width}}(w)$$

- 第 $t$ 帧、位置 $(h, w)$ 的视觉 token，用三维坐标 $(t, h, w)$ 编码；
- 三组旋转矩阵独立作用：**时间维旋转使"第 3 帧"与"第 5 帧"的相对顺序被编码进注意力**；
- 同一帧内 token 的二维空间关系由 (h, w) 维保持（图像能力零损失迁移）。

效果：LLM 的注意力天然变成"时序感知"的——它知道哪些 token 属于同一帧、哪些是"后面发生的帧"，这是视频问答、时序定位、描述顺序正确性的结构基础。数学细节见 [位置编码专题](../技术基础/位置编码专题/M-RoPE.md)。

### 5.3 token 预算与 2fps

视频 token 总数：

$$T_{video} = FPS_{sample} \times D_{seconds} \times T_{frame}$$

- **抽帧率定在 2fps**：30fps 的原始信息对语义理解高度冗余，2fps 是"信息量/成本"的工程平衡点（人类阅读视频也远不需要每帧都看）；
- **每帧 token 上限**：Qwen2.5-VL 把每帧压到 ≤1024 token（动态分辨率 + 智能裁剪：把 2~4 个帧 token 合并，只有语义重要区域保留大分辨率）；
- 算一笔账：10 分钟视频 @2fps = 1200 帧，即使每帧平均 256 token 也达 ≈30 万 token——**必须在抽帧、每帧 token、总预算三处同时节流**。

### 5.4 多帧位置分配（序列怎么排）

所有帧的 token 按时间顺序首尾拼接成一条长序列，帧与帧之间**不加特殊分隔符**：

$$\text{seq} = [\underbrace{\text{帧}_1 的 N_1 个 token}_{\text{位置} (1, h, w)}, \underbrace{\text{帧}_2 的 N_2 个 token}_{\text{位置} (2, h, w)}, \dots]$$

模型区分"第几帧"完全靠 M-RoPE 的时间维分量（$t=1,2,\dots$）。这也解释了为什么视频 LLM 与图像模型直接"拼帧"有本质区别：**不是把 8 帧当 8 张独立图排进序列，而是让位置编码显式给出三维坐标**。

### 5.5 长视频：帧压缩与时间戳

长视频（分钟~小时级）token 仍然爆炸，工程上有四板斧：

1. **帧压缩（Frame Compression）**：时间维池化/合并——把相邻若干帧的相似 token 合并为一个（token merging、temporal pooling），牺牲细节换长度；
2. **分段窗口 + 检索**：把视频切成 30~60 秒片段，先用文本检索/CLIP 粗筛出相关片段，只把相关片段的高清帧送进 LLM（"草稿 → 精读"两阶段）；
3. **长上下文窗口**：Qwen2.5-VL 原生支持长上下文（百万级），token 预算足够时整段送入；
4. **时间戳输出**：训练数据带起止时间标注，模型直接输出"第 X 秒到第 Y 秒"，把"时序定位"变成语言生成任务——这是视频 LLM 做指代定位（Referring）的标准做法。

### 5.6 三个代表模型的实现对比

| 对比项 | Qwen2.5-VL（7B/32B/72B） | InternVideo2.5（8B） | LLaVA-Video（72B） |
| --- | --- | --- | --- |
| 视觉塔 | 自研 ViT（动态分辨率） | InternViT-6B | CLIP ViT-L/14 |
| 采样策略 | 2fps 均匀 + 每帧 ≤1024 token | 动态 FPS（信息量感知） | 动态 FPS + 每帧 token 上限 |
| 时间编码 | M-RoPE（时间/高/宽三维） | 2D RoPE + 时间模块 | 1D 位置编码 + 时间提示 |
| 时间戳输出 | 原生支持（时间定位） | 支持 | 有限 |
| 特色 | 长上下文 + 智能裁剪 | 视频专用数据比重高 | 高分帧率上限、长视频分段 |

**读表结论**：三家的差异集中在"采样策略 + 位置编码"两个点上——这印证了本路线的核心命题：**视频 LLM 的竞争力不来自换更大视觉塔，而来自"怎么抽帧、怎么把时间编码进去"**。

## 六、时序定位任务（Temporal Action Localization）

**定义**：输入视频，输出所有动作事件 $(\text{类别}, t_{start}, t_{end})$，即"什么动作从第几秒开始、持续到第几秒"。与视频分类（只要类别）和视频检测（每帧判类别）的关系：

| 任务 | 输出粒度 | 关系 |
| --- | --- | --- |
| 视频分类 | 整段视频一个类别 | 粗 |
| 帧级动作检测 | 每帧一个类别 | 细（无边界） |
| 时序定位 | 类别 + 起止区间 | 中（动作检测的特例） |

经典方法分两阶段与单阶段：

- **两阶段（proposal + classification，对应检测的 R-CNN 系）**：先用滑动窗口/Boundary-Matching 网络（BMN）生成候选区间，再对候选分类并精修边界；
- **单阶段（对应检测的 YOLO 系）**：直接回归边界，如 GTAD；
- **边界回归**：把区间参数化为中心 + 长度 $b = (c, w)$，对预测 $\hat{b}$ 与真实 $b$ 做回归损失：

$$L_{reg} = \text{SmoothL1}(\hat{c} - c) + \text{SmoothL1}(\hat{w} - w), \quad t_{start} = c - \frac{w}{2}, \ t_{end} = c + \frac{w}{2}$$

评测指标是 **mAP@tIoU**（阈值 0.5/0.7 等），公式与计算流程见 [视频评测与TemporalIoU.md](视频评测与TemporalIoU.md) 第三节——"时间维的 IoU"与空间检测的 IoU 完全同构。

## 七、源码实现（可运行）

### 7.1 抽帧策略对比：均匀采样 vs 关键帧采样

用纯 PyTorch 模拟一段 60 秒、2fps = 120 帧的"视频"：每帧是一个 8 维特征向量，其中第 20~30 帧模拟"镜头切换段"（特征剧烈突变）。

```python
import torch

torch.manual_seed(0)

# 模拟一段 60 秒、2fps → 120 帧的"视频"：每帧是 8 维向量（粗略模拟视觉特征）
n_frames = 120
frames = torch.randn(n_frames, 8) * 0.1
frames[20:31] += torch.randn(11, 8) * 2.0   # 第 20~30 帧为镜头切换段，特征突变

# ---------- 策略一：均匀采样 ----------
def uniform_sample(frames, n_out):
    idx = torch.linspace(0, len(frames) - 1, n_out).round().long()
    return idx, frames[idx]

idx_u, _ = uniform_sample(frames, 8)
print("均匀采样帧号:", idx_u.tolist())        # [0, 17, 34, 51, 68, 85, 102, 119]

# ---------- 策略二：关键帧采样（帧间变化量最大的帧） ----------
def keyframe_sample(frames, n_out):
    diff = frames[1:] - frames[:-1]
    score = diff.norm(dim=1)                      # 每帧相对前一帧的变化量
    idx = score.argsort(descending=True)[:n_out].sort().values
    return idx, frames[idx + 1]

idx_k, _ = keyframe_sample(frames, 8)
print("关键帧采样帧号:", idx_k.tolist())        # [21, 22, 23, 24, 26, 27, 28, 29]

# 对比结论：
# 均匀采样均匀覆盖整个时间轴，不漏时段但每段信息量平均；
# 关键帧采样全部集中到镜头切换处（第 20~30 帧），信息密度高但会漏掉"平静但重要"的时段。
```

### 7.2 最小"视频 → 帧 → 图像模型 → 时间池化 → 分类"管线

演示帧级聚合路线的完整前向：8 帧图像 → 共享 CNN 逐帧提特征 → mean-pool 聚合 → 分类。

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)

# 假设已按 2fps 抽到 T=8 帧，每帧是 3×16×16 的"图像"
T, C, H, W = 8, 3, 16, 16
frames = torch.randn(T, C, H, W)          # 8 帧视频片段

class FrameBackbone(nn.Module):
    """逐帧共享的"图像模型"（真实场景用 ResNet/CLIP-ViT 等预训练塔）"""
    def __init__(self):
        super().__init__()
        self.conv1 = nn.Conv2d(3, 16, 3, padding=1)
        self.conv2 = nn.Conv2d(16, 32, 3, padding=1)
        self.pool = nn.AdaptiveAvgPool2d(1)

    def forward(self, x):                 # x: (B, C, H, W)
        x = F.relu(self.conv1(x))
        x = F.relu(self.conv2(x))
        return self.pool(x).flatten(1)    # (B, 32)

backbone = FrameBackbone()
cls_head = nn.Linear(32, 5)               # 5 类动作

feats = backbone(frames)                  # (8, 32)：每帧一个特征
print("逐帧特征:", feats.shape)           # torch.Size([8, 32])

# 时间池化：把 T 个帧特征聚合为视频级特征（mean-pool）
video_feat = feats.mean(dim=0, keepdim=True)
print("池化后视频特征:", video_feat.shape)  # torch.Size([1, 32])

logits = cls_head(video_feat)             # (1, 5)
probs = logits.softmax(dim=-1)
print("类别概率:", probs.detach().tolist())
# [[0.21119068562984467, 0.18443988263607025, 0.2186933010816574, 0.1684558391571045, 0.21722030639648438]]
print("预测类别:", probs.argmax().item())  # 2

# 局限演示：把帧顺序打乱，mean-pool 结果完全不变 → 帧级聚合"看不见时序"
shuffled = frames[torch.randperm(T)]
print("打乱帧序后特征是否相等:", torch.allclose(video_feat, backbone(shuffled).mean(dim=0, keepdim=True)))  # True
```

> 运行环境：PyTorch ≥ 2.0，无需额外依赖。真实工程中把 `FrameBackbone` 换成 ResNet/CLIP 预训练塔、把池化换成注意力聚合即可，结构不变。

## 八、优缺点与选型

| 路线 | 优点 | 缺点 | 适合场景 |
| --- | --- | --- | --- |
| 帧级聚合 | 实现简单、复用图像预训练、算力低、延迟小 | 无时序感知（运动/顺序全丢） | 粗分类、封面/关键帧筛选、低成本视频标签 |
| 时空建模 | 真正建模运动与边界，动作识别/时序定位 SOTA | 训练数据要求高、推理重、预训练生态弱 | 安防行为识别、体育动作分析、Kinetics 类基准 |
| 视频 LLM | 开放问答、多任务统一、零样本、可输出时间戳 | token 成本高、幻觉、长视频仍难、延迟大 | 审核问答、直播/视频摘要、检索 + 指代定位 |

**选型决策树**：

1. 任务只要"视频里有什么"（分类/封面）→ 帧级聚合，性价比最高；
2. 任务要求"动作与起止时间"且预算充足 → 时空建模（SlowFast 系）；
3. 任务要求"开放问答/描述/时间戳"或希望一个模型通吃 → 视频 LLM；
4. 长视频 → 视频 LLM + 检索分段（两阶段），不要直接整段硬吃。

## 九、面试问答

**Q1：视频为什么比图像难？**
三句话：① 多出时间维度，要建模运动、顺序、事件边界；② 帧间高度冗余，直接逐帧建模浪费算力；③ 按帧展开 token 爆炸（2fps 下 10 分钟视频 ≈ 30 万 token），注意力复杂度平方增长。

**Q2：抽帧策略怎么选？**
按事件密度：动作均匀（演讲/慢动作）用均匀采样；事件稀疏（安防/切片）用关键帧或镜头切分；长视频用动态 FPS 粗采后对可疑区间细采。训练用随机采样做增强，推理固定均匀采样保证可复现。

**Q3：视频 token 太多怎么办？**
四条路：① 降抽帧率（2fps 是工程平衡点）；② 每帧 token 封顶（动态分辨率 + 智能裁剪/帧 token 合并）；③ 帧压缩与时间池化（相邻帧相似 token 合并）；④ 分段 + 检索两阶段，只送相关片段进模型。

**Q4：M-RoPE 在视频里怎么用？**
把 RoPE 位置拆成 (时间 t, 高 h, 宽 w) 三维：视频第 t 帧的 token 用三维坐标编码，时间维旋转使注意力感知帧间顺序；同一帧内空间关系不受影响。效果是 LLM 能分辨"第几帧"、"先后关系"，这是视频问答/时序定位的结构基础。

**Q5：三条路线怎么选？**
任务粗分类选帧级聚合（省钱省力）；要求动作边界与运动建模且预算足选时空建模；开放问答、多任务统一、要时间戳选视频 LLM；长视频一律加检索分段。

**Q6：SlowFast 为什么一个慢一个快？**
语义信息变化慢但维度高（用低帧率配大通道），运动信息变化快但内容简单（用高帧率配小通道）——两种信息对"帧率 × 通道数"的资源需求恰好互补，双路径在相同算力下信息效率更高。

**Q7：TimeSformer 的复杂度为什么低？**
朴素时空注意力是 $O((TN)^2)$；分解成帧内空间注意力 $O(N^2T)$ + 帧间时间注意力 $O(T^2N)$，$T=8,N=196$ 时省约 7.7 倍。代价是放弃少量长程时空交互。

**Q8：长视频理解怎么落地？**
四板斧：帧压缩/时间池化控 token、分段 + 检索两阶段聚焦、长上下文窗口兜底、时间戳输出把定位转成生成。核心是"预算管理 + 局部精读"。

# 多模态RAG与评估：图文文档检索、幻觉缓解与端到端评测

> 本模块索引见 [RAG专题详解](RAG专题详解.md)

多模态 RAG 是 [检索与重排.md](检索与重排.md) 中主链路的扩展：知识库从纯文本升级为"文本 + 图像 + 图文混合文档"，生成器从 LLM 升级为 VLM。本篇讲清三种形态、图文文档管线、检索缓解幻觉的机理，重点放在**评估体系**（检索侧 + 生成侧 + RAGAS 框架），并给出可运行的图像检索最小演示。

## 一、多模态 RAG 的三种形态

| 形态 | 检索对象 | 检索模型 | 生成器 | 典型场景 |
| --- | --- | --- | --- | --- |
| ① 文本检索辅助 VLM | 文本片段 | 文本 embedding（bge/m3e 等） | VLM | 文档问答：VLM 读检索到的文字片段作答 |
| ② 图像检索（图库检索） | 图片 | 跨模态双塔（CLIP/SigLIP） | VLM | 图库问答、商品图检索、以图证答 |
| ③ 图文混合文档 | 文本块 + 图像块 | 文本塔 + 视觉塔（统一向量空间） | VLM | PDF/扫描件问答：答案常要"图 + 文字"一起看 |

区别要点：

- **形态①**：检索结果仍是纯文本，VLM 的优势在于"读复杂片段"（表格、长文）而非"看图"；
- **形态②**：检索结果直接是图片，query 是文本——跨模态对齐质量决定一切（对齐原理见 [图文检索与向量库](../../算法论文基础/14_图文检索与向量库.md)）；
- **形态③**：最接近真实办公场景，文档里"图 + 周围文字"是一个整体，必须一起召回、一起送 prompt，否则 VLM 看到图不知道它在说什么。

## 二、图文文档 RAG 管线

### 2.1 完整管线

```
PDF/扫描件 ──► 版面分析 ──► 文本块 + 图像块 ──► 文本塔 embedding ──┐
     │         (版面切分/OCR)    (图与 caption 配对)    视觉塔 embedding ──┤
     │                                                            │
     │                                          统一向量空间 ──► 混合索引(向量库)
     ▼                                                            │
query(文本/图片) ──► 对应塔编码 ──► 检索（向量 + BM25 融合 + Rerank）──┘
                                     │
                                     ▼
                  组装多模态上下文（图像 + 标题 + 上下文文本块，按文档顺序）
                                     │
                                     ▼
                            VLM 生成（看图 + 读文综合作答）
```

### 2.2 版面分析的输出单元（检索粒度的基础）

| 单元 | 内容 | 向量化 | 元数据 |
| --- | --- | --- | --- |
| 文本块 | 段落/标题/列表文字（OCR 结果） | 文本塔 | 页码、章节 |
| 图像块 | 图片区域（裁剪出的图像） | 视觉塔 | 页码、fig 编号 |
| 表格块 | 表格区域（转成文本/结构） | 文本塔（或表格专用塔） | 页码、表编号 |
| 图文对 | 图像 + 其 caption/引用段（绑定单元） | 视觉塔（图）+ 文本塔（caption 拼入 prompt） | fig-cap 关联 ID |

图文对（fig-cap pair）是检索的最小推荐单元：单独检索图片容易"图对文不对"，单独检索 caption 又丢视觉信息。

### 2.2 各环节要点

1. **版面分析（Layout Analysis）**：把 PDF 页切成语义单元——文本段、标题、图像区域、表格区域，OCR 提取文字；
2. **图与上下文配对（fig-cap pairing）**：图像块必须与其标题/引用它的正文文本绑定成一个检索单元——单检索图时"图片 + caption"一起进 prompt，否则 VLM 不知道这张图在讲什么；
3. **各自编码、统一索引**：文本块用文本塔（bge/SigLIP 文本侧），图像块用视觉塔（CLIP/SigLIP 视觉侧），落在同一向量空间后写入同一个向量库；**跨模态对齐质量 = 检索质量上限**；
4. **组装顺序**：进 prompt 的图像 + 文本按"图 → caption → 上下文"保持文档内相邻关系，顺序对 VLM 的跨图推理有明显影响（VLM 对 prompt 前部的证据权重更高，与 [图文检索与向量库](../../算法论文基础/14_图文检索与向量库.md) 8.3 的级联效应同理）；
5. **图像块切分也要守边界**：一张图不要被切进两个 chunk；大图可缩略图 + 分块（tiling）双轨入库。

## 三、检索缓解 VLM 幻觉的机理

### 3.1 四个机理

| 幻觉来源 | 检索增强的作用 |
| --- | --- |
| 参数记忆有限/过时 | 检索拿到最新事实，prompt 里有据可依，VLM"照着材料说"而非"凭记忆编" |
| 概率解码倾向流畅编造 | 强约束：图像 + 文本证据锚定答案，编造空间被压缩 |
| 多模态长尾知识（罕见物体/专有商标） | 参数里没学过的，检索直接给图 + 描述，"开卷考试" |
| 缺乏可溯源证据 | 检索结果带出处（图片 ID、来源页），答案可复核 |

**知识外置（externalization）**：检索增强的本质是把"参数化记忆"转成"外部可查记忆"。幻觉的本质是模型用参数记忆补足缺失，而 RAG 让缺失的信息在生成时直接可用，模型从"无中生有"变成"对给定证据的推理与转述"。

### 3.2 前提与风险（级联误差）

- 检索质量是缓解效果的天花板：**检索返回了错误图片，VLM 会被"证据"带偏**（检索幻觉）；
- 图文错误比文本错误更隐蔽：一张错图 + 一段像样的 caption，VLM 可能毫无察觉地顺着编；
- 因此多模态 RAG 的评估必须把检索侧指标放在第一位，且在 prompt 中要求 VLM"只依据上下文作答，上下文无证据时明说不知道"。

## 四、评估（重点）

RAG 是级联系统，评估必须分层：**检索侧（找没找对）→ 生成侧（答没答对、有没有据）→ 端到端（整系统好不好用）**。

### 4.1 检索侧指标

对每个 query 有一个（或多个）标准相关项 $g_q$，检索返回 Top-K 列表：

$$\text{HitRate@K} = \frac{1}{|Q|} \sum_{q \in Q} \mathbb{1}\left[\exists\ \text{相关项} \in \text{TopK}(q)\right]$$

$$\text{Recall@K} = \frac{1}{|Q|} \sum_{q \in Q} \mathbb{1}\left[g_q \in \text{TopK}(q)\right]$$

$$\text{MRR} = \frac{1}{|Q|} \sum_{q \in Q} \frac{1}{\text{rank}(g_q)}$$

- HitRate@K 衡量"有没有找到"，Recall@K 衡量"GT 排进前 K 的比例"（R@1 最严格），MRR 惩罚"第一个相关项排太靠后"；
- 注意区分**模型级 R@K**（双塔对齐质量）与**索引级 Recall@K**（ANN 近似损失），两者乘积 ≈ 端到端召回（详见 [图文检索与向量库](../../算法论文基础/14_图文检索与向量库.md) 第七节）。

MRR 手算示例：两个 query——q1 的 GT 排第 2（贡献 1/2=0.5），q2 的 GT 排第 5（贡献 1/5=0.2），则

$$\text{MRR} = \frac{0.5 + 0.2}{2} = 0.35$$

对比 Recall@1 = 0（两个 GT 都没进前 1）：**MRR 能反映"离成功只差一点"的进步，R@K 只看硬性阈值**——图库检索（形态②）里 MRR 尤其重要，因为"第一张命中图"才有用户体验价值。

### 4.2 生成侧指标

| 指标 | 口径 | 公式/算法 |
| --- | --- | --- |
| 忠实度 Faithfulness | 回答中**被检索上下文支持**的句子占比 | $\frac{\text{被证据支持的句子数}}{\text{总句子数}}$（逐句用 LLM judge 判定支持/不支持/矛盾） |
| 答案准确率 | 有标准答案任务（如 NQ、MMQA） | EM / F1，与标准答案对齐 |
| 幻觉率 | 不被证据支持、且与证据矛盾的句子占比 | 1 − faithfulness 的加强版（区分"无依据"与"相矛盾"） |
| 引用准确性 | 每个引用片段是否真的支持其对应句子 | $\frac{\text{引用准确的句子数}}{\text{带引用的句子数}}$（attribution 评测） |

多模态版本的注意点：**逐句验证时，"看图"的句子要拿图片本身做证据**，不能只看文本上下文——"图中有三辆车"这类描述，证据是图像而不是文字。

### 4.3 端到端评估框架：RAGAS 简述

RAGAS（RAG Assessment）是当前最流行的开源框架，核心思想：**不依赖人工标注，用 LLM-as-judge 对"上下文 + 答案 + 问题"三元组自动打分**。

| 指标 | 衡量什么 | 判定方式 |
| --- | --- | --- |
| faithfulness | 答案是否忠于检索上下文 | 答案拆句 → 逐句问 judge"该句是否被上下文支持" → 求比例 |
| answer relevancy | 答案是否回答了问题 | 答案拆句 → 逐句问 judge"该句与问题的相关性" → 平均 |
| context precision | 检索的证据是否精准无冗余 | 对 Top-K 上下文，判断哪些与答案相关（相关项是否排在前面） |
| context recall | 检索的证据是否覆盖答案所需 | 答案拆句 → 问 judge"该句信息是否能在上下文中找到" |

用公式概括（$S$ 为答案句子集，$C$ 为检索上下文，$\mathbb{1}[\cdot]$ 由 judge 判定）：

$$\text{faithfulness} = \frac{\left| \{s \in S : s \ \text{被}\ C\ \text{支持}\} \right|}{|S|}$$

$$\text{context recall} = \frac{\left| \{s \in S : s \ \text{的信息存在于}\ C\} \right|}{|S|}$$

局限与补充：LLM judge 有自身的偏差与成本，规模大时建议配合 5% 人工抽评校准；多模态场景可用 MM-RAG / RAG-MM 等基准，指标思想一致，只是证据从文本变为"图 + 文"。

### 4.4 评估执行流程

1. **建评测集**：50~200 个真实 query；检索侧标注 GT 图文对（哪张图/哪段文本是答案证据），生成侧标注标准答案；
2. **先检索后生成**：跑检索侧指标（HitRate@K / R@K / MRR）定位问题在召回还是重排，检索合格后再跑生成侧（faithfulness / 准确率 / 引用准确率）；
3. **归因 badcase**：生成差 → 查 prompt 里有没有证据（无证据=检索问题，有证据答错=生成问题）；检索差 → 查是"语义没对齐"（换模型）还是"字面没命中"（加 BM25）还是"切分切坏了"（改 chunk）；
4. **回归机制**：每次改切分 / 换 embedding / 换 reranker / 改 prompt，全量重跑指标，检索侧与生成侧分开记录。

## 五、源码实现：多模态 RAG 最小演示（可运行）

纯 Python（无第三方依赖）：模拟"图库 → 视觉塔特征 → 文本 query → 检索最相似图像 → 组装多模态上下文"全流程。特征用手写 8 维向量代替真实 CLIP 编码（含义见注释），结构与真实系统一一对应。

```python
import math

# ---------- 1. 图像库：每张图用 8 维"手写视觉特征"表示（模拟 CLIP 视觉塔输出） ----------
# 特征维度含义: [红, 绿, 蓝, 亮度, 边缘密度, 纹理, 文字密度, 人物]
IMAGES = {
    "red_car.jpg":    [0.95, 0.05, 0.05, 0.70, 0.60, 0.30, 0.00, 0.10],
    "forest.jpg":     [0.10, 0.90, 0.15, 0.45, 0.50, 0.80, 0.00, 0.05],
    "ocean.jpg":      [0.05, 0.30, 0.95, 0.60, 0.20, 0.40, 0.00, 0.05],
    "doc_page.jpg":   [0.95, 0.95, 0.90, 0.90, 0.85, 0.60, 0.95, 0.00],
    "portrait.jpg":   [0.80, 0.60, 0.70, 0.75, 0.45, 0.30, 0.00, 0.95],
    "chart.jpg":      [0.60, 0.60, 0.80, 0.80, 0.90, 0.70, 0.50, 0.00],
    "city_night.jpg": [0.60, 0.20, 0.40, 0.25, 0.55, 0.75, 0.10, 0.15],
    "desert.jpg":     [0.85, 0.75, 0.35, 0.80, 0.40, 0.65, 0.00, 0.00],
}

# 图像的元数据描述（模拟向量库元数据，用于组装多模态上下文）
META = {
    "red_car.jpg":    "一辆红色跑车停在路边",
    "forest.jpg":     "茂密的绿色森林航拍",
    "ocean.jpg":      "蓝色海洋与沙滩",
    "doc_page.jpg":   "公司年报第 3 页，含财务表格",
    "portrait.jpg":   "人物肖像照",
    "chart.jpg":      "季度销售额柱状图",
    "city_night.jpg": "夜晚的城市街景灯光",
    "desert.jpg":     "日落时分的沙漠",
}

# ---------- 2. 文本塔：查询词 → 8 维"语义投影"（模拟 CLIP 文本塔学到的对齐） ----------
QUERY_LEXICON = {
    "红色": [0.9, 0.1, 0.1, 0.7, 0.3, 0.2, 0.0, 0.1],
    "森林": [0.1, 0.9, 0.2, 0.5, 0.4, 0.8, 0.0, 0.1],
    "海洋": [0.1, 0.3, 0.9, 0.6, 0.2, 0.4, 0.0, 0.1],
    "文档": [0.9, 0.9, 0.9, 0.9, 0.8, 0.5, 0.9, 0.1],
    "人像": [0.8, 0.6, 0.7, 0.7, 0.4, 0.3, 0.0, 0.9],
    "图表": [0.6, 0.6, 0.8, 0.8, 0.9, 0.7, 0.5, 0.0],
    "夜晚": [0.4, 0.2, 0.3, 0.2, 0.5, 0.7, 0.0, 0.2],
    "汽车": [0.8, 0.3, 0.2, 0.6, 0.5, 0.3, 0.0, 0.1],
    "销售额": [0.5, 0.5, 0.7, 0.8, 0.9, 0.7, 0.6, 0.0],
}

def query_embed(query: str):
    """文本塔：按词典最大匹配切词，再映射到 8 维特征空间（模拟 CLIP 文本塔）"""
    vec = [0.0] * 8
    max_len = max(len(w) for w in QUERY_LEXICON)   # 最长词长（这里是 3："销售额"）
    i = 0
    while i < len(query):
        hit = None
        for L in range(max_len, 0, -1):            # 从长到短贪心匹配
            if query[i:i+L] in QUERY_LEXICON:
                hit = QUERY_LEXICON[query[i:i+L]]
                i += L
                break
        if hit:
            vec = [a + b for a, b in zip(vec, hit)]
        else:
            i += 1                                 # 词典外字符跳过
    n = math.sqrt(sum(x * x for x in vec)) or 1.0
    return [x / n for x in vec]                    # 文本塔同样做 L2 归一化

def cos(a, b):
    return sum(x * y for x, y in zip(a, b))

# ---------- 3. 图像特征 L2 归一化（双塔同空间前提） ----------
def l2norm(v):
    n = math.sqrt(sum(x * x for x in v)) or 1.0
    return [x / n for x in v]

NORM_IMGS = {name: l2norm(v) for name, v in IMAGES.items()}

# ---------- 4. 多模态 RAG 检索：文本 query → 图库 Top-K → 组装上下文 ----------
def multimodal_retrieve(query: str, top_k=2):
    q_vec = query_embed(query)
    ranked = sorted(NORM_IMGS.items(), key=lambda kv: -cos(q_vec, kv[1]))
    return ranked[:top_k]

query = "红色汽车"
top = multimodal_retrieve(query)
for name, vec in top:
    print(f"命中: {name}  置信度={cos(query_embed(query), vec):.3f}  元数据: {META[name]}")
# 命中: red_car.jpg  置信度=0.981  元数据: 一辆红色跑车停在路边
# 命中: desert.jpg   置信度=0.908  元数据: 日落时分的沙漠

# ---------- 5. 组装多模态上下文并交给 VLM（模拟 VLM 输出） ----------
context = "\n".join(f"[图] {name}: {META[name]}" for name, _ in top)
prompt = f"问题: 图中的交通工具是什么？\n{context}\n请依据以上图片作答。"
print("\n组装后的 prompt:\n" + prompt)
# 组装后的 prompt:
# 问题: 图中的交通工具是什么？
# [图] red_car.jpg: 一辆红色跑车停在路边
# [图] desert.jpg: 日落时分的沙漠
# 请依据以上图片作答。

answer = "依据检索到的图片证据（red_car.jpg：一辆红色跑车停在路边），答案是汽车。"
print("\nVLM 生成:", answer)
# VLM 生成: 依据检索到的图片证据（red_car.jpg：一辆红色跑车停在路边），答案是汽车。
```

要点：真实系统把 `query_embed` 换成 CLIP/SigLIP 文本塔、`IMAGES` 换成图库编码结果、Top-K 换成向量库 ANN + Rerank，本演示的结构与实际管线完全同构——**检索到的每张图都带元数据（出处），这就是"可溯源"的工程实现**。

## 六、工程注意

| 事项 | 说明 | 典型做法 |
| --- | --- | --- |
| 索引更新 | 图库/文档增删改要同步到索引，否则检索到旧图 | 增量入库（仅编码新增）、逻辑删除 + 定期重建索引、版本号元数据过滤 |
| 缓存 | 热门 query 的检索结果高度复用 | query 级缓存（哈希 query → Top-K）、embedding 缓存、图特征缓存 |
| 延迟预算 | 多模态链路环节多，要逐环节卡预算 | 示例：检索 10ms + 重排 50ms + VLM 生成 1~3s；图片下载/OCR 不放进在线路径 |
| 编码成本 | 视觉塔编码 GPU 开销大 | 图库向量化全部离线完成；在线只编码文本 query（单次编码） |
| 向量压缩 | 图库规模大时内存爆炸 | 量化（PQ/OPQ）、降维（Matryoshka），详见 [图文检索与向量库](../../算法论文基础/14_图文检索与向量库.md) |
| 组装顺序 | 图与文本顺序影响 VLM 效果 | 保持文档内相对顺序；多图场景把最相关的图放最前 |
| 兜底策略 | 检索为空/置信度过低 | 阈值过滤 + 显式回答"未找到相关图片"，禁止模型空编 |
| 监控与回归 | 线上质量漂移难感知 | 抽样标注 + 指标看板（检索侧 R@K、生成侧引用准确率），每次改模型/切分先跑回归 |
| 数据安全 | 私有文档/图片外泄风险 | 向量库内网部署、脱敏、检索权限过滤（按用户/部门元数据隔离） |

### 6.1 延迟预算示例（形态②图库问答，目标 P95 < 3s）

| 环节 | 预算 | 说明 |
| --- | --- | --- |
| query 文本编码 | ~5ms | 在线只编码一次文本（单条） |
| 图库向量检索 | ~10ms | ANN（HNSW/IVF）+ 标量过滤（权限/类目） |
| Rerank | ~50ms | 100 条候选 batch 过一次 reranker |
| 组装 prompt + 图片传输 | ~20ms | 图片本地服务直接引用，不重复下载 |
| VLM 生成 | 1.5~2.5s | 大头在生成，留给它的预算最宽裕 |

要点：**视觉塔编码与 OCR 全部离线做，在线链路没有任何"编码大图"的步骤**——这是多模态 RAG 能控延迟的根本前提。

## 七、高频面试问答

**Q1：多模态 RAG 和文本 RAG 的区别？**
三点：① 知识库含图像块，需要版面分析切分 + 跨模态对齐 embedding（CLIP/SigLIP）；② 检索结果要组装成"图 + caption + 上下文文本"一起进 prompt，组装顺序影响 VLM 理解；③ 幻觉缓解从文本证据升级为视觉证据，可溯源更强，但检索错图的级联误差也更隐蔽。

**Q2：怎么评估一个 RAG 系统？**
分层：先测检索侧（HitRate@K / Recall@K / MRR，注意区分模型级与索引级），再测生成侧（忠实度 / 答案准确率 / 幻觉率 / 引用准确性），最后端到端框架（RAGAS 的 faithfulness、answer relevancy、context precision/recall）。定位问题的顺序永远是先检索后生成。

**Q3：RAG 怎么缓解幻觉？**
知识外置：检索把最新/私有/长尾知识放进 prompt，模型从"凭参数记忆编造"变成"对证据的推理转述"；视觉锚点：VLM 看图作答，编造空间被压缩；可溯源：每个答案带出处，幻觉可被复核兜住。前提是检索质量高，否则错误证据反而带偏模型。

**Q4：检索到的图片怎么进 prompt？**
图片经视觉塔编码成视觉 token（或经投影层），与其标题/上下文文本按"图 → caption → 上下文"顺序组装进 prompt；图片带元数据（文件名/来源页）以便引用溯源。多图时最相关图放最前，且要求模型"只依据上下文作答"。

**Q5：图文混合文档（PDF）怎么切分？**
版面分析把页切成文本段、图像区、表格区，OCR 提文字；图像与其 caption/引用正文配对成一个检索单元；文本块用文本塔、图像块用视觉塔各自向量化后统一索引；检索时图与上下文一起召回。

**Q6：RAGAS 的四个指标分别是什么？**
faithfulness（答案是否忠于上下文）、answer relevancy（答案是否回应问题）、context precision（证据是否精准无冗余）、context recall（证据是否覆盖答案所需）。全部用 LLM-as-judge 对"上下文 + 答案 + 问题"打分，无需人工标注。

**Q7：检索侧评测指标里 Recall@K 和 HitRate@K 有什么区别？**
HitRate@K 是"前 K 里是否出现任一条相关项"（衡量有没有找到）；Recall@K 是"GT 是否排进前 K"（衡量标准答案找没找到，R@1 最严格）。工业上看命中率，论文（图文检索）报告 R@1/5/10。

**Q8：多模态 RAG 部署的延迟怎么控制？**
延迟预算拆解：文本 query 编码单次、向量检索毫秒级、重排 batch 推理；视觉塔编码与 OCR 全部离线完成；热门 query 加缓存；检索置信度低时直接兜底回答，不硬生成。

# Qwen-VL 系列演进总览：四代架构、三条主线与完整能力地图（2023 → 2025）

> 本笔记是 Qwen-VL 系列四篇分代笔记（Qwen-VL / Qwen2-VL / Qwen2.5-VL / Qwen3-VL）的**总览篇**：先给一张全局地图，再拆三条演进主线，最后落到选型与面试。事实与数字已与《算法论文基础/09_QwenVL》校核一致，可放心作为面试与笔记体系的地基。核心记忆点：**Qwen-VL 家族 = 阿里通义视觉语言模型，核心竞争力是"任意分辨率/长宽比的图像视频转 token + 3D 位置编码"**。

**阅读导览**：速通用「二、总览表 + 三、三条主线」；精读用「四、各代一页速览」；面试突击用「九、问答 + 十、误区 + 十一、自检」；落地用「七、选型」。每一节都可独立查阅，四代对应论文号见第十二节。

## 一、一句话解释与系列定位

### 1.1 一句话解释

> **Qwen-VL 系列 = 阿里通义千问的视觉语言模型（VLM）家族，核心是把"任意分辨率、任意长宽比的图像与视频"无损地变成 token 喂给 LLM，并用 3D 位置编码（M-RoPE 家族）让 LLM 真正感知空间布局与时间顺序。**

四代演进可以浓缩成四句话：

1. **Qwen-VL（2023）**：OpenCLIP 的 ViT-bigG 当眼睛、单层 cross-attention 当"翻译官"，把视觉 token 压成固定 256 个——解决了"有视觉能力"，但分辨率固定 448；
2. **Qwen2-VL（2024）**：扔掉固定分辨率，发明 **Naive Dynamic Resolution**（动态分辨率）与 **M-RoPE**（3D 位置编码）——解决了"看得清"，文档/OCR 能力大幅跃升；
3. **Qwen2.5-VL（2025.01）**：把 ViT 的全局注意力换成 **Window Attention**，给 token 合并器加"动态预算"，时间轴对齐绝对时间——解决了"看得快、看得久、看得准时间"；
4. **Qwen3-VL（2025）**：视觉塔换 **SigLIP-2 架构**、位置编码升级 **Interleaved-MRoPE**、引入 **DeepStack** 多级特征注入与文本时间戳，上下文拉满 256K（可扩 1M）——解决了"看得懂、想得深、记得久"。

### 1.2 系列定位：在 VLM 生态中的坐标

- **与 LLaVA 比**：不做"最简单"路线（单层 MLP 投影），而是把**分辨率策略、token 压缩、位置编码**三件事都做到机制级创新——Qwen 系是"工程+机制双修"的家族；
- **与 InternVL 比**：不靠超大视觉塔（6B），而是用 675M/SigLIP-2（约 400M）级视觉塔 + 强 LLM 底座，参数比说明瓶颈在 LLM 侧的跨模态推理；
- **与 MiniCPM-V 比**：不主打"极小端侧"，但每代都有小尺寸档位（2B/3B/4B），端侧同样可用；
- **系列定位一句话**：**分辨率最动态、位置编码最三维、Token 压缩最彻底、文档/视频能力最均衡**的国产开源 VLM 第一家族。

### 1.3 模型家族成员一览（四代全尺寸）

| 代数 | 尺寸档位 | 底座 LLM | 定位 |
| --- | --- | --- | --- |
| Qwen-VL | 7B 单档 | Qwen-7B | 验证范式 |
| Qwen2-VL | 2B / 7B / 72B | Qwen2-1.5B / 7.6B / 72B | 端侧 / 性价比主力 / 旗舰对标 GPT-4o |
| Qwen2.5-VL | 3B / 7B / 72B | Qwen2.5-3B / 7B / 72B | 端侧 / 主力 / 旗舰 |
| Qwen3-VL | 密集 2B/4B/8B/32B + MoE 30B-A3B / 235B-A22B | Qwen3 对应版本 | 边缘到主流 / 性价比 / 旗舰原生 256K |

**命名规律（面试可用）**：Qwen 系列 LLM 底座每代升级（Qwen-7B → Qwen2 → Qwen2.5 → Qwen3），VLM 同步跟进；每个尺寸都是"**LLM + 共享视觉塔**"的组合——视觉塔参数（675M/约 400M）不随 LLM 规模增长，这意味着**视觉计算开销不随模型档位变大**，小档位性价比极高。Qwen3-VL 每个尺寸还有 **Instruct（非思维）** 与 **Thinking（思维）** 两个版本：Thinking 版推理时输出长思维链（CoT），非思维版直接作答，按场景切换。

- 视觉塔参数从 1.9B → 675M → 675M → 约 400M，**越变越小但越变越强**——因为创新从"堆参数"转向"堆机制"（动态分辨率、窗口注意力、多级特征注入）；
- LLM 底座与 Qwen 纯文本系列同步演进（Qwen-7B → Qwen2 → Qwen2.5 → Qwen3），语言能力的提升直接传导到 VLM；
- 单图 token 从"固定 256"到"动态 4~16384"再到"默认 256~1280"——数字的收敛意味着**"够用的细节"有了更优的性价比定义**。

**总览表之外的高频数字速记**（面试张口就来的一组数）：

- 论文编号：2308.12966 → 2409.12191 → 2502.13923 → 2511.21631；
- 视觉塔参数：1.9B（OpenCLIP ViT-bigG）→ 675M（自研，patch 14）→ 675M（窗口注意力）→ 约 400M（SigLIP-2 架构，patch 16）；
- 单图 token：固定 256 → 动态 4~16384 → 4~16384 → 默认 256~1280；
- 数据规模：14 亿图文对 → 1.4T → 4.1T → ~2T+；
- 上下文长度：短序列 → 16K 训练/80K 外推 → 32K 训练 → 256K 原生 / 1M 扩展；
- 关键机制：cross-attn 重采样 → 动态分辨率 + M-RoPE → 窗口注意力 + 绝对时间 → Interleaved-MRoPE + DeepStack + 文本时间戳。

## 三、三条演进主线（记忆框架）

整个系列的变化可以压缩成三条主线，面试时按主线讲，逻辑最清晰：

```text
主线一 分辨率：固定 224/448 → 动态分辨率（sub-image 切分）→ 原生分辨率 + 窗口注意力
主线二 位置编码：绝对 PE → 2D-RoPE（ViT 内）→ M-RoPE 3D（LLM 内）→ Interleaved-MRoPE + 文本时间戳
主线三 token 压缩：cross-attn 重采样（固定 256）→ 2×2 卷积+MLP（固定 4×）→ 动态合并器 → 32× 像素压缩
```

### 3.1 主线一：分辨率——从"固定画框"到"图有多大就给多少"

| 阶段 | 代表版本 | 机制 | 解决的问题 |
| --- | --- | --- | --- |
| 固定分辨率 | Qwen-VL | 224 训练、448 推理，强制 resize | 简单，但小字模糊、长宽比畸变、token 浪费 |
| 动态分辨率 | Qwen2-VL | 等比缩放 + 28 网格对齐 + 超 448² 切 sub-image | 任意尺寸/长宽比连续建模，token 随信息量自适应 |
| 原生 + 窗口注意力 | Qwen2.5-VL | 不再固定 sub-image 上限，ViT 换窗口注意力 | 解决"高分辨率下全局注意力 O(N²) 算不动" |
| 原生 + 更强编码器 | Qwen3-VL | SigLIP-2 架构 + patch 16 + 32× 像素压缩 | 同等 token 数下像素信息量翻倍，OCR/文档更强 |

**一句话**：分辨率策略的目标从"让输入符合模型"（固定尺寸）变成了"让模型符合输入"（原生分辨率），支撑它的是 28 网格对齐（patch 14 × 合并 2）与窗口注意力带来的线性复杂度。

### 3.2 主线二：位置编码——从"分层接力"到"统一 3D 再到交错 3D"

| 阶段 | 位置编码方案 | 空间/时间感知来自哪 | 局限 |
| --- | --- | --- | --- |
| Qwen-VL | ViT 内绝对 PE + Adapter 把 2D 绝对 PE 注入 Q-K 对 + LLM 内 1D RoPE | 三层"各管一段"，位置信息在压缩前浓缩进 token | 无时间轴，视频只能拼复合图 |
| Qwen2-VL | ViT 内 2D-RoPE + LLM 内 M-RoPE（t/h/w 分块 `[16,24,24]`） | LLM 直接感知时间×高×宽三维 | 时间 id 是"帧序号"，不知真实间隔 |
| Qwen2.5-VL | 同上，时间 id **对齐绝对时间** | 模型感知"1 秒 = 多少 id 间隔"，秒级定位 | 长视频时间 id 过大且稀疏 |
| Qwen3-VL | **Interleaved-MRoPE**（`[24,20,20]` 交错）+ **文本时间戳** | 频率各轴均衡；模型"读表"而非"猜间隔" | 文本时间戳略增上下文 |

**一句话**：位置编码从"图内空间感（ViT）→ 压缩后不丢位置（Adapter）→ 图文混合生成（1D）"的分层接力，演进为"时间×高×宽统一编码进 LLM 旋转位置（M-RoPE）"，再到"频率交错 + 时间直接用文本表达"。

### 3.3 主线三：Token 压缩——从"固定压到 256"到"每 token 覆盖 1024 像素"

| 阶段 | 压缩机制 | 压缩比 | 可控性 |
| --- | --- | --- | --- |
| Qwen-VL | 单层 cross-attention 重采样（256 个可学习 query） | 448² 时 1024→256（4×）；224² 时 256→256（不压缩） | 固定 256，不可控 |
| Qwen2-VL | 2×2 卷积/分组 + MLP | 固定 4×（2×2 → 1） | 像素预算 min/max_pixels |
| Qwen2.5-VL | 2×2 分组 + 2 层 MLP | 4×，但按预算动态合并 | 像素预算 + 显式尺寸 |
| Qwen3-VL | 2×2 MLP + 时域 2× | **32× 像素**（patch 16：单 token 覆盖 $16\times2\times16\times2=1024$ 像素） | 图像/视频独立预算 |

**一句话**：压缩从"学习式重采样（可训练但固定长度）"变为"几何式合并（邻域冗余几乎无损）"，最后靠提升 patch 尺寸把每 token 承载的像素数从 196（patch 14）提到 1024（patch 16 + 时域 2×），本质是"先省信息再省 token"。

## 四、各代一页速览

### 4.1 Qwen-VL（第一代，2023）：用 Cross-Attention 打开视觉大门

**核心架构一句话**：冻结 OpenCLIP ViT-bigG + 单层 cross-attention 重采样器（位置感知 VL Adapter）压缩到固定 256 token + Qwen-7B 生成。

| 关键数字 | 值 |
| --- | --- |
| 总参数 | 9.6B（LLM 7.7B + ViT 1.9B + Adapter 0.08B） |
| Patch / 分辨率 | patch 14；阶段 1 用 224²、阶段 2/3 用 448² |
| Patch 数 | 224² → 256 个；448² → 1024 个（**448 是分辨率，不是 token 数**） |
| 重采样 | 单层 cross-attention，256 个可学习 query，输出恒为 256 token |
| 位置编码 | 三层：ViT 绝对 PE → **Adapter 把 2D 绝对 PE 注入 Q-K 对** → LLM 1D RoPE |
| 训练数据 | 阶段 1：14 亿图文对（LAION 等，77.3% 英文/22.7% 中文）；阶段 3：350K 指令 |
| 输入输出 | `<img>`/`<box>`/`<ref>` 特殊 token，框坐标 $[0,1000)$ 文本化 |

**代表作**：Qwen-VL / Qwen-VL-Chat（7B 单尺寸）。

**最强能力**：图文对话 + 视觉定位（ref/box，位置感知 Adapter 的 Q-K 位置注入是 grounding 根基）+ 基础 OCR + 中英双语。

**最大局限**：分辨率固定 448、token 固定 256（1024 patch 压 256 丢细节）、**没有时间维位置编码**（视频只能抽帧拼复合大图，无先后感知）。

> 本代对面试的意义在**位置编码体系**：为什么重采样压缩会丢位置（加权求和抹平）、为什么注入 Q-K 对（展开注意力分数可见位置项 $Q\text{PE}^\top + \text{PE}K^\top + \text{PE}\text{PE}^\top$）、为什么叫"位置感知"。
>
> **考点速览**：① 重采样器结构（256 个可学习 query 的单层 cross-attention）；② "448 是分辨率不是 token 数"；③ 三层位置编码各自的职责；④ 三阶段冻结策略（阶段 1 冻结 LLM / 阶段 2 全解冻 / 阶段 3 冻结 ViT）；⑤ 框坐标 $[0,1000)$ 文本化输出的设计。

### 4.2 Qwen2-VL（第二代，2024）：动态分辨率 + M-RoPE（面试重点）

**核心架构一句话**：全系列最重要的一代——自研 675M ViT（patch 14，2D-RoPE）+ 2×2 卷积+MLP 合并（4× 压缩）+ 动态分辨率 + M-RoPE，图像与视频统一建模。

| 关键数字 | 值 |
| --- | --- |
| 模型家族 | 2B / 7B / 72B（LLM 为 1.5B / 7.6B / 72B），**共用同一个 675M ViT** |
| 动态分辨率 | 等比缩放保持长宽比 + H/W 对齐 **28 网格**（patch 14 × 合并 2）+ 超 448² 切 sub-image |
| Token 公式 | $N_{\text{tok}} = \frac{H'}{28} \times \frac{W'}{28} = \frac{H'W'}{784}$，范围 **4~16384**；224² → 64+2=66 token |
| M-RoPE | 位置三元组 $(t,h,w)$；文本 $(i,i,i)$、图像 $(\text{常数}, r, c)$、视频 $(f, r, c)$；7B 配置 `mrope_section=[16,24,24]` |
| 外推能力 | 16K 训练长度 → 80K 推理稳健（位置 id 数值小的隐藏收益） |
| 视频 | 2 FPS 抽帧 + 时域 3D 卷积（temporal_patch_size=2，2 帧并 1 步）；单图视为 2 个相同帧 |
| 训练数据 | 阶段 1 约 600B + 阶段 2 约 800B = **1.4T token**；只对文本 token 算 loss |

**代表作**：Qwen2-VL-7B（性价比主力）、Qwen2-VL-72B（对标 GPT-4o）。

**最强能力**：任意分辨率/长宽比输入（文档、横图、竖图不失真）、OCR 大幅跃升、视频初步时间感知、多图 = 多帧视频。

**最大局限**：时间 id 是帧序号（不知真实间隔）；全局注意力在超高分辨率下昂贵；视频定位精度有限。

> 面试几乎都从这一代出题：动态分辨率五步流程、为什么对齐 28、sub-image 上限 448²、M-RoPE 三维分配规则、2×2 卷积 4× 压缩。
>
> **考点速览**：① 动态分辨率五步（等比缩放 → 28 对齐 → 超限切 sub-image → 逐个过 ViT → 2×2 合并拼回）；② token 公式 $N=\frac{H'W'}{784}$ 与 66/256 的换算；③ M-RoPE 的 $(t,h,w)$ 分配表与文本 $(i,i,i)$ 退化等价；④ "16K 训练外推 80K"的来源；⑤ 视频统一建模（2 FPS + 时域 3D 卷积、图像 = 2 个相同帧）。

### 4.3 Qwen2.5-VL（2025.01）：看得快、看得久、看得准时间

**核心架构一句话**：在 Qwen2-VL 基础上做三件事——ViT 换 Window Attention（提速）、时间轴对齐绝对时间（看得准）、token 合并器动态预算（算力可控）。

| 关键数字 | 值 |
| --- | --- |
| 模型家族 | Qwen2.5-3B / 7B / 72B |
| ViT | 675M，hidden 1280、32 层、16 heads、patch 14，**从零训练**；窗口 **112×112（8×8 patch）**；仅第 {7, 15, 23, 31} 层全局注意力，其余 28 层窗口注意力；RMSNorm + SwiGLU |
| 复杂度 | 全局 $O(N^2)$ → 窗口注意力对 patch 数**线性**（$O(N \cdot w^2)$） |
| Token 预算 | 动态 4~16384（min_pixels/max_pixels 或显式尺寸），视频按总预算调帧分辨率 |
| 时间建模 | 时间 id **对齐绝对时间**（帧间 id 间隔反映真实流速）+ **动态 FPS** 训练；秒 / hmsf（时:分:秒:帧）双格式标注，输出秒级时间戳 |
| 文档解析 | Omni-Document Parsing：表格/图表/公式/乐谱/手写体/多栏版面 → 结构化 HTML、JSON |
| Agent | 截图理解 + UI 定位（框/点双格式 + 绝对坐标 JSON）+ function call 动作空间 |
| 训练数据 | 阶段 1（仅 ViT）1.5T + 阶段 2 2T + 阶段 3（长上下文 32768）0.6T = **4.1T token** |

**代表作**：Qwen2.5-VL-72B（旗舰）、Qwen2.5-VL-7B。

**最强能力**：文档结构化解析（HTML/JSON）、秒级视频时间定位、GUI Agent（屏幕理解→决策→操作）、超 30 分钟视频理解。

**最大局限**：长视频下绝对时间 id 过大且稀疏，长时序仍不稳；推理时间戳依赖各 FPS 均匀采样，数据昂贵。

> **考点速览**：① 窗口注意力设计（窗口 112×112 = 8×8 patch、仅第 {7,15,23,31} 层全局、其余 28 层窗口）与复杂度从 $O(N^2)$ 到 $O(N \cdot w^2)$ 的收益；② 绝对时间对齐与动态 FPS 如何带来秒级定位；③ Omni-Document Parsing 的 HTML/JSON 输出；④ Agent 的"截图 → 定位 → function call"闭环；⑤ 4.1T 的三阶段构成（1.5T + 2T + 0.6T）。

### 4.4 Qwen3-VL（2025）：多模态大模型的新上限

**核心架构一句话**：SigLIP-2 架构视觉塔（约 400M）+ Interleaved-MRoPE + DeepStack 多级特征注入 + 文本时间戳，密集与 MoE 双路线、思考/非思考双模式，原生 256K 上下文。

| 关键数字 | 值 |
| --- | --- |
| 模型家族 | 密集 2B/4B/8B/32B；MoE 30B-A3B / 235B-A22B；每档均有 Instruct（非思维）与 Thinking（思维）双版本 |
| 视觉塔 | **SigLIP-2 架构**（默认 SO-400M 级约 400M，小模型 300M 级），patch 16；另有自研 Qwen3-ViT 消融全面优于 SigLIP-2 基线 |
| 像素压缩 | spatial_merge=2 × temporal_patch=2 → 单 token 覆盖 $16\times2\times16\times2=1024$ 像素 = **32× 像素压缩** |
| 默认 token | 单图 256~1280，视频 256~16384（含 2× 时域压缩） |
| 位置编码 | **Interleaved-MRoPE**（`mrope_section=[24,20,20]`，t/h/w 频率交错排布）→ 长时序建模显著改善，1M 扩展只需缩放因子 2~3 |
| DeepStack | ViT 第 8/16/24 层特征经专用 merger **残差注入 LLM 前 3 层**，不增序列长度（消融 AVG 74.7 → 76.0） |
| 时间建模 | **文本时间戳**（如 `<3.0 seconds>`，秒/HMS 双格式）替代时间 id |
| 长上下文 | 原生 256K（S3 阶段 262144 序列）；30 分钟视频 needle **100%**；YaRN 扩 1M（约 2 小时视频）99.5% |
| 训练 | S0 67B（仅 MLP merger）→ S1 ~1T（8192）→ S2 ~1T（32768）→ S3 100B（262144）≈ **~2T+**；后训练 = 长 CoT SFT（12M+）→ 蒸馏 → RL；loss 改平方根归一化 $\mathcal{L} \propto -\frac{\log p}{\sqrt{N}}$ |
| 数据亮点 | 30M 内部 OCR 图像、共 32 语种（+29）、3M CC PDF + 4M 内部文档、1M 点级定位、8M 数学题、GUI 多步轨迹 |

**代表作**：Qwen3-VL-235B-A22B（旗舰）、Qwen3-VL-30B-A3B（性价比）、Qwen3-VL-4B（端侧）。

**最强能力**：256K/1M 长上下文视频与文档、视频定位/密集字幕、细粒度 OCR 与文档、数学推理（Thinking 模式）、Agent 轨迹、思维模式按需切换。

**最大局限**：训练成本极高（~2T+ token + MoE，非一般团队可复现）；文本时间戳略增上下文；MoE 235B 总参数显存占用大。

> **考点速览**：① Interleaved-MRoPE 与分块 M-RoPE 的差异及 1M 缩放因子 2~3 的来源；② DeepStack 三级注入为什么不增序列；③ 文本时间戳替代时间 id 的动机；④ 4 阶段预训练（S0 仅 MLP → S3 262144）与 3 阶段后训练（CoT SFT → 蒸馏 → RL）；⑤ "视觉塔 6B 说法不成立"的纠正。

### 5.1 档位详注：每个能力拐点的"为什么"

| 能力 | 拐点 | 机制解释 |
| --- | --- | --- |
| OCR | Qwen2-VL | 固定 448 下小字模糊、长文档必须压缩；动态分辨率让任意尺寸图像以原生细节进入模型，OCRBench 大幅跃升；Qwen3-VL 再靠 32× 像素压缩（每 token 覆盖 1024 像素）与 30M 内部 OCR 数据把"清晰度"顶到极限 |
| 文档解析 | Qwen2.5-VL | OCR 只解决"认出字"，结构解析需要"版面理解"——2.5 代 Omni-Document Parsing 直接输出 HTML 保留表格/公式/栏位结构，配合原生分辨率做结构化抽取（JSON） |
| 视频定位 | Qwen2.5-VL | 帧序号 id 只能回答"第几帧"，绝对时间 id + 动态 FPS 让模型感知"1 秒 = 多少间隔"并输出秒级时间戳；Qwen3-VL 的文本时间戳进一步解决长视频 id 过大/稀疏问题 |
| 多图推理 | Qwen2-VL | M-RoPE 把多图视为多帧（时间 id 递增），模型首次在"图间对比"上有了显式位置依据；Qwen3-VL 的 `Picture 1:` 序号前缀让指代更直接 |
| Agent | Qwen2.5-VL | 需要"屏幕理解 → UI 定位 → 操作"闭环：2.5 代提供框/点双格式定位 + 绝对坐标 JSON + function call 动作空间；3 代补上 GUI 多步轨迹与思考模式 |
| 长上下文 | Qwen3-VL | 16K（Qwen2）→ 32K 训练（Qwen2.5）→ 256K 原生（Qwen3 的 S3 阶段 262144），靠 Interleaved-MRoPE 让 1M 扩展只需缩放因子 2~3 |

**面试话术**：讲能力演进不要只报档位，要"**能力 → 拐点版本 → 机制原因**"三段式，比如"视频定位的拐点在 2.5 代，因为绝对时间对齐让模型学会了读真实时间流速，而 3 代改用文本时间戳是为了治长视频的 id 稀疏病"。

## 六、训练范式演进

### 6.1 范式总览：预训练 → 多任务 → SFT → 后训练

Qwen 系统一采用 **"视觉-语言预训练 → 指令微调（SFT）→ 人类偏好对齐"** 三级流水线，Qwen3-VL 在预训练内细分出 S0~S3 四阶段，并首次补齐"后训练（蒸馏 + RL）"：

```text
阶段 A 预训练（图文对齐）
  ├─ 目标：视觉 token 与文本 token 语义对齐（next-token prediction，只监督文本）
  ├─ 数据：图文对、OCR、交错图文文档、视频字幕、知识图谱图像
  └─ 策略：先只训连接器/视觉塔 → 全参数解冻 → 逐步拉长序列（8192 → 32768 → 262144）
阶段 B 指令微调（SFT）
  ├─ 目标：听懂指令，输出对话/框/JSON/HTML/时间戳
  ├─ 数据：VQA、文档、多图、视频、Agent 轨迹（Qwen3-VL 加 12M+ 长 CoT）
  └─ 策略：冻结视觉塔（早期）或全参微调（Qwen3-VL）
阶段 C 后训练（Qwen3-VL 首次补齐）
  ├─ 知识蒸馏：强教师模型
  └─ 强化学习：答案正确率奖励 + 思维预算控制
```

### 6.2 各代数据规模表

| 维度 | Qwen-VL | Qwen2-VL | Qwen2.5-VL | Qwen3-VL |
| --- | --- | --- | --- | --- |
| 预训练数据规模 | **14 亿图文对**（阶段 1） | **1.4T**（600B + 800B） | **4.1T**（1.5T + 2T + 0.6T） | **~2T+**（S0 67B + S1/S2 各 ~1T + S3 100B） |
| 序列长度 | 固定短序列 | 8192 | 8192 → 32768 | 8192 → 32768 → 262144 |
| 阶段划分 | 3 阶段 | 3 阶段 | 3 阶段 | 4 预训练（S0~S3）+ 3 后训练 |
| 对齐手段 | 无（仅 SFT，350K 指令） | 无（仅 SFT） | SFT | SFT + **蒸馏 + RL** |
| 损失函数 | 标准 CE（仅文本 token） | 标准 CE（仅文本 token） | 标准 CE | **平方根归一化** $\mathcal{L} \propto -\frac{\log p}{\sqrt{N}}$ |
| 冻结策略 | 阶段 1 冻结 LLM、阶段 2 全解冻、阶段 3 冻结 ViT | 阶段 1 对齐 ViT、阶段 2 全解冻、阶段 3 冻结 ViT | 同左 | S0 仅训 MLP merger，S1~S3 全参 |

### 6.3 三处值得注意的"反直觉"

1. **Qwen3-VL 预训练 token（~2T+）比 Qwen2.5-VL（4.1T）少**——因为 Qwen3-VL 胜在数据质量（合成 CoT、30M 内部 OCR、长上下文 S3 阶段）与后训练（蒸馏 + RL），证明"预训练数据量不是唯一指标"；
2. **Qwen-VL 阶段 1 冻结 LLM**（先把视觉通路打通，否则 LLM 收到的是噪音），而 Qwen3-VL 的 S0 只训 MLP merger（ViT 与 LLM 双冻结）——相同思想、更彻底的版本；
3. **损失函数只在最后一代改**：平方根归一化是为了平衡文本 token 与多模态 token 的梯度贡献，说明"多模态梯度平衡"是规模化后绕不开的工程问题。

### 6.4 数据构成金字塔（四代通用结构）

```text
底部（预训练主体，量最大）：弱标注图文对、网页交错图文、OCR 图文
中部（能力数据）：          VQA、定位（框/点/区域）、图表/文档解析、数学
顶部（对齐数据，质最高）：   指令对话、长思维链 CoT、GUI Agent 轨迹、多语言 OCR
```

- **Qwen-VL**：底部以 LAION 等 14 亿图文对为主，顶部仅 350K 指令——金字塔两头都很"单薄"；
- **Qwen2-VL**：中部加入定位三元组、交错图文，顶部加入视频与 Agent 数据；
- **Qwen2.5-VL**：底部弱标注占比下降，长视频（>30 分钟）专门合成字幕，文档解析数据成型；
- **Qwen3-VL**：中部能力数据爆发（30M OCR、1M 点级定位、2M 感知 VQA、6M 图表、8M 数学），顶部以 12M+ 合成长 CoT 冷启动——**金字塔重心从"底部堆量"移向"中部/顶部提质"**，这是 4.1T → ~2T+ 反而更强的结构性原因。

### 6.5 推理显存权衡（工程要点）

| 场景 | token 占用 | 对策 |
| --- | --- | --- |
| 长文档截图 | 单图最高 16384 | 调低 max_pixels、按页切图 |
| 长视频 | 每帧 × 帧数，增长快 | 降 FPS、降帧分辨率（Qwen3-VL 用 total_pixels 限制） |
| 多图对比 | 每图独立预算 | 单图预算下调（如 256~1280） |
| 超长上下文 | 256K 原生 / 1M YaRN | 需 flash-attention + 分页/稀疏注意力工程 |
| MoE 档位 | 权重按总参加载（235B） | 显存按总参规划，A22B 只省计算不省权重显存 |

### 7.3 开源协议与使用注意

- 各代权重均可从 HuggingFace / ModelScope 获取，**商用授权以官方模型卡与协议页为准**（早期 Qwen-VL 权重协议较严格，Qwen2-VL 及之后按官方公布的 Apache-2.0 条款发布，使用前务必核对对应版本的 LICENSE）；
- 部署注意：Qwen3-VL 的 MoE 档位（235B-A22B）**总参 235B 需全量加载**，显存需求按总参计算，A22B 只降低计算开销与激活内存；
- 动态分辨率推理的显存峰值由 max_pixels 决定（最高 16384 token/图），线上服务建议调低预算或按页切图。

### 7.4 选型决策树（一句话版）

```text
输入的是什么？
├─ 只有图片、质量要求一般 → Qwen2-VL-7B（性价比最高）
├─ 图片为主但要求精细（票据/报表/小字）→ Qwen2.5-VL-7B/72B（Omni-Document）
├─ 视频为主（定位/摘要/长视频）→ Qwen2.5-VL（秒级定位）或 Qwen3-VL（256K 长视频）
├─ 屏幕 Agent（GUI 自动化）→ Qwen2.5-VL / Qwen3-VL（思考模式辅助决策）
├─ 多语言 OCR（非中英）→ Qwen3-VL（32 语种）
└─ 全都要 / 要求最高 → Qwen3-VL-235B-A22B（旗舰，需多卡）

部署预算呢？
├─ 单卡 24G 以下 → Qwen3-VL-4B / Qwen2.5-VL-3B
├─ 单卡 A100 级别 → Qwen3-VL-30B-A3B（MoE 激活 3B）或 Qwen2.5-VL-7B
├─ 多卡集群 → Qwen3-VL-235B-A22B / Qwen2.5-VL-72B
└─ 显存极紧张 → 调低 max_pixels（256~1280）牺牲细节换吞吐
```

## 八、与其他 VLM 家族的关系

### 8.1 一句话差异

| 家族 | 一句话定位 |
| --- | --- |
| **Qwen-VL** | 唯一做"**原生分辨率 + 3D 位置编码**"的——动态分辨率最彻底、时间感知最强、文档/视频能力最均衡 |
| LLaVA | 最简 MLP 连接，无 token 压缩，靠数据与多尺度切块（anyres）补足，学术基线之王 |
| InternVL | 6B 大视觉塔（InternViT）+ pixel shuffle 高效压缩，走"强感知塔 + 大模型"路线 |
| MiniCPM-V | 小参数量端侧路线，视觉塔 + Q-Former 式 resampler，主打端侧与中英 |

### 8.2 演进树（技术来源关系）

```text
CLIP / OpenCLIP（2021，图文对齐基座）
  ├─ SigLIP（2023，sigmoid 损失替代 softmax）── SigLIP 2（2025）
  │      └─ Qwen3-VL 视觉塔采用 SigLIP-2 架构
  ├─ LLaVA（2023，MLP 投影 + 指令微调范式）── LLaVA-1.5 / NeXT（anyres 多尺度切块）
  └─ BLIP-2（2023，Q-Former 重采样）── MiniCPM-V 的 resampler 思路

Qwen-VL 家族自研主线：
  Qwen-VL（2023）：ViT-bigG + cross-attn 重采样（受 BLIP-2 Q-Former 启发，但做单层 + 位置注入）
    └─ Qwen2-VL（2024）：自研 675M ViT + 动态分辨率 + M-RoPE ← 家族真正的分水岭
         └─ Qwen2.5-VL（2025.01）：Window Attention + 绝对时间 + Omni-Document
              └─ Qwen3-VL（2025）：SigLIP-2 架构 + Interleaved-MRoPE + DeepStack + 文本时间戳
```

### 8.3 对照表（以 Qwen2-VL 为基准）

| 维度 | Qwen2-VL | LLaVA-1.5 / NeXT | InternVL 1.5/2 | MiniCPM-V 2.0/2.5 |
| --- | --- | --- | --- | --- |
| 视觉塔 | 自研 ViT 675M（patch 14） | CLIP ViT-L/14@336 | InternViT-6B（patch 14） | SigLIP-400M / 自研 ViT |
| 连接方式 | 2×2 卷积 + MLP（4× 压缩） | MLP 投影（不压缩） | Pixel Shuffle（4×/16×） | Q-Former 式 resampler |
| 单图 token | 动态 4~16384 | 576 固定 / NeXT anyres 多块 | 448 tile 网格（≤12 块） | 固定 + anyres |
| 动态分辨率 | **原生 + sub-image 切分** | 1.5 无 / NeXT anyres | 448 tile 动态网格 | 2.5 起 anyres |
| 位置编码 | **M-RoPE（3D）** | 绝对 PE / 无 | 2D-RoPE（ViT 内） | 1D RoPE |

| 典型尺寸 | 2B / 7B / 72B | 7B / 13B / 34B | 1B~76B | 2B / 4B |

### 8.4 Qwen 系对生态的反向影响

- **动态分辨率 + 3D 位置编码**成为后来者（含国内多家 VLM 与部分闭源模型）的默认设计语言，M-RoPE 思路也被其他家族借鉴（如视频/多图场景的 3D 位置处理）；
- **"原生分辨率 + sub-image 切分"**替代"多尺度固定档位"成为高分辨率文档场景的主流范式，LLaVA-NeXT 式的 anyres 与 Qwen 的动态分辨率在 2025 年后逐渐趋同；
- **文本化坐标输出**（$[0,1000)$ 的 `<box>` 字符串）与 **Agent 统一 function call** 成了开源 VLM 的标准接口设计；
- 反例警示：**6B 大视觉塔路线（InternVL）**与 **极小端侧路线（MiniCPM-V）**依然并存——说明"视觉塔大小"和"参数量"不是唯一解，机制设计（窗口注意力、DeepStack）可以补足规模。

## 九、高频面试问答

**Q1：Qwen-VL 系列四代各解决了什么问题？**
一代（2023）解决"有视觉能力"：cross-attn 重采样打通图文+定位+OCR；二代（2024）解决"看得清"：动态分辨率 + M-RoPE，文档/OCR 跃升；三代（2025.01）解决"看得快、看得久、看得准时间"：窗口注意力、绝对时间对齐、文档解析与 Agent；四代（2025）解决"看得懂、想得深、记得久"：Interleaved-MRoPE、DeepStack、文本时间戳、256K 上下文与思维模式。

**Q2：动态分辨率 vs 固定分辨率（多尺度训练）的区别？**
固定分辨率（如 Qwen-VL 的 448²）把小字模糊、大图压扁、简单图浪费 token；多尺度训练（如 LLaVA-NeXT anyres）只在预设的几个档位间切块。Qwen2-VL 的动态分辨率是**连续原生分辨率**：保持长宽比缩放 + 对齐 28 网格 + 超 448² 切 sub-image，token 数是分辨率的连续函数 $N=\frac{H'W'}{784}$，范围 4~16384。消融证明没有任何固定分辨率能全 benchmark 最优。

**Q3：M-RoPE 是什么？和标准 RoPE 什么关系？**
M-RoPE（Multimodal RoPE）把位置拆成三维三元组 $p=(t,h,w)$（时间/高度/宽度），在每个 attention head 的维度分组上用各轴 position id 算旋转角（Qwen2-VL-7B 为 `mrope_section=[16,24,24]`）。文本用 $(i,i,i)$ 与 1D RoPE 完全等价；图像用 $(\text{常数}, r, c)$；视频用 $(f, r, c)$。两个隐藏收益：① 空间/时间感知；② 位置 id 数值小，16K 训练可外推到 80K 推理。

**Q4：视觉 token 怎么算？**
Qwen2-VL：缩放后尺寸对齐 28 的倍数，$N=\frac{H'}{28}\times\frac{W'}{28}$，例如 224² → $8\times8=64$ 个（加首尾 2 个特殊 token 共 66 个，论文原话）、448² → 256 个；上限 16384、下限 4。Qwen3-VL：patch 16 + 时域 2×，单 token 覆盖 1024 像素，默认单图 256~1280。Qwen-VL：固定 256（448² 时 1024 个 patch 压缩 4 倍）。

**Q5：为什么对齐单位是 28？为什么 sub-image 上限是 448²？**
28 = patch 14 × 合并 2：合并器把 2×2 的 patch（每个覆盖 14×14 像素）合成 1 个 token，即每个视觉 token 覆盖 28×28 像素，缩放必须对齐 28 才能整数拼接。448² = 32×32 patch 是单次 ViT 前向能处理的合理规模，更大的图切成多个 sub-image 各自编码后按行优先拼回。

**Q6：Qwen-VL 的重采样器为什么不会丢位置信息？**
因为位置感知 VL Adapter 把 2D 绝对位置编码**同时注入 Q 和 K**：$\tilde{Q}=Q+\text{PE}_{2D}$、$\tilde{K}=K+\text{PE}_{2D}$。注意力分数展开后出现 $QK^\top + Q\text{PE}^\top + \text{PE}K^\top + \text{PE}\text{PE}^\top$——内容项 + query-位置匹配项 + 位置-位置交互项，压缩（加权求和）时空间布局被隐式编码进注意力权重，这是 grounding 能力的根基。

**Q7：为什么 Qwen3-VL 用文本时间戳替代 M-RoPE 时间 id？**
Qwen2.5-VL 把时间 id 对齐绝对时间后，长视频产生过大且稀疏的时间 id，损害长时序，且要求各 FPS 均匀采样、数据构造昂贵。Qwen3-VL 改为在视频片段前插入 `<3.0 seconds>` 这类文本 token（秒/HMS 双格式训练），模型"读表"而非"猜间隔"，长视频定位更准、训练更省，代价仅是上下文略增。

**Q8：Interleaved-MRoPE 与 M-RoPE 的区别？**
M-RoPE 按块分配维度（`[16,24,24]`），低频/高频带在三个轴上分布不均；Interleaved-MRoPE 把 t/h/w 分量在嵌入维度上**交错排布**（`mrope_interleaved: true`，`mrope_section=[24,20,20]`），保证每条轴低频高频均匀覆盖。收益：长距离时序建模显著改善；附带收益：interleaved 位置 id 增长更慢，1M 扩展只需缩放因子 2~3（标准 RoPE 要 4）。

**Q9：DeepStack 是什么？为什么不增加序列长度？**
从 ViT 第 8/16/24 层抽取多级特征，经专用 merger 投影后**残差加到 LLM 前 3 层的 hidden state**——不新增 token、不涨上下文。浅层特征保细节（纹理/小字），深层保语义，InfoVQA/DocVQA 等细粒度任务稳定涨点（消融 AVG 74.7 → 76.0）。

**Q10：Qwen2.5-VL 预训练 4.1T token，为什么 Qwen3-VL 只有 ~2T+，反而是升级？**
预训练 token 量不是唯一指标。Qwen3-VL 的 ~2T+（S0 67B + S1/S2 各 ~1T + S3 100B）质量更高：30M 内部 OCR、10 类 PDF 文档、合成 CoT、点级定位等结构化数据占比大，且新增了后训练（长 CoT SFT + 蒸馏 + RL）与超长上下文阶段（262144）；加上 MoE 架构与平方根归一化损失，同样 token 预算下能力上限远高于 2.5 代。

**Q11：Qwen3-VL-235B-A22B 的 MoE 省显存吗？**
不省。总参 235B 意味着模型权重需全量加载，显存按 235B 算；A22B 只降低**计算量与激活内存**（每 token 只激活 22B 参数）。想要省显存选 30B-A3B 或密集档位。

**Q12：一个视频大概吃多少 token？怎么控成本？**
按 2 FPS 抽帧，1 分钟视频 = 120 帧，即使每帧低分辨率也轻松上万 token；30 分钟视频接近 256K 上下文上限（这正是 Qwen3-VL 把上下文拉到 256K 的原因）。控成本手段：降 FPS、降帧分辨率、用 total_pixels/预算限制总 token 数。代价是抽帧即丢信息——高运动、快速翻页场景仍会漏事件。

**Q13：如果让你两分钟向面试官介绍整个 Qwen-VL 家族，怎么组织？**
用"总-分-总"：**总**——一句话定位（任意分辨率转 token + 3D 位置编码的阿里通义 VLM 家族）；**分**——四条演进主线讲两代关键节点：分辨率从固定 448 到动态分辨率（Qwen2）再到原生+窗口注意力（Qwen2.5），位置编码从 Qwen-VL 三层接力到 M-RoPE 3D 再到 Interleaved-MRoPE + 文本时间戳（Qwen3），token 从固定 256 到动态 4~16384 再到 32× 像素压缩；数据从 14 亿图文对到 1.4T / 4.1T / ~2T+；**总**——收在能力地图（OCR/文档/视频/Agent 各代的拐点）与选型建议上。重点是**别背参数，讲"每代解决什么问题"**。

## 十、常见误区

**误区 1：Qwen-VL 的重采样器是"448 个 token 压到 256 个"。**
错。448 是**分辨率（像素）**，不是 token 数。正确事实：448×448 输入产生 1024 个 patch token（$(448/14)^2$），重采样后压到 256 个（4 倍压缩）；224×224 输入产生 256 个 patch，重采样后仍是 256 个（不压缩，只重排列信息）。

**误区 2：Qwen3-VL 的视觉塔升级到了 6B 参数。**
错。官方技术报告与开源 config 均显示视觉塔基于 **SigLIP-2 架构**（默认 SO-400M 级，约 4 亿参数，patch 16）。规模增长在 LLM（MoE 235B-A22B）与训练数据，不在视觉塔。

**误区 3：动态分辨率 = 多尺度训练 / 预设几个固定档位。**
不完全是。Qwen2-VL 是**连续原生分辨率**：保持长宽比 + 对齐 28 网格 + 超限切 sub-image，token 数是分辨率的连续函数，不是 LLaVA-NeXT 那样的预设网格切块。

**误区 4：M-RoPE 是"三个独立的 RoPE 拼在一起"。**
不准确。M-RoPE 是**一个**旋转编码在维度分组上的分解：不同维度组用 t/h/w 各自的 position id 计算旋转角（`[16,24,24]` 分组），文本退化为 $(i,i,i)$ 与 1D RoPE 等价。

**误区 5：MoE 版（235B-A22B）显存小、随便部署。**
错。总参数仍需全量加载，显存按 235B 计算；A22B 只省计算（激活参数），不省权重显存。量级类似的误区还有"视觉塔不随 LLM 增长 = 视觉部分不耗显存"——视觉 token 的 KV cache 才是大头。

**误区 6：视觉 token 压缩越多越好 / 视频输入就是多张图拼接，模型天然懂时序。**
① 2×2 合并是"几乎无损"的邻域冗余压缩，但过度压缩（如固定 256 token 承载大图）丢小字细节，Qwen2.5-VL 起的动态预算就是在精度与成本间显式权衡；② Qwen-VL 把视频帧拼成复合大图、**无时间维位置编码**，感知不到先后顺序——时序感知是从 Qwen2-VL 的 M-RoPE 时间轴才真正开始的。

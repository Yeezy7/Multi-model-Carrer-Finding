# Qwen3-VL（第四代，2025）：MoE + 双思维 + Interleaved-MRoPE + DeepStack + 1M 上下文

> 本笔记覆盖 Qwen3-VL 的完整技术剖析（论文 2511.21631，2025 年发布）。这一代是系列中架构改动最大的一代：LLM 底座升级为密集 + MoE 混合家族、视觉塔换成 SigLIP-2 架构（约 400M，**不是流传的 6B**）、位置编码升级为 Interleaved-MRoPE、引入 DeepStack 多级特征注入与文本时间戳、上下文拉满 256K 原生（可扩 1M）、并标配 Thinking/Non-Thinking 双思维模式。面试被问"MoE 怎么部署""Interleaved-MRoPE 是什么""DeepStack 为什么不涨 token""为什么放弃时间 id"时，本篇是完整答案。

## 一、一句话解释

### 1.1 一句话解释

> **Qwen3-VL = 用 MoE 稀疏化 + 双思维模式 + Interleaved-MRoPE + DeepStack 多级特征注入 + 文本时间戳五件套，把多模态 LLM 推到"看得懂（细粒度）、想得深（长推理）、记得久（256K/1M 上下文）"的新上限。**

### 1.2 五个关键词速览

| 关键词 | 所属模块 | 核心设计 | 一句话收益 |
|--------|----------|----------|-----------|
| MoE | LLM 底座 | 30B-A3B / 235B-A22B 稀疏激活 | 用激活参数换能力，性价比与旗舰兼顾 |
| 双思维模式 | 推理范式 | Instruct（非思维）/ Thinking（思维）双版本 | 快答与深思按场景切换 |

| DeepStack | 视觉-语言融合 | ViT 第 8/16/24 层特征注入 LLM 前 3 层残差 | 不增 token 拿到多级特征，细粒度任务涨点 |
| 文本时间戳 | 时间建模 | 视频片段前插入 `<3.0 seconds>` 文本 token | 模型"读时间"，弃用过大稀疏的时间 id |

## 三、MoE 架构：稀疏激活

### 3.1 稀疏激活的含义

MoE（Mixture-of-Experts）的核心：**每一层的前馈网络（FFN）由多个并行的"专家"组成，每个 token 只激活其中少数几个**。

```text
MoE 层（如 64 个专家）:
    token ──> Router 选出 Top-2 专家 ──> 只在这 2 个专家上计算 FFN
                                        └──> 输出加权合并
```

- **总参数（权重）**：所有专家的权重都要存在显存里；
- **激活参数（算力）**：每个 token 实际只走 2 个专家的前向，计算量近似"2/64 × 全量"。

### 3.2 30B-A3B 的部署含义

Qwen3-VL-30B-A3B：**30B 总参数，每个 token 只激活 3B**。

| 维度 | 含义 | 类比 |
|------|------|------|
| 权重显存 | 30B 参数 × 2 字节（BF16）≈ **60GB** | 与 30B 密集模型同量级 |
| 单 token 计算量 | ≈ 3B 密集模型的前向 | 与 3B 模型同量级 |
| 推理速度 | 每 token 计算≈3B 级，远快于 30B 密集 | 吞吐接近小模型 |
| 质量上限 | 记忆/知识容量由 30B 权重承载 | 能力强于 3B 密集 |

**一句话**：MoE 把"权重显存"和"计算成本"解耦——**显存按总参数买，算力按激活参数花**。

### 3.3 激活小 ≠ 权重小（面试核心）

| 误区 | 事实 |
|------|------|
| "A3B 只有 3B 那么大" | 错。**权重 30B**，只是每 token 计算走 3B 激活 |
| "MoE 部署很便宜" | 部分对。算力便宜（激活小），**显存不便宜**（权重全量加载） |
| "30B-A3B ≈ 30B 密集" | 错。能力接近更大密集模型（知识在权重里），但速度接近小模型 |
| "MoE 不需要大显存" | 错。权重全量驻留显存，235B-A22B 需要多卡分载 |

### 3.4 参数/激活/显存对照

| 模型 | 总参 | 激活参 | 权重显存（BF16） | 每 token 计算量 |
|------|------|--------|-----------------|----------------|
| Qwen3-VL-32B | 32B | 32B | ≈64GB | 32B 级 |
| Qwen3-VL-30B-A3B | 30B | **3B** | ≈60GB | **3B 级** |
| Qwen3-VL-235B-A22B | 235B | **22B** | ≈470GB（需多卡） | **22B 级** |

## 四、视觉编码器（重点）：SigLIP-2 架构 + 32× 像素压缩

### 4.1 SigLIP-2 架构

视觉塔从"自研 675M ViT"换为 **SigLIP-2 架构**：

| 属性 | 值 |
|------|-----|
| 架构 | SigLIP-2（Google 2025，多目标训练：对比 + 自蒸馏 + 掩码重建） |
| 参数量 | 官方默认 **SO-400M 级（约 4 亿）**，小模型用 300M 级 |
| patch | **16**（Qwen2.5-VL 为 14） |
| 分辨率 | 沿用动态分辨率训练（原生任意分辨率输入） |
| 位置编码 | 2D-RoPE（按输入插值） |

换 SigLIP-2 的收益：SigLIP-2 的多目标训练（对比 + 自蒸馏 + 掩码重建）让视觉塔的**细粒度特征与密集特征更强**——这正是文档、OCR、图表任务需要的（与 05 篇 SigLIP 笔记的结论一致：SigLIP-2 在 VLM 视觉塔场景全面超越 SigLIP-1）。

### 4.2 patch 16 + 32× 像素压缩

每个视觉 token 覆盖的像素计算：

$$\text{像素/token} = \underbrace{16}_{\text{patch}} \times \underbrace{2}_{\text{spatial merge}} \times \underbrace{16}_{\text{patch}} \times \underbrace{2}_{\text{temporal}} = 1024 \text{ 像素}$$

即每个视觉 token 覆盖 32×32 的像素块 × 2 帧（时域合并），**32× 像素压缩**：

| 版本 | patch | 合并 | 像素/token | 压缩比 |
|------|-------|------|-----------|--------|
| Qwen2.5-VL | 14 | 2×2 空间 | $14\times2\times14\times2=784$ | 28×28 块 |
| Qwen3-VL | **16** | 2×2 空间 + **2× 时域** | $16\times2\times16\times2=1024$ | **32×32×2 块（32×）** |

时域上 `temporal_patch_size=2`：相邻 2 帧合并为 1 个时间步（时域卷积处理），**时间维再压缩 2 倍**——视频 token 数因此减半。

### 4.3 token 预算

| 模态 | 默认 token 预算 |
|------|----------------|
| 单图 | **256 ~ 1280**（默认） |
| 视频 | **256 ~ 16384**（含 2× 时域压缩） |

单图默认预算比 Qwen2.5-VL 的 4~16384 收窄（常用档位更集中），视频预算不变。

### 4.4 Qwen3-ViT：自研变体

除了 SigLIP-2 架构，还训练了**自研 Qwen3-ViT**（自研 CLIP 式预训练版本）：

- 同一套架构族，不同预训练数据与目标；
- 消融实验中 **Qwen3-ViT 全面优于 SigLIP-2 基线**；
- 发布时默认选择，兼顾开源生态（SigLIP-2 权重）与内部最优（Qwen3-ViT）。

### 4.5 纠正"6B 视觉塔"传言（面试必考）

> **社区一度流传"Qwen3-VL 的视觉塔升级到 6B 参数"——不成立。官方技术报告与开源 config 均显示：视觉塔基于 SigLIP-2 架构，约 4 亿参数级（SO-400M 默认 / 300M 小模型），patch 16。**

规模增长的真实去向：

| 维度 | 实际增长 |
|------|----------|
| LLM | 密集 2B~32B + MoE 30B-A3B / **235B-A22B** |
| 训练数据 | S1/S2 各约 1T token，多阶段流水线 |
| 上下文 | 256K 原生 / 1M YaRN |

**为什么视觉塔不用更大**：视觉塔与 LLM 的参数比（约 1:10 到 1:200）说明瓶颈在 LLM 侧的跨模态推理与记忆；400M 视觉塔 + DeepStack 多级特征已覆盖细粒度需求，增大视觉塔的边际收益低于增大 LLM。

## 五、Interleaved-MRoPE（重点）：修复频率失衡

### 5.1 Qwen2 分块 M-RoPE 的频率失衡

Qwen2 系把 head 维度**按块**分配给 t/h/w 三轴（如 Qwen2-VL-7B 的 `mrope_section = [16, 24, 24]`，head_dim=128 → 64 对旋转频率）：

```text
分块分配 [16, 24, 24]:
维度 0~31   → 时间轴 t（16 对频率）
维度 32~79  → 高度轴 h（24 对频率）
维度 80~127 → 宽度轴 w（24 对频率）
```

**问题**：旋转频率从低频（$b^{-2i/d}$，$b=10000$，$i$ 小）到高频（$i$ 大）单调分布。分块后：

- **时间轴独占低频段**（i=0~15），中高频时间信息缺失；
- h/w 轴只有中高频段，**低频位置敏感度不足**（长距离空间关系弱）；
- 长视频场景下，时间轴需要大量低频分量表达远距离帧间关系，频谱有偏导致长时序建模退化。

### 5.2 交错分配（interleaved）

Qwen3-VL 的修复：**t/h/w 的频率对在嵌入维度上交替排布**（配置 `mrope_interleaved: true`，`mrope_section: [24, 20, 20]`）：

```text
交错分配 [24, 20, 20]（64 对频率）:
频率对 1~24   → 时间轴 t（24 对）
频率对 25~44  → 高度轴 h（20 对）
频率对 45~64  → 宽度轴 w（20 对）
分配时 t/h/w 分量按交替方式散布在维度上
```

关键差异：分块版让某轴**独占一段连续频率带**；交错版让**每条轴都同时覆盖低、中、高频带**：

| 轴 | 分块版覆盖 | 交错版覆盖 |
|----|-----------|-----------|
| t（时间） | 仅低频段 | 低 + 中 + 高频均有 |
| h（高度） | 仅中频段 | 低 + 中 + 高频均有 |
| w（宽度） | 仅中频段 | 低 + 中 + 高频均有 |

### 5.3 收益

**收益一：长时序建模显著改善。** 时间轴拿到低频分量后，长视频的远距离帧间关系可被有效编码，长视频 benchmark 提升。

**收益二：位置 id 增长更慢，缩放因子更小。** 交错分配下位置 id 数值增长更慢，同等长度外推需要的缩放因子更小：

- **1M 上下文扩展只需 YaRN factor 2~3**；
- 标准 RoPE / 分块方案需要 factor **4**。

> 细节：旋转角公式 $\theta_i = b^{-2i/d}$（$b=10000$，$d$ 为 head 维），频率覆盖范围由该轴分配到的频率对决定；交错分配让每条轴的频率跨度拉满，等效"用更少的 id 增长表达同样多的相对距离"。

### 5.4 与 Qwen2 对比表

| 维度 | Qwen2-VL / 2.5-VL | Qwen3-VL |
|------|-------------------|----------|
| 分配方式 | 分块（blockwise） | **交错（interleaved）** |
| 配置 | `mrope_section=[16,24,24]` | `mrope_section=[24,20,20]` + `mrope_interleaved: true` |
| 频率覆盖 | 各轴只覆盖一段频带 | 每轴覆盖低中高频 |
| 长时序 | 频谱有偏，退化 | 显著改善 |
| 1M 缩放因子 | 4（标准 RoPE） | **2~3** |

## 六、DeepStack（重点）：多级 ViT 特征注入 LLM

### 6.1 思路来源

DeepStack 启发自同名技术（把多尺度输入"堆叠"进 Transformer），但 Qwen3-VL **不是**把多尺度输入堆起来，而是**从 ViT 的中间层抽取特征，直接注入 LLM 的浅层 hidden state**。

### 6.2 结构

```text
ViT 第 8 层特征  ──┐  专用 merger 投影
ViT 第 16 层特征 ──┼──> 直接加到 LLM 第 1~3 层的 hidden state（残差相加）
ViT 第 24 层特征 ──┘
```

| 设计 | 值 |
|------|-----|
| ViT 特征层 | 第 **8 / 16 / 24** 层（均匀分布的三级） |
| 注入位置 | LLM **前 3 层**（第 1~3 层）的 hidden state |
| 注入方式 | **残差相加**（同位置 token 直接相加） |
| 新增参数 | 每级一个专用 merger 投影 |
| 序列长度 | **不增加**（只往已有 token 上做残差注入） |

### 6.3 为什么不增加 token

主流多尺度方案（如把不同分辨率图各过一遍 ViT 再拼接）会**成倍增加 token 数**，直接吃掉上下文与 KV cache。DeepStack 的残差注入：

- token 数量与单尺度过 ViT 完全一致；
- LLM 前 3 层在原有 hidden state 上**叠加**多级视觉特征；
- 上下文长度、注意力计算量均不受影响。

### 6.4 浅层细节 + 深层语义

| 特征层 | 特征类型 | 贡献 |
|--------|----------|------|
| 第 8 层（浅层） | 纹理/边缘/小字 | 细粒度细节（OCR 小字、表格线） |
| 第 16 层（中层） | 局部结构/部件 | 中等粒度（图形、图表元素） |
| 第 24 层（深层） | 语义/对象级 | 全局语义（场景、版面类型） |

从 low-level 到 high-level 全覆盖：**浅层保细节、深层保语义**，弥补窗口注意力的局部性缺陷与单层特征的信息瓶颈。

### 6.5 消融结果

| 配置 | AVG（多任务平均） |
|------|------------------|
| 无 DeepStack（基线） | 74.7 |
| **+ DeepStack** | **76.0（+1.3）** |

收益集中在 **InfoVQA、DocVQA 等细粒度任务**——正是"浅层细节特征注入"的直接受益者。

## 七、文本时间戳：为什么放弃时间 id

### 7.1 Qwen2.5-VL 时间 id 的两个问题

Qwen2.5-VL 的绝对时间对齐（时间 id = 真实时间戳）存在：

1. **过长且稀疏的时间 id**：视频越长时间 id 数值越大（30 分钟视频 2 FPS ≈ 3600 个 id，更长视频上万），超出训练分布且分布稀疏，**损害长时序建模**；
2. **数据构造昂贵**：需要在各种 FPS 下均匀采样训练数据才能让模型学会时间流速，成本高。

### 7.2 解法：显式文本时间戳 token

Qwen3-VL 改为**在每个视频时间片段前插入显式的文本时间戳 token**：

```text
视频 → 抽帧 → 片段切分
    → 片段 1: <0.0 seconds> [视觉 token ...]
    → 片段 2: <3.0 seconds> [视觉 token ...]
    → 片段 3: <6.5 seconds> [视觉 token ...]
```

| 设计 | 值 |
|------|-----|
| 时间戳形式 | 文本 token，如 `<3.0 seconds>` |
| 训练格式 | 同时使用**秒**与 **HMS**（时:分:秒）两种格式 |
| 作用机制 | 模型直接"读"到时间文本，而不是从位置编码"猜"间隔 |

### 7.3 为什么"读时间"比"猜时间"好

| 维度 | 时间 id（2.5-VL） | 文本时间戳（3-VL） |
|------|-------------------|-------------------|
| 时间信息载体 | 旋转位置数值 | **文本 token 内容** |
| 长视频 | id 过大稀疏，退化 | 文本值域无上限，稳定 |
| 训练数据 | 需各 FPS 均匀采样（昂贵） | 无需特殊采样，**训练更省** |
| 精度 | 秒级（hmsf） | 秒级 + HMS |
| 代价 | — | 上下文长度小幅增加 |

**代价**：每个时间片段多几个文本 token，上下文略有增加——换来的是视频定位/密集字幕更准、长视频更稳、训练更省。

## 八、双思维模式：Thinking / Non-Thinking

### 8.1 两种模式

| 模式 | 版本 | 行为 | 输出 |
|------|------|------|------|
| 非思维 | Instruct | 直接作答 | 简洁答案 |
| 思维 | Thinking | 先生成**长思维链（CoT）**再作答 | 推理过程 + 答案 |

用户按场景切换：日常对话用 Instruct，复杂推理用 Thinking。

### 8.2 RL 强化推理

Thinking 版本的能力来自**后训练强化学习（RL）**：

- 长 CoT SFT 冷启动（12M+ 合成思维链样本）→ 蒸馏 → RL 三个阶段（见第十节）；
- RL 的奖励包含**答案正确率奖励**与**可调思维预算**（控制 CoT 长度）；
- 训练出的思维模式是"深思"而非"空想"——推理链受正确率约束。

### 8.3 部署延迟影响

| 影响点 | 说明 |
|--------|------|
| 延迟 | Thinking 模式生成 CoT，**token 数成倍增加**，首字延迟与总延迟显著上升 |
| 吞吐 | 长输出占用解码带宽，并发吞吐下降 |
| 权衡 | 简单任务用 Instruct（低延迟），难题用 Thinking（高质量） |
| 预算控制 | 可调思维预算限制最大 CoT 长度，延迟可控 |

### 8.4 与 MoE 的叠加效果

- 30B-A3B 激活小 → 单 token 解码快 → **Thinking 模式的超长输出也负担得起**；
- 235B-A22B → 权重多、知识广 → 深思质量上限最高；
- 双思维 × MoE 的组合让"深度 × 速度"可同时调节。

## 九、长上下文：256K 原生，1M 可扩

### 9.1 数值一览

| 能力 | 数值 |
|------|------|
| 原生训练上下文 | **256K**（S3 阶段序列长度 262144） |
| 视频理解 | 30 分钟视频 needle-in-a-haystack **100%**（256K 内） |
| 1M 外推 | **YaRN** 扩展到 1M（约 2 小时视频），准确率 **99.5%** |
| 纯文本 | 多项文本 benchmark **超过同规模纯文本底座**（能力不退化） |

### 9.2 256K 怎么来的

```text
S1（8192）→ S2（32768）→ S3（262144）
           多模态预训练    超长上下文适配（100B token）
```

逐级拉长序列，每级在更长上下文中继续训练，最终原生支持 262144 序列。

### 9.3 1M 怎么扩的

- 原生 256K 之后用 **YaRN**（旋转位置外推）扩展到 1M；
- Interleaved-MRoPE 的收益在此体现：**位置 id 增长更慢，1M 扩展只需 factor 2~3（标准方案要 4）**；
- 1M ≈ 2 小时视频的 token 规模，needle 检索准确率 99.5%。

### 9.4 长视频 needle 测试的意义

30 分钟视频 needle-in-a-haystack 100%：在 256K 上下文中随机埋入细节信息（如"第 X 秒出现某物体"），模型能精确找回——这是长视频问答、视频检索的技术底气，也验证了文本时间戳 + Interleaved-MRoPE 的组合在超长序列下不失忆。

## 十、训练流水线：4 阶段预训练 + 3 阶段后训练

### 10.1 四阶段预训练（S0~S3）

| 阶段 | 目标 | 训练参数 | token 预算 | 序列长度 |
|------|------|---------|-----------|---------|
| **S0** | 视觉-语言对齐 | **仅 MLP merger**（ViT 与 LLM **冻结**） | 67B | 8192 |
| **S1** | 多模态预训练 | 全部 | ~1T | 8192 |
| **S2** | 长上下文预训练 | 全部 | ~1T | 32768 |
| **S3** | 超长上下文适配 | 全部 | 100B | 262144 |

要点：

1. **S0 只训 merger**：ViT 与 LLM 完全冻结，先把"视觉特征 → LLM 表示"的连接器对齐（67B token），再解冻全量——与 Qwen2.5-VL"阶段 1 仅 ViT"的思路互补（一个先训连接器、一个先训视觉塔）；
2. **S1/S2 各约 1T token**：全部参数解冻，先普通序列再拉长序列；
3. **S3 用 100B token 做 262144 超长适配**：专门的超长上下文数据（长视频、长文档）。

### 10.2 后训练三阶段

| 阶段 | 内容 |
|------|------|
| (i) **长 CoT SFT** | **12M+ 合成思维链样本**冷启动（让模型学会"先想后答"） |
| (ii) **知识蒸馏** | 强教师模型（更大/更优模型）蒸馏 |
| (iii) **强化学习 RL** | 含**答案正确率奖励**、**可调思维预算** |

后训练直接从长思维链 SFT 起步（而不是普通 SFT）——双思维模式（尤其 Thinking）的能力主要在这一阶段塑造。

### 10.3 平方根归一化损失

Qwen3-VL 把逐 token 的交叉熵损失改为**平方根归一化**：

$$\mathcal{L} \propto -\frac{\log p}{\sqrt{N}}$$

其中 $p$ 为该 token 的预测概率，$N$ 为该样本的 token 总数（序列长度）。

**动机**：一个样本的损失是逐 token 求和，**长样本（如长视频、长文档）天然贡献更多梯度**，会压过短样本（如纯文本对话）。除以 $\sqrt{N}$ 后：

- 长样本的梯度贡献被**归一化**，不再天然占优；
- 文本与多模态 token 的梯度贡献更平衡；
- 训练目标从"总损失最小"变为"**平均每 token 损失（方差抑制）最小**"。

## 十二、高频面试问答

**Q1：Qwen3-VL-30B-A3B 部署时到底要多少显存？**
权重显存按总参数算：30B × 2 字节（BF16）≈ 60GB，与 30B 密集模型同量级；单 token 计算量按激活参数算 ≈ 3B 级。即"算力便宜、显存不便宜"——这是 MoE 部署的核心认知。

**Q2：Interleaved-MRoPE 解决了什么问题？**
Qwen2 分块分配（[16,24,24]）让时间轴独占低频段、h/w 轴只有中频段，频率覆盖不均，长视频时序建模退化。交错分配（`mrope_interleaved: true`，[24,20,20]）让每条轴都覆盖低中高频带，长时序改善，且位置 id 增长更慢——1M 扩展只需 YaRN factor 2~3（标准方案 4）。

**Q3：DeepStack 是什么？为什么不增加序列长度？**
从 ViT 第 8/16/24 层抽取多级特征，经专用 merger 投影后**直接加到 LLM 前 3 层对应位置的 hidden state**（残差相加）。不是多尺度输入拼接，不新增 token、不涨上下文。浅层保细节（纹理/小字）、深层保语义，InfoVQA/DocVQA 受益明显，消融 AVG 74.7 → 76.0。

**Q4：为什么 Qwen3-VL 放弃时间 id、改用文本时间戳？**
时间 id 两个问题：① 长视频产生过大且稀疏的时间 id，损害长时序；② 需在各 FPS 下均匀采样训练数据，构造昂贵。改为在视频片段前插入 `<3.0 seconds>` 文本 token（训练同时用秒与 HMS 格式），模型直接"读时间"，长视频与定位更稳、训练更省，代价仅是上下文略增。

**Q5：Thinking 和 Instruct 版本是什么关系？**
同一权重架构的两个推理模式（对应 Qwen3 LLM 双模式）。Instruct 直接作答（低延迟）；Thinking 输出长思维链再作答（高质量），由长 CoT SFT + 蒸馏 + RL 训练而来，RL 含答案正确率奖励与可调思维预算。部署时按场景切换。

**Q6：Qwen3-VL 的视觉塔是 6B 吗？**
不是。官方技术报告与开源 config 均显示：视觉塔基于 SigLIP-2 架构（默认 SO-400M 级约 4 亿参数，patch 16），小模型用 300M 级。真正的规模增长在 LLM（MoE 235B-A22B）与训练数据（约 1T×2 阶段）。视觉塔无需更大：瓶颈在 LLM 跨模态推理，400M + DeepStack 已覆盖细粒度需求。

**Q7：32× 像素压缩怎么算出来的？**
patch 16 × 空间合并 2 × patch 16 × 时域合并 2 = 1024 像素/视觉 token，即每个 token 覆盖 32×32×2 的像素-时间块（32× 压缩）。相比 Qwen2.5-VL（patch 14、784 像素/token）单 token 覆盖面积更大，视频侧还多了 2× 时域压缩。

**Q8：256K 原生上下文和 1M 扩展是什么关系？**
256K 是 S3 阶段（262144 序列长度、100B token）训练出来的原生能力；1M 是训练后用 YaRN 旋转位置外推得到的扩展能力（约 2 小时视频，needle 准确率 99.5%）。Interleaved-MRoPE 让 1M 只需 factor 2~3 缩放。

**Q9：训练流水线分哪几个阶段？**
预训练四阶段：S0 仅训 MLP merger（ViT/LLM 冻结，67B token，8192）→ S1 全参数（约 1T，8192）→ S2 全参数（约 1T，32768）→ S3 全参数（100B，262144）。后训练三阶段：长 CoT SFT（12M+ 合成样本）→ 知识蒸馏（强教师）→ RL（答案正确率奖励 + 思维预算）。损失用平方根归一化：$\mathcal{L} \propto -\log p / \sqrt{N}$。

**Q10：Qwen3-VL 的主要局限？**
高分辨率显存压力（token 峰值 16384 × 256K 上下文）、训练成本高（约 2T+ token 多阶段）、幻觉与"首尾帧效应"、Thinking 模式延迟成本高需预算控制。

## 十三、常见误区

**误区 1：Qwen3-VL 的视觉塔是 6B 参数。**
错。官方报告与 config 均为 **SigLIP-2 架构约 400M**（SO-400M 级，patch 16）。规模增长在 LLM（MoE 235B）与训练数据，不在视觉塔。

**误区 2：MoE 模型（30B-A3B）部署很便宜。**
不准确。算力便宜（激活 3B），但**权重显存全量驻留**（30B ≈ 60GB）。便宜的是推理计算，不是显存。

**误区 3：Thinking 版本就是"多生成点文字"。**
不是。Thinking 由**长 CoT SFT + 蒸馏 + RL（答案正确率奖励）**专门训练，思维链是"深思"的产物而非堆字数；且可调思维预算控制长度。简单任务用 Thinking 反而浪费延迟。

**误区 4：DeepStack = 多尺度输入拼接 / 增加视觉 token。**
错。DeepStack 是**从 ViT 中间层抽特征残差注入 LLM 前 3 层**，序列长度完全不变；它受同名技术启发但实现不同（不堆多尺度输入）。

**误区 5：文本时间戳 = 把时间 id 换成文本，没区别。**
区别在载体与训练：时间 id 靠位置数值"猜间隔"（长视频过大稀疏）；文本时间戳让模型**直接读时间文本**，值域无上限、无需各 FPS 均匀采样数据（训练更省），代价仅是上下文小幅增加。

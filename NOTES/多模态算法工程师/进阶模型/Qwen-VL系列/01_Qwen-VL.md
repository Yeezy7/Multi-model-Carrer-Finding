# Qwen-VL 第一代（2023）：冻结视觉塔 + 重采样器压缩 + LLM 生成

> 本笔记是 Qwen-VL 系列的第一篇，聚焦第一代 Qwen-VL（2023.08，论文 2308.12966）。它是整个系列的"范式验证者"：**冻结视觉塔 + 重采样器压缩 + LLM 生成**。面试被问"第一代 VLM 怎么搭""resampler 是什么""位置编码怎么分层"时，本文是完整答案。第二代 Qwen2-VL 见本目录 `02_Qwen2-VL.md`。

---

## 一、一句话解释

> **Qwen-VL = 把 OpenCLIP 预训练的 ViT-bigG（1.9B）当"眼睛"、单层 cross-attention 重采样器当"翻译官"，把任意数量的视觉 patch 压缩成固定 256 个 token，喂给 Qwen-7B LLM 做统一自回归生成的视觉语言模型。**

三个关键词记住这一代：

1. **冻结视觉塔**：视觉编码器几乎不训练，直接复用 OpenCLIP 的 ViT-bigG——证明"不用重新训视觉塔也能做出能看图、能定位、能读文字的 VLM"；
2. **重采样器压缩**：位置感知 VL Adapter（Re-Attention）用 256 个可学习 query 把 256/1024 个 patch token 重排成固定 256 个视觉 token；
3. **LLM 生成**：视觉 token 作为"特殊单词"插进文本序列，由 Qwen-7B 做统一的 next-token 预测，用语言完成对话、定位、OCR。

**一句话定位**：第一代解决了"有视觉能力"，代价是分辨率固定 448、token 固定 256、没有时间建模——这三个短板正是第二代 Qwen2-VL 要解决的。

## 二、背景与动机：当时 VLM 的两条路

### 2.1 时代背景（2023 年）

2023 年前后的视觉语言模型大致分成两条技术路线：

| 路线 | 代表 | 做法 | 优点 | 缺点 |
|------|------|------|------|------|
| 双塔对比（dual-tower contrastive） | CLIP、SigLIP、BLIP | 图塔 + 文塔分别编码，对齐到同一向量空间 | 检索/分类强、训练稳定 | 不能生成文本，只有"匹配度" |
| 生成式（generative） | LLaVA、BLIP-2、Qwen-VL | 图像特征接入 LLM，统一 next-token 生成 | 对话、定位、OCR 通用 | 桥接设计复杂、视觉信息易丢失 |

Qwen-VL 选的是**第三条细化路线**：在"生成式"大框架内，采取 **"冻结视觉塔 + 轻量桥接"** 的子策略。

### 2.2 为什么选"冻结视觉塔 + 轻量桥接"

| 方案 | 训练成本 | 效果上限 | Qwen-VL 的选择 |
|------|---------|---------|---------------|
| 视觉塔 + LLM 全量从头训练 | 极高 | 最高 | ✗ |
| 视觉塔与 LLM 同时全量微调 | 高 | 高（但易过拟合、不稳定） | ✗（阶段 2 短暂全解冻） |
| **冻结视觉塔 + 训桥接层 + LLM** | 低 | 高 | ✓ 核心策略 |

三点理由：

1. **视觉塔已被 OpenCLIP 大规模预训练**（15 亿+图文对），通用视觉特征已经很好，重新训练边际收益低；
2. **LLM 是语言底座**，冻结它可以保住语言能力不退化；
3. **瓶颈在"桥"**：图像特征怎么变成 LLM 能读的 token、怎么保住空间位置——这才是需要专门训练的部分。

> **记忆点**：第一代的范式是"冻结的眼睛 + 训练的手（Adapter）+ 借用的嘴（LLM）"。这套范式后来被 BLIP-2、MiniCPM-V 等大量沿用。

### 2.3 与同时期桥接方案的对比

同一时期（2023）的生成式 VLM 在"视觉 → LLM"的桥接上有三种主流做法，Qwen-VL 属于其中一种：

| 桥接方案 | 代表 | 做法 | 压缩能力 | 位置信息处理 |
|---------|------|------|---------|-------------|
| MLP 投影 | LLaVA | patch token 逐个过一层 MLP 进 LLM | 无压缩（token 数不变） | 依赖 ViT 自带 PE |
| Q-Former | BLIP-2 | 少量 query + 多层 cross-attention | 强压缩（32 query） | 学习式，无显式位置注入 |
| **单层重采样器** | **Qwen-VL** | 256 query + 单层 cross-attention | 固定 256 | **显式 2D 位置注入 Q-K 对** |

三个方案的取舍：

- LLaVA 简单但 token 贵（576 个固定 token），且位置信息只依赖 ViT；
- BLIP-2 压缩狠但 query 数量少（32），细节丢失严重，位置信息靠"学"不靠"编"；
- **Qwen-VL 取中间值**：256 个 query 在"信息量"与"序列长度"之间平衡，并用**显式位置注入**保证压缩不掉位置——这是它在 grounding 任务上能赢的关键。

## 三、架构总览：三组件

### 3.1 三组件参数表

总参数量 9.6B：

| 组件 | 参数量 | 初始化 | 说明 |
|------|--------|--------|------|
| LLM | 7.7B | Qwen-7B | 语言底座，中英双语 |
| 视觉编码器 | 1.9B | OpenCLIP ViT-bigG | patch 14，阶段 1/2 训练、阶段 3 冻结 |
| 位置感知 VL Adapter | 0.08B | 随机初始化 | 单层 cross-attention 重采样器（Re-Attention） |

### 3.2 数据流 ASCII 图

```text
图像 (224/448²)
    │
    ▼
ViT-bigG (patch 14, 1.9B) ──> 256 / 1024 个 patch token
    │
    ▼
位置感知 VL Adapter（单层 Cross-Attention，256 个可学习 query）
★ 2D 绝对位置编码注入 Q-K 对（本模型最大创新）
    │
    ▼
固定 256 个视觉 token（与输入分辨率无关）
    │
    ▼
Qwen-7B LLM（文本侧 1D RoPE）统一 next-token 生成
```

### 3.3 三个组件的分工

- **ViT-bigG**：只做"像素 → 特征"，不含任何语言信息；
- **VL Adapter**：把可变数量的 patch token 压成固定 256 个，同时保住空间位置——"翻译官 + 位置保险丝"；
- **LLM**：把视觉 token 当"特殊单词"接进文本序列，做统一的 next-token 预测。

## 四、组件详解（重点）

### 4.1 组件一：视觉编码器 ViT-bigG（OpenCLIP 预训练）

| 属性 | 值 |
|------|----|
| 出处 | OpenCLIP 预训练的 ViT-bigG |
| 参数量 | 1.9B（远超 Qwen2-VL 自研的 675M） |
| Patch | 14×14 |
| 输入分辨率 | 阶段 1 用 224×224；阶段 2/3 用 448×448 |
| Patch 数量 | 224 → $16\times16=256$ 个；448 → $32\times32=1024$ 个 |
| 位置编码 | **可学习绝对位置编码**（OpenCLIP 自带，448 时按 224 的权重双线性插值扩展） |
| 冻结策略 | 阶段 1 训练、阶段 2 训练（低学习率）、阶段 3 冻结 |

**Patch 数量怎么算**：patch 大小为 14，所以

$$N_{\text{patch}} = \left(\frac{224}{14}\right)^2 = 16^2 = 256 \qquad N_{\text{patch}} = \left(\frac{448}{14}\right)^2 = 32^2 = 1024$$

> **数字澄清（面试易错，务必记住）**：网上流传"448 个 token 压到 256 个"是**错误说法**——**448 是分辨率（像素）**不是 token 数。正确事实：448×448 输入产生 **1024 个 patch token**，重采样后压到 256 个（**4 倍压缩**）；224×224 输入产生 256 个 patch，重采样后仍是 256 个（不压缩，只重排列信息）。

### 4.2 组件二：位置感知 VL Adapter（Re-Attention 重采样器）

**为什么需要重采样**：patch token 数量随分辨率变化（256 或 1024），而 LLM 的序列位置有限、batch 内还需要统一形状。直接全量喂 LLM 序列不可控，所以必须压到**固定长度**。

**结构**：单层 cross-attention，用 256 个可学习 query 从图像 patch 中抽取信息：

$$\text{Attn}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d}}\right) V$$

- $Q \in \mathbb{R}^{256 \times d}$：256 个**可学习 query 向量**（每个 query 相当于"我要从图像里提取哪类信息的模板"）；
- $K, V \in \mathbb{R}^{N \times d}$：来自 ViT 的图像 patch 特征（$N=256$ 或 $1024$）；
- 输出恒为 256 个 token，**与输入分辨率无关**——这是"固定 256 token"的来源。

**为什么固定 256**：

| 理由 | 说明 |
|------|------|
| 序列可控 | LLM 上下文有限，视觉 token 不能无限膨胀 |
| 批内统一 | 不同分辨率图片输出相同长度，batch 拼装方便 |
| 信息压缩 | 256 个 query 相当于 256 个"信息抽取模板"，够覆盖一图的主要语义 |

**为什么叫 "Re-Attention"**：它本质是"再注意力"——先让 ViT 做过自注意力，再用一层跨注意力把结果**重新组织**成固定数量、保留位置的 token。命名强调"又一次注意力"而非"新的编码器"。

**局限预告**：固定 256 意味着 448² 图像（1024 patch）被压缩 4 倍，细节（尤其是小字）会丢——这是第二代改"动态 token 数"的直接动机。

### 4.3 组件三：LLM 侧接收视觉 token

Qwen-7B 本身不做任何视觉改造，它看到的输入是：

```text
<|im_start|>user
<img> [256 个视觉 token] </img> 这张图里有什么？
<|im_end|>
<|im_start|>assistant
图里有一只戴红帽子的猫。<|im_end|>
```

- 视觉 token 与文本 token 走**同一套 embedding + 同一套 transformer**；
- LLM 不需要知道"token 来自图像还是文字"，只做 next-token 预测；
- 损失只在文本 token 上计算，视觉 token 无监督目标——这是 VLM 训练的通用约定。

### 4.4 为什么选 OpenCLIP 的 ViT-bigG

| 考量 | 说明 |
|------|------|
| 预训练质量 | OpenCLIP 用大规模公开图文对训练，ViT-bigG（giant）是其中最大规格之一 |
| 无需重新训练 | 1.9B 的视觉塔从头训练成本极高，复用即得强视觉特征 |
| patch 14 的细粒度 | patch 越小，单位图像上的 token 越多，细节保留越好（也是后面"448 才有 1024 patch"的原因） |
| 代价 | 1.9B 参数冻结为主，视觉表示与 LLM 的对齐受限——第二代换 675M 自研 ViT 并全程可训 |

## 五、位置编码三层体系（本篇重点，最详细）

> Qwen-VL 里位置信息**分三层**处理，每一层解决不同问题。面试讲位置编码，把这三层讲清楚就赢了——这是本模型最容易被一笔带过、面试却最爱深挖的地方。

```text
第一层（ViT 内部）：可学习绝对位置编码（2D 网格位置）
    ↓ 作用：让 patch token 之间能区分"上/下/左/右"
第二层（VL Adapter 内）：2D 绝对位置编码注入 Q-K 对 ★ 本模型最大创新
    ↓ 作用：压缩到 256 token 时不丢空间布局 → 定位能力来源
第三层（LLM 内部）：文本 1D RoPE，视觉 token 只占普通序列位置
    ↓ 作用：保证视觉 token 与文本 token 能混在一起生成
```

### 5.1 第一层：ViT 内部的可学习绝对位置编码

ViT-bigG 是 OpenCLIP 预训练的，自带**可学习绝对位置编码**：每个 patch 网格位置一个可学习向量。

- 224 输入时：$16\times16=256$ 个位置向量；
- 448 输入时：按 224 的位置编码**双线性插值**成 $32\times32=1024$ 个（因为 patch 数变多，原来的位置向量不够用，插值扩展）。

作用与局限：

| 维度 | 说明 |
|------|------|
| 作用 | patch 与 patch 之间的自注意力能感知"谁在谁旁边"，图内空间感正确 |
| 局限 | 它是**图像内部的编码**，信息出了 ViT 就不管用——所以第二层必须接力 |

### 5.2 第二层：2D 绝对位置编码注入 Q-K 对（核心设计）

#### 5.2.1 问题：压缩会抹平空间信息

cross-attention 压缩的本质是"加权求和"：

$$o = \sum_i \alpha_i v_i$$

如果 $K$ 不带位置信息，query 只能按"内容像不像"去加权——它无法区分"左上角的猫"和"右下角的猫"，**压缩后空间信息会被加权求和抹平**。那模型就只知道"有只猫"，不知道"猫在哪"，更无法画框。

#### 5.2.2 解法：把 2D 绝对位置编码同时加到 Q 和 K 上

论文原话：*"we inject the 2D position information into the query-key pairs, avoiding the loss of spatial position information during the compression"*。

注意措辞：是**同时加到 Q 和 K 上**（所以叫注入 "query-key pair"），不是只加一边，更不是"加到 pair 之外"：

$$\tilde{Q} = Q + \text{PE}_{2D}, \qquad \tilde{K} = K + \text{PE}_{2D}$$

注意力分数展开：

$$\alpha_{q,k} = \text{softmax}\left(\frac{\tilde{Q}\tilde{K}^\top}{\sqrt{d}}\right) = \text{softmax}\left(\frac{QK^\top + Q\cdot\text{PE}^\top + \text{PE}\cdot K^\top + \text{PE}\cdot\text{PE}^\top}{\sqrt{d}}\right)$$

展开后的四项各有语义：

| 项 | 语义 |
|----|------|
| $QK^\top$ | 内容相似度（纯内容匹配） |
| $Q\cdot\text{PE}^\top$ | **query 与"某个位置的 patch"的匹配度**——query 可以问"这个位置的 patch 里有什么" |
| $\text{PE}\cdot K^\top$ | 同理，位置与内容的匹配度 |
| $\text{PE}\cdot\text{PE}^\top$ | 位置与位置的交互（相对空间距离） |

后三项都与位置有关，也就是说**注意力权重里隐式编码了空间关系**，256 个压缩 token 因此保留了布局信息。

#### 5.2.3 直觉比喻

- 没有位置编码的压缩 = "把一桌菜打成糊装进 256 个罐子，吃的时候不知道哪罐是哪个位置的菜"；
- 加了 Q-K 位置注入 = "每个罐子都带坐标标签，还能记住菜原本摆在桌子的哪个区域"。

#### 5.2.4 数值小例：注入前后对比

假设只有 2 个 query（q₁ 代表"找猫"、q₂ 代表"找车"）和 4 个 patch（左上角是猫、右下角是车，中间是草地），简化 $d=1$：

| 配置 | 注意力分布 | 结果 |
|------|-----------|------|
| 不加 PE | q₁ 对 4 个 patch 的权重接近均匀（内容都"不像猫"） | 压缩后"猫"信号被草地稀释 |
| 加 PE 后 | q₁ 对"左上角位置"的 patch 权重高（$Q\cdot\text{PE}^\top$ 把"找猫"和"左上角"关联起来） | 压缩 token 里保留"左上角有猫" |

数值上：若 $\text{PE}_{\text{左上}} \cdot \text{PE}_{\text{右下}} < \text{PE}_{\text{左上}} \cdot \text{PE}_{\text{左上}}$，位置项会自动让"左上角 patch 与左上角 query"的分数更高——**位置相似性进入 softmax 分子**，空间布局得以保留。这就是"为什么压缩后还能定位"的微观机制。

#### 5.2.5 为什么不能直接复用第一层（ViT 的 PE）

| 方案 | 问题 |
|------|------|
| 直接用 ViT 的输出特征（含其 PE） | 跨注意力是对内容加权求和，ViT 的 PE 藏在特征里，会被 $\sum \alpha_i v_i$ 的加和"平均掉"，位置差异无法影响注意力权重 |
| 只把 PE 加在 V 上 | V 侧位置只影响"输出的内容值"，不影响"选哪个 patch"（注意力权重），依然选错 |
| **同时加在 Q 和 K 上** | 位置直接进入注意力分数的计算，影响"选哪个"，这才是压缩保位的正确位置 |

一句话：**位置信息必须进入"注意力选择"这一步，而不是只进入"输出内容"这一步**——这就是注入 Q-K 对而不是注入 V 的数学理由。

#### 5.2.4 这是 grounding 的根源

**Qwen-VL 能做视觉定位（referring / bounding box）的根基就在这一层**——它也是 Adapter 被称为"位置感知（position-aware）"的原因。如果第二层去掉，模型能答"图里有猫"但画不出框。

### 5.3 第三层：LLM 内的 1D RoPE（视觉 token 只占序列位置）

压缩后的 256 个视觉 token 被 `<img>`/`</img>` 包起来、插进文本序列，在 LLM 里和其他文本 token 一样**只按序列顺序编号**（Qwen-7B 的 1D RoPE）：

```text
序列:  [<img> | v_1 | v_2 | ... | v_256 | </img> | 这 | 张 | 图 | 里 | 有 | 什 | 么 | ？]
RoPE:    0     1     2     ...   256    257    258   259  ...
```

| 维度 | 说明 |
|------|------|
| 作用 | 视觉 token 和文本 token 共享同一套位置编号，能无缝混合做自回归生成 |
| 局限 | **序列位置 ≠ 空间位置**。第一层/第二层的位置信息在进入 LLM 前已经"浓缩"进 token 的内容里了，LLM 侧没有显式的 2D/3D 坐标概念 |
| 另一个局限 | 只有一个序列轴，**没有时间轴**——视频帧之间没有位置区分（见 5.4 表最后一行） |

### 5.4 三层位置编码的后果总结

| 能力 | 由哪层提供 | 表现 |
|------|-----------|------|
| 图内空间感（patch 间相对位置） | 第一层（ViT 绝对 PE） | 视觉塔特征正确 |
| 压缩后仍能定位（画框、指代） | 第二层（Q-K 位置注入） | grounding 能力 |
| 图文混合生成 | 第三层（1D RoPE 统一编号） | 对话/生成正常 |
| 视频时间先后 | **三层都没有** | 时间感知弱（视频只能拼成复合大图） |

> **预告对比**：Qwen-VL 的三层方案是"各管一段"；Qwen2-VL 用 **M-RoPE** 把时间/高/宽三维位置直接编码进 LLM 的旋转位置里，视觉塔内改 2D-RoPE——**位置编码从"分层接力"变成"统一 3D"**，这是两代最本质的架构差异之一。

## 六、三阶段训练

| 阶段 | 数据 | 分辨率 | 冻结策略 |
|------|------|--------|---------|
| 阶段 1 预训练 | 清洗后 14 亿图文对（LAION 等，77.3% 英文 / 22.7% 中文） | 224×224 | **冻结 LLM**，训练 ViT + Adapter（5 万步） |
| 阶段 2 多任务预训练 | 细粒度标注：字幕、VQA、定位（image-caption-box 三元组）、OCR、交错图文 | 448×448 | **全部解冻**（ViT 低学习率） |
| 阶段 3 指令微调 | 350K 指令数据（Chat 格式） | 448×448 | **冻结 ViT**，训练 LLM + Adapter |

### 6.1 冻结策略的三点讲究

1. **阶段 1 冻结 LLM**：先把"图像 → 视觉 token"这条路打通（否则 LLM 收到的视觉 token 是噪音，梯度互相干扰）；
2. **阶段 2 全解冻**：多任务数据（尤其定位三元组）让视觉塔与 LLM 充分对齐——这也是位置感知真正被训出来的阶段；
3. **阶段 3 冻结 ViT**：指令数据量小（350K），冻结视觉塔防止特征漂移与过拟合。

### 6.2 为什么要阶段化

| 问题 | 阶段化的解法 |
|------|-------------|
| 视觉 token 一开始是噪音 | 阶段 1 只对齐视觉侧，LLM 冻结 |
| 桥接层能力不足 | 阶段 2 多任务数据全量解锁 |
| 指令数据少、容易过拟合 | 阶段 3 冻结 ViT，只微调 LLM + Adapter |

### 6.3 每个阶段在"学什么"

| 阶段 | 模型在学什么 | 验证方式 |
|------|-------------|---------|
| 阶段 1 | ViT 输出 → 固定 256 token 的压缩映射（重采样器的"翻译"能力） | 图文对齐程度（loss 下降、简单 caption） |
| 阶段 2 | 细粒度对应关系：框 ↔ 对象、文字 ↔ 位置（位置感知真正被训出来的阶段） | grounding、OCR 能力出现 |
| 阶段 3 | 对话格式与指令服从（Chat 化） | 指令跟随、多轮对话质量 |

### 6.4 训练细节补充

- 阶段 2 的 image-caption-box 三元组：一条数据 = 图片 + 描述文本 + 图中对象的位置框，模型被训练成"看到 `<ref>` 对象名 → 输出 `<box>` 坐标"；
- 中文占比约 22.7%，决定了 Qwen-VL 是当时少有的**中英双语 VLM**（多数同期模型以英文为主）；
- 全程只对文本 token 计算损失，视觉 token 是"条件输入"。

## 七、输入输出接口：为定位而生

### 7.1 特殊 token

| Token | 含义 |
|-------|------|
| `<img>` / `</img>` | 包裹视觉 token 序列 |
| `<box>` / `</box>` | 标记检测框 |
| `<ref>` / `</ref>` | 标记被指代的对象 |

### 7.2 坐标文本化

- 框坐标归一化到 $[0, 1000)$；
- 文本化为 `(x_tl, y_tl), (x_br, y_br)`（左上、右下角点）；
- 模型输出例如：`<box>(256,145),(672,512)</box>` 这样的字符串。

### 7.3 为什么用文本 token 表达坐标

**位置用文本 token 表达**：无需专门的坐标输出头，模型直接用 next-token 预测输出框坐标字符串——这是"**用语言完成定位**"的设计，Qwen2-VL 沿用至今（第二代换成了 JSON 风格的 `[x1,y1,x2,y2]`，但思想一致）。

### 7.4 输入输出示例

**指代定位（referring）**：

```text
用户: 图中戴红帽子的那只猫在哪？<ref>红帽猫</ref>
模型: 它在 <box>(256,145),(672,512)</box>
```

**检测（detection）**：

```text
用户: 找出图中所有的狗。
模型: 有两只：<box>(30,40),(200,210)</box> 和 <box>(500,300),(780,610)</box>
```

**坐标范围约定**：所有坐标在 $[0,1000)$ 区间内（左上角为原点，x 向右、y 向下），整数化后作为普通文本 token 输出。这个"千分制"约定让坐标与分辨率解耦——无论输入是 224 还是 448，输出坐标系一致。

### 7.5 交错图文输入

Qwen-VL 支持多张图与文本交错输入（interleaved input），处理规则：

1. 每张图独立编码成自己的 256 个视觉 token；
2. 各自的 token 序列按文中出现顺序插入，各自用 `<img>`/`</img>` 包裹；
3. 多图之间没有显式的"第几张图"位置编码——图与图的关系只能靠文本描述和序列顺序隐式表达（第二代 M-RoPE 用时间轴 id 显式解决了多图/视频的排序问题）。

## 八、能力与局限（为什么必须被第二代取代）

### 8.1 能力

| 能力 | 说明 |
|------|------|
| 图文对话 | 看图问答、描述、多轮对话 |
| 视觉定位 | referring / bounding box（ref/box），得益于第二层位置注入 |
| OCR 阅读 | 448² 下可读中等大小的文字 |
| 中英双语 | 语言底座 Qwen-7B 自带 |
| 交错图文输入 | 文本与多张图交错拼接输入 |

### 8.2 局限

1. **固定分辨率（224→448）**：448×448 对文档、小字 OCR 依然不够清晰；
2. **固定 256 token**：高分辨率图像信息被过度压缩（1024 patch → 256 token），细节丢失；
3. **没有时间维位置编码**（对应 5.3 的第三层缺陷）：视频只能抽帧后**拼成一张复合大图**输入（帧间无时间位置），模型感知不到"先后顺序"与"时间间隔"，跨帧推理、时间戳定位基本不可用；
4. **ViT 阶段 1/3 冻结**：视觉表示与 LLM 对齐不充分，可训练性低于 Qwen2-VL 的全参数方案。

| 局限 | 第二代 Qwen2-VL 的对策 |
|------|----------------------|
| 固定分辨率 | Naive Dynamic Resolution（任意分辨率） |
| 固定 256 token | 动态 token 数 $N = H'W'/784$（4~16384） |
| 无时间建模 | M-RoPE 三维位置 + 2fps 视频统一建模 |
| ViT 冻结 | 阶段 2 全解冻 + 自研 675M ViT 全程参与训练 |

## 九、高频面试问答

**Q1：Qwen-VL 的架构由哪几部分组成？**
三部分：OpenCLIP 预训练的 ViT-bigG 视觉编码器（1.9B，patch 14）+ 位置感知 VL Adapter（0.08B，单层 cross-attention 重采样器）+ Qwen-7B LLM（7.7B），总参 9.6B。

**Q2：重采样器是怎么工作的？为什么输出固定 256？**
单层 cross-attention：256 个可学习 query 作为 Q，ViT 输出的 256/1024 个 patch 特征作为 K/V，attention 输出恒为 256 个 token。固定 256 是为了序列可控、批内形状统一，同时 256 个 query 足够覆盖一图的主要语义。

**Q3：224 和 448 分辨率分别产生多少 patch token？压缩比是多少？**
224×224 → $(224/14)^2 = 256$ 个 patch，重采样后 256 个（不压缩）；448×448 → $(448/14)^2 = 1024$ 个 patch，重采样后 256 个（4 倍压缩）。注意 448 是分辨率不是 token 数。

**Q4：Qwen-VL 的位置编码有几层？分别是什么？**
三层：① ViT 内部可学习绝对 PE（图内空间感）；② VL Adapter 内把 2D 绝对 PE 同时注入 Q 和 K（压缩后仍能定位，grounding 的根源）；③ LLM 侧 1D RoPE（视觉 token 与文本 token 统一序列编号）。

**Q5：为什么把位置编码加到 Q 和 K 上而不是只加一边？**
展开注意力分数 $\tilde{Q}\tilde{K}^\top = QK^\top + Q\text{PE}^\top + \text{PE}K^\top + \text{PE}\text{PE}^\top$：加在 Q 上让 query 能"按位置提问"（$Q\text{PE}^\top$），加在 K 上让 patch 能被"按位置检索"（$\text{PE}K^\top$），再加位置间交互（$\text{PE}\text{PE}^\top$），空间关系才完整进入注意力权重。

**Q6：三阶段训练分别冻结什么？为什么？**
阶段 1 冻结 LLM（先打通视觉到 token 的路径，避免噪音干扰）；阶段 2 全部解冻（多任务数据对齐，位置感知在这阶段被训出来）；阶段 3 冻结 ViT（指令数据仅 350K，防止过拟合和特征漂移）。

**Q7：Qwen-VL 怎么用语言表达检测框？**
坐标归一化到 $[0,1000)$，文本化为 `(x_tl,y_tl),(x_br,y_br)` 字符串，用 `<box>`/`</box>` 标记，模型直接 next-token 生成，不需要专门的坐标输出头。

**Q8：Qwen-VL 的 OCR 能力为什么有限？**
固定 448×448 分辨率下小字模糊；且 1024 patch 被压到固定 256 token，文字细节在压缩中丢失。

**Q9：为什么视频理解基本不可用？**
三层位置编码都没有时间轴，视频只能抽帧拼成一张复合大图，帧间没有先后位置信息，模型感知不到时间顺序与间隔。

**Q10：Qwen-VL 最大的设计贡献是什么？**
范式验证：冻结视觉塔 + 轻量重采样桥接 + LLM 生成这条路可行，且 Adapter 的"2D 位置注入 Q-K 对"是空间信息不随压缩丢失的关键设计——它直接影响了后续所有"压缩型"桥接器（Q-Former、Perceiver 等）对位置信息的处理思路。

## 十、常见误区

**误区 1：Qwen-VL 的重采样器是"448 个 token 压成 256 个"。**
错。448 是**第二阶段的分辨率**。准确说法：448×448 时 ViT 输出 1024 个 patch（$(448/14)^2$），重采样器压缩到固定 256 个；224×224 时 256→256 不压缩。**448 是像素不是 token 数**。

**误区 2：Qwen-VL 的位置编码就是"文本的 1D RoPE"。**
不准确。Qwen-VL 是**三层位置编码体系**：ViT 内部可学习绝对 PE（图内空间感）+ VL Adapter 把 2D 绝对 PE 注入 Q-K 对（压缩后仍可定位，这是它叫"位置感知"的原因）+ LLM 侧 1D RoPE（图文混合生成）。三层缺一不可，真正被面试深挖的是第二层。

**误区 3："位置编码注入 query-key pair"是指加在注意力输出上 / 只加在 value 上。**
错。是**同时加到 Q 和 K 上**（所以叫 pair）：$\tilde{Q}=Q+\text{PE}_{2D}$、$\tilde{K}=K+\text{PE}_{2D}$，注意力分数里展开出 $Q\text{PE}^\top + \text{PE}K^\top + \text{PE}\text{PE}^\top$ 三个位置项，隐式编码空间关系，支撑 grounding。

**误区 4：固定 256 token 是优点，越多越好压缩没问题。**
固定 256 带来"信息瓶颈"：1024 patch 压到 256 个，小字、密集文字细节丢失（OCR 差）。第二代为此改成动态 token 数——压缩不是越多越好，要在信息量与算力之间权衡。

**误区 5：Qwen-VL 的视觉塔全程冻结。**
分阶段。阶段 1/2 训练（阶段 2 全解冻、ViT 低学习率），只有阶段 3 冻结 ViT——"冻结视觉塔"是整个范式的标签，但不是每一阶段都冻结。

# Qwen-VL 系列：视觉 Token 与位置编码专题

> 本笔记是 Qwen-VL 系列技术专题的第一篇，聚焦"图像如何变成 LLM 能读的 token 序列"与"位置信息如何在 3D 世界（时间×高×宽）里编码"两条主线。全篇纯理论，所有数字以《09_QwenVL.md》为基准：token 公式 $N=H'\cdot W'/784$、28 对齐单位、sub-image 上限 448²、`max_pixels = 16384×28×28`、M-RoPE 的 $(t,h,w)$ 与 `mrope_section=[16,24,24]`、16K 训练外推 80K 等。面试被问"视觉 token 怎么算""28 从哪来""M-RoPE 为什么能外推"时，本笔记是完整答案。

---

## 一、视觉 Token 是什么

### 1.1 一次关键转换：从连续像素到离散序列

LLM 的本质是一个**离散序列上的自回归模型**：输入是 token id 序列，输出逐 token 预测下一个 token。而图像是**二维连续信号**（$H \times W \times 3$ 的像素网格），两者形态完全不同：

| 维度 | 图像 | 文本 |
|------|------|------|
| 数据结构 | $H \times W \times 3$ 连续像素网格 | 离散 token id 序列 |
| 空间结构 | 2D 空间 + 通道 | 1D 时序 |
| 存在方式 | 像素"同时存在"（无先后） | 逐 token 依次出现 |
| 长度 | 由分辨率决定（可达百万像素） | 由语义决定（几百~几千） |

多模态模型要"看图说话"，就必须完成一次转换：**把图像编码成一条视觉 token 序列，与文本 token 拼接后统一喂给 LLM**。这条链路贯穿 Qwen-VL 四代架构，从未改变。

### 1.2 视觉 token 的精确定义

一个**视觉 token** = 进入 LLM 输入序列的、与文本 token 同维度同性质的"视觉单词"。它由 ViT 的 patch 特征经过**压缩（合并）与投影（MLP）**得到，进入 LLM 后参与与文本 token 完全相同的 QKV 计算、attention 与 next-token 预测。

**patch ≠ token**，这是最常见的概念混淆：

| | 图像 patch | 视觉 token |
|--|-----------|-----------|
| 来源 | 像素块（14×14 或 16×16） | patch 特征合并/投影后 |
| 维度 | ViT 隐藏维（1280 / 1152） | LLM 隐藏维（Qwen2-VL-7B 为 3584） |
| 数量 | 由像素÷patch 决定 | 由压缩策略决定 |
| 语义 | 局部像素块的浅层特征 | 与文本对齐的高层语义单元 |

### 1.3 为什么所有多模态模型都要走这条链路

1. **统一生成范式**：图文共享同一个自回归解码器，不需要专门的图像解码头（Qwen-VL 的定位输出也是文本化的 `<box>(256,145),(672,512)</box>`）；
2. **复用训练范式**：仍用 next-token prediction，且只对文本 token 计算 loss（Qwen 系预训练"只监督文本 token"）；
3. **成本可控**：token 数是序列长度、显存、算力的"计费单位"，模型设计者通过压缩策略直接决定成本——这正是三代压缩演进的意义。

## 二、图像到 token 的完整流程（七环节）

```text
原图 (H, W)
  ↓ ① 预处理：等比缩放 → 对齐 28 网格 → 超 448² 切 sub-image
  ↓ ② Patch 化：切成 14×14 / 16×16 的 patch
  ↓ ③ ViT 编码：逐 sub-image 过视觉塔（全局/窗口注意力）
  ↓ ④ 位置注入：ViT 内 2D 位置编码（绝对 PE / 2D-RoPE）
  ↓ ⑤ 压缩/合并：cross-attn 重采样 / 2×2 卷积+MLP / 动态 Merger / 32× 像素压缩
  ↓ ⑥ 投影：MLP 投影到 LLM 隐藏维
  ↓ ⑦ 拼接 LLM：替换 <|image_pad|> 占位符，<|vision_start|>/<|vision_end|> 包裹
  ↓ M-RoPE position id 分配 → LLM 前向
```

### 2.1 各环节可选方案与影响（总表）

| 环节 | 可选方案 | 代表模型 | 影响 |
|------|---------|---------|------|
| ① 预处理 | 固定分辨率 / 动态分辨率（缩放+28 对齐+切 sub-image）/ 原生分辨率 | Qwen-VL / Qwen2-VL / Qwen2.5-VL+ | 决定 token 数量、长宽比保真、小字清晰度 |
| ② Patch 化 | patch 14 / patch 16 | Qwen2 系 / Qwen3-VL | 决定单 token 覆盖的像素面积（配合合并器） |
| ③ ViT 编码 | 全局注意力 / 窗口注意力（8×8 patch，仅 4 层全局） | Qwen2-VL / Qwen2.5-VL | 高分辨率下计算复杂度 O(N²) vs O(N) |
| ④ 位置注入 | 可学习绝对 PE / 2D-RoPE / Q-K 位置注入 / M-RoPE | 四代各有分工 | 空间、时间感知能力 |
| ⑤ 压缩/合并 | cross-attn 重采样 / 2×2 卷积+MLP / 动态 Merger / 32× 像素压缩 | 四代主线 | token 数量与信息保真度（见第三节） |
| ⑥ 投影 | MLP 投影到 LLM 隐藏维 | 全部 | 维度对齐（1280 → 3584） |
| ⑦ 拼接 | 占位符替换 + 特殊 token 包裹 | 全部 | 序列结构、多图/视频编排 |

### 2.2 环节要点速览

- **① 预处理**：Qwen2-VL 的"Naive Dynamic Resolution"五步流程——等比缩放（$s=\min(1,\sqrt{\text{max\_pixels}/(H\cdot W)})$）→ 对齐 28 → 超 448² 切 sub-image → 逐块编码 → 行优先拼接。这是 token 数量的源头控制点。
- **② Patch 化**：patch 14 是 Qwen-VL 到 Qwen2.5-VL 的标配，Qwen3-VL 升到 16（配合 SigLIP-2 架构），是 32× 像素压缩的起点。
- **③ ViT 编码**：Qwen2-VL 自研 675M ViT（patch 14，全系列共享，不随 LLM 规模增长）；Qwen2.5-VL 改窗口注意力让高分辨率可行。
- **④ 位置注入**：三处注入点（ViT 内 / Q-K 对 / LLM 内），详见第六节。
- **⑤ 压缩/合并**：四代演进的绝对重点，详见第三节。
- **⑥ 投影**：把 ViT 的 1280 维特征映射到 LLM 隐藏维（Qwen2-VL-7B 为 3584），属于线性变换，本身不改变 token 数量。
- **⑦ 拼接**：Qwen 推理时用真实视觉 token 替换 `<|image_pad|>` 占位符，序列头尾加 `<|vision_start|>`/`<|vision_end|>`（Qwen3-VL 用 `<|image_pad|>` 计数占位）。

## 三、四代压缩方案对比（重点）

### 3.1 为什么必须压缩

1. **计算成本**：attention 是 O(n²)，KV cache 随 token 数线性增长，token 数直接决定显存与延迟（详见第四节）；
2. **邻域冗余**：相邻 patch 像素高度相似，2×2 合并几乎无损（参考论文：4× 压缩下信息几乎不丢）；
3. **信息密度不均**：简单图与复杂图所需 token 不同，固定预算要么浪费、要么不够。

四代压缩策略演进主线：

```text
cross-attn 重采样（固定 256）→ 2×2 卷积+MLP（固定 4×）→ 动态 Merger（预算 4~16384）→ 32× 像素压缩
```

### 3.2 第一代：Cross-Attention 重采样（Qwen-VL，固定 256）

**背景**：ViT-bigG（1.9B，patch 14）输出 patch 数随分辨率变化——224×224 时 256 个（$16^2$），448×448 时 1024 个（$32^2$）。而 LLM 序列需要统一形状，必须压到**固定长度**。

**结构**：单层 cross-attention（论文称 Re-Attention，"再注意力"），用 **256 个可学习 query** 从 patch 特征中抽取信息：

$$\text{Attn}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d}}\right) V$$

- $Q \in \mathbb{R}^{256 \times d}$：256 个可学习 query 向量；
- $K, V \in \mathbb{R}^{N \times d}$：ViT 输出的 patch 特征（$N=256$ 或 1024）；
- 输出**恒为 256 个 token**，与输入分辨率无关。

**Query 模板思想**：每个 query 相当于"我要从图像里提取哪类信息的模板"——query 1 可能偏向"主体物体"，query 2 偏向"文字区域"……256 个 query 覆盖 256 种信息偏好。这是"重采样"与"池化"的本质区别：**学习出来的模板去查询，而不是固定窗口做平均**。

**位置保持（本代核心设计）**：cross-attention 压缩本质是加权求和 $o=\sum_i \alpha_i v_i$，若不处理位置，加权后空间信息会被抹平（只知道"有只猫"，不知道"猫在哪"）。Qwen-VL 把 **2D 绝对位置编码同时注入 Q 和 K**：

$$\tilde{Q} = Q + \text{PE}_{2D}, \qquad \tilde{K} = K + \text{PE}_{2D}$$

展开注意力分数可见位置如何起作用：

$$\alpha_{q,k} = \text{softmax}\left(\frac{\tilde{Q}\tilde{K}^\top}{\sqrt{d}}\right) = \text{softmax}\left(\frac{QK^\top + Q\cdot\text{PE}^\top + \text{PE}\cdot K^\top + \text{PE}\cdot\text{PE}^\top}{\sqrt{d}}\right)$$

- $QK^\top$：内容相似度；
- $Q\cdot\text{PE}^\top$ 与 $\text{PE}\cdot K^\top$：query 与"某个位置的 patch"的匹配度；
- $\text{PE}\cdot\text{PE}^\top$：位置与位置的交互（相对空间距离）。

**数字澄清（面试易错）**："448 个 token 压到 256 个"是错误说法——448 是**分辨率**。正确事实：448×448 产生 1024 个 patch（$(448/14)^2$），重采样到 256 个（**4 倍压缩**）；224×224 产生 256 个 patch，重采样后仍是 256 个（**不压缩**，只重新组织信息）。

| 特性 | 值 |
|------|-----|
| 压缩机制 | 单层 cross-attention + 256 可学习 query |
| 压缩比 | 448² 时 4×（1024→256）；224² 时 1×（256→256） |
| 可控性 | 不可控（固定 256） |
| 位置保持 | 2D 绝对 PE 注入 Q-K 对 |
| 主要缺陷 | 固定分辨率 + 固定 token，高分辨率细节被过度压缩 |

### 3.3 第二代：2×2 卷积 + MLP（Qwen2-VL，固定 4×）

**流程**：ViT 输出 patch 特征（patch 14，每 token 1280 维）后做空间合并：

```text
ViT 输出:  H_p × W_p 个 patch token（patch 14，1280 维）
    ↓ 2×2 分组（等价 2×2 卷积，stride 2）
    每个 2×2 patch 特征拼接成 4×1280 维
    ↓ MLP 投影到 LLM 隐藏维（Qwen2-VL-7B 为 3584）
    得到 (H_p/2) × (W_p/2) 个视觉 token
```

**固定 4× 压缩**：2×2 → 1。一张 224×224 图：$16\times16=256$ 个 patch → **64 个 token**（加首尾特殊 token 共 66 个，论文原文数据）。

**28 对齐单位的来源**（面试高频）：

$$\underbrace{28}_{\text{对齐单位}} = \underbrace{14}_{\text{patch 边长}} \times \underbrace{2}_{\text{2×2 合并边长}}$$

合并后每个视觉 token 覆盖 $28\times28$ 像素。若只对齐 14，合并后可能出现"半格"（token 覆盖区域越界或不对齐），无法整数拼接。所以动态分辨率里缩放后的 $H', W'$ 必须都是 28 的倍数，token 数 = $\frac{H'}{28} \times \frac{W'}{28}$。

**为什么压了还是几乎无损**：4× 压缩 ≈ 4× 更少的前向计算与 KV cache，而 2×2 邻域信息高度冗余——相邻 patch 的 1280 维特征高度相似，合并丢掉的只是冗余。

| 特性 | 值 |
|------|-----|
| 压缩机制 | 2×2 分组（等价卷积）+ MLP |
| 压缩比 | 固定 4×（空间） |
| 可控性 | 像素预算（min/max_pixels），间接控制总 token |
| 28 对齐 | patch 14 × merge 2 = 28 |
| 主要缺陷 | 压缩比固定，简单图与复杂图无法差异化 |

### 3.4 第三代：动态 Merger（Qwen2.5-VL，预算 4~16384）

**结构**：延续 2×2 分组 + 2 层 MLP 的压缩范式（`2×2 邻域 concat → 2 层 MLP 投影`），但强调**动态性**：

- 默认单图 token 范围 **4 ~ 16384**（对应 `min_pixels = 4×28×28`，`max_pixels = 16384×28×28`）；
- 通过设置 `min_pixels` / `max_pixels` 或直接指定 `resized_height/width`（自动对齐 28），在**精度与成本之间任意调节** token 预算；
- 视频侧按总 token 预算动态调整帧分辨率。

**配套前提：Window Attention**。原生分辨率输入下，ViT 全局注意力 O(N²) 直接算不动。Qwen2.5-VL 把 32 层 ViT 中的 28 层换成窗口注意力（窗口 8×8 patch = 112×112 像素），仅第 {7,15,23,31} 层保留全局注意力，复杂度从 O(N²) 降为 O(N·w²)（线性于 patch 数）。

| 特性 | 值 |
|------|-----|
| 压缩机制 | 2×2 分组 + 2 层 MLP |
| 压缩比 | 4×（可配预算） |
| 可控性 | 像素预算 + 显式尺寸，任意调节 |
| 动态能力 | 单图 4~16384；视频帧分辨率随预算调整 |

### 3.5 第四代：32× 像素压缩（Qwen3-VL，patch 16 + temporal 2）

**结构升级**：

- 视觉塔基于 **SigLIP-2 架构**（官方默认 SO-400M 级，约 4 亿参数，patch 16）——注意：**Qwen3-VL 没有 6B 视觉塔**，这是社区流传的错误说法；
- `spatial_merge_size=2`（空间 2×2 合并）+ `temporal_patch_size=2`（时域 2 帧合并）；
- 每个视觉 token 覆盖：

$$16 \times 2 \times 16 \times 2 = 1024 \text{ 像素}$$

即 **32× 像素压缩**（patch 14 时代的 28×28=784 像素/token，Qwen3 升到 1024 像素/token）。

**预算设置**：官方处理器默认单图 token 预算 **256~1280**，视频 256~16384（含 2× 时域压缩）；图像与视频独立设置预算。

**信息损失的补偿**：32× 压缩比 4× 更有损，Qwen3-VL 用 **DeepStack** 补偿——从 ViT 第 8/16/24 层抽取多级特征，经专用 merger 投影后直接加到 LLM 前 1~3 层的 hidden state（残差相加，不增加序列长度）。浅层特征保细节（纹理/小字），深层特征保语义，消融 AVG 74.7 → 76.0。

| 特性 | 值 |
|------|-----|
| 压缩机制 | 2×2 MLP 合并 + 时域 2× |
| 压缩比 | **32× 像素**（patch 16 起） |
| 可控性 | 像素预算（图像/视频独立） |
| 默认预算 | 单图 256~1280；视频 256~16384 |
| 补偿机制 | DeepStack 多级特征注入 |

### 3.6 四代压缩方案对比总表

| 版本 | 压缩机制 | 压缩比 | 可控性 | 信息损失 | 适用场景 |
|------|---------|--------|--------|---------|---------|
| Qwen-VL | cross-attention 重采样 | 4×（448² 时 1024→256） | 不可控（固定 256） | 高分辨率损失大（1024→256 过度压缩） | 固定分辨率图文对话、定位 |
| Qwen2-VL | 2×2 卷积 + MLP | 固定 4× | 像素预算（min/max_pixels） | 邻域冗余，几乎无损 | 动态分辨率文档/OCR/视频 |
| Qwen2.5-VL | 2×2 分组 + 2 层 MLP | 4×（可配预算） | 预算 + 显式尺寸 | 预算可调，显式权衡 | 高分辨率文档解析、Agent |
| Qwen3-VL | 2×2 MLP + 时域 2× | **32× 像素**（patch16 起） | 像素预算（图/视频独立） | 有损，DeepStack 补偿 | 256K 长上下文、长视频、细粒度 |

**一句话记忆**：压缩从"固定长度"走向"固定倍率"再走向"可调预算"，信息损失从"被动接受"走向"主动管理（DeepStack 补偿）"。

## 四、token 数量估算（重点）

### 4.1 核心公式

设缩放并对齐后的尺寸为 $H' \times W'$（均为 28 的倍数），进入 LLM 的视觉 token 数为：

$$N_{\text{tok}} = \frac{H'}{28} \times \frac{W'}{28} = \frac{H' \cdot W'}{784}$$

前置处理（Qwen2-VL 起）：

$$s = \min\left(1, \sqrt{\frac{\text{max\_pixels}}{H \cdot W}}\right), \qquad H' = \text{round\_to\_multiple}(s\cdot H,\ 28),\quad W' = \text{round\_to\_multiple}(s\cdot W,\ 28)$$

预算参数：

| 参数 | 值 | 含义 |
|------|-----|------|
| max_pixels | $16384 \times 28 \times 28 = 12,845,056$ | 缩放后总像素上限 |
| min_pixels | $4 \times 28 \times 28$ | 小图至少放大到 4 个 token |
| 单图 token 上限 | 16384 | 决定 GPU 显存峰值 |
| 单图 token 下限 | 4 | 极简图的下界 |

### 4.2 计算器：典型输入逐一计算

| 输入 | 处理过程 | $H' \times W'$ | token 数 |
|------|---------|--------------|---------|
| 224×224 方形 | 预算内不缩放 | 224×224（8×8 个 28-格） | $8\times8=64$（+2 = **66**） |
| 336×224 | 预算内不缩放 | 336×224（12×8） | **96** |
| 448×448 方形 | 预算内不缩放（=1 个 sub-image 上限） | 448×448（16×16） | **256** |
| 896×560 | 预算内不缩放，切 2 个 sub-image | 896×560（32×20） | $32\times20=$ **640** |
| 1920×1080（1080p） | 约 2.07M 像素 ≤ 预算，不缩放；对齐 28 | 约 1064×1904（38×68） | $38\times68\approx$ **2584** |
| 3000×1200 长文档截图 | 3.6M 像素 ≤ 预算，不缩放；对齐 28 | 2996×1176（107×42） | **4494**（预算内） |
| 极端大图 | 缩放至预算内再切 | 满足 $H'\cdot W' \le 12{,}845{,}056$ | **≤ 16384** |

计算示例（1080p）：$1920\times1080 = 2{,}073{,}600 \le 12{,}845{,}056$，$s=1$；$1080 \to 1064$（38×28），$1920 \to 1904$（68×28）；$N = 38 \times 68 = 2584$。切分成若干 448² 的 sub-image 编码后按行优先拼回。

### 4.3 视频：2 FPS 统一建模

- 视频按 **2 FPS** 抽帧；
- **时域卷积（depth=2 的 3D 卷积）**：连续帧的时空 tube 一起过卷积，**2 帧合并为 1 个时间步**（`temporal_patch_size=2`），不增加序列长度就能处理更多帧；
- 为统一训练，**单张图片被视为 2 个相同帧**；
- 每个视频的总 token 数上限 **16384**（训练时动态调帧分辨率）。

| 视频场景 | 计算 | 结果 |
|---------|------|------|
| 10 秒视频，2 FPS | 20 帧 → 10 时间步，每步 64 token（224²） | 640 |
| 1 分钟视频，2 FPS | 120 帧 → 60 时间步，每步 256 token（448²） | 60×256 = **15360** ≈ 上限 16384 |
| 1 分钟视频，2 FPS | 120 帧 → 60 时间步，每步 64 token（224²） | 3840 |
| 30 分钟视频（Qwen3-VL 256K 上下文） | 接近 256K 上限 | 需要长上下文基建 |

**要点**：视频 token = 时间步 × 每帧 token。即使每帧低分辨率，长时间视频也轻松上万 token——抽帧与帧分辨率是视频侧仅有的两个调节旋钮（Qwen3-VL 可配 fps/num_frames 与 total_pixels）。

### 4.4 token 数对显存与计算的影响

**KV cache 公式**（BF16 精度）：

$$M_{\text{KV}} = \underbrace{2}_{\text{K 和 V}} \times \underbrace{L}_{\text{层数}} \times \underbrace{n}_{\text{token 数}} \times \underbrace{d}_{\text{隐藏维}} \times \underbrace{2}_{\text{BF16 = 2 字节}}\ \text{(bytes)}$$

算例（Qwen2-VL-7B 的 LLM：$L=28$ 层，$d=3584$，BF16）：

| token 数 n | KV cache | 说明 |
|-----------|----------|------|
| 512（纯文本问题） | $2\times28\times512\times3584\times2 \approx 0.21$ GB | 文本基线 |
| 2584（1080p 单图） | $\approx 1.04$ GB | 视觉 ≈ 文本的 **5 倍** |
| 16384（长文档/视频上限） | $2\times28\times16384\times3584\times2 \approx 6.58$ GB | 单条序列就吃掉大半显存 |

**Attention 计算**：prefill 阶段每层要算 n×n 的注意力分数矩阵，复杂度 O(n²)；朴素实现下 n=16384、L=28 时分数矩阵共 $16384^2 \times 28 \approx 75$ 亿个元素（BF16 约 15 GB）——必须用 flash-attention 避免物化。decode 阶段每步新 query 与全部 n 个 KV 交互，复杂度 O(n)。

**token 翻倍的连锁反应**：

| 指标 | n → 2n 的变化 |
|------|--------------|
| KV cache | ×2（线性） |
| prefill 注意力计算 | ×4（平方） |
| decode 单步延迟 | ×2（线性） |
| TTFT | 近似 ×4 或更高（算力密集部分平方增长） |

**工程结论**：token 预算是最强效的显存/延迟杠杆——`max_pixels` 从 16384×28×28 降到 512×28×28，KV 与 prefill 成本下降一个量级。

## 五、M-RoPE 深挖（重点）

### 5.1 从 RoPE 到 M-RoPE：1D RoPE 的数学

**旋转位置编码**：对第 $i$ 对频率维度（共 $d/2$ 对），位置 $m$ 处的旋转角为 $\theta_i \cdot m$，其中：

$$\theta_i = b^{-2i/d}, \qquad b = 10000$$

对维度对 $(2i, 2i+1)$ 施加 2D 旋转：

$$\begin{pmatrix} x'_{2i} \\ x'_{2i+1} \end{pmatrix} = \underbrace{\begin{pmatrix} \cos(m\theta_i) & -\sin(m\theta_i) \\ \sin(m\theta_i) & \cos(m\theta_i) \end{pmatrix}}_{R(m\theta_i)} \begin{pmatrix} x_{2i} \\ x_{2i+1} \end{pmatrix}$$

**复数形式**：令 $z = x_{2i} + i\, x_{2i+1}$，旋转等价于：

$$z' = z \cdot e^{i\, m \theta_i}$$

**内积的相对性**（RoPE 的灵魂）：query 旋转到位置 $m$、key 旋转到位置 $n$ 后，两者内积只依赖相对位置：

$$\left\langle R_m(q),\, R_n(k) \right\rangle = \operatorname{Re}\left(q\, \bar{k}\, e^{i(m-n)\theta_i}\right)$$

即内积中 $e^{i(m-n)\theta_i}$ 只与 $m-n$ 有关——绝对位置被消掉，留下**相对位置**。这就是"旋转位置编码"名字的由来。

**局限**：1D RoPE 只有一根时间轴，能表达"第几个 token"，却无法表达"图像第几行第几列"或"视频第几帧"。

### 5.2 三维分解：位置 = (t, h, w)

M-RoPE 把每个 token 的位置表示成三元组：

$$p = (t, h, w)$$

- $t$：时间轴（视频帧序 / 多图序号 / 图片内恒为常数）；
- $h$：高度轴（行坐标）；
- $w$：宽度轴（列坐标）。

位置编码由三个轴的分量组合而成（论文表述："把旋转嵌入分解为 temporal、height、width 三个分量"）：

$$\mathrm{M\text{-}RoPE}(t, h, w) = \mathrm{Rot}_t(t) \circ \mathrm{Rot}_h(h) \circ \mathrm{Rot}_w(w)$$

**实现上不是三个独立 RoPE**，而是**同一个旋转编码在维度分组上的分解**：不同维度组用不同轴的 position id 计算旋转角。对两个 token $p_1=(t_1,h_1,w_1)$、$p_2=(t_2,h_2,w_2)$，内积中 t 组维度的旋转差为 $(t_1-t_2)\theta_i$、h 组为 $(h_1-h_2)\theta_i$、w 组为 $(w_1-w_2)\theta_i$——三个轴各自保持"相对性"，空间与时间关系被完整编码。

### 5.3 mrope_section 分组机制

Qwen2-VL-7B 配置：`mrope_section = [16, 24, 24]`。head_dim = 128 → 旋转频率对共 64 对（每对覆盖 2 个维度）：

| 分组 | 频率对范围 | 覆盖维度 | 使用的 position id |
|------|-----------|---------|-------------------|
| 前 16 对 | $i = 0 \sim 15$ | 维 0~31 | 时间 id t |
| 中间 24 对 | $i = 16 \sim 39$ | 维 32~79 | 高度 id h |
| 后 24 对 | $i = 40 \sim 63$ | 维 80~127 | 宽度 id w |

$$\underbrace{[16,\ 24,\ 24]}_{16+24+24 = 64\ \text{对}}$$

每个 head 的 128 维被切成三段，同一位置向量上：前 32 维按时间旋转、中间 48 维按行旋转、后 48 维按列旋转。由于 $\theta_i = b^{-2i/d}$ 中 $i$ 越小频率越高，**前 16 对恰好是最"高频"的频带**——这一点是 Qwen3-VL 改成交错分配的动机（见 5.7）。

### 5.4 三种模态的 position id 规则

| 输入 | 时间 id t | 高度 id h | 宽度 id w |
|------|-----------|-----------|-----------|
| 文本第 i 个 token | i | i | i |
| 图像 token（第 r 行第 c 列） | 固定常数 | r | c |
| 视频第 f 帧、第 r 行第 c 列 | f | r | c |

**四条关键规则**：

1. **文本用 $(i,i,i)$**：三维退化为 1D，M-RoPE 在纯文本上与标准 RoPE 完全等价（证明见 5.5）；
2. **图片内所有 token 的时间 id 相同**：图片是"单帧"（Qwen2-VL 训练时视为 2 个相同帧以满足时域卷积）；
3. **模态间不冲突**：多模态拼接时，每种模态的编号从前一种模态最大 position id + 1 开始；
4. **id 数值小**：图像/视频按局部坐标编号而非整体序列绝对位置，这是 16K→80K 外推的来源（见 5.6）。

### 5.5 文本退化等价性证明

**命题**：纯文本输入下，M-RoPE 与 1D RoPE 完全等价。

**证明**：文本 token 位于序列第 $m$ 位时，三轴 id 均为 $m$，即 $(m, m, m)$。

对任意频率对 $i$（不论属于哪一组）：

- 1D RoPE：位置 $m$ 处该对的旋转角为 $m\theta_i$；
- M-RoPE：t/h/w 三组都用 id $m$ 计算旋转角，该对的旋转角同样是 $m\theta_i$。

逐频率对逐一比对，所有维度的旋转角完全一致 → 位置编码矩阵完全相同。再取任意两个文本 token $m, n$，任意频率对上的相对旋转差为 $(m-n)\theta_i$，与 1D RoPE 一致。□

**推论**：M-RoPE 不损害文本能力——消融实验（论文 3.3.2）显示下游任务全面更优（尤其视频 benchmark 提升显著），文本能力不降。

### 5.6 位置 id 数值小 → 长度外推收益（16K → 80K）

**标准 RoPE 为什么难以外推**：推理长度超过训练长度时，会出现训练中**从未见过的超大 position id**。这些 id 对应的高频旋转角没有被充分学习，注意力分布偏移，模型"失稳"。外推的本质是"训练时见过的位置频段是否覆盖推理时的频段"。

**M-RoPE 的机制**：

1. 图像/视频 token 用**局部坐标**编号——行 $r$、列 $c$ 只随分辨率增长（28 网格下 ≤ 约 128 量级），帧号 $f$ 也远小于序列总长；总上下文 80K 里，视觉 token 的 id 依然在训练覆盖的小数值区间内；
2. 大 id 只出现在文本段，而文本相对短（几百~几千），在 16K 训练覆盖内；
3. 旋转角只由局部 id 决定（不是由"序列中第几个 token"决定），所以**旋转编码层面没有未见过的角度**。

效果：论文 Figure 5 验证——训练上限 16K token，推理 80K 依然稳健。这是 M-RoPE 除"空间感知"外的第二个隐藏收益。

**再进一步的扩展**：NTK 缩放 / YaRN 插值用于更长上下文。Qwen3-VL 原生训练 256K，用 YaRN 扩到 1M（约 2 小时视频，准确率 99.5%）——且因 interleaved 位置 id 增长更慢，**1M 扩展只需 factor 2~3，而非标准 RoPE 的 4**。

### 5.7 Interleaved-MRoPE（Qwen3-VL 修复频率失衡）

**问题**：块状分配（如 [16,24,24]）下，前 16 对（最高频）全部分给 t 轴，h/w 轴只有中低频——**低频/高频带在三个轴上分布不均**，长视频场景频谱有偏：时间轴缺低频（长程时序弱），空间轴缺高频（细节弱）。

**修复**：频率交错分配——t/h/w 分量在嵌入维度上**交替排布**（配置 `mrope_interleaved: true`，`mrope_section: [24, 20, 20]`），保证每条轴在低频与高频带都被均匀覆盖。

| | Qwen2 系（块状） | Qwen3-VL（交错） |
|--|----------------|----------------|
| 配置 | `mrope_section: [16,24,24]` | `mrope_interleaved: true` + `[24,20,20]` |
| 频带分布 | t 轴只有高频，h/w 只有中低频 | 每轴高低频均匀覆盖 |
| 收益 | — | 长距离时序建模显著改善，长视频 benchmark 提升 |
| 附带 | — | 位置 id 增长更慢，1M 扩展缩放因子 2~3 而非 4 |

## 六、位置编码演进与各代架构位置

### 6.1 四代位置编码总表

| 版本 | ViT 内位置编码 | 桥接/LLM 内位置编码 | 时间建模 |
|------|--------------|-------------------|---------|
| Qwen-VL | 可学习绝对 PE（224→448 双线性插值） | Adapter：2D 绝对 PE 注入 Q-K 对；LLM：1D RoPE（视觉 token 只占序列位置） | 无（视频抽帧拼成复合大图） |
| Qwen2-VL | 2D-RoPE（任意尺寸可外推） | M-RoPE（t/h/w 分块，`[16,24,24]`） | 帧序号 |
| Qwen2.5-VL | 2D-RoPE | M-RoPE + 绝对时间对齐 | 真实时间（动态 FPS） |
| Qwen3-VL | 2D-RoPE（按输入插值） | Interleaved-MRoPE（`[24,20,20]` 交错） | 文本时间戳 token |

演进主线：**绝对 PE → 2D-RoPE（ViT 内）→ M-RoPE 3D（LLM 内）→ Interleaved-MRoPE**；时间建模：**无 → 帧序号 → 绝对时间 → 文本时间戳**。

### 6.2 位置注入位置图：三处注入点

```text
                        ┌────────────────────────────────────────┐
图像 → ViT → patch 特征 │ ① ViT 内：可学习绝对PE / 2D-RoPE        │
                        │   作用：patch 之间区分上/下/左/右          │
                        ├────────────────────────────────────────┤
  压缩/合并（cross-attn）│ ② Q-K 对：2D 绝对PE 注入 Q̃=Q+PE, K̃=K+PE  │
                        │   作用：压缩后不丢空间布局 → 定位能力      │（仅 Qwen-VL）
                        ├────────────────────────────────────────┤
  视觉 token 序列         │ ③ LLM 内：1D RoPE → M-RoPE → Interleaved│
   + 文本 token           │   作用：图文混合生成 + 3D 空间时间感知    │
                        └────────────────────────────────────────┘
```

| 注入点 | 代表 | 解决的问题 | 失效时的表现 |
|--------|------|-----------|-------------|
| ① ViT 内 | 绝对 PE / 2D-RoPE | 图内空间感（patch 间相对位置） | 视觉塔特征混乱 |
| ② Q-K 对 | Qwen-VL Adapter | 压缩时位置信息被加权求和抹平 | 无法画框、指代失效 |
| ③ LLM 内 | M-RoPE 家族 | 图文统一编号 + 3D 时空建模 | 多图/视频时间顺序错乱 |

关键演进：Qwen-VL 是"分层接力"（三层各管一段）；Qwen2-VL 起 M-RoPE 把时间/高/宽三维直接编码进 LLM 的旋转位置里，位置编码从"分层接力"变成"统一 3D"。

## 七、常见工程问题

### 7.1 多图/视频的位置冲突

若多张图都从 (常数, 0, 0) 开始编号，图 1 与图 2 的 token 会拥有完全相同的 (t,h,w)，attention 无法区分"这个 token 属于哪张图"。规则：**每种模态从前一种模态最大 position id + 1 开始编号**；多图的时间 id 递增——第 2 张图时间 id = 第 1 张 + 1，即"**多图 = 多帧视频**"。视频内部帧号同理递增，不同视频片段之间也偏移，避免任意两 token 的 id 三元组碰撞。

### 7.2 sub-image 边界

- 切分是**空间分区**而不是"各自独立"：每个 sub-image 的 token 在 M-RoPE 中保留其**全局网格坐标**，LLM 依然能感知每个 sub-image 在整图中的位置；
- 遗留问题：Qwen2.5-VL 的窗口注意力（8×8 patch 窗口）在 tile 边缘的跨区域交互受限，依赖仅 4 层全局注意力缓解；窗口/位置编码在 tile 边缘的表现仍是细节问题（参考论文 §10.1）。

### 7.3 切分顺序：行优先

sub-image 切分顺序固定为**行优先（row-major）**：先左后右、先上后下，合并后的 token 也按此顺序拼回一条序列。若改成列优先，相邻 token 的空间位置会跳变，M-RoPE 的相对位置关系与 2D 网格对不上，模型的空间感知被破坏。token 拼接顺序必须与 position id 的网格坐标一致。

### 7.4 interleaved 交错图文

- 多张图按出现顺序各自编码、顺序拼接，每张图独立 `<|vision_start|>`/`<|vision_end|>` 包裹；
- Qwen3-VL 支持给图加序号前缀（`Picture 1: ...`），便于"对比第 1 张和第 3 张"这类跨图指代；
- Qwen3-VL 用**文本时间戳 token**（如 `<3.0 seconds>`）表达视频时间，插入在每个时间片段前——放弃"位置编码式时间"，模型直接"读表"，代价仅是上下文小幅增加。

## 八、高频面试问答

**Q1：Qwen2-VL 的一张图 token 数量怎么算？**
缩放后尺寸 $H'\times W'$（28 的倍数），$N = \frac{H'}{28}\times\frac{W'}{28} = \frac{H'W'}{784}$。224² → 64（+2 特殊 token 共 66）；448² → 256；1080p → 约 1064×1904 → 2584。上限由 `max_pixels = 16384×28×28` 决定，即单图最多 16384 token。

**Q2：为什么对齐单位是 28 而不是 14？**
patch 是 14×14，合并器把 2×2 个 patch 合并为 1 个视觉 token，所以每个 token 覆盖 28×28 像素（28 = 14 × 2）。缩放尺寸若只对齐 14，合并后可能出现半格、无法整数拼接。

**Q3：M-RoPE 的原理是什么？**
把位置拆成 (t, h, w) 三维，在同一个旋转编码内部按维度分组：不同维度组用不同轴的 position id 计算旋转角（Qwen2-VL-7B 为 `[16,24,24]` 分组，head_dim=128 共 64 对频率）。文本用 (i,i,i) 退化为 1D，图像用 (常数, 行, 列)，视频用 (帧, 行, 列)。

**Q4：四代视觉 token 压缩方案有什么区别？**
cross-attn 重采样（固定 256，可学习 query 模板）→ 2×2 卷积+MLP（固定 4×，28 对齐的来源）→ 动态 Merger（预算 4~16384 可调）→ 32× 像素压缩（patch 16 + 时域 2，Qwen3-VL 默认单图 256~1280）。压缩比 4×→4×→可调→32×，可控性逐步增强。

**Q5：M-RoPE 为什么能 16K 训练外推到 80K 推理？**
外推困难来自"未见过的超大 position id"及其高频旋转角。M-RoPE 中视觉 token 用局部坐标（行/列/帧号）编号，id 数值不随序列总长增长；长序列里绝大部分 token 的 id 仍在训练覆盖区间，旋转编码层面没有未见过的角度（论文 Figure 5）。

**Q6：Qwen-VL 为什么固定 256 个视觉 token？**
用单层 cross-attention 重采样，256 个可学习 query 从 patch 中抽取信息，输出恒为 256 与输入分辨率无关——这是"固定 256 token"的来源。448² 时是 1024→256（4× 压缩），224² 时 256→256（不压缩）。位置由 2D 绝对 PE 注入 Q-K 对保住。

**Q7：为什么说纯文本下 M-RoPE 与 1D RoPE 等价？**
文本 token 的 id 三元组是 (i,i,i)，任意频率对的旋转角都是 iθᵢ，与 1D RoPE 逐对一致；任意两文本 token 的相对旋转差 (m−n)θᵢ 也一致。因此文本能力不降，消融中下游任务全面更优。

**Q8：一个 1920×1080 的图大概多少 token？**
约 2.07M 像素 ≤ 12.8M 预算，不缩放；对齐 28 后约 1064×1904（38×68），token ≈ 2584 个，切成若干 448² 的 sub-image 编码后行优先拼回。

**Q9：token 数量如何影响显存？**
KV cache = 2×L×n×d×2B。以 28 层、3584 维、BF16 为例：512 token ≈ 0.21 GB，2584 token ≈ 1.04 GB，16384 token ≈ 6.58 GB；prefill 注意力 O(n²)（16384 时朴素分数矩阵约 15 GB，必须 flash-attention），decode O(n)。

**Q10：视频 token 怎么估算？**
视频按 2 FPS 抽帧，时域卷积 2 帧合并 1 时间步，token = 时间步 × 每帧 token。1 分钟视频 120 帧 → 60 步，每帧 448²（256 token）→ 15360 ≈ 上限 16384；每帧 224²（64 token）→ 3840。帧率与帧分辨率是仅有的两个调节旋钮。

## 九、常见误区

**误区 1：Qwen-VL 是"448 个 token 压到 256 个"。**
错。448 是**分辨率**（第二阶段）。448×448 产生 1024 个 patch（$(448/14)^2$），重采样到 256（4× 压缩）；224×224 是 256→256 不压缩。

**误区 2：M-RoPE 是"三个独立的 RoPE 拼在一起"。**
不准确。M-RoPE 是**一个**旋转编码在维度分组上的分解：同一组 θ 序列，不同维度组用 t/h/w 各自的 id 计算旋转角，并非三个独立的位置编码器。

**误区 3：视觉 token 压缩越多越好。**
不对。2×2 合并是"几乎无损"的邻域冗余压缩；但过度压缩（如固定 256 token 承载大图）会丢小字细节。Qwen2.5-VL 起用动态预算就是在精度与成本间显式权衡；Qwen3-VL 的 32× 有损压缩需要 DeepStack 补偿。

**误区 4：视觉 token 越多 = 看得越清楚。**
不成立。清晰度取决于预训练分辨率覆盖与信息保真度；盲目提高预算只增加 KV 与 O(n²) 计算，超过训练分布（如 min_pixels 过大把极小图过度放大）反而损害 OCRBench 等任务（OOD）。

**误区 5：sub-image 切分后各块互相独立。**
不是。切分顺序固定行优先，且每个 sub-image 的 token 在 M-RoPE 中保留全局网格坐标——切分是"空间分区"，LLM 仍能感知每块在整图中的位置。

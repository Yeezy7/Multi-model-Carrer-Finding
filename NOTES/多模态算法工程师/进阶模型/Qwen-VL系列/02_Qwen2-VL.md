# Qwen2-VL 第二代（2024）：动态分辨率 + M-RoPE + 4× 压缩

> 本笔记是 Qwen-VL 系列的第二篇，聚焦第二代 Qwen2-VL（2024.08/09，论文 2409.12191）。这是**全系列最重要的一代**：Naive Dynamic Resolution（朴素动态分辨率）和 M-RoPE（3D 位置编码）两个创新奠定了后两代的基础，几乎所有 Qwen 系面试题都从这里出。第一代见本目录 `01_Qwen-VL.md`。

---

## 一、一句话解释

> **Qwen2-VL = 扔掉固定分辨率与固定 token 数的第一代方案，用 Naive Dynamic Resolution 把任意分辨率/任意长宽比的图像与视频无损地变成 token，用 M-RoPE 把时间×高×宽三维位置直接编码进 LLM 的旋转位置里，并用 2×2 卷积 + MLP 做固定 4× 的 token 压缩。**

三个关键词记住这一代：

1. **Naive Dynamic Resolution（朴素动态分辨率）**：保持长宽比缩放 + 28 像素对齐 + 超限切 sub-image，token 数从固定 256 变成**动态的 4~16384**；
2. **M-RoPE（Multimodal RoPE）**：把位置拆成 (t, h, w) 三维，文本/图像/视频三种模态统一建模，位置编码从第一代的"分层接力"变成"统一 3D"；
3. **4× 压缩**：2×2 卷积（或分组）+ MLP 把 patch 特征合并为视觉 token，压缩比固定 4×，几乎无损。

**一句话定位**：第一代解决了"有视觉能力"，第二代解决了"看得清、看得懂空间与时间"——文档/OCR 能力大幅跃升，视频第一次成为一等公民。

---

## 二、动机：第一代的三大局限

第一代 Qwen-VL 能用，但四个短板限制了它的上限，Qwen2-VL 逐一回应：

| 第一代局限          | 具体表现                                 | Qwen2-VL 的对策                                     |
| -------------- | ------------------------------------ | ------------------------------------------------ |
| 固定分辨率（224→448） | 文档、小字 OCR 模糊不可读；极端长宽比图像被 resize 压扁失真 | Naive Dynamic Resolution：任意分辨率、保持长宽比             |
| 固定 256 token   | 448² 图像 1024 个 patch 被压到 256 个，信息丢失  | 动态 token 数 $N = H'W'/784$（4~16384），大图多 token 保细节 |
| 没有时间维位置编码      | 视频只能抽帧拼成复合大图，帧间无先后位置                 | M-RoPE：时间轴 t + 高度 h + 宽度 w 三维位置编码                |
| ViT 冻结为主       | 视觉表示与 LLM 对齐不充分                      | 自研 675M ViT，阶段 2 全解冻参与训练                         |


> **记忆点**：第二代的两大创新（动态分辨率、M-RoPE）分别回答"图像怎么无损进来"和"空间时间怎么告诉模型"两个问题。

## 三、模型家族：三尺寸共享同一个视觉塔

### 3.1 模型表

论文编号：**2409.12191**（Qwen2-VL: Enhancing Vision-Language Model's Perception of the World at Any Resolution）。

| 模型 | 视觉编码器 | LLM | 总参数 | 定位 |
|------|-----------|-----|--------|------|
| Qwen2-VL-2B | 675M | 1.5B | 2B | 端侧部署 |
| Qwen2-VL-7B | 675M | 7.6B | 8B | 性价比主力 |
| Qwen2-VL-72B | 675M | 72B | 72B | 旗舰，对标 GPT-4o |

### 3.2 关键设计：共享 675M ViT

**三个尺寸共用同一个 675M ViT**——视觉计算开销不随 LLM 规模增长，2B 与 72B 的"眼睛"是一样的，差距全在"大脑"（LLM）。

| 属性 | 值 |
|------|----|
| 参数量 | 675M（远小于第一代的 1.9B ViT-bigG） |
| Patch | 14×14 |
| 位置编码 | **2D-RoPE**（去掉绝对位置编码） |
| 初始化 | DFN 预训练权重 |
| 训练状态 | 阶段 1/2 参与训练，阶段 3 冻结 |

**为什么必须去掉绝对位置编码换 2D-RoPE**：绝对位置编码隐含"固定序列长度"的假设（224 是 16×16 的位置表、448 要插值成 32×32），而动态分辨率下输入尺寸任意——位置编码必须能在**任意网格尺寸**下工作。2D-RoPE 按行/列坐标计算旋转角度，天然支持任意尺寸，这是动态分辨率的前提之一。

### 3.3 为什么 675M 比 1.9B 更好用

第一代用了 1.9B 的 ViT-bigG，第二代反而换成 675M，看似"退步"，实则三点原因：

| 原因 | 说明 |
|------|------|
| 训练参与度 | 第一代 ViT 以冻结为主（阶段 1/3 冻结），与 LLM 对齐不足；675M 的 ViT 可以在阶段 1/2 全程训练，**参数少反而敢放开训** |
| 成本 | 1.9B 视觉塔前向 + 梯度开销巨大；675M 在同样显存预算下能喂更多视觉数据 |
| 收益边际 | 视觉编码器的收益在规模上已趋饱和，瓶颈转移到"视觉-语言对齐"——用更小、更可训的视觉塔做深度对齐，性价比更高 |

> **记忆点**：第一代是"大而冻"，第二代是"小而训"——参数规模让位于对齐质量。

### 3.4 论文中的其他设计

- ViT 用 **DFN**（Data Filtering Networks）预训练权重初始化，而非 OpenCLIP；
- 视觉塔输出 patch 特征维度 1280，经合并器投影到 LLM 隐藏维（7B 为 3584）；
- 全系列共享同一套 processor 逻辑（缩放/对齐/切分），只是 LLM 部分大小不同。

## 四、Naive Dynamic Resolution（朴素动态分辨率，重点，最细）

### 4.1 动机：固定分辨率的三大问题

| #   | 问题              | 场景例子                           |
| --- | --------------- | ------------------------------ |
| 1   | **文档/OCR 场景失效** | 小字在 448×448 下模糊不可读，票据、截图、论文识别崩 |
| 2   | **极端长宽比失真**     | 横版全景图、竖版长截图被 resize 后内容被压扁/拉伸  |
| 3   | **token 浪费**    | 简单小图被强制放大到固定分辨率（如 448²），白耗算力   |

> 论文的解法理念："每个像素都是信息"——token 数应该由图像的实际内容量决定，而不是由模型的固定输入规格决定。

### 4.2 算法流程（五步）

```text
输入：任意分辨率原图 (H, W)，token 预算 max_pixels
  ↓
① 等比缩放：保持长宽比，使 H×W ≤ max_pixels
    缩放因子 s = min(1, √(max_pixels / (H·W)))
  ↓
② 对齐网格：H' = round_to_multiple(s·H, 28)，W' = round_to_multiple(s·W, 28)
    为什么是 28？patch 14 × 合并 2 = 28（合并后每个 token 覆盖 28×28 像素）
  ↓
③ 切分 sub-image：超过 448×448（= 32×32 patches）就切成多个 sub-image，逐个编码
  ↓
④ 分别过 ViT：每个 sub-image 独立得到 patch 特征
  ↓
⑤ 合并 + 拼接：每个 sub-image 的 2×2 patch 合并为 1 个 token，按左上→右下顺序拼回一条序列
    每张图以 <|vision_start|> 开始、<|vision_end|> 结束
```

**逐步骤展开**：

- **① 等比缩放**：先按总像素预算缩到"最大总像素"以内，缩放因子 $s = \min(1, \sqrt{\text{max\_pixels}/(H \cdot W)})$。小于 1 表示降采样，等于 1 表示原图输入；
- **② 对齐 28 网格**：缩放后 H、W 必须是 28 的倍数（四舍五入），否则合并器会出现半格无法整数拼接；
- **③ 切 sub-image**：任何超过 448×448 的图切成若干个 ≤448² 的块——每个块仍然保持**全局像素坐标**，后续 token 的 M-RoPE 位置按全局网格计算；
- **④ 各自过 ViT**：sub-image 之间无注意力交互（各自独立编码），信息融合发生在 LLM 侧；
- **⑤ 合并拼接**：行优先（row-major）顺序拼成一条序列，首尾加视觉起止 token。

### 4.3 关键参数表

| 参数 | 值 | 含义 |
|------|-----|------|
| 缩放对齐单位 | **28**（= patch 14 × merge 2） | 缩放后 H、W 均为 28 的倍数 |
| sub-image 上限 | **448×448**（= 32×32 patches） | 大图切成若干 sub-image，各自过 ViT |
| 单图 token 上限 | **16384**（7B/72B 默认 max_pixels = 16384×28×28） | 决定 GPU 显存峰值 |
| 单图 token 下限 | **4**（min_pixels = 4×28×28） | 小图至少放大到 4 个 token |

**为什么对齐单位是 28 而不是 14**：

```text
patch 14×14 像素 → 2×2 合并 → 1 个视觉 token 覆盖 28×28 像素
```
 
合并器把 2×2 的 patch（各 14×14 像素）合并为 1 个 token，因此每个视觉 token 覆盖 28×28 像素。若只对齐 14，合并后可能出现半格、无法整数拼接。

**为什么 sub-image 上限是 448²**：448 = 32 个 patch × 14 像素，即 32×32 = 1024 个 patch 的块，合并后恰好是 16×16 = 256 个 token——这个尺寸在显存与切分粒度之间取得平衡（太小切块过多、太大单块计算压力高）。

**min/max_pixels 的作用**：它们是用户可调的"token 预算"旋钮——大图给大预算保细节，小图给最小预算省算力，精度与成本可以按场景任意调节。

### 4.4 token 数计算公式（面试必考）

设缩放后尺寸为 $H' \times W'$（均为 28 的倍数），则进入 LLM 的视觉 token 数为：

$$N_{\text{tok}} = \frac{H'}{28} \times \frac{W'}{28} = \frac{H' \cdot W'}{784}$$

| 输入尺寸    | 计算过程                                              | 合并后 token | 加上首尾 token     |
| ------- | ------------------------------------------------- | --------- | -------------- |
| 224×224 | $\frac{224}{28}\times\frac{224}{28} = 8\times8$   | 64        | **66**（论文原文数据） |
| 448×448 | $\frac{448}{28}\times\frac{448}{28} = 16\times16$ | 256       | 258            |


> **与第一代对比记忆**：第一代 448² → 1024 patch → 固定 256 token；第二代 448² → 256 token（4× 压缩后）——数字巧合相同，但第二代的是"压缩的自然结果"，第一代是"重采样器的固定输出"。

**完整换算示例（走一遍五步，896×560 的横版图）**：

1. 原图 $H \cdot W = 896 \times 560 = 501760$ 像素，缩放因子 $s = \min\left(1, \sqrt{\frac{16384 \times 784}{501760}}\right) = \min(1, \sqrt{25.6}) = 1$（总像素远小于预算，不缩放）；
2. 对齐 28：$896/28 = 32$，$560/28 = 20$，恰好都是 28 的倍数（32×20 个 28-格），无需取整；
3. 560 > 448，沿高方向切成 **2 个 sub-image**：32×16 与 32×4 个 28-格（每块 ≤ 32×32）；
4. 两个 sub-image 分别过 ViT，得到 $32\times16=512$ 与 $32\times4=128$ 个 patch 网格；
5. 各 sub-image 内部做 2×2 合并，行优先拼回一条序列：

$$N_{\text{tok}} = \frac{896}{28}\times\frac{560}{28} = 32\times20 = 640 \ \text{个视觉 token}$$

与上表一致。第二块 sub-image 的 token 在 M-RoPE 中保留**全局行号**（从第 17 行开始），而不是从 0 开始——所以 LLM 知道它属于整图的下面部分。

### 4.5 不同长宽比的 sub-image 切分示例

| 原图              | 缩放后（对齐 28）            | sub-image 数量      | 合并后 token 数 |
| --------------- | --------------------- | ----------------- | ----------- |
| 224×224 方形      | 224×224               | 1                 | 64          |
| 336×224         | 336×224（12×8 个 28-格）  | 1                 | 96          |
| 896×560         | 896×560（32×20）        | 2（各 32×16 与 32×4） | 640         |
| 1600×900 横版     | 约 1120×644 → 1120×644 | 4 左右              | 约 920       |
| 3000×1200 长文档截图 | 缩放至预算内再切              | 若干                | ≤ 16384     |

**切分的重要细节**：切分顺序固定为**行优先（row-major）**，且每个 sub-image 的 token 在 M-RoPE 中保留其**全局网格坐标**——切分是"空间分区"而不是"各自独立"，LLM 依然能感知每个 sub-image 在整图中的位置。比如 896×560 切成上下两块，第二块的 token 坐标从第 17 行开始算，而不是从 0 行重新算。

### 4.6 消融结论（论文 3.3.1）

1. **固定分辨率没有一个值能在所有 benchmark 上同时最优**——448 时小图浪费、1344 时大图显存爆，动态分辨率平均 token 更少、效果最稳；
2. **适当提高 min_pixels（把小图放大）能提升 InfoVQA、OCRBench 等感知类任务**——小图放大后小字可读；
3. **但 min_pixels 过大反而损害 OCRBench**：大量极小图被过度放大，脱离训练分布（OOD）。

| 消融发现 | 一句话结论 |
|---------|-----------|
| 固定分辨率 | 无全能值，动态更稳 |
| min_pixels 适度调大 | 感知类任务（InfoVQA/OCRBench）提升 |
| min_pixels 过大 | 过度放大脱离训练分布，反而掉点 |

## 五、M-RoPE（Multimodal RoPE，3D 位置编码，重点，最细）

### 5.1 背景：1D RoPE 的局限

标准 RoPE（Rotary Position Embedding）把位置编码进 token 间的**相对角度**：对第 $i$ 对频率维度，位置 $m$ 处旋转角为 $\theta_i \cdot m$，其中：

$$\theta_i = b^{-2i/d}, \qquad b = 10000$$

它只有**一根时间轴（序列轴）**，无法表达"图像里第几行第几列"或"视频第几帧"。第一代的做法是"分层接力"（ViT 绝对 PE → Adapter Q-K 注入 → LLM 1D RoPE），位置信息到 LLM 前已经浓缩进 token 内容，LLM 侧没有显式的 2D/3D 坐标。

### 5.2 核心思想：把位置拆成三维

M-RoPE 把每个 token 的位置表示成三元组：

$$p = (t, h, w)$$

- $t$：时间轴（视频帧序 / 多图序号 / 图片内恒为常数）；
- $h$：高度轴（行坐标）；
- $w$：宽度轴（列坐标）。

位置编码由三个轴的分量组合而成（论文表述为"把旋转嵌入分解为 temporal、height、width 三个分量"）：

$$\mathrm{M\text{-}RoPE}(t, h, w) = \mathrm{Rot}_t(t) \circ \mathrm{Rot}_h(h) \circ \mathrm{Rot}_w(w)$$

### 5.3 实现：维度分组（mrope_section）

实现上（开源模型配置 `mrope_section`）：**每个 head 的维度被分组**，不同分组使用不同轴的 position id 计算旋转角。

Qwen2-VL-7B 配置：

| 配置项             | 值                |
| --------------- | ---------------- |
| head_dim        | 128（即 64 对旋转频率对） |
| `mrope_section` | **[16, 24, 24]** |
| 前 16 对频率        | 用时间轴 id t 计算旋转角  |
| 中间 24 对频率       | 用高度轴 id h 计算旋转角  |
| 后 24 对频率        | 用宽度轴 id w 计算旋转角  |

```text
head_dim = 128 = 64 对频率
[ t 轴 × 16 对 ] [ h 轴 × 24 对 ] [ w 轴 × 24 对 ]
```

### 5.4 三种模态的 position id 分配规则

| 输入 | 时间 id t | 高度 id h | 宽度 id w |
|------|-----------|-----------|-----------|
| 文本第 i 个 token | i | i | i |
| 图像 token（第 r 行第 c 列） | 固定常数 | r | c |
| 视频第 f 帧、第 r 行第 c 列 | f | r | c |

**关键点展开**：

1. **文本用 $(i, i, i)$**：三个轴用同一个 id，旋转编码完全退化为 1D——M-RoPE 在纯文本上与标准 RoPE **完全等价**，所以语言能力不降；
2. **图片内所有 token 的时间 id 相同**：图片是"单帧"，没有时间维度；
3. **多模态拼接时**：每种模态的编号从前一种模态最大 position id +1 开始——避免不同模态位置冲突（比如文本已经用到位置 300，图像的行坐标必须从"全局行号"而非 0 开始）；
4. **位置 id 数值变小**：图像/视频不再按"整体序列绝对位置"编号，而是按局部坐标编号（行号、列号、帧号都比总序列号小得多）——这是 M-RoPE 除"空间感知"外的**第二个隐藏收益**（见 5.6）。

### 5.5 为什么文本时退化为标准 RoPE（数学视角）

标准 1D RoPE 中，位置 $m$ 的 token 在第 $j$ 对频率上的旋转角为 $\theta_j \cdot m$。M-RoPE 中文本 token 的三维 id 都是 $i$：

$$p = (i, i, i) \implies \text{Rot}(i, i, i)$$

三个轴的旋转角都以 $i$ 为位置参数，组合效果与 1D RoPE 完全一致——**M-RoPE 是 RoPE 的严格超集**，文本输入时自动退化回 1D。这让 Qwen2-VL 可以放心复用 Qwen2 的语言预训练成果。

### 5.6 位置 id 数值小 → 外推能力的隐藏收益

| 现象   | 说明                                                                                     |
| ---- | -------------------------------------------------------------------------------------- |
| 训练长度 | 16K token 上限                                                                           |
| 推理外推 | **80K token 依然稳健**（论文 Figure 5 验证）                                                     |
| 原因   | 图像/视频 token 的位置 id 是"局部坐标"（行、列、帧号），数值远小于序列绝对位置——LLM 实际看到的 position id 区间比序列长度小得多，外推压力小 |

如果视觉 token 仍按"绝对序列位置"编号，16K 训练的模型在长序列（多图 + 长文本 + 长视频）推理时 position id 会大幅超出训练分布；M-RoPE 让每个视觉 token 的位置 id 保持"小数值"，即使序列本身很长，模型遇到的 position id 仍落在训练见过的范围内。

### 5.7 消融结论（论文 3.3.2）

| 对比                      | 结果                               |
| ----------------------- | -------------------------------- |
| M-RoPE vs 1D-RoPE（下游任务） | 全面更优                             |
| **视频类 benchmark**       | **提升显著**（视频需要时间轴感知，1D RoPE 完全没有） |
| 文本能力                    | 不降（因退化为 1D）                      |

## 六、视觉 token 压缩：2×2 卷积 + MLP

### 6.1 流程

ViT 输出的 patch 特征先做**空间合并**再进 LLM：

```text
ViT 输出:  H_p × W_p 个 patch token（patch 14，每个 1280 维）
    ↓ 2×2 分组（等价 2×2 卷积，stride 2）
    每个 2×2 的 patch 特征拼接成 4×1280 维
    ↓ MLP 投影到 LLM 隐藏维（Qwen2-VL-7B 为 3584）
    得到 (H_p/2) × (W_p/2) 个视觉 token
```

### 6.2 关键数字

| 数字 | 值 |
|------|----|
| 压缩比 | **固定 4×**（2×2 → 1） |
| 224×224 图 | $16\times16=256$ 个 patch → **64 个 token** |
| 448×448 图 | $32\times32=1024$ 个 patch → 256 个 token |
| 视觉 token 数量公式 | $\frac{H'}{28} \times \frac{W'}{28}$，与动态分辨率公式自洽 |

**自洽性验证**：一个 token 覆盖 28×28 像素（14×2 每边），所以 $N = (H'/28)(W'/28)$——无论是从"像素对齐"还是从"patch 合并"算，结果一致。

### 6.3 为什么还要压？为什么几乎无损？

| 压缩的收益    | 说明                                            |
| -------- | --------------------------------------------- |
| 计算量      | **4× 更少的前向计算**（LLM 是主要开销，token 少 4 倍）         |
| KV cache | 4× 更小的 KV cache（长序列、大 batch 显存收益显著）           |
| 为什么无损    | 2×2 邻域的 patch 高度冗余（相邻 patch 特征几乎一样），合并丢不掉多少信息 |

> **对比第一代**：第一代用 cross-attention 重采样把 1024 patch 压到 256（同样 4×），但那是"全局重排列"（所有 patch 都可能参与一个 token 的计算）；第二代是**局部 2×2 合并**——只融合空间相邻的 4 个 patch，信息损失更可控，且保留了严格的网格结构（M-RoPE 的 (r, c) 坐标正好一一对应）。

## 七、视频统一建模

### 7.1 设计要点

| 设计 | 值/做法 | 目的 |
|------|---------|------|
| 抽帧率 | **2 FPS** | 平衡信息量与 token 量 |
| 时域卷积 | **depth=2 的 3D 卷积** | 连续帧的 3D 时空 tube 一起过卷积，而非逐帧 2D patch |
| 时域合并 | **temporal_patch_size=2**（2 帧合并为 1 个时间步） | 不增加序列长度就能处理更多帧 |
| 单张图片 | **视为 2 个相同帧** | 满足时域卷积的输入结构，图像/视频同一套模型 |
| 视频 token 上限 | **16384** | 训练时动态调整帧分辨率来控制 |

### 7.2 "图像即 1 帧视频"的统一哲学

```text
视频 = T 帧图像（2 FPS 抽帧）
图像 = 2 个相同帧（满足时域卷积结构）
多图 = 多帧（时间 id 递增）

图像和视频走同一套视觉编码器 + 同一套 M-RoPE
```

- M-RoPE 里视频第 $f$ 帧的 token 位置为 $(f, r, c)$——时间轴 t 就是帧号；
- 多图对比时，第 2 张图的时间 id = 第 1 张 +1，即"多图 = 多帧视频"；
- 时域卷积让模型天生考虑"相邻帧的运动"，而不是逐帧独立理解。

## 十、局限

### 10.1 高分辨率显存开销

动态分辨率允许大图输入，但 **token 峰值可达 16384**：

- KV cache 与 attention 计算随 token 数线性/平方增长；
- 显存上限由"最坏情况"决定，batch 内打包困难；
- 对策：调低 max_pixels、flash-attention、按需二次缩放。

### 10.2 16384 token 峰值本身

- 一张超大图（如 3000×1200 长截图）可能用满 16384 个 token，占满上下文；
- 视频更贵：1 分钟视频按 2 FPS = 120 帧，即使每帧低分辨率也轻松上万 token。

### 10.3 坐标精度有限

- 坐标定位基于 [0,1000) 文本化框，**像素级精度有限**（依赖 token 网格，28×28 像素一个 token）；
- 细粒度空间关系（小物体、遮挡）依旧不稳；
- 视频时间定位是"帧序号"级，不知道两帧之间隔了多久（第三代 Qwen2.5-VL 用绝对时间对齐解决）。

### 10.4 其他

- 视频抽帧即丢信息：高运动、快速翻页场景仍会漏事件；
- 与所有 VLM 一样存在物体/属性/计数幻觉（尤其小物体、极端光照）；
- 训练成本高：1.4T token 预训练，非一般团队可复现。

## 十一、高频面试问答

**Q1：Qwen2-VL 的动态分辨率具体怎么实现？**
保持长宽比缩放使总像素 ≤ max_pixels，H/W 对齐到 28 的倍数（patch 14 × 2×2 合并），超过 448×448 就切成多个 sub-image 各自过 ViT，再把合并后的 token 按行优先拼回一条序列；token 数 = H'·W'/784，默认上限 16384。

**Q2：为什么对齐单位是 28 而不是 14？**
合并器把 2×2 的 patch（14×14 像素）合并为 1 个 token，因此每个视觉 token 覆盖 28×28 像素；若只对齐 14，合并后可能出现半格、无法整数拼接。

**Q3：为什么 sub-image 上限是 448×448？**
448 = 32 个 patch × 14 像素，即 32×32 = 1024 个 patch 的块，合并后恰好 16×16 = 256 个 token——在显存与切分粒度之间平衡；且每个 sub-image 独立过 ViT 后，token 保留全局网格坐标。

**Q4：一张 224×224 的图在 Qwen2-VL 里变成多少 token？**
$N = (224/28)\times(224/28) = 8\times8 = 64$ 个视觉 token；加上首尾 2 个特殊 token（`<|vision_start|>`、`<|vision_end|>`）共 **66 个**（论文原文数据）。448×448 → 256 个。

**Q5：M-RoPE 和标准 RoPE 的区别？**
标准 RoPE 只有 1D 位置；M-RoPE 把位置拆成 (t, h, w) 三维，head 维度分组（`mrope_section=[16,24,24]`）后分别用三个轴的 position id 计算旋转角。文本 token 用 (i, i, i)（等价 1D RoPE），图像用 (常数, 行, 列)，视频用 (帧, 行, 列)。

**Q6：M-RoPE 为什么能外推？16K 训练怎么支持 80K 推理？**
位置 id 数值小：图像/视频 token 按局部坐标（行、列、帧号）编号，而非整体序列绝对位置，数值远小于序列长度，外推压力小。论文 Figure 5 验证：训练上限 16K token，推理 80K 依然稳健。

**Q7：视觉 token 是怎么合并压缩的？为什么几乎无损？**
ViT 输出后把空间相邻 2×2 的 patch 特征做 2×2 卷积/分组拼接（4×1280 维），再过 MLP 投影到 LLM 隐藏维（7B 为 3584），token 减少 4 倍。2×2 邻域 patch 高度冗余，合并几乎不丢信息，却省 4× 的前向计算与 KV cache。

**Q8：Qwen2-VL 怎么统一处理图像和视频？**
视频按 2 FPS 抽帧，depth=2 的时域卷积把相邻 2 帧合并为 1 个时间步（temporal_patch_size=2）；单张图片视为 2 个相同帧；图像和视频走同一套视觉编码器与 M-RoPE——"图像即 1 帧视频，视频即 T 帧图像"。

**Q9：Qwen2-VL 的 min_pixels 和 max_pixels 调大调小有什么影响？**
min_pixels 控制小图放大程度：适度调大提升 InfoVQA、OCRBench 等感知任务，但过大导致大量极小图过度放大、脱离训练分布（OOD），反而损害 OCRBench；max_pixels 控制单图 token 上限，调小省显存但丢细节。

**Q10：Qwen2-VL 相比 Qwen-VL 在架构上的核心变化？**
① 固定分辨率 → Naive Dynamic Resolution（任意分辨率 + 动态 token 4~16384）；② 三层位置编码 → M-RoPE 统一 3D 位置编码（ViT 内改 2D-RoPE）；③ cross-attention 重采样 → 2×2 卷积 + MLP 固定 4× 压缩；④ 1.9B 冻结视觉塔 → 675M 自研 ViT 全程可训；⑤ 视频从"拼复合大图"变成"2fps + 时域卷积 + M-RoPE 时间轴"的统一建模。

## 十二、常见误区

**误区 1：动态分辨率 = 多尺度训练 / 把图缩放到几个固定档位。**
不完全是。Qwen2-VL 是**连续原生分辨率**：保持长宽比 + 对齐 28 网格 + 超限切 sub-image，token 数是分辨率的连续函数，而非预设的几个档位（LLaVA-NeXT 的 anyres 才是指定网格切块）。

**误区 2：M-RoPE 就是"三个独立的 RoPE 拼在一起"。**
不准确。M-RoPE 是**一个**旋转编码在维度分组上的分解：不同维度组用 t/h/w 各自的 position id 计算旋转角（Qwen2-VL-7B 为 `[16,24,24]` 分组），文本退化为 $(i,i,i)$ 与 1D RoPE 等价；且位置 id 数值小、利于长度外推。

**误区 3：Qwen2-VL 的 ViT 是冻结的。**
分阶段。阶段 1 主要训 ViT、阶段 2 全解冻、阶段 3 冻结 ViT 只训 LLM——"冻结"只是最后一个阶段的策略，且与第一代（阶段 1/3 冻结、只训 adapter）不同。

**误区 4：视觉 token 压缩越多越好。**
不对。2×2 合并是"几乎无损"的邻域冗余压缩；但过度压缩（如固定 256 token 承载超大图）会丢失小字细节。Qwen2-VL 用像素预算（min/max_pixels）在精度与成本间显式权衡。

**误区 5：28 对齐单位是为了凑整数。**
不只是。28 = patch 14 × merge 2，是"一个视觉 token 覆盖的像素边长"——对齐 28 保证合并后 token 网格是整数的、与 M-RoPE 的 (r, c) 坐标一一对应。这是结构约束，不是随便选的数字。
